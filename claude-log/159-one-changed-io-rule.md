# 159 — "차이 난 IO" 한 규칙: 히트맵 · 대시보드 · 그래프 목록 = 메인 칸 (1.68)

> 이거 히트맵쪽에 차이가 난 IO개수 뜨는거랑 메인이랑 다른거 같은데?

## 까닭

같은 "차이 난 IO" 를 화면마다 다른 계산으로 셌습니다.

| 화면 | 1.67 까지 셈 |
|---|---|
| 메인 칸 | 정상 판정 (모든 표본 · 양쪽 · 시간 여유 · 단계 맞춤 · 허용 반영) |
| 히트맵 | 칸 (1 분 등) 의 최대 오차가 허용 오차를 넘었는지 — 시간 여유 · 허용 없음 |
| 대시보드 · 그래프 목록 | 같은 시각끼리 비교 (2 만 점) — 시간 여유 · 허용 없음 |

예: 0.3 초 늦게 올라간 IO 는 판정에서는 정상 (시간 여유 안), 히트맵 · 대시보드에서는 차이. 메인에서 허용한 오차도 히트맵에는 그대로.

## 한 것

판정이 있으면 모두 **판정에서 허용 안 된 값 오차가 있는 IO** 로 셉니다 (`AppState.OpenValueIoKeys`).

```
 메인 칸 "차이 발생 N"  =  값 오차 IO  +  한쪽에만 있는 IO
 대시보드 차이 발생     =  메인과 같은 N  (아래 글에 둘로 나눠 적음)
 히트맵 "차이가 난 IO"  =  값 오차 IO  (한쪽에만 있는 IO 는 줄이 없어 요약에 "메인에는 k 개 더" 로)
 그래프 목록 차이 표시  =  값 오차 IO
```

- 히트맵 칸 색 · 퍼센트는 그대로 (칸마다 센 값). 줄로 올라오는지 · 수만 판정 기준
- 오차를 허용하면 대시보드 · 그래프 목록은 바로, 히트맵은 보고 있으면 바로 다시 셈

## 확인
- Linux: 테스트 1097 통과 (새 것: 메인 4 = 대시보드 4 = 히트맵 4, RAMP 는 어디서도 차이 아님, 허용하면 모두 3), 실제 csc 7.3 오류 0, 검사 스크립트 통과
- **Windows 에서 못 봄**: 대시보드 · 히트맵 요약 글이 길어져 줄이 넘치는지, 그래프 목록 색
- 남는 점: 히트맵에서 판정으로 차이인 IO 인데 칸은 모두 허용 오차 안 (예: 이전에만 있던 짧은 펄스가 칸 최대에 안 잡힘) 이면 줄은 있는데 빨간 칸이 없을 수 있음
