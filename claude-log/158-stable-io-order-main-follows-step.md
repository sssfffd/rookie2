# 158 — 그룹 안 IO 차례 고정 · 단계 맞춤이 메인 칸에도 (1.67)

> 이거 분석 1에서 단계 맞춤 했을때 그룹안의 IO순서들 바뀌는건 문제가 있다
> 그리고 메인화면에 뜨는 차이발생 개수 및 요약이 단계맞춤이나 다른 동작해서 IO차이가 없어졌을때 연동되게 해주셈

## 1. 그룹 안 IO 차례

| 어디 | 1.66 | 1.67 |
|---|---|---|
| 히트맵 (그룹으로 나눠 봄) | 그룹 안 = 차이 크기 순 → 단계 맞춤 등으로 차이가 바뀌면 뒤바뀜 | **그룹에 적힌 차례** |
| 히트맵 "그룹에 없는 IO" | 차이 크기 순 | **로그 열 차례** (이후에만 있는 IO 는 뒤) |
| 메인 칸 그룹 펼침 | 나쁜 것 먼저 | **그룹에 적힌 차례** ("묶지 않은 IO" 는 로그 열 차례) |
| 그래프 IO 목록 | 그룹에 적힌 차례 (원래 고정) | 그대로 |

## 2. 메인 칸 연동

까닭: 메인 칸의 수 = 정상 판정. 판정은 그래프에서 고른 단계와 **상관없게** 만들어 두어서
(1.63), 분석 1 에서 단계를 골라 맞춰 차이가 없어져도 메인 칸은 그대로였습니다.

```
 오차 = 단계 맞춤에서 벗어남 ∩ 전체 맞춤에서 벗어남 ∩ 분석 1 에서 고른 단계 맞춤에서 벗어남 (새로)
```

- 분석 1 에서 맞춰 없어진 차이 → 메인 칸 수 · 그룹 "N / M 달라짐" · 펼친 IO 줄 · LLM 판정 글에서도 없어짐. 풀면 돌아옴
- 그 맞춤으로 다른 단계가 어긋나 **새로 생기는** 차이는 메인 칸에 안 늘어남
- 그 밖의 동작 (시간 맞추기 · 손 밀기 · 시작 맞춤 · 허용 오차 · IO 별 허용 · 허용) 은 원래 판정에 들어가 연동됨

## 확인
- Linux: 테스트 1093 통과 (새 것: 고른 단계로 메인 칸 1 → 0 → 1, 히트맵 차례 · 메인 펼침 차례), 실제 csc 7.3 오류 0, 검사 스크립트 통과
- **Windows 에서 못 봄**: 단계 고를 때 판정을 다시 찾는 시간 (큰 로그에서 몇 초 — 진행 창), 히트맵 · 메인 펼친 차례 화면
- 남는 점: "이번만 허용" 은 오차 시작 시각으로 기억해서, 단계를 골라 오차 모양이 바뀌면 풀릴 수 있음 ("앞으로도 허용" 은 그대로)
