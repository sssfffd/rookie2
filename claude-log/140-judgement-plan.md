# 140 — 정상 판정 · 차이 분석: 정상 로그 하나로 어떻게 (학습은 나중)

> 그래서 정상 판정이나 차이 분석을 어떻게 하는게 좋을까 / 지금 여러 정상 로그를 학습시키는거는 공수가 많이들어서 많이 후순위임

(제안 — 코드 안 바꿈)

## 한 줄 요약
**"이전 = 정상 기준 1 개" 를 단계마다 맞춘 뒤, 시간 허용 띠로 차이를 찾고, 그 차이가 얼마나 · 어디서 · 무엇에서
났는지로 판정.** DTW · 학습 없이, 사람이 정하는 건 중요 표시 · 엄격도 둘 (139).

## 순서

```
 이전(정상) · 이후(검사)
   │
 1 단계로 자르고 짝짓기 ─────────────── (있음: StepPairs)  단계가 없으면 전체를 한 단계로
   │   단계 수 · 차례가 다르면 → 공정 이상 (FAIL)
 2 단계마다 시간 맞추기
   │   시작 맞춤 (있음) + 길이가 다르면 단계 안을 비례로 늘이고 줄임   ← "중간 동작 시간차" 흡수
   │   단계 길이 차가 크면 (보통 ±20 %) → WARNING "2 단계가 4.1 s 길어짐"
 3 IO 마다 시간 허용 띠로 "넘음" 찾기
   │   이후의 t 값이 이전의 [t−Δt, t+Δt] 최소~최대 ± 값 허용 오차 밖이면 넘음
   │   Δt = 단계 길이 2 % (0.5~5 s) × 엄격도         ← 작은 시간차 · 작은 오차 흡수
 4 Δt 보다 짧게 이어진 넘음은 지움 (순간 튐)
 5 정도 재기 — IO 마다: 넘은 시간 · 비율 · 가장 긴 연속 · 구간 수 · 어느 단계 · 최대 초과량
 6 IO 판정
   │   중요 IO: 넘음이 하나라도 남으면 FAIL (= Δt 넘게 이어진 차이)
   │   일반 IO: 비율 ≥ 20 % FAIL, ≥ 5 % WARNING, 아니면 PASS (× 엄격도)
   │   디지털 · 상태: 바뀌는 횟수 · 차례가 다르면 WARNING (중요면 FAIL)
 7 분석 1 판정 = 가장 나쁜 것 + 원인 상위 5 개
```

## 예 (60 분 로그, 보통)

| 상황 | 3~5 결과 | 판정 |
|---|---|---|
| 2 단계가 30 s 늦게 시작 · 모양 같음 | 시작 맞춤으로 사라짐 | PASS |
| 3 단계가 10 % 길어짐 · 모양 같음 | 비례로 늘여 사라짐, 단계 길이 차 10 % < 20 % | PASS |
| TEMP 가 시작 1 분만 다름 | 비율 1.7 % | PASS (정도는 적어 둠) |
| PRES 10 분 다름 | 비율 16.7 %, 가장 긴 연속 8 분, 2 · 3 단계 | WARNING |
| PRES 50 분 다름 | 83 % | FAIL |
| DOOR_LOCK(중요) 10 초 다름 | Δt(1.2 s) 넘게 이어짐 | FAIL |

## 왜 이 방식
- 단계 맞춤 + 비례 늘이기 + Δt 띠가 DTW 가 하던 일(시간 어긋남 흡수)을 하면서 **진짜 지연은 숨기지 않음** —
  얼마나 늘였는지가 그대로 "단계 길이 차" 로 남음.
- 계산은 IO 당 O(n) (구간 최소/최대를 미는 창으로) — 1000 만 칸도 지금 비교와 비슷한 시간.
- 판정 근거가 숫자 몇 개라 화면 · LLM 입력에 바로 "왜" 를 적을 수 있음.

## 만드는 차례 (제안)
1. 3~7 (띠 · 튐 지움 · 정도 · IO 판정 · 분석 1 판정) — 핵심. 지금 100 고정 점수도 여기서
2. 1~2 의 공정 검사 (단계 수 · 차례 · 길이) + 단계 안 비례 늘이기
3. 화면: 그룹에 "중요" 체크 · 설정에 엄격도 · 대시보드/메인 칸에 IO 판정과 정도
4. (나중) 정상 로그 여러 개로 Δt · 비율 배우기
