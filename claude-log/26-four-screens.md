# 26 — 화면을 넷으로. 메인과 분석 1·2·3

> 요청: "이거 큰 범위로 화면 4개 나눌꺼임
> 일단 프로그램 키면 위에 설정 로그 읽기 관련은 똑같이 뜨는 메인화면으로
> 메인화면에선 3가지가 뜨는데 각각 1 2 3 분석 결과로 나타나는 점수
> 그리고 점수를 클릭했을 때 해당화면으로 넘어가게
> 지금까지 개발한게 분석 1번임 … 2번 3번 화면 전환시에는 지금 빈화면으로
> 냅두면됨 / 그리고 왼쪽위에 현재 logscope를 누르면 각각의 화면으로 전환할
> 수 있게끔 목록들이 떠야됨"

---

## 1. 화면 전환이 두 겹이 됐습니다

```
큰 화면 (Screen)
├─ 메인          ← 켜면 여기부터
├─ 분석 1  ── 안에서 다시 ─→ 대시보드 / 그래프 / 히트맵  (Page)
├─ 분석 2        ← 빈 화면
└─ 분석 3        ← 빈 화면
```

**한 겹으로 합치지 않았습니다.** 대시보드·그래프·히트맵은 같은 로그 한 쌍을
세 가지로 보는 것이라 서로 상태를 나눠 씁니다 — 고른 IO, 확대 상태,
시간 맞추기. 분석 1·2·3 은 그런 사이가 아닙니다. 같은 줄에 늘어놓으면
나중에 분석 2 를 만들 때 "이 IO 선택이 어느 화면 것인가" 가 엉킵니다.

그래서 `Screen` 과 `Page` 를 따로 뒀습니다.

---

## 2. 위 줄

**설정 · 로그 읽기 쪽은 그대로**입니다. 어느 화면에 있든 로그를 열고 세트를
바꾸고 설정을 볼 수 있습니다.

바뀐 것은 둘입니다.

### [LogScope] 가 단추가 됐습니다

누르면 화면 목록이 내려옵니다.

```
[LogScope ▾]  분석 1 — 로그 비교   v0.26
   ↓
 ┌────────────────────────┐
 │ 화면                    │
 │ 1.  메인                │
 │ 2.  1번 화면 — 로그 비교 │
 │ 3.  2번 화면            │
 │ 4.  3번 화면            │
 └────────────────────────┘
```

옆에 **지금 어느 화면인지**를 적어 둡니다. 화면이 넷이 되면 위 줄만 보고는
어디 있는지 알기 어렵습니다.

목록을 접어 둔 이유는 자리 때문입니다. 분석이 늘어날 때마다 위 줄에 단추를
하나씩 더하면 로그 단추들이 아래로 밀립니다.

> 팝업을 연 단추를 다시 누르면 팝업이 먼저 닫히고 그 다음 Click 이 도착해
> 또 열립니다. 가로축·시간 맞추기 판에서 겪은 그 자리라, 같은 방법으로
> 막았습니다 — 방금 닫혔으면 그 한 번은 무시합니다.

### [대시보드] [그래프] [히트맵] 은 분석 1 에서만 보입니다

다른 화면에서도 보이면 눌러 놓고 왜 안 바뀌나 하게 됩니다.

`F1` `F2` `F3` 은 반대로 했습니다 — **어느 화면에 있든** 분석 1 의 그 화면으로
데려갑니다. "그래프 보여 줘" 라는 뜻인데 아무 일도 안 일어나면 단축키가
고장 난 것처럼 보입니다.

`Esc` 는 목록이 열려 있으면 닫고, 아니면 메인으로 돌아갑니다.

## 3. 메인 화면

분석 셋을 칸으로 늘어놓고 점수를 크게 적습니다.

```
┌──────────────────────┐ ┌──────────────────────┐ ┌──────────────────────┐
│ [분석 1]  로그 비교    │ │ [분석 2]  분석 2      │ │ [분석 3]  분석 3      │
│                      │ │                      │ │                      │
│  100 점              │ │  100 점              │ │  100 점              │
│  만점 (100점 만점)    │ │  아직 만들지 않았습니다│ │  아직 만들지 않았습니다│
│                      │ │                      │ │                      │
│ 이전 로그와 이후 로그를│ │ 아직 정해지지 않았습니다│ │ 아직 정해지지 않았습니다│
│ 견줍니다. 대시보드 ·   │ │                      │ │                      │
│ 그래프 · 히트맵.       │ │                      │ │                      │
└──────────────────────┘ └──────────────────────┘ └──────────────────────┘
```

**칸 전체가 단추입니다.** 요청은 "점수를 누르면" 이었는데, 점수 글자만
눌리게 하면 과녁이 너무 작습니다. 칸 어디를 눌러도 같은 자리로 가고,
점수도 그 안에 들어 있습니다.

### 점수는 아직 계산하지 않습니다

모두 만점입니다. 분석마다 무엇을 어떻게 점수로 매길지 아직 정해지지
않았는데, 그 전에 아무 수식이나 넣어 두면 **그 수가 진짜인 줄 알고 읽게
됩니다.** 화면에도 그렇게 적어 뒀습니다.

나중에 채울 자리는 `MainVm.Refresh()` 한 곳입니다.

```csharp
public void Refresh()
{
    for (int i = 0; i < Cards.Count; i++) Cards[i].Score = AnalysisCardVm.MaxScore;
    ...
}
```

아직 만들지 않은 분석 2·3 은 **점수를 흐린 색으로** 둡니다. 만점이라고
초록색으로 크게 적어 놓으면 뭔가 재서 나온 수인 줄 압니다.

## 4. 분석 2·3

빈 화면입니다. 다만 진짜로 아무것도 안 그리면 프로그램이 멈춘 것처럼
보여서, 어디인지와 어떻게 나가는지만 적어 뒀습니다.

```
            분석 2
     아직 만들지 않았습니다.

  왼쪽 위 [LogScope] 를 누르면
  다른 화면으로 넘어갈 수 있습니다.
```

두 화면이 같은 `PlaceholderView` 하나를 씁니다. 이름만 바꿔 끼웁니다.

## 5. 새로 만든 것

| 파일 | 하는 일 |
|---|---|
| `ViewModels/AnalysisCardVm.cs` | 분석 칸 하나 — 번호 · 이름 · 점수 |
| `ViewModels/MainVm.cs` | 칸 셋과 점수 다시 세기 |
| `Views/MainView.xaml` | 메인 화면 |
| `Views/PlaceholderView.xaml` | 아직 없는 분석 화면 |
| `Themes/Controls.xaml` | `CardButton`(누를 수 있는 칸), `BrandButton`, `MenuItemButton` |

`ShellVm` 에 `Screen` 과 `ScreenChanged` 가 붙었고, 히트맵을 처음 열 때
한 번 계산하는 자리는 `EnsureHeatmap()` 한 곳으로 모았습니다 — 큰 화면과
안쪽 화면 둘 다 그 자리를 거치는데, 조건이 같은데 두 군데에 적어 두면
한쪽만 고치게 됩니다.

## 6. 확인한 것 / 못 한 것

- C# 은 컴파일해서 확인했습니다 (테스트 275 통과, 그대로).
- **화면 모양은 확인하지 못했습니다.** 이번 건 거의 전부 XAML 이고, XAML 은
  여전히 윈도우에서만 컴파일됩니다. 칸 크기 · 팝업 자리 · 좁은 창에서의
  줄바꿈은 실제로 띄워 봐야 압니다.
- 새 뷰모델(`MainVm` · `AnalysisCardVm`)은 App 프로젝트라 테스트가 닿지
  않습니다. 점수가 실제로 뭔가를 재기 시작하면 그 계산은 Core 로 내려서
  테스트를 붙이는 편이 맞습니다.
