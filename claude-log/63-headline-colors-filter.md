# 63 — 세 숫자 · 줄 색 · 걸러 보기 · SQL 출력 (0.82)

## 주신 말

> db분석에서 표2개중이란 말 빼고
> 차이 발생 : (개수)개 없어진 IO : (개수)개 새로 생긴 IO : (개수)개로 나타내줘
> 그리고 List에서 value 차이 발생 시 빨간 색 / v1 혹은 v2 차이 발생시
> 노란색으로 칠해주고
> 차이가 발생한 IO만 보기 기능도 추가해줘
> SQL 저장 대신 sql문 출력으로 바꿔주고

---

## 1) 화면 위 한 줄을 바꿨습니다

```
전:  표 2 개 중  달라짐 1 · 이전에만 0 · 이후에만 1 · 같음 0      (읽은 행 …)
후:  차이 발생 : 2개      없어진 IO : 1개      새로 생긴 IO : 1개      (읽은 행 …)
```

**IO 를 셉니다 (줄이 아닙니다).** 한 IO 가 세 열에서 달라지면 줄은 세
개지만 **1 개**로 셉니다. 줄을 세면 "차이 발생 12 개" 인데 실제 IO 는
3 개인 일이 생기고, 그러면 보는 사람이 수를 믿을 수 없게 됩니다.

세는 일과 글자는 **Core 에 뒀습니다** (`DbDiffList.Count` ·
`DbDiffList.Headline`). 화면에서 셈을 또 짜면 걸러 보기를 켰을 때 수가
달라집니다.

(읽은 행 수는 남겼습니다 — "0 개" 가 나왔을 때 "읽긴 읽었나" 를 답해
주는 숫자라서입니다.)

## 2) 줄 색

| 색 | 언제 |
|---|---|
| **빨강** (옅게) | value 가 달라진 줄 |
| **노랑** (옅게) | `v1` · `v2` 가 달라진 줄 |
| 안 칠함 | 생기거나 없어진 줄, 표·열 줄 |

목록 머리 줄에 **색 설명**을 함께 넣었습니다. 색만 칠해 두고 말을 안
하면 읽을 수가 없습니다.

생기거나 없어진 줄을 칠하지 않은 이유: 그건 "값이 달라진" 것이 아니고
**위 요약에서 따로 세어 보여 줍니다.** 같은 것을 두 가지 방법으로
알려 주면 수가 안 맞아 보일 때 어느 쪽이 맞는지 알 수 없습니다.

### 어느 열을 v1 · v2 로 볼지는 한 곳입니다

```csharp
// src/LogScope.Db/DbNames.cs
public static readonly string[] SideColumns = { "v1", "v2" };
```

설비 DB 의 열 이름이 다르면 **이 한 줄**만 고치면 됩니다. 색을 정하는
쪽도 화면도 이 배열을 봅니다. 시험으로 확인했습니다 — 이 배열을
`{ "zz" }` 로 바꾸면 노란 줄이 0 개가 되고 빨간 줄이 3 개가 됩니다.

### 여기서 함정 하나를 먼저 고쳐야 했습니다

줄 모양(`ListRow`)의 템플릿이 배경을 `Transparent` 로 **박아** 두고
있었습니다. 그러면 줄마다 색을 주려고 `Background` 를 넘겨도 **아무 일도
안 납니다** — 템플릿이 그 값을 안 보기 때문입니다. `TemplateBinding` 으로
받게 고쳤습니다.

마우스 올림·고름은 템플릿 트리거가 직접 칠하므로 줄 색보다 앞섭니다 —
**칠한 줄도 고르면 고른 표시가 보입니다.**

## 3) 차이가 발생한 IO만 보기

목록 머리에 체크 칸을 넣었습니다. 켜면 **칠한 줄(빨강 · 노랑)만**
남고, 생기거나 없어진 줄과 표·열 줄은 감춥니다.

감춘 것이 "없는 것" 으로 읽히면 안 되므로 둘을 지킵니다.

- 켜 둔 동안에도 **위의 세 숫자는 전체 기준 그대로**입니다
- 줄 수 옆에 `(걸러 보는 중 · 전체 N 줄)` 이라고 적습니다

`[목록 CSV 저장]` 은 **걸러 보는 중이어도 전체**를 내보냅니다 (알림
줄까지). 설명 글도 그렇게 고쳤습니다 — 전에는 "지금 보이는 목록" 이라고
적혀 있었는데, 걸러 보기가 생기면서 그 말이 거짓이 됐습니다.

## 4) SQL 저장 → SQL 문 출력

`[SQL 문 출력]` 이 창을 띄웁니다. 그 창에 `[글 복사]` 와
`[파일로 저장]` 이 있습니다.

0.79 까지는 화면 아래에 글 칸이 붙어 목록 높이를 늘 반 가져갔고,
0.80 에서 그걸 없애고 **보지도 않고 바로 파일로 저장**하게 했습니다.
그게 이상했습니다 — 이 글은 사람이 읽어 보고 직접 돌리는 것입니다.

창은 `src/LogScope.App/Common/TextViewWindow.xaml` 입니다. 글을
만드는 쪽과 보여 주는 쪽을 나눠 두었으므로 다른 화면에서도 씁니다.
