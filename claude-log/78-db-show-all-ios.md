# 78 — "모든 IO 보기" 가 되게 · 요약 칸은 달라진 IO 목록으로

> 그리고 분석2에서 모든 io보는거랑 차이 있는 io보는거중에 차이있는 io만
> 보여지고 있음
>
> 그리고 요약칸이 분석1처럼 여러 그룹으로 나누지 말고 하나만해서 차이난
> io만 쭉 보여줬으면 좋겠음 해당 io누르면 이동하게 하고

## 1. 왜 "모든 IO" 가 안 됐나 — 체크박스가 아니라 그 아래였습니다

체크박스는 멀쩡했습니다. **견주는 쪽이 차이만 담고 있었습니다.**

```csharp
// DbDiff — 행 하나를 견준 뒤
if (changed.Count == 0) continue;     // ← 같으면 아무것도 안 남김
```

같은 행은 **아예 기록되지 않았습니다.** 그러니 화면에서 무엇을 어떻게
걸러도 차이 난 IO 만 나옵니다 — 걸러 보기를 꺼도 똑같았습니다. 이름이
`[차이가 발생한 IO만 보기]` 라서 "끄면 모든 IO" 로 읽히는데, 끈 상태는
**차이 전체**(값 차이 + 생김/없어짐 + 열 차이)였을 뿐입니다.

같은 IO 가 목록에 없으면 **"이 IO 는 봤는데 괜찮았다" 를 확인할 길이
없습니다.** 안 본 것과 보고 같았던 것이 똑같이 안 보입니다.

### 고친 것

- `TableDiff.SameRows` — 같은 행도 담습니다. **차이 목록과 따로** 담습니다:
  한 통에 담으면 같은 줄이 상한을 다 먹고 차이가 밀려 나갑니다.
- 상한 **2 만 개/표**. 넘으면 담기를 그치고 알림에 적습니다 (`RowsSame` 은
  담은 수보다 클 수 있습니다 — 센 것과 담은 것을 따로 둡니다).
- `DbDiffList.Options.IncludeSame` — 켜면 같은 줄도 목록에 나옵니다.
  **차이 뒤에** 붙입니다 (섞으면 차이를 눈으로 찾아야 합니다).
- 같은 줄은 **행 하나에 한 줄**입니다. 값 열이 하나뿐인 표(.csv 로 읽은 IO
  표가 그렇습니다)는 그 값을 적고, 여러 열이면 행 전체를 한 칸에 적습니다 —
  같은 값을 열 수만큼 적으면 목록이 그것만으로 찹니다.
- 차이가 하나도 없는 **표**도 "모든 IO" 에서는 보입니다 (전에는 표째
  건너뛰었습니다).

### 화면 — 셋 중 하나로

```
보기  (값이 달라진 것만) (차이 전체) (모든 IO)
```

이름으로 셋을 적어 두면 "끈 상태가 무엇인가" 를 짐작할 일이 없습니다.

어느 보기든 **위의 세 숫자와 판정은 그대로**입니다 — 보기를 바꿀 때마다
PASS/WARNING/FAIL 이 흔들리면 안 됩니다. 시험으로 못을 박았습니다.
CSV 저장은 **보고 있는 것과 같은 범위**로 바꿨습니다 (화면과 파일이 다르면
어느 쪽이 참인지 알 수 없습니다).

## 2. 메인 화면 요약 칸 — 달라진 IO 를 한 줄씩

```
전 (0.94)              후 (0.98)
요약                   요약
● 차이 발생   12개      ● TEMP_MAX
● 없어진 IO    3개      ● PRES_SET
● 새로 생긴 IO 0개      ● VALVE_1
● 달라진 IO            ● FLOW_SET
  TEMP_MAX, PRES_…     ● 외 8개 더
```

분석 1 처럼 묶음으로 가르지 않습니다. 분석 2 에는 그룹이 없고, 보는 사람이
찾는 것은 "어느 IO 가 달라졌나" 하나입니다. **수는 낱말 아래 한 줄이 이미
적습니다** (차이 발생 12개 · 없어진 IO 3개 …).

**줄을 누르면 분석 2 화면으로 넘어가 그 IO 의 줄을 골라 줍니다.** 화면만
열면 수백 줄 가운데서 다시 찾아야 하니, 그러면 누른 뜻이 없습니다.

60 개까지 적고 넘으면 "외 N개 더" 한 줄이 붙습니다 (그 줄은 누를 것이
없어서 잠깁니다). 달라진 IO 가 없으면 "값이 달라진 IO 가 없습니다" 가
적히고, 없어진·새로 생긴 IO 가 있으면 그 수도 같이 적습니다.

이름을 모으는 상한이 둘이 됐습니다 — 한 줄에 늘어놓는 쪽은 여덟 개
(`DbVerdict.MaxNames`), 요약 칸에 줄로 적는 쪽은 예순 개(`MaxListIos`).
자르는 자리를 `DbVerdict.Why` 안으로 넣어서 "외 N 개" 가 어긋나지 않게
했습니다 — 긴 목록을 넘겨도 한 줄은 여덟 개까지만 씁니다.

## 시험

`통과 817 / 실패 0` (+16).

| 무엇 | 왜 |
|---|---|
| 같은 행을 세고 담는지 | 안 담으면 "모든 IO" 가 성립하지 않습니다 |
| 차이만 = 1 줄, 모든 IO = 3 줄 | 눈으로는 "원래 이것뿐인가" 와 구별이 안 됩니다 |
| 같은 줄은 `같음` 이고 칠하지 않음 | 칠하면 차이로 읽힙니다 |
| 같은 줄이 차이 **뒤에** 오는지 | 섞이면 차이를 눈으로 찾아야 합니다 |
| 보기를 바꿔도 센 수가 같은지 | 판정이 흔들리면 안 됩니다 |
| 차이 없는 표도 모든 IO 에 나오는지 | 표째 건너뛰고 있었습니다 |
