# 57 — 같은 눈으로 나머지를 훑음 (0.76)

## 주신 말

> 응 다른 곳도 살펴봐

0.75 에서 "표시명 하나 바꾸는데 파일 네 개" 를 고쳤고, 같은 눈으로
저장소 전체를 보기로 했습니다. 눈으로 훑지 않고 세었습니다.

## 어떻게 재었나

두 가지를 기계로 세었습니다.

1. **같은 글자가 여러 파일에 적힌 자리** — 147 군데 (한글이 든 것 78)
2. **그중 한쪽이 그 글자를 비교하는 자리** — 이게 진짜 문제입니다

1 번만으로는 못 가립니다. "닫기" 가 세 창에 적혀 있는 건 문제가 아닙니다
(같은 글자지만 서로 상관없는 단추입니다). 2 번이 다릅니다 — **한 파일이
쓰고 다른 파일이 견주는 글자**는, 한 군데만 고쳤을 때

- 컴파일이 됩니다
- XAML 파싱도 됩니다
- 시험도 통과합니다
- 그리고 화면에서 **색만 조용히 안 나옵니다**

이게 이 저장소에서 제일 비싼 고장 종류입니다. 0.59 의 드롭 칸 색 문제도
이 종류였습니다.

## 찾은 것 — 다섯

| 글자 | 쓰는 곳 → 견주는 곳 | 어긋나면 |
|---|---|---|
| `same` `changed` `onlyBefore` `onlyAfter` | ChannelListVm → IoRowVm + **GraphView.xaml 트리거 3** | IO 목록의 줄 색이 안 나옴 |
| `good` `warn` `bad` (점수 등급) | ScoreBands(상수 있었음) → **MainView.xaml 트리거 12** | 점수 칸 색이 안 나옴 |
| `none` `bad` `good` `same` (지난번 대비) | HistoryRowVm → **MainView.xaml 트리거 3** | 저장 결과 숫자 색이 안 나옴 |
| `표` `열` `행` `알림` / `생김` `없어짐` `달라짐` `자리` | DbCompare 10 곳 → DbVm + 시험 8 곳 | 알림이 목록에 섞여 나옴 |
| `raw` `delta` (세로 눈금) | AppSettings 3 곳 → GraphVm 4 곳 → 시험 3 곳 | 눈금 단추가 안 켜짐 |

여기에 둘 더.

| 자리 | 무엇 |
|---|---|
| `Tag="before\|Brush.Window"` | **두 파일이 각자 손으로 쪼개고 있었습니다** (`Lit()` 이 글자만 다른 같은 코드 두 벌) |
| `AssemblyInfo.cs` | 프로그램 이름·설명이 `AppConfig` 기본값과 따로 또 적혀 있었습니다 |

트리거 18 군데가 XAML 에 글자로 박혀 있었습니다. **여기서는 XAML 이 컴파일되지
않으므로**, 이 글자들은 지금까지 아무도 봐 주지 않았습니다.

## 고친 것

### 1) 글자는 상수로, XAML 은 x:Static 으로

```
IoRowVm.StatusSame / StatusChanged / StatusOnlyBefore / StatusOnlyAfter
HistoryRowVm.DeltaNone / DeltaBad / DeltaGood / DeltaSame
DbDiffLine.KindTable / KindColumn / KindRow / KindNote
DbDiffLine.ChangeAdded / ChangeGone / ChangeDiff / ChangeMoved
AppSettings.ScaleRaw / ScaleDelta
BoolToVisibility.Invert
```

XAML 트리거 18 군데가 이 상수를 읽습니다:

```xml
<DataTrigger Binding="{Binding Status}" Value="{x:Static vm:IoRowVm.StatusChanged}">
```

**갈래·구분은 config.txt 로 바꾸지 않습니다.** 칸 *이름* 은 0.75 에서 설정으로
뺐지만(`db.col.v1`), 이 글자는 **견주는 값**입니다. 견주는 값을 설정으로
바꾸게 하면 그 순간 견주기가 깨집니다. 이건 일부러 다르게 뒀습니다.

### 2) 끌어다 놓는 칸: `Infrastructure/CardTag.cs` 한 곳

`Tag` 를 쪼개고 칸을 밝히고 되돌리는 일이 메인 화면과 DB 화면에 두 벌
있었습니다 (`Lit()` 두 개가 거의 글자 단위로 같았습니다). 한 곳으로 모으고,
모르는 쪽 글자는 조용히 '이후' 로 보지 않고 디버그 빌드에서 걸리게 했습니다 —
오타가 단추를 반대쪽으로 들게 하는 것보다 낫습니다.

### 3) 검사기 규칙 둘 (XAML 이 컴파일 안 되는 자리를 메움)

- **x:Static 이 가리키는 상수가 실제로 있는가.** 타입은 파일 이름이 아니라
  `class` 선언으로 찾습니다 (`ScoreBands` 는 `AnalysisCardVm.cs` 안에 있습니다).
- **XAML 의 Tag 글자를 코드가 아는가.**

둘 다 일부러 깨뜨려 실제로 잡는지 봤습니다:

```
x:Static 대상 없음 IoRowVm.StatusChangedd <- Views/GraphView.xaml
x:Static 대상 없음 ScoreBands.GradeWarning <- Views/MainView.xaml
Tag 글자를 코드가 모름 "aftr" <- Views/MainView.xaml
```

### 4) 검사기가 눈을 감던 자리

놓는 칸의 되돌릴 배경을 보는 규칙(0.59 에서 만든 것)은 **코드 비하인드에
`SetResourceReference` 글자가 있는 화면만** 봤습니다. 그 줄을 `CardTag` 로
옮기자 두 화면을 조용히 건너뛰게 됐습니다. 제가 만든 리팩터링이 제가 만든
검사기를 껐습니다 — 조건을 고치고, 일부러 어긋나게 해서 다시 잡는 것을
확인했습니다.

### 5) 시험 하나 더

`갈래·구분은 정해 둔 글자뿐` — 목록의 모든 줄이 정해 둔 여덟 글자 안에
있는지 봅니다. 나중에 누가 상수 대신 글자를 손으로 적어 넣으면 걸립니다
(일부러 `Kind = "행 "` 으로 적어 넣어 시험이 실패하는 것을 봤습니다).

## 고치지 않은 것 — "이전 / 이후"

가장 많이 나온 글자입니다 (40 군데, 파일 10 개). **일부러 안 모았습니다.**

v1 과 다릅니다. v1 은 **칸 머리글 하나**가 네 군데 적혀 있었고, 그중 하나가
견주는 자리였습니다. "이전 / 이후" 는 대부분 **문장 속의 낱말**입니다 —
"이전 로그를 열어 주세요", "이전 DB 를 이후와 같게 만드는 글". 이걸 한 곳에
모으면 문장이 전부 `Names.Before + " 로그를 열어 주세요"` 같은 이어붙이기가
되고, 그건 0.74 에서 지적하신 "사람이 보기 힘든 코드" 쪽으로 가는 길입니다.

그리고 **조용히 깨지지 않습니다.** 한 군데를 빠뜨리면 화면에 낱말이 섞여
보이므로 바로 압니다. 바꿀 일이 생기면 찾아 바꾸기로 충분합니다.

바꾸고 싶어지시면 말씀해 주세요 — 낱말 두 개만 config.txt 로 빼고, 문장은
그대로 두는 중간 방법도 있습니다.

## 숫자

|---|---|---|
| 우리가 만든 글자를 손으로 견주는 자리 | 10 | 0 |
| XAML 에 글자로 박힌 트리거 | 18 | 0 |
| `Tag` 를 손으로 쪼개는 코드 | 4 (2 파일) | 1 (CardTag) |
| 검사기 규칙 | 6 | 8 |
| 시험 | 642 | 643 |

남은 글자 견주기는 **글자가 곧 형식인 것들**뿐입니다: config.txt 의 열쇠
(`name`, `db.before` …), 로그의 참·거짓 낱말(`TRUE`, `ON` …), xlsx 안의
XML 이름. 이건 우리가 정한 이름이 아니라 파일 형식이라, 한 곳(파서)에
있는 것이 맞습니다.

## 확인한 것 · 못 한 것

- `통과 643 / 실패 0`, 검사기 넷 지적 없음
- 새 규칙 셋은 일부러 깨뜨려 잡는 것을 확인했습니다

  실제로 같은 색을 내는지. XAML 은 여기서 컴파일되지 않습니다.
  색이 안 나오는 칸이 보이면 그 자리를 알려 주세요.
