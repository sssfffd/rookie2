# 29 — 칸마다 요약, 이동은 화살표로, 그룹을 누르면 히트맵으로

> 요청: "메인화면에서 분석 1,2,3밑에 요약 넣어 주는게 좋을 꺼 같음
> 그리고 메인화면의 전체 요약 없애고
> 분석 칸 클릭하면 이동하는게 아니라 오른쪽 위에 이동 화살표 만들어서
> 그거 누르면 이동하게 하곰
> 아래 요약칸에 그룹들 별로 요약내용 넣을꺼거든? 해당 그룹 클릭하면
> 그 그룹 관련 IO 히트맵으로 이동할 수 있게 만들어줘"

---

## 1. 요약이 칸 안으로 들어왔습니다

화면 아래에 따로 있던 **전체 요약 칸은 없앴습니다.** 대신 분석 칸마다
그 아래에 요약을 답니다.

```
┌─────────────────────────────┐
│ [분석 1] 로그 비교      [↗] │
│                             │
│  100 / 100                  │
│  만점                       │
│                             │
│ 견준IO  달라진  한쪽에만     │
│  184개   12개     3개        │
│                             │
│ ┌ 요약 ───────────────────┐ │
│ │ ● 밸브 묶음   0 / 12 달라짐│ │
│ │   미구현                  │ │
│ │ ● 압력 계통   3 / 8 달라짐 │ │
│ │   미구현                  │ │
│ │ ● 온도 계통   9 / 10 달라짐│ │
│ │   미구현                  │ │
│ └─────────────────────────┘ │
└─────────────────────────────┘
```

그룹 줄 **아래 한 줄**은 "어떤 차이가 났는지" 를 적을 자리입니다.
지금은 비어 있고 `미구현` 이라고만 적혀 있습니다 — 4 장을 보세요.

전체 요약이 하나 있을 때보다 이쪽이 맞습니다. **요약할 내용이 분석마다
다르기 때문입니다.** 분석 2·3 이 생기면 각자의 요약이 그 칸에 붙습니다.

---

## 2. 그룹별로 셉니다

그룹은 설정에 담긴 것을 그대로 씁니다 (그래프 화면 왼쪽에서 묶는 그것).
각 줄은 **그 그룹의 IO 중 몇 개가 달라졌는지**입니다.

```
0 / 12 달라짐   ← 초록. 이 묶음은 멀쩡합니다
3 / 8  달라짐   ← 노랑. 몇 개 어긋났습니다
9 / 10 달라짐   ← 빨강. 절반 넘게 어긋났습니다
```

### "묶지 않은 IO" 줄을 붙입니다

어느 그룹에도 안 담긴 IO 가 남으면 줄을 하나 더 붙입니다. 이걸 빼 버리면
칸의 `달라진 IO 12개` 와 요약의 합이 안 맞습니다. 그러면 **어느 쪽이 틀린
건지 알 수가 없습니다.**

그룹에 담겨 있어도 **이 로그에 없는 IO 는 세지 않습니다.** 그룹은 로그보다
오래 살아남는 것이라(설정에 저장됩니다), 예전 설비의 IO 가 그대로 남아
있을 수 있습니다.

---

## 3. 이동은 오른쪽 위 화살표만

칸 전체가 단추이던 것을 되돌렸습니다. **칸 안에 누를 것(그룹 줄)이
생겼는데, 바깥까지 단추면 그룹을 누른 손이 칸도 같이 누릅니다.**
Click 은 위로 올라가는 사건이라 그냥 겹칩니다.

그래서 이동은 오른쪽 위의 작은 `↗` 만 맡습니다. 마우스를 올리면 파랗게
차서 눌리는 것이 보입니다.

---

## 3-2. 그룹 줄 아래 — 어떤 차이가 났는지

그룹 줄마다 그 아래에 한 줄을 비워 뒀습니다.

```
● 압력 계통          3 / 8 달라짐
  미구현                              ← 여기
```

**무엇을 어떤 말로 적을지 아직 정해지지 않았습니다.** "밸브 3 개가 늦게
열림" 처럼 사람이 읽는 문장이 될 텐데, 그걸 무엇으로 판단할지가 먼저입니다.

**미리 자리를 잡아 두는 이유**는 나중에 글이 들어올 때 줄 높이가 달라져
목록이 통째로 다시 접히지 않게 하려는 것입니다. 지금 비워 뒀다가 나중에
넣으면 그룹 목록의 높이 상한도 같이 다시 잡아야 합니다.

글은 여러 줄이 될 수 있어서 줄바꿈을 켜 뒀고, 그룹 이름 아래에 붙도록
점 자리만큼(15) 들여 썼습니다. 이 줄을 눌러도 그룹 줄을 누른 것과 같습니다 —
한 덩어리가 통째로 단추입니다.

채울 자리는 `GroupSummaryVm.SetDetail()` 한 곳입니다.

---

## 4. 그룹을 누르면 히트맵으로 — 그 그룹만

여기가 이번 작업에서 실제로 손이 간 곳입니다.

그냥 히트맵으로 넘어가기만 하면 **수백 줄 가운데서 그 그룹을 다시 찾아야
합니다.** 넘어온 뜻이 없습니다. 그래서 히트맵이 **이름으로 추릴 수 있게**
만들었습니다.

```csharp
public HashSet<string> OnlyNames;   // 비어 있으면 모두
```

- **느슨하게 맞춥니다** (공백·대소문자·`_ - .` 무시). 그룹은 사람이 손으로
  담는 것이라 로그의 이름과 살짝 다를 수 있는데, 그 규칙(`LooseKey`)은
  채널을 찾을 때 이미 쓰고 있습니다.
- **빈 목록은 "추리지 않음"** 입니다. 실수로 빈 목록이 들어왔을 때 아무것도
  안 남으면, 화면이 비어 버리고 왜 비었는지 알 수가 없습니다.

넘어가면 위에 띠가 뜹니다.

```
┌────────────────────────────────────────────────────┐
│ "압력 계통" 그룹의 IO 8개만 보고 있습니다. [모든 IO 보기] │
└────────────────────────────────────────────────────┘
```

**추리고 있다고 말해 주지 않으면 "IO 가 왜 이것밖에 없지" 가 됩니다.**

### 넘어가기 전에 추립니다

```csharp
_vm.Screen = ShellVm.ScreenAnalysis1;
_vm.GoHeatmap();
Heatmap.FocusGroup(e.GroupName, e.Members);
```

화면을 먼저 바꾸면 `OnPageChanged` 가 추리기 전의 조건으로 한 번 계산해
버립니다. 전체를 그렸다가 곧바로 다시 그리게 되는데, IO 가 수백 개면 그
한 번이 눈에 띕니다. 그래서 `FocusGroup` 이 직접 다시 계산합니다.

---

## 5. 자체 테스트

추리기는 화면 없이 도는 계산이라 Core 에서 진짜로 돌렸습니다
(328개 통과, 9개 늘었습니다).

| 테스트 | 확인하는 것 |
|---|---|
| `HeatmapNameFilter` | 추리기 전에는 셋 다 나오는지, 둘만 고르면 둘만 남고 `견준 수`도 같이 줄는지, 안 고른 것이 빠지는지, **이름이 살짝 달라도**(`밸브A`, `압력_PT01`) 붙는지, **빈 목록은 추리기가 아니어서** 전부 남는지 |

그룹별로 세는 것(`MainVm.BuildGroups`)과 화면은 App 프로젝트라 테스트가
닿지 않습니다. 코드로만 확인했습니다.

### 아직 확인 못 한 것

화면 모양은 여전히 윈도우에서만 확인됩니다. 특히 칸이 셋으로 나뉜 상태에서
요약 줄이 읽을 만한 폭인지 — 그룹 목록에는 높이 상한(118)을 걸어 칸이
늘어나지는 않게 해 뒀습니다.
