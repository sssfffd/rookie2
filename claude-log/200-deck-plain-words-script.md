## 요청 (요청 227)

> 이거 발표자로에 인코딩/ 시간축 배치 적혀있는거 이해가 잘 안가는데 어떻게 바꾸지
> 청자가 이해하기 쉬운걸로 바꿔야함
> 그리고 시간 정렬 오차 띠 양방향 등 IO 이상 발생 여부 아는거 어떤게 어떻게 사용됬는지 설명해주셈(내가 말해야해)

## 바꾼 말

| 전 | 후 |
|---|---|
| 로그 파서 · 인코딩 · 시간축 · 배치 | 로그 읽기 · 시간 · IO 열 자동 인식 |
| 덤프 파서 · .sql · .csv · 실행 없음 | DB 파일 읽기 · 내용만 읽음 (실행 안 함) |
| 판정 엔진 · 시간 정렬 · 오차 띠 · 양방향 | 판정 엔진 · 시점 맞춤 · 허용 범위 · 양쪽 확인 |
| 구조 비교 · 표 → 열 → 행 · 키 짝 | 설정값 비교 · 표 → 항목 → 값 순서로 |
| 파싱 (공통): 인코딩 판별 BOM → ASCII → UTF-8 → CP949 … | 파일 읽기 (공통): 한글이 깨지지 않게 저장 방식을 스스로 알아냄 · IO 가 가로든 세로든 시간 열이 어디든 자동으로 찾음 · 큰 파일도 한 번만 읽음 · DB 파일은 명령을 실행하지 않음 |
| 시간 맞추기 / 허용 오차 띠 / 양방향 검사 / 점수화 | 시점 맞추기 / 허용 범위 만들기 / 양쪽에서 확인 / 판정 · 점수 (설명도 쉬운 말로) |

2 장 발표자 메모에 아래 대본을 넣음.

## 발표 대본 (IO 이상을 찾는 법)

1. **시점 맞추기** — 이후 로그는 몇 초 늦게 시작하거나 중간 단계가 늘 수 있어, 먼저 두 로그의 "같은 순간" 을 맞춤.
   기준: 로그 시작 · 특정 신호가 켜지는 순간 · 같은 이름 공정 단계의 시작 (단계가 있으면 단계마다).
2. **허용 범위 만들기** — 한 점끼리 비교하면 표본 간격 때문에 생기는 아주 작은 어긋남도 차이로 잡힘. 그래서 이전 로그가
   그 시각 앞뒤 잠깐 (단계 길이의 2 %, 최대 5 초) 동안 가진 최솟값 ~ 최댓값을 정상 범위로 잡고, 허용 오차 (% · 절대값 · IO별) 만큼 넓힘.
3. **양쪽에서 확인** — 이후 값이 범위 밖 → 값이 다름. 거꾸로 이전 로그를 이후 로그의 범위에 대 보면 이전에 있던 짧은 펄스가
   이후에 사라진 것까지 잡힘. 단계로 맞춘 결과와 전체로 맞춘 결과 둘 다에서 다른 곳만 남겨 맞추는 방법 때문에 생긴 가짜 차이를 지움.
4. **판정** — 다른 구간이 한 공정 단계 시간의 20 % 이상이면 그 IO 는 이상, 짧으면 주의, 한쪽 로그에만 있는 IO 도 이상.
   공정 일치율은 다른 IO 비율 · 다른 시간 · 크기로 (IO 하나는 15 % 까지) → 95 정상 · 80 주의.
