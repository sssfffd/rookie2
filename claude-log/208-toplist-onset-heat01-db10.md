# 208 — 2.04 차이 발생 IO List (최대 오차 막대 · 먼저 발생한 순) · 히트맵 0.1초 · 최종 판정 점수 · 분석 2 기준 · 종합 분석 체크

## 요청 (요청 235)

> 이거 차이 발생 io 상위 n개할때 막대기 채우는거 시간 오차 말고 최대 오차 비율로 채워주고 순서를 어떤 오차가 먼저 발생했는지로 상위 n개 뽑아주셈
> 오차 발생 순서 정할땐 1초 기준으로 볼지 0.1로 볼지 10초로 볼지 내가 정할 수 있게 해주고 히트맵은 0.1초도 가능하게 변경해주고 최종판정에 정상 주의 뜰때 오른쪽에 스코어 뜨게 해줘
> 그리고 분석 2는 10개이상 변경 시 주의 뜨게 해주고
> 종합분석에 체크랑 분석 1 이름 이렇게 뜰텐데
> 분석 1,2,3뜨는 것들은 지워주셈 체크랑 이름만 남게

## 한 것

| 요청 | 바꾼 것 | 파일 |
|---|---|---|
| 막대 = 최대 오차 비율 | 차이 발생 IO List 막대를 **최대 오차 비율** (이전 값 대비 가장 크게 벗어난 %, 100 % 넘으면 꽉 참) 로. 옆 글도 그 % ("34 %"), 한쪽 로그에만 있는 IO 는 꽉 찬 막대 + "이후에 없음". 오차 시간 (허용 오차 밖 시간 비율) 은 옆 칸 "오차 시간" 으로 | `MainDashVm.BuildTop`, `MainView.xaml` |
| 먼저 발생한 순 | 상위 8 개를 **오차가 처음 난 시각** 순으로. 같은 단위 칸 안이면 최대 오차가 큰 IO 먼저, 한쪽 로그에만 있는 IO 는 맨 앞 (처음부터). 머리 글 "먼저 발생한 순 · 단위", "N개 중 먼저 발생한 M개" | `MainDashVm.OnsetKey` |
| 단위 0.1 · 1 · 10 초 | 제목 옆 고르기 (기본 1 초), 설정에 저장 (`onsetSec`). 숫자 시간 열은 초로 봄 (머리 단위 ms · min 바꿔 셈), 표본 번호 축은 시각 그대로 | `MainDashVm.OnsetIndex`, `AppSettings.OnsetSeconds` |
| 히트맵 0.1 초 | 칸 폭에 "0.1초" 추가 (칸이 너무 많으면 폭을 두 배씩 넓히고 칸 폭 글에 적음) | `HeatmapVm` |
| 최종 판정 점수 | 정상 · 주의일 때 판정 낱말 **오른쪽**에 종합 점수 ("정상 95.1"). 이상은 넉아웃일 수 있어 안 붙임. 아래 줄은 넉아웃 까닭만 | `OverallVm.ScoreBeside`, `MainView.xaml` |
| 분석 2 10 개부터 주의 | 0 ~ 9 PASS · **10 ~ 99 WARNING** · 100+ CRITICAL (예전 1 개부터 WARNING). PASS 인데 차이가 있으면 "차이 발생 3개 (10개부터 WARNING)" | `DbVerdict` |
| 종합 분석 체크 | "분석 N · " 과 점 · "완료 / 안 함" 을 빼고 **체크와 이름만** (결과가 없으면 체크가 꺼짐, 까닭은 마우스 글) | `LlmPanelVm`, `MainView.xaml` |

```
차이 발생 IO List  먼저 발생한 순 · 단위 [1초▼]  ▆ 막대 = 최대 오차 비율 …   12개 중 먼저 발생한 8개
판정  IO          그룹    최대 오차율          오차 시간   언제
이상  TEMP_ZONE2  가열부  ██████████ 340 %      18 %    12:00:40 ~ 12:01:10
```

- 발표 자료 두 개도 새 기준으로 고침 (분석 2 "0 ~ 9 PASS · 10 ~ 99 WARNING", 차이 발생 IO List 설명).

## 확인

- 시험 1158 통과 (새 시험: 발생 칸 0.1 · 1 초 · 한쪽에만 있는 IO · 단위 저장, 막대 0 ~ 100, 낱말 옆 점수 · 이상이면 없음, 히트맵 0.1초, 분석 2 1 ~ 9 PASS · 10 WARNING, 체크 이름). check 스크립트 · XAML 형식 통과.
- **Windows 에서 못 본 것**: 제목 옆 고르기 상자 · 낱말 옆 점수 위치, 0.1 초 히트맵 속도 (칸이 많으면 폭을 넓힘).
