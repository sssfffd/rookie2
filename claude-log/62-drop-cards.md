# 62 — 끌어다 놓기를 로그 분석과 같은 칸으로 (0.81)

## 주신 말

> 아니 끌어다 놓는 거는 로그 분석처럼 각 칸에 들어갈 수 있게 해야자

0.80 에서 제가 **화면 아무 데나** 놓으면 "비어 있는 쪽" 을 찾아 넣게
만들었습니다. 그게 아니라 **메인 화면의 로그 칸처럼 각 칸이 자기
자리를 받는** 모양이어야 한다는 말씀입니다. 맞습니다 — 되돌렸습니다.

## 고친 것

### 1) 화면 전체 받기를 없앴습니다

`DockPanel` 의 `AllowDrop` 과 핸들러 셋(`OnAnyDragOver` ·
`OnAnyDragLeave` · `OnAnyDrop`)을 걷어 냈습니다.

**한 칸 = 한 자리**입니다. 이전 칸에 놓으면 이전만, 이후 칸에 놓으면
이후만 바뀝니다. 0.80 에는 "이전 칸에 둘을 놓으면 이후까지 채운다" 는
것도 있었는데 그것도 뺐습니다 — 놓지 않은 쪽이 바뀌면 안 됩니다.

### 2) 칸을 메인 화면과 같은 모양으로

전에는 한 줄짜리 입력 칸 둘이 위아래로 있었습니다. 이제 메인 화면의
로그 칸과 같이 **좌우로 나란한 칸 둘**입니다.

```
견줄 DB    (칸에 끌어다 놓으면 들어갑니다. 폴더도 파일도 됩니다)
┌───────────────────────────┐ ┌───────────────────────────┐
│ ● 이전          [폴더][파일] │ │ ● 이후          [폴더][파일] │
│ D:\db\2026-03-14          │ │ D:\db\2026-03-21          │
│ 폴더                       │ │ 폴더                       │
└───────────────────────────┘ └───────────────────────────┘
```

- 색 점과 이름은 그래프의 이전(파랑) · 이후(빨강)와 같은 색입니다
- 칸 전체가 놓는 자리이고, 끌고 가면 **밝아집니다**
- 경로는 그대로 **고칠 수 있습니다** (타 넣기 · 붙여넣기)
- 아래 작은 글이 그 자리가 **무엇인지** 말해 줍니다

### 3) 칸 아래 글이 "없는 자리" 를 알려 줍니다 (새로 넣음)

| 적히는 글 | 뜻 |
|---|---|
| `끌어다 놓거나, 타 넣거나, 단추로 고르세요` | 아직 비었음 |
| `폴더` / `파일` | 그 자리가 있고, 무엇인지 |
| `이 자리에 아무것도 없습니다` | **경로가 틀렸음** |
| `들여다볼 수 없는 자리입니다` | 권한 없음 |

경로를 손으로 타 넣다 한 글자 틀리면, 전에는 `[DB 읽기]` 를 눌러야
알게 됐고 그때 나오는 말은 "읽은 표가 없습니다" 라서 **왜인지 알 수가
없었습니다.** 이제 칸 아래에 바로 적힙니다.

### 4) 아래 안내 글에서 겹치는 줄을 뺐습니다

칸 머리글과 칸 아래 글이 "어떻게 넣나" 를 이미 말합니다. 아래 안내는
"무엇을 읽나" 와 "기억한다" 만 말합니다.

## 0.80 의 고침은 그대로 남습니다 — 그게 드롭이 안 됐던 까닭입니다

칸 안의 `TextBox` 에 `AllowDrop="False"` 가 붙어 있어야 합니다.
TextBox 는 파일 드롭을 **받지도 않고 위로 올려 보내지도 않습니다.**
칸 넓이의 거의 전부가 그 TextBox 라서, 그게 없으면 "놓아도 아무 일
없는" 칸이 됩니다.

**메인 화면 칸은 안에 TextBox 가 없어서 처음부터 됐던 것입니다.** 그
차이가 "로그 분석에서는 되는데 DB 에서는 안 되는" 까닭이었습니다.
검사기 규칙(0.80)이 이 자리를 지킵니다.

## 확인한 것 · 못 한 것

- `통과 654 / 실패 0`, 검사기 넷 지적 없음
- **Windows 에서 확인 못 했습니다**: 칸 둘의 모양과 폭, 그리고
  **끌어다 놓기가 실제로 되는지**. 아직 안 되면 `PreviewDrop` 으로
  바꿔 보겠습니다 — 그때는 "칸에 놓으면 색이 바뀌나요?" 도 같이
  알려 주세요. 색이 바뀌는데 안 들어가면 Drop 쪽, 색도 안 바뀌면
  DragOver 가 아예 안 오는 것이라 고칠 자리가 다릅니다.
