# 59 — `vm:` 빌드 에러 (0.78)

## 주신 말

> vm어쩌구하면서 빌드에러남

0.77 에서 제가 낸 것입니다. 죄송합니다.

## 무엇이었나

`GraphView.xaml` 에서 **접두어 선언을 지웠는데 쓰는 쪽을 다 안 고쳤습니다.**

0.77 에서 `ViewModels/` 와 `Controls/` 와 `Views/` 를 `Logs/` 한 폴더로
모았더니, 그 파일의 접두어 셋(`ctl` · `vm` · `local`)이 전부 같은 이름
공간을 가리키게 됐습니다. 군더더기라 `vm` 과 `local` 선언을 지웠는데,
파일 안에 `vm:` 을 쓰는 자리가 **다섯 군데** 남아 있었습니다.

```xml
<DataTemplate DataType="{x:Type vm:GroupRowVm}">          ← 2 군데
<DataTrigger ... Value="{x:Static vm:IoRowVm.Status…}">   ← 3 군데
```

## 고친 것

접두어를 `logs:` 하나로 모았습니다 (셸 창이 쓰는 이름과 같습니다).
`GraphView.xaml` 과 `HeatmapView.xaml` 둘입니다.

## 왜 검사기가 못 잡았나 — 여기가 더 중요합니다

규칙이 둘 다 **접두어를 안 보고 있었습니다.**

| 규칙 | 보던 것 | 못 본 것 |
|---|---|---|
| XML 로 읽히는가 | `<vm:Foo>` 는 "unbound prefix" 로 걸립니다 | **속성 값 안의** `{x:Static vm:…}` 는 그냥 글자라 안 걸립니다 |
| x:Static 대상이 있는가 | 타입 이름만 찾았습니다 (`IoRowVm` 는 어딘가에 있으니 통과) | 그 **접두어가** 어디를 가리키는지 |

`{x:Static vm:...}` 은 XML 에게는 평범한 글자입니다. 그래서 XML 검사도,
상수 검사도, 컴파일도 통과하고 **Windows 에서 창을 띄울 때**서야 터졌습니다.

### 규칙을 고쳤습니다

이제 세 가지를 봅니다.

1. **쓰는 접두어가 선언되어 있는가** ← 이번 버그
2. 그 접두어가 가리키는 이름 공간에 그 타입이 있는가
3. x:Static 이 가리키는 상수가 그 타입에 있는가

보는 자리도 셋으로 늘렸습니다: `<접두어:타입>` · `{x:Type 접두어:타입}` ·
`{x:Static 접두어:타입.이름}`. 전에는 첫째와 셋째만 봤고, `x:Type` 은
아예 안 봤습니다 (이번에 거기도 두 군데였습니다).

네 가지로 일부러 깨뜨려 전부 잡는 것을 확인했습니다.

```
XAML 접두어 logs: 가 선언되어 있지 않음 (logs:GroupRowVm)
XAML 이 쓰는 inf:BoolToVisibility 가 LogScope.App.Themes 에 없음
x:Static 대상 없음 IoRowVm.StatusChangd
```

### 규칙 하나 더 — 폴더 = 이름 공간

0.77 부터 폴더가 "기능" 입니다. 폴더와 이름 공간이 어긋나면 "DB 화면은
`App/Db` 를 열면 된다" 가 거짓말이 되고, XAML 의 `clr-namespace` 를 적을
때마다 틀립니다. 컴파일은 되므로 아무도 말해 주지 않습니다. 그래서
`src/<프로젝트>/<폴더>/*.cs` 의 이름 공간이 `<프로젝트>.<폴더>` 인지
봅니다. 이것도 어긋내 봐서 잡는 것을 확인했습니다.

## 남은 눈먼 자리 (솔직하게)

XAML 안에서 이름을 글자로 적는 자리는 아직 더 있습니다 — `Binding` 의
속성 이름, `StaticResource` 가 아닌 글자, `Setter Property`. 거기까지
보려면 사실상 XAML 컴파일러를 흉내 내야 합니다. **여기서는 XAML 이
컴파일되지 않는다**는 사실은 그대로입니다. 빌드 에러가 또 나면 글을
그대로 주세요 — 잡을 수 있는 종류면 규칙으로 만들겠습니다.
