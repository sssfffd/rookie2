# 162 — 히트맵 칸을 눌러 그래프로 갈 때 엉뚱한 · 마이너스 시간대 (1.71)

> 단계별로 히트맵에서 나눈다음에 칸 누르면 해당 시간대의 그래프로 이동하잖아 근데 몇칸은 정상으로 이동하는데 또 몇 칸은 막 마이너스 시간대부터 이상한 시간대로 이동함.
> 이거 로직좀 확실하게좀 짜보셈

## 까닭

칸을 누르면 그 칸의 **이전 로그 시각** (시작 ~ 끝 ± 25 %) 만 그래프에 넘겼습니다. 그런데 그래프는

| 그래프 상태 | 일어난 일 |
|---|---|
| 다른 단계가 골라져 있음 + [시작을 0 으로] | 눈금이 **그 단계 시작부터** 셈 → 앞 단계 칸은 마이너스 시각 |
| 다른 단계가 골라져 있음 | 이후 로그를 **그 단계의 밀기 값** 으로 맞춤 → 히트맵이 견준 맞춤 (칸마다 그 단계) 과 달라 어긋나 보임 |
| 단계로 나눠 보기 켜짐 | 칸 나눔 화면이라 시간 구간이 뜻이 없음 |
| 시간 칸 첫 칸 | 앞 여유 25 % 가 로그 시작보다 앞 (0 초 로그면 마이너스) |

→ 그래프에 골라 둔 단계와 같은 단계의 칸만 정상으로 보였습니다.

## 고침 — 갈 곳을 한 곳 (`HeatJump.Plan`) 에서

```
 단계 칸 (가로를 단계로)          시간 칸
 ─────────────────────           ─────────────────────
 그 단계를 그래프에서 고름          칸 구간 ± 25 %
 (히트맵이 쓴 그 단계 맞춤)         → 로그가 있는 구간 안으로 자름
 구간 = 그 단계 (두 로그 중 긴 쪽)  나눠 보기는 끔
 눈금 0 = 그 단계 시작
```

- 히트맵 칸마다 어느 단계 짝인지 들고 다님 (`HeatBuckets.PairOf`). 짝 이름이 안 맞으면 (단계가 그 사이 바뀜) 시간 칸처럼
- 단계를 바꾸면 그래프가 미뤄서 다시 견주므로 (1.69) 구간은 그 **뒤에** 검
- 단계 칸을 누르면 그 단계가 골라지므로 메인 판정 아래에 "고른 단계 반영 중" 이 뜰 수 있음 (1.67 · 1.69) — [전체 구간] 으로 풀면 됨

## 확인
- Linux: 테스트 1107 통과 (단계 칸 셋 모두 → 그 단계 · 그 구간, 짝 못 찾으면 시간, 시간 칸 첫 칸 0 부터 · 끝 칸 로그 끝까지), 실제 csc 7.3 오류 0, 검사 스크립트 통과
- **Windows 에서 못 봄**: 실제로 눌러 넘어가는 화면 (단계 칸 → 그 단계 · 눈금 0 부터)
