# 04 — 히트맵 화면

> 요청: "위에 메뉴로 이동하는 새 창중에 heatmap이라는 걸 만들어줘.
> 차이가 나는 io를 왼쪽에 띄워주고 가로축은 시간(1분단위) 해당 시간대에
> 차이가 발생했으면 네모 칸으로 차이 발생 띄워주고 평균 차이값이 표시된
> 네모칸을 빨간색으로 띄워줘. 해당 구간에 차이 안발생했으면 네모칸으로
> 정상 띄워주고 한 0.1% 오차는 오류 아닌거임"

위 메뉴에 **[대시보드] [그래프] [히트맵]** 세 개가 생겼습니다 (F1 / F2 / F3).

```
                 00:00   00:01   00:02   00:03   00:04
 밸브 OPEN   3칸 │ 정상 │ 정상 │ 10.0 │ 12.4 │ 정상 │     ← 빨간 칸 = 차이 발생
 압력 PT-01  1칸 │ 정상 │ 정상 │ 2.31 │ 정상 │ 정상 │
 온도 TT-07  0칸 │ 정상 │ 정상 │ 정상 │ 정상 │ 기록없음│
```

## 1. 칸에 적는 숫자 — 왜 "절대 차이의 평균" 인가

이게 이번 요청의 핵심이었습니다. 후보를 하나씩 따져 보면 하나만 남습니다.

| 지표 | 문제 |
|---|---|
| 부호 있는 합계 (Σ(a−b)) | **+1 / −1 로 진동하면 0** 이 되어 차이를 통째로 놓칩니다 |
| 절대값 합계 (Σ\|a−b\|) | **구간이 길수록 무조건 커집니다.** 표본이 많은 칸이 늘 더 빨개져서 칸끼리 비교가 안 됩니다 |
| 절대 차이의 평균 (Σ\|a−b\| / n) | 구간 길이에 휘둘리지 않고, 진동해도 0 이 되지 않습니다. 다만 **기준 안에 든 표본까지 같이 평균을 내서** 허용 오차와 견줄 수가 없었습니다 ([08](08-heatmap-tolerance-mismatch.md)) |
| **기준을 넘은 표본만의 평균** | 위의 장점은 그대로이면서, **늘 허용 오차보다 큽니다.** **← 이걸 씁니다** |
| RMS | 큰 차이에 더 무게를 둡니다. 함께 담아 두고 마우스를 올리면 보입니다 |
| 최대 | 한 번만 튄 것도 크게 보입니다. 이것도 함께 담아 둡니다 |

칸에 적히는 것은 **기준을 넘은 표본만의 평균**("벌어졌을 때 이만큼
벌어졌다")이고, 마우스를 올리면 아래 띠에 구간 전체 평균·최대·표본 수·
기준값이 값과 %로 모두 나옵니다. 처음에는 구간 전체의 평균을 적었는데,
그러면 위에 적어 둔 허용 오차와 칸의 숫자가 어긋나 보였습니다 —
왜 그런지와 어떻게 고쳤는지는 [08-heatmap-tolerance-mismatch.md](08-heatmap-tolerance-mismatch.md).

칸의 **빨간 정도**는 그 줄에서 가장 큰 값 대비입니다 — 칸에 적히는 그 값과
같은 것이라, 숫자와 색이 따로 놀지 않습니다.

## 2. "0.1% 오차는 오류 아님" 을 어떻게 넣었나

채널마다 기준값(`Threshold`)을 따로 잡습니다.

```
기준값 = max( 절대 허용 오차 , 값 범위 x 0.1% )
```

- **아날로그**: 범위가 5000 인 채널이면 기준값 5. 2 정도 흔들리는 것은
  오류로 세지 않습니다.
- **디지털**: 범위가 1 이라 기준값 0.001. 0 과 1 의 차이는 그대로 잡힙니다.
- 0.1% 는 도구 줄의 "허용 오차 (값 범위의 %)" 에서 바꿀 수 있습니다.
- 설정 창의 절대 허용 오차와는 **큰 쪽**을 씁니다. 둘 다 걸고 싶을 때를
  위한 것입니다.

칸이 "차이 발생" 인지는 **그 구간에서 한 번이라도 기준값을 넘었는지**로
봅니다. 잠깐 크게 튄 것을 평균이 묻어 버리지 않게 하기 위해서입니다.
칸에 적는 숫자도 그 판정과 같은 표본들에서 냅니다 — 그래서 빨간 칸의 숫자는
**언제나 기준값보다 큽니다.**

## 3. 1분 단위를 어떻게 정하나

- 시간축이 **시각**(`00:01:23` 또는 날짜)으로 읽힌 로그 → **1 분**으로 자릅니다.
  도구 줄에서 1분 / 5분 / 10분 / 30분 / 1시간으로 바꿀 수 있습니다.
- 시간축이 시각이 아니면(샘플 번호나 단위 없는 숫자) "1 분" 이라는 게 뜻이
  없으므로 전체를 **60 칸**으로 나눕니다. 도구 줄에 그 사실을 적어 둡니다.
- 어느 쪽이든 칸이 4000 개를 넘으면 폭을 두 배씩 넓혀 줄입니다.

## 4. 성능

채널 하나당 **표본 수에 비례**해서 끝납니다.

이전 로그의 표본을 시간 순서대로 훑으면서 이후 로그의 자리를 **같이 앞으로
밀며** 값을 읽습니다 (`Heatmap.cs` 의 `BuildRow`). 표본마다 이진 탐색을 하면
채널 200 x 표본 5 만 = 1000 만 번의 탐색이 되는데, 이 방식은 한 번 훑는
것으로 끝납니다.

그리는 쪽도 **화면에 보이는 칸만** 그립니다. 줄 200 개 x 칸 500 개 = 10 만
칸이어도 실제로 그리는 것은 수천 개뿐입니다.

계산은 배경 스레드에서 돌고 진행 창이 뜹니다 (취소 가능).

## 5. 조작

| 하고 싶은 것 | 방법 |
|---|---|
| 히트맵 열기 | 위 메뉴 [히트맵] 또는 **F3** |
| 다시 계산 | [히트맵 다시 계산] (허용 오차나 칸 폭을 바꾼 뒤) |
| 자세한 값 보기 | 칸 위에 마우스를 올리면 아래 띠에 나옵니다 |
| **그래프로 넘어가기** | **칸을 누르면** 그 IO 만 켜진 채로, 그 시간대로 확대된 그래프가 열립니다 |
| 칸 너비 | **Ctrl + 휠** 또는 [칸 넓게] / [칸 좁게] |
| 옆으로 굴리기 | **Shift + 휠** 또는 아래 스크롤바 |
| 위아래로 굴리기 | 휠 |
| 차이 없는 IO도 보기 | 도구 줄 토글 (기본은 차이가 난 IO 만 보여 줍니다) |

```

src/LogScope.App/ViewModels/HeatmapVm.cs     설정과 요약
src/LogScope.App/Views/HeatmapView.xaml(.cs) 화면
```

테스트 두 개를 함께 넣었습니다 (`LogScope.Tests`).

- `HeatmapBuckets` — 5 분치 로그에서 2 분대에만 차이를 넣고, **그 칸만**
  빨갛게 잡히는지와 평균값이 맞는지 확인합니다.
- `HeatmapRelativeTolerance` — 범위 5000 인 채널이 2 만큼 벌어질 때
  0.1% 기준에서는 **정상**, 0.01% 로 낮추면 **차이**로 잡히는지 확인합니다.
