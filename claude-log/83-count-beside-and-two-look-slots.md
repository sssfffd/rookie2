# 83 — 차이 개수는 판정 오른쪽 · 파일 칸은 위로, 모양은 둘

> 일단 분석2에서 차이발생 갯수가 fail판정 오른쪽에 있으면 좋겠고
> 메인화면 이전 이후 로그 여는거 칸은 열고 난 후는 지금이 나은데
> 열기전엔 이전게 이쁘네 타협점 잘 찾아보고
> 열고난 후 아래가아니라 위에 있어야할득

## 1. 차이 개수 — 낱말 오른쪽

```
전 (1.02)                     후 (1.03)
FAIL                          FAIL   차이 발생 152 개
차이 발생  152 개
```

같은 줄, 바닥을 맞췄습니다. 수는 판정 낱말과 **같은 크기(24pt)·같은 색**
입니다 (PASS 초록 · WARNING 노랑 · FAIL 빨강). 둘이 한 덩어리로 읽힙니다.

## 2. 파일 칸 — 타협점: "칸마다 상태로 모양이 바뀜"

```
열기 전 (0.99 모양)               연 뒤 (1.02 모양)
┌────────────────────────┐
│ ● 이전                  │       ● 이전  2026-03-14_가열_A.csv   IO 180 · 표본 5,000
│ 누르거나 끌어다 놓아 여세요 │       ● 이후  2026-03-20_가열_A.csv   IO 180 · 표본 5,100
└────────────────────────┘
┌ ● 이후 … ──────────────┐
└────────────────────────┘
```

- **열기 전** = 테두리 상자. 빈 자리는 "여기 놓으라" 로 보여야 해서
  예전 모양이 맞습니다.
- **연 뒤** = 납작한 한 줄. 그때는 이름만 읽히면 됩니다.
- **칸마다 따로** 바뀝니다. 이전만 열었으면 위는 줄, 아래는 상자.
- 자리는 **제목 바로 아래** (결과 위). 한 줄씩이라 결과를 가리지 않습니다.
- 분석 2 견줄 자리도 똑같이 했습니다.

## 3. 어떻게 — 한 자리에 Border 둘

| 모양 | 보이는 조건 | Tag | 바탕 / 테두리 |
|---|---|---|---|
| 상자 | `BeforeHint` 가 있을 때 (= 아직 안 염) | `before\|Brush.Window` | Window / Border |
| 줄 | `BeforeShown` 이 있을 때 (= 염) | `before\|Brush.Panel\|Brush.Panel` | Panel / Panel |

Border 하나에서 Tag 와 색을 바인딩으로 바꿔 끼우지 않은 까닭: 끌기가 끝나면
`CardTag.Lit` 이 Tag 에 적힌 색으로 되돌리는데, 둘이 따로 바뀌면 어긋나는
순간이 생깁니다 (0.59 · 1.02 에 겪은 고장). 둘로 두면 Tag·색이 고정이라
`check_sources.py` 가 그 짝을 검사할 수 있습니다.

`BeforeShown` 을 새로 둔 까닭: `BeforeFileName` 은 경로에서, `BeforeHint` 는
열린 데이터에서 나와서 **경로만 있고 아직 못 연 순간** 에 둘 다 보이거나 둘 다
안 보일 수 있습니다. `BeforeShown` 은 `BeforeHint` 와 같은 조건(데이터 유무)의
정확한 반대라 늘 하나만 보입니다. 분석 2 는 원래 `DbBeforeName` / `DbBeforeHint`
가 같은 경로 하나에서 나와 그대로 썼습니다.

## Windows 에서 확인 못 한 것

- XAML 은 여기서 컴파일되지 않습니다 (스텁 + 검사기만 통과).
- 상자 → 줄로 바뀔 때 카드 높이가 줄어드는 느낌, 24pt 개수와 낱말의 바닥
  맞춤은 실제 화면에서 봐야 합니다. 어긋나면 개수 쪽 `Margin` 아래 값만 고치면
  됩니다.
- 검사: 컴파일 · 테스트 830 통과 · `check_sources` / `check_handlers` /
  `check_shadowing` 지적 없음.
