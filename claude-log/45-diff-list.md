# 45. 차이를 칸으로 쪼갠 목록 (0.55)

> 그리고 차이를 러프하게 알려주는데 list쫙뽑아서 보여줄 수 있음?
> 각 데이터마다 칸 안에 담아서

## 전에는 글 한 덩이였습니다

0.51 에서 DB 화면을 만들 때, 고른 표의 차이를 **글**로 적었습니다. 그 자리에
저는 이런 주석을 달아 뒀습니다.

> 글로 적습니다. 표로 그리면 열 수가 표마다 달라 빈 칸이 많아지고,
> 무엇이 바뀌었는지는 결국 글로 읽어야 합니다.

틀린 판단이었습니다. 제가 생각한 "표" 는 **DB 의 표를 그대로 그리는 것**
(열이 그대로 화면의 칸이 되는 것) 이었고, 그러면 정말로 표마다 칸 수가
달라집니다. 하지만 필요한 것은 그게 아니었습니다. **차이 하나가 한 줄**이고
칸은 늘 같은 여덟 개면 됩니다.

```
표            갈래  구분      행        열      이전   이후   설명
mydb.users    열    생김                email          VARCHAR(200) NULL
mydb.users    행    달라짐    id=7      name    김     김철수
mydb.users    행    달라짐    id=7      age     30     31
mydb.users    행    없어짐    id=3      name    이
other.log     알림                                            기본 키가 없어…
```

## 한 줄에 값 하나

가장 중요한 결정입니다. **값이 바뀐 행은 바뀐 열마다 한 줄**로 적습니다.

한 행을 한 줄로 묶으면 `이전` 칸에 `name: 김, age: 30` 처럼 여러 값이 들어가
**다시 글이 됩니다.** 칸으로 쪼갠 보람이 없어지고, 무엇보다 **같은 열이 몇
군데서 바뀌었는지 셀 수가 없습니다.** "이번 변경은 거의 `temp_max` 하나다" 를
알려면 `열` 칸이 값 하나여야 합니다.

생기거나 없어진 행도 같은 이유로 열마다 펼칩니다. 여기서는 한 가지가 더
걸립니다 — **없는 쪽 칸은 빈 칸으로 둡니다.** `NULL` 로 적으면 안 됩니다.

```
구분      열      이전    이후
없어짐    a       NULL            ← 값이 NULL 인 열
없어짐    b       30              ← 그 행이 이후에 없음 (빈 칸)
```

둘을 같은 글자로 적으면 "NULL 로 바뀐 것" 과 "행이 없어진 것" 이 섞입니다.
`구분` 칸이 그걸 가려 주지만, 칸 자체도 거짓말을 하지 않는 편이 낫습니다.

## 펼치지 않는 자리

**표 자체가 한쪽에만 있을 때는 행을 펼치지 않습니다.**

새로 생긴 표에 행이 1 만 개 있으면, 칸마다 펼치면 20 만 줄이 깔립니다. 그런데
거기서 아는 것은 **"이 표가 새것" 하나**뿐입니다. 20 만 줄을 읽어도 같은 말이
20 만 번 적혀 있을 뿐이고, 그 사이에 다른 표의 진짜 차이가 묻힙니다.

그래서 열 모양만 적고, 행 수는 알림 줄에 적습니다.

> 표 자체가 이후에만 있습니다 — 열 12 개 · 읽은 행 10,000 개.
> 행은 칸마다 적지 않습니다 (전부 한쪽에만 있는 것이라 적어도 같은 말입니다).

## 상한은 소리를 냅니다

표 하나 5,000 줄, 목록 전체 5 만 줄입니다. 닿으면 `알림` 줄로 적습니다.

조용히 끊으면 **"차이가 이것뿐" 으로 읽힙니다.** 이 프로그램에서 가장 나쁜
고장은 "없는 차이를 있다고 하는 것" 과 "있는 차이를 없다고 하는 것" 이고,
말없이 자르는 것은 후자입니다.

표마다 따로 세는 이유도 같습니다. 한 표가 5 만 줄을 다 먹으면 그 뒤의 표는
차이가 있어도 화면에 한 줄도 못 나옵니다.

## 목록은 엑셀로 넘깁니다

`[목록 CSV 저장]` 을 붙였습니다. 걸러 보고 정렬하는 일은 **엑셀이 이 화면보다
훨씬 잘합니다.** 화면에 정렬·필터를 다 만드는 대신 통로를 냈습니다.

- BOM 을 붙입니다. 안 붙이면 한국어 윈도우의 엑셀이 CP949 로 읽어 한글이
  깨집니다 — 그게 가장 흔한 사고입니다.
- **값은 손대지 않습니다.** 그래서 `=` 로 시작하는 값은 엑셀이 수식으로 읽을
  수 있습니다. 앞에 따옴표를 붙여 막는 방법이 있지만, 그러면 `-5` 같은 흔한
  값까지 글자로 바뀝니다. **차이를 보려고 뽑은 목록의 값이 원래와 달라지는
  쪽이 더 나쁩니다.** 알고 쓰시라고 README 에 적었습니다.

## 쪼갠 곳 — 화면이 아니라 Core 에

`LogScope.Core/Db/DbDiffList.cs` 입니다. 화면에 두지 않은 이유는 두 가지입니다.

1. **테스트가 됩니다.** WPF 없이 돌아가므로 이 컨테이너에서 25 개를 돌립니다.
2. **CSV 가 공짜로 나옵니다.** 화면이 보는 목록과 파일로 나가는 목록이 같은
   함수에서 만들어집니다. 따로 만들면 둘이 어긋납니다.

## 속도 — ObservableCollection 을 안 썼습니다

목록이 몇 만 줄입니다. `ObservableCollection` 에 하나씩 `Add` 하면 그만큼
"바뀌었다" 알림이 날아가고, 그걸 다 WPF 가 받아 처리합니다. 통째로 만들어
한 번만 알립니다.

`ListView` 는 기본으로 보이는 줄만 만들어 그립니다(가상화). 그 성질을
망가뜨리지 않으려고 줄 모양은 테마의 `ListRow` 를 그대로 쓰고
**마우스 설명만** 덧붙였습니다 — `BasedOn` 을 빼면 테마의 줄 모양이 통째로
사라집니다.

## 지운 것

`DbVm.Describe` 와 `DbVm.Key` 를 지웠습니다. 목록이 같은 내용을 더 잘 적으니
글 만드는 코드를 남겨 두면 둘이 어긋납니다. 행을 가리키는 글
(`id=7`) 은 `DbDiffList.KeyText` 로 옮겼습니다.

## 검사

- 테마 · 핸들러 · 이름 겹침 검사 셋 다 통과.
- 테스트 **515 통과 / 0 실패** (DB 목록 25 개 새로 더함).
- 새 테스트가 지키는 것: 바뀐 열마다 한 줄, 없는 쪽은 빈 칸, NULL 은 NULL,
  한쪽에만 있는 표는 행을 안 펼침, 상한을 표마다 따로 세고 밝힘, CSV 의
  쉼표·따옴표 처리, 표 하나만 뽑기.

**못 해 본 것**: 화면 모양입니다. XAML 은 이 컨테이너에서 컴파일되지 않아
칸 폭(여덟 칸이 한 화면에 들어오는지), 줄 높이, 가로 스크롤은 윈도우에서
봐 주셔야 합니다.
