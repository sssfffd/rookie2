# 67 — 파일 이름이 달라도 짝짓기 (0.86)

## 주신 말

> 이거 앞뒤로 .csv파일명 같아야 동작하는 거지?? 파일명 달라도 가능하게
> 만들어줘

**맞습니다.** `.csv` 는 **파일 이름이 곧 표 이름**이고, 표는 이름으로
짝지었습니다. 그래서 `2026-03-14.csv` 와 `2026-03-21.csv` 를 넣으면
"없어진 표 1 + 새로 생긴 표 1" 이 되어 **차이를 하나도 못 봤습니다.**

## 고친 것

짝짓기를 세 걸음으로 바꿨습니다.

1. **이름이 같은 것끼리** (전과 같습니다)
2. 남은 것끼리 — **열 구성이 똑같은 표가 양쪽에 하나씩**일 때 짝짓습니다
3. 그래도 남으면 한쪽에만 있는 표입니다

### 규칙을 하나로 줄인 까닭

처음에는 "양쪽에 남은 표가 하나씩이면 그 둘" 도 넣었습니다. **그게
위험했습니다** — 서로 상관없는 표 둘이 남아 있을 때 그것들을 견주게
됩니다. 제 시험이 바로 그걸 잡았습니다 (`gone` 과 `born` 을 짝지어
버렸습니다).

열 이름이 똑같다는 것은 **같은 자료를 두 번 뽑았다**는 꽤 센 근거이고,
이름이 다를 때 우리가 가진 유일한 근거입니다. 열 순서는 안 가립니다.

### 짝지을 때마다 말합니다

```
이름이 다른 표를 짝지었습니다: '2026-03-14' ↔ '2026-03-21' (열 구성이 같아서).
```

말없이 견주면 보는 사람은 **같은 표를 본 줄로 압니다.**

못 지었을 때도 왜인지 적습니다.

```
이름이 다른 표가 이전 쪽에 2 개, 이후 쪽에 3 개 남았습니다.
열 구성이 같은 짝이 하나씩일 때만 이름이 달라도 견줍니다 —
파일 이름을 맞춰 주시면 그대로 짝지읍니다.

'레시피' 와 열 구성이 같은 표가 이후 쪽에 2 개 있어 어느 것과 견줄지
정할 수 없었습니다.
```

### 표 이름은 안 바꿨습니다

`TableDiff.Name` 을 `"a ↔ b"` 로 바꾸고 싶었는데, 그 이름이 그대로
`ALTER TABLE` 의 식별자로 나갑니다 (`DbSql`). 화살표가 섞이면 돌아가지
않는 SQL 이 됩니다. 짝 이름은 `TableDiff.PairedName` 에 따로 뒀습니다.

## 시험

"짝지어야 할 때" 보다 **"안 지어야 할 때"** 가 더 중요해서 둘 다 넣었습니다
(10 개). 상관없는 표를 말없이 견주면 **없는 차이를 만들어 냅니다.**

| 넣은 것 | 기대 |
|---|---|
| 이름만 다르고 열 구성 같음 | 짝지음 + 그렇다고 적음 + **값 차이가 실제로 보임** |
| 이름도 열 구성도 다름 | **짝짓지 않음** + 까닭 적음 |
| 같은 열 구성이 이후 쪽에 둘 | **짝짓지 않음** + "어느 것과 견줄지" 적음 |
| 이름이 같음 | 전처럼 조용히 짝지음 (짝 이름은 빈 글자) |
| 열 순서만 다름 | 같은 구성으로 봄 |

기존 시험 하나의 자료를 고쳐야 했습니다 — `gone(k)` 과 `born(k)` 이 열
구성이 같아서 새 규칙에 걸립니다. 그 시험이 보려는 것은 "한쪽에만 있는
표" 라서, 열 구성을 다르게 두고 까닭을 주석에 적었습니다.

## 아직 남은 문제 — 이게 더 클 수 있습니다

**`.csv` 에는 열쇠(기본 키)가 없습니다.** 그래서 값이 하나 바뀐 행이
"달라짐" 이 아니라 **"없어진 행 1 + 생긴 행 1"** 로 보입니다.

그 말은 0.82 에 넣은 것들이 CSV 에서는 거의 안 보인다는 뜻입니다.

- 빨간 줄(value 차이) · 노란 줄(v1 · v2 차이)
- `차이 발생 : N개` — 대신 `없어진 IO` 와 `새로 생긴 IO` 로 세어집니다
- `차이가 발생한 IO만 보기` — 걸릴 줄이 없음

지금은 그렇다고 적기만 합니다 ("기본 키가 없어 모든 열이 같은 행끼리만
짝지었습니다").

### 고칠 방법

**첫 열을 열쇠로 보는 것**입니다. 다만 짐작이라 조건을 걸어야 합니다 —
그 열의 값이 **양쪽에서 겹치지 않을 때만**, 그리고 **그렇게 봤다고
적을 때만**. 그러면 CSV 에서도 "이 IO 의 이 값이 이렇게 바뀌었다" 가
빨간 줄로 나옵니다.

짐작이 틀리면 **엉뚱한 행끼리 견주어 없는 차이를 만듭니다.** 그래서
이번에 같이 넣지 않고 여쭙니다. 하실까요?
(어느 열을 열쇠로 볼지 직접 정하는 쪽이 더 좋으시면 그것도 됩니다.)

## 확인한 것 · 못 한 것

- `통과 682 / 실패 0` (669 → 682), 검사기 넷 지적 없음
- **Windows 에서 확인 못 했습니다**: 실제 `.csv` 두 장을 다른 이름으로
  넣었을 때 짝지어지는지. 안 되면 **두 파일의 머리 줄(열 이름)** 을
  알려 주세요 — 열 이름이 한 글자라도 다르면 짝을 안 짓습니다.
