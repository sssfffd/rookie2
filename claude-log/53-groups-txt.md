# 53. 그룹을 빌드 전에 정해 두기, 긴 이름 폭 (0.66)

> full name을 원하는 길이로 적으면 너무 화면에서 차지하는 비율이 긴데?
>
> 그룹 설정에 관한 거를 내가 out파일에서 수정하는 게 아니라 빌드 전에
> 수정해서 적용하고 싶은데 config.txt랑 비슷하게 설정할 수 있는 곳 정해줘

## 긴 이름 폭

`fullname` 을 길게 적으면 위 줄의 **화면 단추(메인 · 분석 1·2·3)를 밀고**
들어갑니다. 그 줄은 글자와 단추가 함께 쓰는 자리입니다.

**폭을 220 픽셀로 가뒀습니다.** 넘으면 `…` 로 자르고, 마우스를 올리면 전체가
나옵니다. 길이를 제한하지 않고 자리를 제한하는 쪽이 맞습니다 — 몇 글자까지만
되는지 세어 가며 적게 만들면 안 됩니다.

## 그룹 파일 — `groups.txt`

그룹은 지금까지 `LogScope.settings.json` 에만 있었습니다. 그건 **프로그램이
쓰는 파일**이라 빌드 전에 미리 넣어 둘 수가 없었습니다. 설비마다 IO 를 수십
개씩 묶는데 PC 마다 손으로 다시 하는 것은 할 일이 아닙니다.

저장소 뿌리에 `groups.txt` 를 뒀습니다. `config.txt` 와 같은 자리, 같은 규칙,
같은 인코딩 처리입니다.

```
가열부 = TEMP_1, TEMP_2, HEATER_ON
압력   = PRS_MAIN, PRS_SUB
예비   =
```

- 쉼표 · 세미콜론 · **탭**으로 가릅니다. 엑셀에서 한 줄 복사해 붙여넣는 길을
  막지 않으려고 탭을 넣었습니다.
- **같은 이름이 또 나오면 앞의 그룹에 더합니다.** 긴 목록을 여러 줄로 나눠
  적을 수 있고, 같은 이름의 그룹이 둘로 보이는 일도 없습니다.
- 이름만 적고 비우면 **빈 그룹**입니다. 화면에서 끌어다 넣을 자리로 쓰므로
  빼지 않습니다.
- 틀린 줄(등호 없음 · 이름 없음)은 **그 줄만** 건너뜁니다.

### 이번 설계에서 제일 조심한 것

**"파일이 있으면 주인" 으로 하면 안 됩니다.**

저장소에 둘 `groups.txt` 는 **설명만 적힌 빈 틀**입니다 (예시를 그대로 살려
두면 아무 설비에나 엉뚱한 그룹이 생깁니다). 그 틀이 `out` 으로 따라가는데,
"파일이 있으면 주인" 이었다면 **빌드하는 순간 그때까지 묶어 둔 그룹이 전부
지워집니다.**

그래서 규칙이 이렇습니다.

| 상태 | 주인 |
|---|---|
| **그룹을 하나라도 정함** | **그 파일** |
| 파일이 없거나 **전부 주석** | `LogScope.settings.json` (지금까지의 방식) |

### 되돌아가는 것을 말없이 두지 않습니다

파일이 주인일 때 화면에서 그룹을 고치면, 그 자리에서는 바뀌지만 다시 켤 때
파일 쪽으로 돌아갑니다.

**그걸 적어 두지 않으면 고친 사람은 저장이 고장 난 줄 압니다.** 0.61 에서
"그룹이 저장되지 않던 것" 을 고친 바로 다음이라 더 그렇습니다. 그룹 칸에
적습니다.

> 그룹은 groups.txt 가 정합니다. 여기서 고친 것은 다시 켜면 그 파일 쪽으로
> 돌아갑니다 — 그대로 두려면 파일을 고치세요.

### 화면에서 묶은 것을 파일로

`[groups.txt 글 복사]` 를 붙였습니다. 지금 묶어 둔 것을 그 파일 꼴로
클립보드에 담습니다. 손으로 다시 적는 일을 없애려는 것입니다.

**파일로 바로 저장하지 않습니다.** 저장할 자리는 *저장소의* `groups.txt` 이고
그건 프로그램이 돌고 있는 폴더가 아닙니다. 어디에 쓸지 우리가 짐작하면 엉뚱한
자리에 씁니다. 클립보드에 담고 "어디에 붙여넣으면 되는지" 를 알려 주는 쪽이
맞습니다.

## 인코딩 읽기를 두 번 짜지 않았습니다

`config.txt` 를 읽는 함수(BOM → UTF-8 → CP949)를 공개해 `groups.txt` 도 그걸
씁니다. 두 번 짜면 한쪽만 고쳐져 **"config.txt 는 한글이 되는데 groups.txt 는
깨지는"** 일이 생깁니다.

## 검사

- 테스트 **626 통과 / 0 실패** (17 개 새로 더함). 가름(쉼표·세미콜론·탭) ·
  같은 이름 합치기 · 빈 그룹 · 틀린 줄 건너뛰기 · **전부 주석이면 빈 목록** ·
  UTF-8 과 CP949 파일 · 적고 다시 읽어도 같은지.
- 검사 넷 다 통과. WPF 스텁에 `Clipboard` 를 더했습니다.

가는 길에 시험 하나가 터졌습니다. 리눅스 모노에는 CP949 가 없는데 거기서
던지는 예외가 `ArgumentException` 이 아니라 `NotSupportedException` 이었습니다.
`AppConfig.Legacy()` 는 원래 둘 다 받고 있었는데, 새로 쓴 시험이 한쪽만 받아
그대로 터졌습니다 — 같은 자리에서 같은 실수를 두 번 하지 않으려면 기존 코드를
먼저 봐야 합니다.

**못 해 본 것**: `[groups.txt 글 복사]` 가 실제로 클립보드에 담기는지와
220 픽셀이 적당한지입니다. 둘 다 윈도우에서 봐 주세요.

## 뒷이야기 — 긴 이름을 창 제목으로 (0.68)

> 근데 fullname 넣으면 좀 많이 길어지는데 방법이 없나?

0.66 에서 220 픽셀로 가뒀는데도 길다고 하셨습니다. 맞습니다 — **가둬도
220 픽셀은 먹습니다.** 자리를 아끼는 게 아니라 조금 덜 먹게 한 것뿐이었습니다.

### 이미 그려져 있는 자리가 있었습니다

창 제목이 이렇게 **박혀** 있었습니다.

```csharp
public string WindowTitle { get { return AppConfig.Current.Name + " — IO 로그 그래프 뷰어"; } }
```

`IO 로그 그래프 뷰어` — 그 자리가 처음부터 긴 이름 자리였습니다. 코드에 박아
두고, 정작 사람이 적는 긴 이름은 위 줄에 밀어 넣고 있었습니다.

**창 제목은 운영 체제가 이미 그려 줍니다.** 화면을 하나도 더 쓰지 않고,
작업 표시줄과 Alt+Tab 에도 그대로 나옵니다. "이 프로그램이 무엇인지" 를 적어
두기에는 거기가 제자리입니다. 그래서 **길이도 안 자릅니다** — 아무리 길게
적어도 됩니다.

```
창 제목     LogScope — 설비 Log 비교 · 분석 도구 (가열로 2호기)
위 줄       LogScope  v0.68        ← 긴 이름이 빠졌습니다
```

### 프로그램 안에서도 한 번은 보여야 합니다

위 줄에서 뺐으니 프로그램 안에서는 안 보입니다. 왼쪽 위 **이름에 마우스를
올리면** 나오게 했습니다 (이름 · 긴 이름 · 판 번호 · 어디서 바꾸는지).
폭은 0 입니다.

`fullname` 을 비워 두면 제목에 전에 쓰던 글이 붙습니다 — 창 제목이 프로그램
이름만 있는 것보다는 낫습니다.

### 규칙을 Core 로

시험을 쓰다가 제가 같은 규칙을 두 번 적고 있는 것을 알았습니다 — 화면에
한 번, 시험에 한 번. 그러면 한쪽만 고쳐지는 날이 옵니다. `TraceColors` 와
같은 이유로 `AppConfig.WindowTitle` 로 모았고, 화면과 시험이 **그 하나를
부릅니다.**

테스트 **630 통과 / 0 실패** (4 개 새로 더함 — 긴 이름이 제목에 들어가는지,
안 적었을 때 무엇이 붙는지, 이름을 바꾸면 따라가는지, **120 자를 적어도 자르지
않는지**). 검사 넷 다 통과.

### 그래도 위 줄에 보고 싶으시면

넣을 자리는 둘입니다.

- **메인 화면의 종합 칸** 머리에 한 줄 (메인에서만 보이고, 세로 몇 픽셀).
- **위 줄 오른쪽 끝** (설정 단추 옆). 거기는 단추가 적어서 여유가 있습니다.

말씀해 주시면 그쪽으로 옮기겠습니다.

## 뒷이야기 2 — 긴 이름을 아랫줄로 (0.69)

> 지금 fullname이 sw name오른쪽 아래 들어가는데 그냥 아래부터 시작되게 가능?

됩니다. **그게 0.66 과 0.68 보다 나은 답입니다.**

### 세 번 만에 제자리를 찾았습니다

| | 어디에 | 무엇이 문제였나 |
|---|---|---|
| 0.60 | 이름 **옆**, 판 번호 옆 | 길면 화면 단추를 밀고 들어옴 |
| 0.66 | 같은 자리, 폭 220 으로 가둠 | 가둔 220 은 그대로 먹음 |
| 0.68 | 창 제목으로 옮김 | 화면 안에서는 안 보임 (마우스를 올려야) |
| **0.69** | **위 줄의 아랫줄** | — |

```
┌──────────────────────────────────────────────────────────────┐
│ LogScope  [메인][로그 비교][DB 분석][분석 3] │ … [설정]      │
│ 설비 Log 비교 · 분석 도구 (가열로 2호기)  v0.69               │
└──────────────────────────────────────────────────────────────┘
```

**아랫줄에는 단추가 없습니다.** 그래서 미는 것이 아무것도 없고, 창 폭까지
길게 적어도 윗줄은 그대로입니다. 길이를 가둘 이유도 없어졌습니다 — 창 폭을
넘을 때만 `…` 로 자릅니다.

제가 0.66 에서 "길이를 제한하는 대신 자리를 제한했다" 고 적었는데, 그건 같은
줄 안에서 자리를 뺏는 일이었습니다. **줄을 하나 내리는 것이 진짜로 자리를
안 뺏는 방법**이었습니다.

### 값

작은 글자 한 줄, 약 15 픽셀만큼 아래 화면이 줄어듭니다. 0.65 에서 메인 화면
높이를 100 픽셀 줄여 뒀으니 그 안에서 감당됩니다. 위 줄의 안쪽 여백도
`12,6` → `12,5` 로 2 픽셀 줄여 보탰습니다.

**긴 이름을 안 적었으면** 아랫줄에 판 번호만 남습니다. 줄 자체를 없애려면
판 번호를 다시 윗줄로 올려야 하는데, 그러면 적었을 때와 안 적었을 때 모양이
달라집니다 — 한 가지 모양이 낫다고 봤습니다.

창 제목(0.68)은 그대로 둡니다. 작업 표시줄과 Alt+Tab 에서 보이는 것은 그쪽
글이고, 화면 안에서 보이는 것은 아랫줄입니다.

테스트 **630 통과 / 0 실패**, 검사 넷 다 통과.

**못 해 본 것**: 위 줄이 두 줄이 되면서 실제로 몇 픽셀 늘었는지입니다.
메인 화면에 다시 스크롤이 생기면 `MainView.xaml` 의 `MinHeight` 를 390 에서
조금 더 내리면 됩니다.
