# 164 — 단계를 풀어도 단계 진입이 같은 시각으로 나오던 것 · 분석 1 다시 검사 (1.73)

> 아니 분명히 단계를 풀었는데 원래는 다른 시간대에 단계 진입하는데 같은 시간대 진입한다고 나오는 건 뭐임
> 분석 1 다시 싹 검사해서 고쳐

## 까닭

그래프의 이후 로그 밀기 값 · 대시보드 · 판정 · 메인 칸은 모두 **마지막 비교 결과**를 그립니다
(그래프 밀기 값 = `Comparison.AppliedShift`). 그런데 **설정 창을 닫을 때는 다시 견주지 않았습니다** (0.9x 부터,
허용 오차 % 만 1.66 에 예외).

```
 단계 B 고름 → 비교 (이후를 −10 밀어 B 시작을 겹침)
 설정 창에서 단계 IO 지움 → 단계 · 고른 단계 풀림   ← 여기서 다시 안 견줌
 그래프 → 옛 비교의 밀기 값 −10 그대로 → B 진입이 같은 시각으로 보임
```

시작 맞춤 · 손 밀기 · 절대 허용 오차 · IO 별 허용 오차를 설정 창에서 바꿔도 같은 일 (옛 결과).

## 고침

| | |
|---|---|
| 비교가 지금 설정과 맞는지 | 비교할 때 쓴 것 (고른 단계 + 그 밀기 값 · 단계 IO · 시작 맞춤 · 손 밀기 · 사건 맞추기 · 허용 오차 · IO 별 허용) 을 글 하나로 적어 두고 지금 것과 다르면 "옛 결과" (`AppState.ComparisonStale`) |
| 설정 창 닫을 때 | 옛 결과면 **시간 맞추기부터 다시 · 다시 견줌** (대시보드 · 그래프 · 판정 · 메인 · 히트맵) |
| 화면 · 쪽을 옮길 때 | 안전망 — 옛 결과면 다시 견줌 (어느 길로 바뀌었든) |
| 단계 바뀜 처리 | 견줄 것이 바뀐 때만 다시 견줌 (나눠 보기 · [시작을 0 으로] 는 모양만 → 빠름, 히트맵도 안 지움) |
| 메인 IO 창의 [그래프] | 히트맵 칸처럼 (1.71) — 오차가 난 **단계를 고르고** (판정과 같은 맞춤, 같은 이름이면 오차 시각이 든 단계), 나눠 보기 끔, 구간은 로그 안으로 (마이너스 없음) |
| 그래프에서 그룹을 고침 | 메인 칸 요약도 바로 새 그룹으로 (예전에는 다음 비교까지 옛 그룹) |

## 다시 검사한 것 (분석 1 · 창이 받는 일 전부)

| 일 | 결과 |
|---|---|
| 로그 열기 · 놓기 · [분석] | 시간 맞추기 → 견줌 → 모두 다시 · 고른 단계 풀림 — 맞음 |
| 시간 맞추기 판 | 다시 맞춤 → 견줌 — 맞음 |
| 단계 고르기 · 풀기 · 나눠 보기 · 0 으로 | 미뤄서 (1.69), 견줄 것이 바뀐 때만 견줌 — 고침 |
| 그래프 · 히트맵 허용 오차 칸 | 둘 다 · 견줌 (1.66) — 맞음 |
| 설정 창 | **안 견줬음 → 고침** |
| 허용 · 허용 풀기 | 판정만 다시 · 대시보드 · 그래프 목록 · 히트맵 (1.68) — 맞음 |
| 히트맵 칸 → 그래프 | 1.71 — 맞음 |
| 메인 IO 창 [그래프] | 시각만 넘겼음 → **고침** |
| 그룹 고치기 | 히트맵만 → **메인도** |
| 판정 (단계 켬 ⊆ 끔) | 무작위 1000 쌍 다시 — 어긋남 0 |

## 확인
- 테스트 1115 통과 (새 것: 단계 B 고름 → 밀기 −10 → 단계 IO 지움 → 옛 결과로 보임 → 다시 견주면 밀기 0, 손 밀기 · 시작 맞춤 ·
  허용 오차 · IO 별 허용도 옛 결과로 · 상관없는 설정은 아님, 오차 → 그래프), 실제 csc 7.3 오류 0, 검사 스크립트 통과
- **Windows 에서 못 봄** — 창 (설정 창 닫기 · 화면 옮기기) 흐름은 여기서 못 돌림. 계산 쪽 (옛 결과 가리기 · 밀기 값) 은 테스트로 확인
