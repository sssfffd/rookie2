# 122 — 분석 3 요약 줄: 길면 줄 바꿈 + [오류] 꼬리표 색

> 근데 지금 분석 3 요약 메세지 보내면 한줄한줄 길어서 가로가 짤리네 우짜지
>
> 그리고 오류 경고 정상에 왼쪽에 불들어오게 했잖아? 그거 오류 경고 정상 문구도 같은 색으로
> 칠해지게 해줘(전체 줄 말고 [오류] 이것만)

## 바꾼 것 (1.40)

```
 전                                         후
 ● [오류] 압력 센서 응답이 기준 시간…        ● [오류] 압력 센서 응답이 기준 시간을
                                              넘었습니다 (12.3 s)
                                            ↑ 빨간 점   ↑ [오류] 만 빨간 글씨
```

| | 분석 2 줄 | 분석 3 줄 |
|---|---|---|
| 이름이 길 때 | … 으로 자름 (IO 이름) | **줄을 바꿔 다 보임**, 점은 첫 줄 높이 |
| 오른쪽 값 | 240 까지, 자름 | 140 폭에서 줄 바꿈 |
| `[오류]` 같은 꼬리표 | (거의 없음) | **꼬리표만 점과 같은 색** (빨강 · 노랑 · 초록) |
| 줄에 마우스 | "분석 2 화면에서 이 IO 를 찾아 줍니다." | "분석 3 화면으로 넘어갑니다." |

- 꼬리표 = 이름이 `[` 로 시작하고 12 글자 안에 `]` 가 있는 앞부분 (`CardLineVm.TagOf`).
- 색을 안 정해 보냈으면(`Grade` 비움) 꼬리표 낱말로 고름 — 오류·에러·ERROR·FAIL·NG 빨강, 경고·주의·WARN·WARNING
  노랑, 정상·OK·PASS 초록 (`CardLineVm.GradeOfTag`). 정해 보냈으면 그 색.
- XAML: 이름 TextBlock 을 Run 둘(꼬리표 · 나머지)로. `Run.Text` 는 기본이 양방향 바인딩이라 `Mode=OneWay`.

## 확인

- 리눅스 컴파일 · 시험 919 통과 (꼬리표 · 줄 바꿈 9 개 더), 실제 C# 7.3 컴파일러 오류 0.
- **못 한 것**: XAML 화면 — Run 의 색 트리거 · 줄 바꿈 모양은 Windows 에서 확인 필요.
