## 1. 분석 칸 셋을 가로로

> 처음에는 "세로로 3개, 가로로 길게" 로 만들었다가, 이어진 요청으로
> **가로 배치**로 되돌렸습니다. 아래는 지금 모습입니다.

```
┌─────────────────────┐ ┌─────────────────────┐ ┌─────────────────────┐
│ [분석 1] 로그 비교   │ │ [분석 2] 분석 2      │ │ [분석 3] 분석 3      │
│                     │ │                     │ │                     │
│  100 / 100          │ │  ?? / 100           │ │  ?? / 100           │
│  만점               │ │  아직 만들지 않았습니다│ │  아직 만들지 않았습니다│
│                     │ │                     │ │                     │
│ 견준IO 달라진 한쪽에만│ │                     │ │                     │
│  184개  12개   3개   │ │                     │ │                     │
│                     │ │                     │ │                     │
│ 이전 로그와 이후    │ │ 아직 정해지지        │ │ 아직 정해지지        │
│ 로그를 견줍니다…    │ │ 않았습니다.          │ │ 않았습니다.          │
└─────────────────────┘ └─────────────────────┘ └─────────────────────┘
```

**WrapPanel 이 아니라 UniformGrid 입니다.** WrapPanel 은 창이 좁아지면 한
칸이 아래로 내려가 2+1 로 접힙니다. 셋이 나란히 있어야 서로 견줘 보이는
것이라, 좁아지면 **다 같이 좁아지는** 편이 낫습니다. 폭도 똑같이 나눠 가집니다.

설명 줄의 높이를 고정해 세 칸의 키를 맞췄습니다. 글 길이가 달라도 칸이
들쭉날쭉해지지 않습니다.

칸 가운데의 숫자(견준 IO / 달라진 IO / 한쪽에만)는 견주면서 이미 나온 값이라
새로 세지 않습니다. 견주기 전에는 그 줄이 통째로 사라집니다.

아주 넓은 모니터에서 끝없이 늘어나지 않게 전체 폭은 1180 에서 멈춥니다.

## 2. 점수는 견주기 전에는 `??`

```
견주기 전   ?? / 100     로그를 견주면 점수가 나옵니다
견준 뒤    100 / 100     만점
```

**0 점도 만점도 아닌 이유**가 있습니다. 0 으로 두면 "다 틀렸다", 만점으로
두면 "다 맞았다" 는 뜻이 됩니다. 아직 아무것도 재지 않았는데 둘 다
거짓말입니다.

`??` 는 회색, **만점일 때만 초록**입니다. 안 재 본 값까지 초록이면 다
맞았다는 뜻으로 읽힙니다.

분석 2·3 은 만들지 않았으므로 견주든 말든 계속 `??` 입니다.

### 점수 규칙은 아직 안 넣었습니다

견주고 나면 100 점을 줍니다. 무엇을 어떻게 점수로 매길지 정해지기 전에
아무 수식이나 넣어 두면 **그 수가 진짜인 줄 알고 읽게 됩니다.** 화면 아래에도
그렇게 적어 뒀습니다.

채울 자리는 `MainVm.Refresh()` 의 한 줄입니다.

```csharp
Cards[0].SetScore(AnalysisCardVm.MaxScore);   // ← 진짜 점수가 들어갈 자리
```

## 3. "뭘 더 넣으면 좋을까" — 넣은 것

### 열어 둔 로그 (칸 위)

```
┌──────────────────────────────────────────────────────────────────────────┐
│ 열어 둔 로그                                                             │
│ ● 이전  발생시간 2026-03-14   IO 184 · 표본 52,310                       │
│ ● 이후  발생시간 2026-03-21   IO 187 · 표본 49,882   칸을 누르면 그 분석 │
│         비교 실행  2026-09-22 14:32:07                화면으로 넘어갑니다 │
└──────────────────────────────────────────────────────────────────────────┘
```

이 정보가 **아래 알림 줄 한 줄에만** 있었습니다. 메인 화면이라면 "지금 무엇을
보고 있는가" 가 제일 먼저 보여야 합니다. 이전/이후 점 색은 그래프의 선 색과
같은 것을 씁니다.

### 발생시간은 파일 이름 앞부분입니다

로그 파일 안에는 **"이 로그가 언제 기록된 것인가" 가 적혀 있지 않습니다.**
시간 열은 0 부터 세는 경과 시간일 수도 있고, 시각이어도 날짜가 없을 수
있습니다. 대신 파일 이름 앞에 날짜를 붙이는 것이 보통이라, 그 **앞 10 글자를
그대로** 떼어 보여 줍니다.

```
2026-03-14_before.xlsx  →  2026-03-14
20260314_설비A.csv       →  20260314_설
```

자른 자리에 `_` `-` `.` 이 걸리면 지저분해서 끝만 다듬습니다. **짐작해서
날짜 모양으로 만들어 내지는 않습니다** — 이름이 그렇게 생기지 않은 파일에서
엉뚱한 날짜를 지어내게 됩니다. 전체 경로는 그 줄에 마우스를 올리면 나옵니다.

### 비교 실행 시각

허용 오차나 시간 맞추기를 바꾸고 **다시 견주는 일이 잦습니다.** 그런데 지금
화면에 떠 있는 결과가 언제 나온 것인지 알 수 없으면, 고치고 [비교 다시 하기]
를 안 누른 채 옛 결과를 새것으로 착각하게 됩니다.

`AppState.Recompare()` 가 끝날 때 시각을 적어 둡니다.

### 겹치는 구간은 뺐습니다

자리를 비교 실행 시각에 내줬습니다. 그 값은 대시보드와 히트맵 요약에
그대로 있습니다.

로그가 없으면 그 자리에 무엇을 해야 하는지 적습니다 — "위쪽의 [이전 로그
열기] / [이후 로그 열기] 로 파일을 먼저 열어 주세요."

### 분석마다의 숫자 (칸 가운데)

| 숫자 | 어디서 |
|---|---|
| 견준 IO | 양쪽 로그에 다 있는 IO 수 |
| 달라진 IO | 허용 오차를 넘은 IO 수 |
| 한쪽에만 | 이전에만 + 이후에만 있는 IO 수 |

셋 다 이미 견주면서 나온 값이라 새로 세지 않습니다. 견주기 전에는 칸이
비어 있습니다.

### 넣을까 하다가 안 넣은 것

| | 왜 안 넣었나 |
|---|---|
| 작은 그래프 미리보기 | 어느 IO 를 보여 줄지 정할 근거가 없습니다. 아무거나 고르면 그게 중요한 IO 인 줄 압니다 |
| 최근 연 파일 목록 | 이미 세트가 그 일을 합니다. 두 가지 길이 생기면 어느 쪽이 최신인지 헷갈립니다 |
| 가장 많이 달라진 IO 순위 | 대시보드가 이미 하는 일입니다. 같은 것을 두 군데서 다르게 정렬해 보여 주면 서로 안 맞아 보입니다 |

## 4. 점수 색 설명 (오른쪽 아래)

점수만 숫자로 적어 놓으면 60 이 나쁜 건지 보통인지 알 수가 없습니다.
그래서 색으로도 읽히게 하고, 그 색이 무슨 뜻인지 화면 오른쪽 아래에 작게
적어 둡니다.

```
                                                점수 색
                                          ● 90 ~ 100   이상 없음
                                          ● 70 ~ 89    확인 필요
                                          ● 0 ~ 69     점검 필요
```

칸의 큰 점수도 같은 색으로 칠합니다. **아직 안 재 본 `??` 는 회색**입니다 —
안 재 본 값에 초록이나 빨강을 칠하면 재 본 값으로 읽힙니다.

### 경계 값은 한 곳에만

```csharp
public static class ScoreBands
{
    public const double GoodFrom = 90;
    public const double WarnFrom = 70;
    ...
    public static List<BandVm> Legend() { ... }
}
```

칸의 점수 색과 아래의 색 설명이 **같은 값을 봅니다.** 따로 적어 두면 한쪽만
고치게 되고, 그러면 설명이 화면과 다른 말을 하게 됩니다. 설명 줄도 이
상수에서 만들어 내므로 "90" 을 "85" 로 바꾸면 글자까지 같이 바뀝니다.

C# 은 컴파일해서 확인했습니다 (테스트 275 통과, 그대로).

실제로 띄워 봐야 압니다 — 왼쪽 칸에 최소 폭 220 을 걸어 두긴 했습니다.

재기 시작하면 그 계산은 Core 로 내려서 테스트를 붙이는 편이 맞습니다.
