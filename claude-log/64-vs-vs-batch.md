# 64 — VS 는 성공, 배치는 실패 · 테스트는 왜 있나 (0.83)

## 주신 말

> 내가 db안에 파일들 고치니까 visual studio에서는 빌드 성공하는데
> 배치파일은 fail이 뜸
>
> 그리고 test 코드들은 목적이 뭐야 없어도돼?

---

## 1) 왜 다른가 — `build.bat` 은 두 가지를 더 합니다

| | Visual Studio (F5 · 프로젝트 빌드) | build.bat |
|---|---|---|
| LogScope.App 과 그게 참조하는 것 | 빌드 | 빌드 |
| **LogScope.Tests 를 빌드** | **안 함** | 함 |
| **테스트를 돌림** | **안 함** | 함 |
| out 폴더로 모으기 | 안 함 | 함 |

VS 는 **시작 프로젝트와 그것이 참조하는 것만** 빌드합니다. `LogScope.App`
은 `LogScope.Tests` 를 참조하지 않으므로 **Tests 는 아예 컴파일되지
않습니다.** build.bat 은 솔루션을 통째로 빌드하고 테스트까지 돌립니다.

그래서 둘 중 하나입니다. **화면의 글이 어느 쪽인지 말해 줍니다.**

```
빌드 실패. 오류 줄만 추려 보면:     ← ①  Tests 가 컴파일 안 됨
[오류] 테스트가 실패했습니다.        ← ②  테스트가 실패
```

### ① 이면

`DbDiffList` 같은 것의 이름이나 인수가 바뀌어서, 그걸 부르는 시험
코드가 안 맞는 것입니다. 오류 줄에 `src\LogScope.Tests\Program.cs` 가
적혀 있습니다. VS 에서 같이 보시려면 **[빌드] → [솔루션 빌드]** 입니다.

### ② 이면

**제 잘못일 가능성이 큽니다.** 아래 2 번을 보세요.

### build.bat 이 이제 그 차이를 말해 줍니다

실패할 때 "VS 에서는 성공으로 보일 수 있다 — VS 는 테스트를 돌리지
않는다" 와 `[빌드] → [솔루션 빌드]` 를 함께 적습니다. 글을 몰라서 한
번 더 물어보게 되는 자리였습니다.

## 2) 제가 넣어 둔 시험 하나가 당신 수정을 막고 있었습니다

```csharp
Check("v1 은 비어 있음", bb.V1.Length == 0, bb.V1);   // ← 틀린 시험
Check("v2 도 비어 있음", bb.V2.Length == 0, bb.V2);
```

`DbDiffList.Build` 가 만든 줄의 `v1` 이 **비어 있어야 한다**고 못 박아
두었습니다. 그런데 그 칸을 채우는 것이 바로 제가 "여기서 채우세요" 라고
알려 드린 일입니다 (`DbDiffList.OneRow`). **채우는 순간 이 시험이
실패합니다.**

시험이 "하라고 알려 준 일" 을 막으면 그건 시험이 틀린 것입니다. 두
가지만 보도록 고쳤습니다.

1. `new DbDiffLine()` 의 기본값이 빈 글자인지 (지어낸 값이 아닌지)
2. 채우면 CSV 와 마우스 설명 글에 그대로 나가는지

`OneRow` 에 `ln.V1 = DbRow.Show(...)` 를 실제로 넣어 보고 **670 개가
전부 통과하는 것**을 확인했습니다.

## 3) 테스트는 왜 있나 — 없어도 되나

### 짧게

**없어도 프로그램은 돕니다.** `build.bat Release nt` 로 건너뛸 수
있고, out 폴더에 들어가지도 않습니다. 다만 이 저장소에서는 **값을
하고 있습니다.**

### 왜 있나

이 프로그램은 **"두 벌이 다르다/같다" 를 말해 주는 도구**입니다. 여기서
가장 나쁜 고장은 터지는 것이 아니라 **조용히 틀린 답을 하는 것**입니다 —
없는 차이를 만들거나, 있는 차이를 가리는 것. 그건 눈으로 봐서는
모릅니다. 화면도 멀쩡하고 오류도 안 납니다.

그리고 제가 개발하는 환경은 **윈도우가 아닙니다.** XAML 도 WPF 도 여기서
돌려볼 수 없습니다. 화면은 당신이 켜 보셔야만 압니다. 그 대신 **값을
다루는 쪽은 기계가 봅니다.**

### 실제로 잡은 것들 (제가 낸 버그입니다)

| 무엇 | 안 잡혔으면 |
|---|---|
| `0xZZ` 를 넣으면 `ZZ` 가 나옴 (떼어 낸 `0x` 를 안 돌려줌) | 값이 조용히 달라짐 |
| CSV 머리글과 화면 머리글이 어긋남 | 엑셀에서 칸이 밀림 |
| 갈래 글자를 손으로 적어 `알림` 이 목록에 섞임 | 알림이 차이인 줄 보임 |
| CP949 덤프를 UTF-8 로 읽음 | **한글 값이 전부 쓰레기** |
| `GroupsChanged` 를 아무도 안 들음 | 그룹 변경이 저장 안 됨 |

마지막 두 개는 **당신이 쓰시다가 발견하셨을 것**들입니다.

### 그래서 어떻게 하시면 되나

| 하려는 것 | 명령 |
|---|---|
| 평소 (권합니다) | `build.bat` |
| 지금 당장 exe 만 필요 | `build.bat Release nt` |
| 테스트만 돌려 보기 | `src\LogScope.Tests\bin\Release\LogScope.Tests.exe` |

**시험이 당신 코드를 틀렸다고 하면 알려 주세요.** 이번처럼 시험이 틀린
경우가 있습니다. 그때는 시험을 고치는 것이 맞습니다 — 코드를 시험에
맞추려고 비틀면 안 됩니다.

지우기를 원하시면 지웁니다 (`src/LogScope.Tests` 와 솔루션에서 한
줄씩). 다만 그러면 위 표의 종류를 **윈도우에서 쓰시다가** 만나게
됩니다. 제 쪽에서 더는 막을 방법이 없습니다.
