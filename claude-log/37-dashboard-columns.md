# 37 — 대시보드에서 RMS · 구간 수 빼기

> 요청: "대시보드에서 RMS 구간수는 빼줘"

## 무엇을 뺐나

차이 목록의 칸 여덟 개 중 둘을 뺐습니다.

```
전:  IO 이름 · 구분 · 최대 오차 % · 최대 차이 · 평균 차이 · RMS · 차이 시간 · 구간 수
후:  IO 이름 · 구분 · 최대 오차 % · 최대 차이 · 평균 차이 · 차이 시간
```

설정 창의 **[목록 정렬 기준]** 콤보에서도 같이 뺐습니다. 안 보이는 칸을
정렬 기준으로 고를 수 있으면, 목록 차례가 왜 그렇게 됐는지 알 수가 없습니다.

## 예전 설정이 그 기준을 들고 있으면

`차이 면적` 을 뺐을 때와 같게 처리합니다 — 읽을 때 기본값(`최대 차이`)으로
돌립니다.

```csharp
if (s.SortMetric == DiffMetric.Area
 || s.SortMetric == DiffMetric.Rms
 || s.SortMetric == DiffMetric.SegmentCount) s.SortMetric = DiffMetric.MaxAbs;
```

그대로 두면 **아무 칸에도 삼각형이 붙지 않은 채** 보이지 않는 기준으로
정렬됩니다. 목록은 뒤죽박죽인데 왜 그런지 알 수 없는 상태가 됩니다.

## 계산은 남겨 뒀습니다

`ChannelDiff` 의 RMS 와 구간 수는 **Core 에 그대로 있습니다.** 화면에서만
뺐습니다. 나중에 다시 꺼내 쓸 수도 있고, 지금도 그래프 쪽에서 쓰는 값이라
지울 이유가 없습니다.

## 자체 테스트

**테스트 3 개를 더했습니다 (386 → 389).** 뺀 차이량 셋(`차이 면적`·`RMS`·
`구간 수`)이 예전 설정 파일에 남아 있을 때 기본값으로 돌아오는지 봅니다.

이미 있던 "정렬 기준" 검사가 `구간 수` 로 돌고 있어서 그 자리에서
**실패로 잡혔습니다.** 화면에서 뺀 값을 검사가 아직 기대하고 있던 것이라,
검사 쪽을 `차이 시간` 으로 옮기고 빠진 자리를 위 검사로 메웠습니다.

### 아직 확인 못 한 것

칸을 둘 뺐으니 남은 칸들의 폭이 바뀝니다. 목록이 가로로 남는지 모자라는지는
윈도우에서 봐 주세요.
