# 136 — 센서 로그 비교 기법 (DTW 등) — 정상이어도 시간차 · 작은 오차가 있을 때

> 그리고 로그 분석할 때 여러 기법이 있잖아? DTW같은 것들 / 분석 1에서 센서 값 로그들 비교하는 건데(시간에 따른
> 변화량이 나타남) / 얘네 비교할때 차이점을 나타내고 싶으면 어떤 기법 쓰는게 좋을까 / 현실 센서값 문제가 동일
> 동작의 정상 작동이여도 물리적인 이슈때문에 시간차이나 사소한 오차는 있을 수 있는거잖아

(질문 — 코드 안 바꿈)

## 지금 분석 1 이 하는 것
시작(또는 기준 IO 사건 · 단계)으로 한 번 밀어 맞춘 뒤 **같은 시각끼리 한 점씩** 빼서 허용 오차(% · 절대)를 넘는지.
→ 0.3 초만 늦게 올라가도 그 0.3 초 동안 "큰 차이" 로 잡힘. 단계마다 밀기(StepPairs)로 일부 줄였지만 단계 **안**의
늘어짐 · 흔들림은 못 걸러 냄.

## 기법 비교

| 기법 | 무엇을 견딤 | 약점 | 10M 칸에서 |
|---|---|---|---|
| 상호상관(cross-correlation) 으로 지연 찾기 | 일정한 시간 밀림 | 늘어짐 · 줄어듦은 못 맞춤 | 빠름 |
| **시간 허용 띠 (envelope)** — 이후 값이 이전의 [t−Δt, t+Δt] 최소~최대 ± 값 허용 오차 안이면 같음 | 작은 시간차 · 작은 오차 **둘 다** | Δt 보다 큰 지연은 차이로 잡힘 (그게 맞음) | O(n), 빠름 |
| **DTW** (동적 시간 워핑) | 늘어짐 · 줄어듦 · 지연 | O(n·m) · **진짜 지연까지 "맞춰서" 숨김** · 결과 설명이 어려움 | 원본으론 불가 → 단계별 · 줄여서(1~2 천 점) · 띠 제한(Sakoe-Chiba) |
| 단계별 특징값 — 길이 · 평균 · 최대/최소 · 오버슈트 · 상승 시간 · 안정 시간 · 기울기 · 면적 | 시간차 · 잡음 대부분 | 모양의 세부는 못 봄 | 아주 빠름 · 설명 쉬움 |
| 디지털 사건 짝짓기 (k 번째 켜짐끼리, ±Δt) | 지연 | 아날로그엔 안 맞음 | 빠름 |
| 정상 로그 여러 개로 기준 띠 (평균 ± kσ) | 정상 흔들림 자체를 배움 | 정상 로그가 여러 개 있어야 | 빠름 |
| 걸러 내기 (이동 중앙값 · 저역 통과 · 데드밴드) | 순간 튐 · 잡음 | 짧은 진짜 이상도 깎임 | 빠름 |

## 추천 — 층으로

```
 1) 단계로 자르기 (있음)  → 단계마다 시작 맞추기 (있음)
 2) 단계 안: 시간 허용 띠로 "다름" 판정     ← 주 판정. Δt · 값 허용 오차를 IO/그룹마다
 3) 단계별 특징값 표 (길이 · 최대 · 상승 시간 …) ← "무엇이 어떻게 다른가" 설명 · LLM 입력
 4) DTW 는 판정이 아니라 "시간 어긋남 크기" 재는 데만
      → "이후가 평균 0.3 s 늦음, 최대 1.2 s", 맞춘 뒤 남은 값 차이도 따로
 5) 디지털 · 상태: 사건 짝짓기 + 지연 분포 (±Δt 안이면 정상)
 (나중) 정상 로그 여러 개가 쌓이면 기준 띠
```

DTW 를 주 판정으로 쓰지 않는 까닭: 밸브가 1 초 늦게 열린 것이 진짜 문제여도 DTW 는 그 1 초를 휘어 맞춰
"같음" 으로 만듭니다. 그래서 **휘어진 양(경로가 대각선에서 벗어난 정도)을 따로 지표로** 내는 쪽으로만.

설정에 더할 것: IO · 그룹별 **시간 허용 Δt** (예: 밸브 ±0.2 s, 온도 ±2 s) — 지금의 값 허용 오차 표 옆.

다음: 2) 시간 허용 띠 + 3) 단계별 특징값부터 만들지 사용자에게 물음.
