# 31 — 끌어다 놓을 때 이전/이후를 화면 반쪽으로

> 요청: "드래그해서 log올릴 때 어떤 곳에 놓아야 이전 log고 어떤 곳이 이후
> log인지 구분이 힘든데"

## 무엇이 문제였나

끌어다 놓기를 처음 붙일 때 놓을 자리를 **메인 화면의 이전/이후 줄**로 뒀습니다.

```
● 이전  발생시간 2026-03-14  2026-03-14_before.xlsx  IO 184 · 표본 52,310
● 이후  발생시간 2026-03-21  2026-03-21_after.xlsx   IO 187 · 표본 49,882
```

줄 높이가 20 픽셀 남짓입니다. **마우스로 겨냥할 수 있는 크기가 아닙니다.**
게다가 파일을 끌고 있는 동안에는 커서 옆에 파일 아이콘이 붙어서 그 줄을
가립니다. 어느 줄 위에 있는지 보이지도 않았습니다.

그리고 메인 화면에서만 됐습니다. 분석 1 화면에서 끌어다 놓으면 창 아무
데나 놓는 규칙(비어 있는 자리 → 물어보기)이 걸리는데, 그건 놓기 전에는
알 수가 없습니다.

## 어떻게 했나

**파일이 창에 들어오는 순간 화면을 반으로 갈라 크게 보여 줍니다.**

```
┌───────────────────────────────────────────────────────────┐
│           끌고 온 파일 : 2026-03-21_after.xlsx            │
│                                                           │
│  ┌─────────────────────┐   ┌─────────────────────┐        │
│  │          ●          │   │          ●          │        │
│  │        이전         │   │        이후         │        │
│  │  여기에 놓으면      │   │  여기에 놓으면      │        │
│  │  이전 로그 (기준)   │   │  이후 로그 (견줄 것)│        │
│  │                     │   │                     │        │
│  │  지금 : before.xlsx │   │  지금 비어 있습니다 │        │
│  │  놓으면 이것을      │   │                     │        │
│  │  덮어씁니다         │   │                     │        │
│  └─────────────────────┘   └─────────────────────┘        │
│        창 밖으로 끌고 나가면 취소됩니다                   │
└───────────────────────────────────────────────────────────┘
```

- **왼쪽 = 이전, 오른쪽 = 이후.** 반쪽씩이라 겨냥할 필요가 없습니다.
- 테두리와 글자 색이 **본문 그래프의 이전/이후 색과 같은 색**입니다
  (`Brush.Before` / `Brush.After`). 메인 화면의 점 색과도 같습니다.
- 커서가 올라간 쪽이 **밝아지고 테두리가 굵어집니다** — 놓기 전에
  어디로 들어갈지 보입니다.
- 그 자리에 **이미 무엇이 들어 있으면 그 이름과 "덮어씁니다"** 를 적습니다.
  덮어쓸 것을 모르고 놓는 일이 없게.
- **어느 화면에 있든** 똑같이 나옵니다 (메인·분석 1·2·3). 창에 붙인
  안내 판이라서 그렇습니다.
- 두 개를 한꺼번에 놓으면 **어느 쪽에 놓아도** 이름 순으로 이전 → 이후 로
  들어갑니다. 아래 줄에 그렇게 적습니다.

메인 화면의 이전/이후 줄 놓기도 그대로 남겨 뒀습니다. 안내 판이 어떤 이유로
안 뜨는 경우의 대비입니다.

## 걸렸던 것들

**1. `DragLeave` 는 자식 사이를 지날 때도 올라옵니다.**
그때마다 판을 닫으면 커서를 움직일 때마다 깜빡입니다. 창 밖으로 나갔을
때만 닫습니다.

```csharp
Point p = e.GetPosition(this);
if (p.X <= 0.5 || p.Y <= 0.5 || p.X >= ActualWidth - 0.5 || p.Y >= ActualHeight - 0.5)
    HideDropOverlay();
```

**2. 반쪽의 `Drop` 에서 `e.Handled` 을 세워야 합니다.**
안 세우면 창의 `Drop` 까지 올라가서 **같은 파일을 두 번 읽습니다** (한 번은
고른 자리로, 한 번은 "비어 있는 자리" 규칙으로). 반대로 `DragOver` /
`DragLeave` 에서는 세우지 <b>않습니다</b> — 창까지 올라가야 위의 판단을 할 수
있습니다.

**3. 끌기가 취소됐는데 판이 남는 경우.**
`Esc` 를 누르거나 창 밖에서 놓으면 `DragLeave` 가 안 올 수 있습니다. 보험을
하나 뒀습니다 — 끌고 있는 동안에는 `MouseMove` 가 오지 않으므로(마우스를
끌기 원본이 잡고 있습니다) `MouseMove` 가 왔다는 것은 끌기가 끝났다는
뜻입니다.

**4. 자리를 정해 놓고 두 개를 놓으면?**
전에는 둘째를 버렸습니다. 왜 하나만 들어왔는지 알 수가 없는 동작입니다.
이제 둘째는 반대쪽으로 갑니다.

## 자체 테스트

테스트 328 통과(그대로). 화면 쪽이라 Core 에 붙일 것이 없었습니다.
`x:Name` 일곱 개는 검사 스크립트가 진짜 WPF 타입으로 붙여 컴파일까지
확인했습니다 (`Grid` / `Border` / `TextBlock`), 처리기 시그니처도 검사했습니다.

### 아직 확인 못 한 것

**끌어다 놓기는 실제로 마우스로 해 봐야 압니다.** 특히

- 판이 뜨는 순간 커서 밑이 판으로 바뀌는데, 그 다음 `DragOver` 가 반쪽에
  제대로 들어오는지
- 두 모니터를 쓰거나 창이 화면 밖에 걸쳐 있을 때 `ActualWidth` 기준의
  창 밖 판단이 맞는지

두 가지는 윈도우에서 봐 주셔야 합니다.
