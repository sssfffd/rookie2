# 65 — 테스트가 빌드를 막지 않게 (0.84)

## 주신 말

> test는 너가 쓰기 위한거라고?
>
> ㅇㅇ A처럼 바꿔줘

## 맞는 지적이었습니다

테스트는 **대부분 제 안전망**입니다. 제 환경은 윈도우가 아니라서 XAML 도
WPF 도 못 돌려 봅니다. 값 다루는 코드를 고쳤을 때 무엇이 깨졌는지 알 수
있는 수단이 그것뿐입니다.

그런데 그 비용을 **당신이** 내고 있었습니다 — 제 안전망이 당신 빌드를
멈춰 세웠습니다. 지금까지 테스트가 잡은 것은 전부 제 버그였고, 어제는
오히려 당신이 하려던 일(v1 채우기)을 막았습니다.

순서가 뒤바뀐 것이었습니다.

## 고친 것

### `build.bat` — 테스트 실패가 빌드를 멈추지 않습니다

```
전:  테스트 실패 → goto :fail → exe 없음, 종료 코드 1
후:  테스트 실패 → 알리고 계속 → exe 그대로, 종료 코드 0
```

실패하면 두 번 말합니다.

1. 테스트 바로 뒤에서
   ```
   [알림] 테스트가 실패했습니다. 위의 FAIL 줄을 보세요.
          빌드는 계속합니다. exe 는 그대로 만들어집니다.
          Visual Studio 에서는 이 글이 안 나옵니다.
          VS 는 테스트를 돌리지 않습니다.
          테스트를 아예 건너뛰려면: build.bat Release nt
   ```
2. **맨 끝 "완료" 뒤에 한 번 더** — 테스트는 빌드 중간에 지나가서 글이
   스크롤로 밀려 올라갑니다. 끝에서 다시 적지 않으면 못 보게 됩니다.
   ```
   [알림] 테스트가 실패한 채로 만들어졌습니다.
          위쪽 FAIL 줄을 한 번 봐 주세요.
          값을 다루는 쪽이 틀렸을 수 있습니다.
   ```

### 이제 `build.bat` 이 실패로 끝나면 그건 컴파일 오류입니다

판별이 간단해졌습니다.

| 화면의 글 | 무엇 | 멈추나 |
|---|---|---|
| `빌드 실패. 오류 줄만 추려 보면:` | 컴파일 오류 | **멈춤** |
| `[알림] 테스트가 실패했습니다.` | 테스트 실패 | 계속 |

### 제 쪽은 그대로 둡니다

`scripts/check_compile.sh`(리눅스에서 제가 돌리는 것)는 **테스트 실패가
곧 실패**입니다. 그건 제 안전망이고, 저는 그것에 막히는 것이 맞습니다.

막히는 쪽과 안 막히는 쪽을 나눈 것이 이번 고침의 전부입니다.

## 안 바꾼 것

- 테스트 자체는 그대로입니다 (669 개). 지우지 않았습니다 — 지우기를
  원하시면 말씀해 주세요.
- `build.bat Release nt` 도 그대로 있습니다. 테스트를 **돌리지도** 않고
  싶을 때 (조금 더 빠릅니다).

## 확인한 것 · 못 한 것

- `build.bat` 은 **CP949 · CRLF 그대로**이고, 괄호 블록 균형을 다시
  셌습니다 (끝값 0, 음수가 되는 줄 없음)
- `통과 669 / 실패 0`, 검사기 넷 지적 없음
- **Windows 에서 확인 못 했습니다**: `cmd.exe` 를 여기서 돌릴 수
  없습니다. `set "TESTFAIL=1"` 을 `if (...)` 블록 안에서 두고
  `if defined TESTFAIL` 로 밖에서 읽는 모양이라 지연 확장 없이도
  도는 것이 맞지만, **한 번 돌려 보시고 끝에 그 글이 나오는지만**
  봐 주세요. 테스트가 성공하면 아무 글도 안 나와야 합니다.
