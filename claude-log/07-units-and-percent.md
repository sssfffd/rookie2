# 07 — 세로축 단위와 히트맵의 값/퍼센트

> 요청: "히트맵에서 오차 발생 값들 기존 value랑 % 선택해서 볼 수 있게 해줘"
> "그래프 창이 좀 분석하기가 힘든 것 같은뎀 세로축들이 좀 이상하네
> 일단 세로축에 단위도 적어줘"

두 가지 모두 **"이 숫자가 무슨 숫자냐"** 를 알 수 없다는 같은 문제였습니다.

---

## 1. 세로축에 단위 — 사실 읽고 나서 버리고 있었습니다

먼저 찾아본 것은 "단위가 어디에 있느냐" 입니다. 두 군데에 있었습니다.

| 어디 | 생김새 |
|---|---|
| 머리 행 바로 아래의 단위 줄 | `Time / sec`, `PT01 / bar`, `TT01 / degC` |
| IO 이름 끝의 괄호 | `압력 PT-01 [bar]`, `AI_TEMP(degC)` |

그런데 표를 읽는 쪽(`TableBuilder`)은 단위 줄을 **찾아내서 건너뛰기만** 하고
있었습니다. 값이 아닌 줄이라 표에서 빼는 것까지는 맞는데, 빼고 나서 그냥
버렸습니다. 세로 눈금에 적을 것이 바로 그거였는데도요.

그래서 버리지 않고 들고 옵니다.

```csharp
Cell[] unitRow = null;
if (IsUnitRow(probe, dataStart, c0, timeCol))
{
    unitRow = probe[dataStart];   // 예전에는 dataStart++ 만 했습니다
    dataStart++;
}
...
acc.Unit = UnitFor(unitRow, j, name);   // 단위 줄 → 없으면 이름 끝 괄호
```

이름 끝 괄호를 읽는 쪽(`ValueParse.ExtractUnit`)에는 조건을 두 개 뒀습니다.

- 괄호 안이 **숫자면 단위가 아닙니다.** `밸브(2)` 의 `2` 는 번호입니다.
- 괄호 안이 **16 글자를 넘으면 단위가 아닙니다.** `압력(고온부 2단 출구)`
  같은 설명을 단위라고 눈금에 적으면 더 헷갈립니다.

그리고 **이름 자체는 건드리지 않습니다.** "엑셀에 적힌 IO 이름을 그대로
쓴다" 는 약속이 있어서, 단위를 떼어내 이름을 `압력 PT-01` 로 줄이는 짓은
하지 않습니다. 목록에 나오는 이름은 여전히 `압력 PT-01 [bar]` 입니다.

### 눈금 자체도 손봤습니다

단위만 적으면 "세로축이 이상하다" 는 말의 절반밖에 안 풀립니다. 나머지 절반은
**숫자가 뜻이 없는 채널** 이었습니다.

| 채널 종류 | 예전 눈금 | 지금 눈금 |
|---|---|---|
| 상태 (문자열) | `0`, `0.5`, `1`, `1.5`, `2` | `IDLE`, `RUN`, `STOP` |
| 디지털 (0/1) | `0`, `0.25`, `0.5`, `0.75`, `1` | `0`, `1` |
| 아날로그 | 숫자 | 숫자 + 왼쪽 위에 단위 |

상태 채널의 값은 상태 이름표의 **번호**입니다. 거기에 `0.5` 라고 적어 봐야
있을 수 없는 값이고, `2` 라고 적어도 그게 `STOP` 인지 알 길이 없습니다.
그래서 눈금 글자를 상태 이름으로 바꿨습니다. 디지털도 마찬가지로 `0.5` 는
존재할 수 없으니 `0` 과 `1` 에만 눈금을 답니다.

레인 왼쪽 위에는 그 눈금이 무엇인지 한 마디로 적습니다.

| 눈금 모드 | 적히는 글 |
|---|---|
| 원래값, 단위 있음 | `bar` |
| 원래값, 상태 채널 | `상태` |
| 0–1 정규화 | `0–1 정규화` |
| 변화만 | `Δ bar` |
| 겹쳐보기인데 단위가 서로 다름 | (아무것도 안 적음) |

마지막 줄이 중요합니다. 겹쳐보기에서 `bar` 채널과 `degC` 채널이 한 눈금을
같이 쓸 때 둘 중 하나를 적으면 **거짓말**이 됩니다. 그럴 때는 비웁니다.

눈금 글자 자리는 66 → 80 픽셀로 넓혔습니다. `IDLE` 같은 상태 이름이 들어가야
해서입니다. 자리를 넘는 글자는 `…` 로 줄입니다.

## 2. 히트맵 — 값이냐 퍼센트냐

칸에 적히는 숫자는 그 구간의 **절대 차이 평균**입니다(왜 평균인지는
[04-heatmap.md](04-heatmap.md)). 문제는 이 숫자 하나만 보면 **IO 끼리 견줄
수가 없다**는 것입니다.

| IO | 값 범위 | 평균 차이 | 실제로는 |
|---|---|---|---|
| 유량 FT-01 | 0 ~ 5 | 3 | 60% 틀어짐. 큰일입니다 |
| 압력 PT-09 | 0 ~ 4000 | 3 | 0.075%. 잡음입니다 |

칸에는 둘 다 `3` 이라고 적힙니다. 그래서 도구 줄에 고르는 단추를 뒀습니다.

```
칸에 적을 값   [ 값 그대로 ] [ % (값 범위 대비) ]
```

퍼센트로 나눌 밑값은 **허용 오차와 똑같은 값 범위**(`ToleranceRule.BaseRange`)
입니다. 이게 어긋나면 "허용 오차 0.1%" 와 칸에 적힌 "0.1%" 가 서로 다른 뜻이
되어 버립니다. 같은 밑값을 쓰니까 **칸에 `0.09%` 라고 적혀 있으면 그건 기본
기준 아래**라고 그대로 읽으면 됩니다.

상태 이름으로 견주는 줄은 차이가 0 아니면 1 이라서 밑값을 1 로 둡니다.
그러면 평균 `0.25` 가 곧 **"표본의 25% 가 달랐다"** 가 되어 퍼센트가 그대로
뜻이 통합니다.

값 범위가 0 인 채널(로그 내내 한 자리에 머물렀고 값도 0)은 나눌 수가 없어서
퍼센트를 못 적습니다. 그럴 때 `0%` 라고 적으면 "차이 없음" 으로 잘못 읽히므로
값 그대로 적습니다.

### 마우스를 올리면 둘 다 보입니다

칸은 좁아서 한쪽만 적을 수 있지만, 아래 띠에는 자리가 넉넉합니다.

```
압력 PT-01   09:12:00 ~ 09:13:00   차이 발생 (표본 41 / 60)
평균 차이 3 bar (0.075%)   최대 7 bar   RMS 3.9 bar   기준 4 bar
```

고른 쪽이 앞, 나머지가 괄호 안입니다. 단위도 여기에 같이 적습니다
(1 번에서 읽어 온 그 단위입니다). 칸 안에는 단위를 넣지 않았습니다 —
글자가 칸을 넘으면 숫자까지 통째로 사라지기 때문입니다.

고른 값은 설정에 남아서 다음에 켜도 그대로입니다.

## 3. 새로 넣은 자체 테스트

| 테스트 | 확인하는 것 |
|---|---|
| `UnitsFromUnitRowAndName` | 단위 줄에서, 그리고 이름 끝 괄호에서 단위가 들어오는지. 이름은 그대로인지. `밸브(2)` 의 `2` 를 단위로 읽지 않는지 |
| `HeatmapRangeForPercent` | 퍼센트의 밑값이 허용 오차와 같은 값 범위인지 |
