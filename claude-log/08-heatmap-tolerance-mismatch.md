# 08 — 히트맵의 허용 오차와 칸의 퍼센트가 안 맞던 것

> 요청: "이거 히트맵에서 위에 설정하는 허용오차하고 아래 뜨는 오차 퍼센티지가
> 일치하지 않는 것 같은데?"

맞습니다. 어긋난 곳이 **세 군데**였고, 그중 둘은 07 에서 제가 만든 것입니다.

---

## 1. (가장 큰 것) 색을 정한 숫자와 칸에 적은 숫자가 달랐습니다

칸 하나를 만드는 코드는 이랬습니다.

```csharp
if (diff > row.Threshold) cell.OverSamples++;   // 판정 — 표본 하나하나
...
cell.Mean = sum[k] / cell.Samples;              // 표시 — 구간 전체 평균
```

- **빨갛게 칠할지**는 그 구간에서 **표본 하나라도** 기준을 넘었는지로 봤고,
- **칸에 적는 숫자**는 그 구간 **전체의 평균**이었습니다.

이 둘은 같은 숫자가 아닙니다. 60 표본짜리 1 분 칸에서 **한 표본만** 5% 벌어지고
나머지 59 개가 0 이면

```
판정 :  5% > 0.1%   →  차이 발생 (빨강)
표시 :  5% / 60     =  0.083%   →  칸에 "0.08%" 라고 적힘
```

위에는 **허용 오차 0.1%**, 아래 빨간 칸에는 **0.08%**. 안 맞는 게 당연했습니다.

### 고친 방법 — 판정에 쓴 표본으로만 평균을 냅니다

칸에 적는 값을 **"기준을 넘은 표본만의 평균"** 으로 바꿨습니다.

```csharp
if (diff > row.Threshold) { cell.OverSamples++; overSum[k] += diff; }
...
cell.OverMean = overSum[k] / cell.OverSamples;
```

뜻은 **"벌어졌을 때 이만큼 벌어졌다"** 입니다. 이러면

- 빨간 칸의 숫자는 **언제나 기준보다 큽니다.** 정의상 그렇습니다.
- 정상 칸은 넘은 표본이 아예 없으므로 0 입니다.
- 즉 **"칸이 빨갛다" 와 "이 숫자가 허용 오차보다 크다" 가 같은 말**이 됩니다.

처음에 평균을 고른 이유(합계는 구간이 길수록 커지고, 부호 있는 합계는
진동하면 0)는 그대로 지켜집니다. 여전히 합계가 아니라 평균이고, 절대값입니다.

구간 전체의 평균도 버리지 않고 `Mean` 에 그대로 두어, 마우스를 올리면
아래 띠에 같이 보여 줍니다.

칸을 칠하는 진하기도 같은 값으로 바꿨습니다. 예전에는 색은 전체 평균으로,
숫자는 전체 평균으로 — 우연히 같았지만 이제는 한 곳(`HeatRow.ValueOf`)에서만
정해서 앞으로도 갈라지지 않게 했습니다.

## 2. 기준값을 값으로만 적어서 견줄 수가 없었습니다

아래 띠에 이렇게 나왔습니다.

```
평균 차이 3 bar (0.075%)   최대 7 bar   RMS 3.9 bar   기준 4 bar
```

허용 오차는 위에 **`0.1`(%)** 라고 적혀 있는데 아래는 **`4 bar`** 입니다.
같은 값인데(값 범위 4000 x 0.1% = 4) 글자만 봐서는 알 수가 없습니다.

이제 **양쪽 다** 적습니다. 고른 쪽이 앞, 나머지가 괄호 안입니다.

```
압력 PT-01   09:12 ~ 09:13   차이 발생
차이 난 구간의 평균 6 bar (0.15%)   (기준을 넘은 표본 3 / 60)
기준 4 bar (0.1%)   최대 7 bar (0.175%)   구간 전체 평균 0.3 bar (0.0075%)
```

`0.15% > 0.1%` 가 눈으로 바로 보입니다. 정상 칸에도 "표본 60개 모두 기준 안"
이라고 적어서 왜 초록인지 알 수 있게 했습니다.

---

## 3. 허용 오차를 바꿔도 히트맵은 예전 기준 그대로였습니다

히트맵 계산은 채널 수 x 표본 수만큼 걸려서 배경 스레드로 돌립니다. 그래서
숫자를 고칠 때마다 다시 돌리지 않고 **[히트맵 다시 계산]** 을 눌러야 합니다.

그런데 그 사실을 아무 데도 안 적어 놨습니다. `0.1` 을 `0.5` 로 고치면 위 칸의
숫자만 바뀌고 아래 히트맵은 **예전 0.1% 기준 그대로** 있었습니다. 이것만으로도
"위아래가 안 맞는다" 가 됩니다.

이제 어긋나 있는 동안 요약 위에 줄이 하나 뜹니다.

```
허용 오차를 바꿨습니다. 아래 히트맵은 아직 예전 기준(0.1%)으로 그려져
있습니다 — [히트맵 다시 계산] 을 눌러 주세요.
```

다시 계산하면 저절로 사라집니다. 자동으로 다시 계산하지 않은 이유는, 로그가
크면 몇 초에서 몇십 초가 걸려서 숫자를 고치다가 오래 멈춰 서면 더 답답하기
때문입니다.

---

## 4. 덤으로 찾은 버그 — 절대 오차를 크게 잡으면 상태 차이를 놓쳤습니다

상태(문자열) 채널은 이름이 같으면 0, 다르면 1 로 봅니다. 그런데 기준값은
다른 채널과 똑같이 계산하고 있었습니다.

```
기준값 = max( 절대 허용 오차 , 값 범위 x 비율 )
```

설정 창에서 **절대 허용 오차를 1 이상**으로 적어 두면 `1.0 > 2.0` 이 거짓이라,
`IDLE` 이 `RUN` 으로 통째로 바뀌어도 **차이로 세지 않았습니다.**

상태 이름에 "0.1% 만큼 다르다" 는 말은 성립하지 않습니다. 그래서 이런 줄은
기준값을 **0** 으로 두고 "이름이 다르면 차이" 로 못박았습니다. 아래 띠에도
`기준 없음 (이름이 다르면 차이)` 이라고 적습니다.

---

## 5. 새로 넣은 자체 테스트

| 테스트 | 확인하는 것 |
|---|---|
| `HeatmapCellNumberMatchesTolerance` | 60 표본 중 하나만 튀는 칸을 만들어, **구간 전체 평균은 기준보다 작지만 칸에 적히는 값은 기준보다 크다**는 것을 값과 %로 모두 |
| `HeatmapStateNamesIgnoreAbsoluteTolerance` | 절대 오차를 2 로 잡아도 `IDLE` → `RUN` 이 잡히는지 |

앞의 테스트가 바로 이번에 지적하신 상황입니다. 다시 어긋나면 빌드가 실패합니다.
