# 165 — 공정 단계 줄 · 조금 어긋난 IO 를 알려 주고 묻기 (1.74)

> 근데 단계 비교하고나면 IO에서 공정 단계라고 나오는건 어캄?
> 그리고 지금 파형 비슷한 로그 넣어도 결과가 너무 다르다고 떠버리네...
> 일정하게 조금씩 높거나 시간축 조금 틀어진건 알려주고 판정 묻고 허용할지 해야겠던데
> 대신 이제 그런것들은 알려주는걸 사용자가 알기쉽고 편하게 해야지

## 메인 분석 1 칸

```
 ┌ 분석 1 ─────────────────────────────── WARNING  차이 발생 5 개 ┐
 │ ▌공정 단계 (IO 아님)                                   보기 ›  │  ← 그룹 줄에서 뺌
 │ ▌ 길이 다름 2 · 차례 바뀜                                       │
 │ ▌파형은 같고 조금 어긋난 IO                    확인하고 허용 ›  │  ← 새로
 │ ▌ IO 3 개 — 시간 밀림 1 · 높이 차이 1 · 둘 다 1                 │
 │ ● 그룹 1        2 / 10 달라짐                                   │
 │ ● 그룹 2        0 / 8 달라짐                                    │
```

알림 줄을 누르면:

```
 ┌ 파형은 같고 조금 어긋난 IO ──────────────────────────────────────┐
 │ IO 3 개 — 시간 밀림 1 · 높이 차이 1 · 둘 다 1                     │
 │ 시간만 조금 밀리거나 높이만 조금 다른 IO 입니다. 판정은 오차로 … │
 │ ☑ LATE   이후가 7.81초 늦음                             [그래프] │
 │          오차 구간 11 개                                          │
 │ ☑ HIGH   이후 값이 10 높음                              [그래프] │
 │ ☑ BOTH   이후가 15초 늦음 · 이후 값이 10 높음           [그래프] │
 │ [모두 고르기] [모두 풀기]   [고른 것 이번만 허용] [고른 것 앞으로도 허용] [닫기] │
```

- 판정은 그대로 (오차로 셈) — 사용자가 보고 허용하면 그때 빠짐
- 허용하는 것은 **그 제안이 붙은 오차 구간만** — 같은 IO 의 튐 같은 다른 오차는 그대로 (줄 아래에 "그 밖의 오차 N 개는 그대로")

## 찾는 셈 고침

| | 1.73 | 1.74 |
|---|---|---|
| 고르는 법 | 시간 먼저, 되면 끝 | 시간 · 높이 · 둘 다 모두 보고 남는 오차가 가장 적은 것 (같으면 높이 → 시간 → 둘 다) |
| 높이만 다른 사인파 | "시간 밀림" 으로 잘못 (가파른 곳이 시간 여유 띠에 들어감) | "높이 차이" |
| 시간도 높이도 다름 | 못 찾음 (시간만 밀어서는 안 줄어서) | 높이를 뺀 채 시간을 찾아 "둘 다" |
| 잔떨림만한 제안 | "0.003 높음" 같은 것 | 안 함 (잔떨림 2 배 · 시간 여유 절반보다 작으면) |
| 훑는 횟수 | 시간 후보 33 번 | 성기게 → 둘레 촘촘히 약 16 번, 한도 150 → 1000 IO · 단계 |

## 같이 고친 것
- 머리 글이 "HIGH" · "ON" · "F" · "007" 이면 IO 이름이 "TRUE" · "FALSE" · "7" 로 바뀌던 것 (참거짓 · 숫자로 읽어서) → 적힌 글자 그대로

## 알아 둘 점 — 비슷한 로그가 많이 다르다고 나오는 다른 까닭
기본 허용 오차가 **0.1 %** (이전 값 대비) 로 아주 좁습니다. 잔떨림이 있는 아날로그 IO 는 그것만으로 오차가 될 수 있습니다.
설정 창 [비교] 의 허용 오차 · IO 별 허용 오차로 넓힐 수 있습니다 (판정 규칙이라 제가 바꾸지 않았습니다).
