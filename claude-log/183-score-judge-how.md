# 183 — (질문) 분석 1 점수 · 판정을 내는 방법

## 요청 (요청 210)

> 점수 내는 거 지금 판정 방법 좀 알려 주셈

## 답 (코드 변경 없음 — 버전 그대로)

### 1) 오차 찾기 — `Analysis1/Judge/JudgeEngine.cs`

IO 마다 **모든 표본**으로 (대시보드처럼 2 만 점으로 줄이지 않음):

1. **시간 맞추기**: 이후 시각 + 밀기 값 = 이전 시각. 단계가 있으면 단계마다 시작을 맞춘 밀기 값 (단계 안은 늘이거나 줄이지 않음).
2. **시간 여유 (slack)** `Slack()` `:574` = 단계 (없으면 전체) 길이 × **2 %**, 시각 로그면 최대 **5 초**, 최소 **표본 간격 × 2**.
3. **띠 검사** `Scan()` `:921`: 이후 값 x 가 이전 로그의 **[t − 여유, t + 여유] 동안 나온 값의 최소 ~ 최대** (+ 그 시각 값) 안이면 같음.
   띠 밖이어도 **최소나 최대와의 차이가 허용 오차 이내**면 같음 (IO 별 허용 오차 → 없으면 기본 % · 절대값, `ToleranceRule.IsOver`).
   상태 값 (글자) 은 그 동안 나온 상태 중에 있으면 같음.
4. **양쪽에서** 봄: 이후 → 이전, 이전 → 이후 (이전에만 있던 짧은 펄스도 잡게). 벗어난 표본이 이어지면 오차 구간 하나, 여유만큼 떨어진 구간은 합침 `Merge()`.
5. **단계 맞춤과 전체 맞춤 둘 다에서** 벗어난 곳만 남김 (`Intersect` — 단계를 켜서 오차가 늘지 않게, 1.79). 그래프에서 고른 단계 맞춤도 같이 (`ViewShift`).
6. **빼는 것**: 단계 IO, 허용한 오차 ("이번만" · "앞으로도"), 짧은 튐도 지우지 않음 — **0.1 초 한 점도 범위 밖이면 오차**.
7. 그 밖: IO 가 한쪽에만 있음 (IoMissing / IoExtra), 단계가 없어짐 · 생김 · 차례 바뀜, 단계 길이가 여유보다 많이 다름.

오차 한 줄의 낱말 — 한 단계 안에서 오차 시간이 **20 % 이상이면 CRITICAL**, 아니면 WARNING (심한 정도 표시용).

### 2) 점수 — `JudgeScore.Of` `:134` (1.81, 사용자가 정한 셈)

```
이전 로그 전체 시간
|----|----|----|----| … |----|   100 칸
  ■■   ■              ■        ← 허용 안 된 오차가 걸친 칸

IO 오차율   = 걸친 칸 수 (%)          한쪽에만 있는 IO = 100 %, 차이 난 IO 는 적어도 1 % (1.88)
평균 오차율 = 차이 난 IO 들의 오차율 평균  (차이 없는 IO 는 안 넣음)
점수        = 100 − 평균 오차율          (차이 난 IO 가 없으면 100)
차이 a / b  = 차이 난 IO 수 / 두 로그 IO 수 (합집합, 단계 IO 뺌)
```

예: IO 120 개 중 5 개가 차이 — 오차율 3 · 8 · 1 · 100 · 6.5 % → 평균 23.7 % → **점수 76.3**, 옆에 **차이 5 / 120**.

### 3) PASS / WARNING / CRITICAL (등급) — `:1297`

허용 안 된 오차가 있는 IO 수: **0 → PASS, 10 이하 → WARNING, 넘으면 CRITICAL**. 단계가 없어짐 · 생김 · 차례 바뀜이면 IO 수와
상관없이 CRITICAL. 메인 칸에는 1.81 부터 등급 대신 점수가 나오고, 등급은 LLM 글 · 오차 목록에 쓰입니다.

### 기억할 점

- 점수는 **얼마나 오래 (몇 칸) 다른가** 의 평균이고, **몇 개가 다른가** 는 옆의 a / b 가 맡습니다.
- 오차 크기 (몇 % 벗어났나) 는 점수에 안 들어갑니다 — 한 칸 안에서 조금 벗어나도, 많이 벗어나도 그 칸은 1 칸.
- 바꿀 수 있는 숫자: 여유 2 % · 최대 5 초 · 최소 2 표본 · 20 % · 10 개 (`JudgeOptions` `:62`), 허용 오차 (설정 · tolerances.txt).
