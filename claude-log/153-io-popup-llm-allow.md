# 153 — IO 를 누르면 오차 창 · 그룹 아래 글 빼기 · IO 줄 크게 · 허용을 LLM 에 (1.62)

> 아니 일단 그룹에서 가장 긴오차 이런거 빼셈
> 그리고 그룹눌렀을때 IO나오는거 그룹보단 작게하대 지금보단 조금 더 io칸 하나 크기가 커야지
>
> 그리고 IO눌러서 허용오차 선택하는 거는
> 팝업 새로 띄워서 거기서 선택하는걸로 하셈
>
> 그리고 허용한거 LLM분석에도 반영되게끔 해야된다

## 바뀐 것
| 무엇 | 1.61 | 1.62 |
|---|---|---|
| 그룹 줄 아래 글 | "가장 긴 오차: …" | **뺌** (그룹 이름 13 굵게 · 개수만) |
| IO 줄 | 글 11 · 요약 "오차 1 · 가장 긴 8분 3초 · 2" | 글 **12** · 요약 **"오차 1 · 허용됨 1"** · 여백 4,3 (그룹 13 · 4,4 보다 작게) |
| IO 누르기 | 아래에 구간별 오차 펼침 | **작은 창 (IoErrorsWindow)** — 구간별 오차 + [그래프] [이번만 허용] [앞으로도 허용] [허용 풀기] [닫기] |
| 공정 단계 · 한쪽에만 있는 IO 줄 | 펼침 | 누르면 같은 창 |
| LLM | 판정 정보 없음 | `LlmRequest.Analysis1Judgement` — 판정 · 허용 안 된 오차 · **사용자가 허용한 오차** (Markdown 표, "정상 변동으로 판단됨 — 이상의 근거로 쓰지 말 것"), `LlmRequest.Judgement` 원본 |

창에서 허용하면 메인 칸 판정 · 개수 · 그룹 색이 그 자리에서 바뀜. 창의 [그래프] 는 창을 닫고 그 구간을 그래프로.

## 사용자 코드(LlmExport)에서 할 일
`OverallLlmAnalyzer` 가 서버에 보내는 글에 **`request.Analysis1Judgement` 를 넣어야** 허용이 LLM 에 반영됨.
(1.43 의 Analysis1Digest 는 예전 비교(Comparison)만 봐서 허용을 모름 — 그 부분 대신 또는 함께)

```csharp
if (request.Use1) text += "\n\n" + request.Analysis1Judgement;
```
