# 195 — 1.99 히트맵 칸 폭 (숫자 시간 열) · 초기 오차 무시

## 요청 (요청 222)

> 왜 히트맵에 시간 고정되어 있움?
> 이거 설마 히트맵 100칸 맞춘거임? 히트맵은 맞추지 말라니까 그리고
> 설정에 초기 오차 무시 설정 넣어서
> 체크하고 시간 넣으면 몇초동안 오차는 무시하는거 넣어주셈

## 까닭 (히트맵 시간 고정)

- 히트맵은 점수 · 대시보드의 **100 칸과 묶이지 않았습니다** (HeatmapBuilder 는 그대로, 100 칸은 JudgeScore 에만).
- 고정된 까닭은 **1.89** 의 규칙: 시간 열이 시각 (hh:mm:ss) 이 아니고 **숫자** 면 "초 · 분이 뜻이 없다" 고 보고
  전체를 **60 칸**으로 나누고 칸 폭 고르기를 꺼 버렸습니다. 숫자 시간 열 (0, 0.1, … 초) 로그는 늘 60 칸 고정이었습니다.

## 한 것

| 무엇 | 바꾼 것 | 파일 |
|---|---|---|
| 숫자 시간 열 칸 폭 | 숫자를 **초**로 보고 1초 ~ 1시간 고르기 켬. 머리 단위 `ms` · `min` · `h` 는 바꿔 셈 (`LogDataset.AxisPerSecond`). 칸 폭 글도 "1초" 처럼 | `HeatmapVm.cs`, `HeatmapBuilder.cs`, `LogDataset.cs` |
| 초기 오차 무시 | 설정 → 비교: `[v] 처음 [10] 초 동안 오차 무시` (저장됨) | `AppSettings.cs`, `SettingsVm.cs`, `SettingsWindow.xaml`, `SettingsTexts.cs` |
| 적용 자리 | 이전 로그 시작 + N 초 전의 값 오차는 안 셈 — 판정 (Scan 두 방향), 비교 (IO 목록 차이 IO), 히트맵 (넘음 안 셈, 값은 보임), 그래프 차이 영역 칠하기. 점수 · 대시보드 · 최종 판정은 판정을 따라감 | `JudgeEngine.cs`, `DiffEngine.cs`, `HeatmapBuilder.cs`, `GraphCanvas.cs`, `AppState.cs` |
| 다시 견주기 | 비교 · 판정 서명에 넣어 설정을 바꾸면 다시 셈 | `AppState.cs` |

```
설정 › 비교
  초기 오차 무시   [v] 처음 [ 10 ] 초 동안 오차 무시
```

- 단계 없어짐 · 차례 · 공정 시간 (로그 길이) 판정은 무시 대상이 아닙니다 (값 오차만).
- 표본 번호 축 (시간 열 없음) 은 초가 뜻이 없어 무시 설정 · 칸 폭 둘 다 안 먹습니다.

## 확인

- 시험 1130 통과 (새 시험 7 개: 히트맵 · 판정 · 비교에서 처음 N 초 무시, 서명, 초 환산, 설정 저장), check 스크립트 · XAML 형식 통과.
- **Windows 에서 못 본 것**: 설정 창 새 줄 모양, 숫자 시간 열 로그의 칸 폭 고르기, 그래프에서 처음 N 초가 안 칠해지는 모양
  (단계별 나눠 보기에서는 왼쪽부터 N 초까지만 건너뜀).
