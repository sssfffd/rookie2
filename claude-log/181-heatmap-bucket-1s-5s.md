# 181 — 1.89 히트맵 칸이 고른 폭과 맞게 · 1 초 · 5 초

## 요청 (요청 208)

> 히트맵 뜨는 칸이 위에 설정한 거랑 안 맞는 것 같은데 맞춰 주고 1 초랑 5 초 설정도 추가해 줘

## 원인 (셋)

| # | 무엇 | 그 결과 |
|---|---|---|
| 1 | 칸 폭 콤보를 바꿔도 **다시 세지 않음** (단계 단추 · 차이 없는 IO 단추만 다시 셈) | 위에는 "10초" 인데 칸은 옛 "1분" 그대로 |
| 2 | 칸이 4000 개를 넘으면 폭을 **두 배씩 넓힘** | 긴 로그에서 "10초" 를 골라도 20 초 · 40 초 칸 (아래 글에만 적힘) |
| 3 | 칸 경계가 **겹치는 구간 시작 시각부터** (예: 10:03:27.4) | "1분" 칸이 10:03:27 ~ 10:04:27 — 시계의 분과 어긋남 |
| (+) | 시간축이 시각이 아니면 고른 폭을 버리고 60 칸 — 그런데 콤보는 켜져 있음 | 골라도 안 먹음 |

## 한 것

| 무엇 | 어떻게 | 파일 |
|---|---|---|
| 1 초 · 5 초 | 칸 폭 목록에 더함 (자동 · 1초 · 5초 · 10초 · 1분 · 5분 · 10분 · 30분 · 1시간) | `HeatmapVm.cs` |
| 바로 다시 셈 | 칸 폭이 바뀌면 `Recalculate` | `HeatmapView.xaml.cs` |
| 정각 경계 | 시각 로그면 경계를 폭의 배수 (00 초 · 00 분) 에 — 첫 · 끝 칸은 겹치는 구간에서 잘림 (그 밖은 한쪽 로그만 있어 가짜 차이). 경계는 k × 폭 으로 셈 (더해 가며 쌓이는 오차 없음) | `HeatmapBuilder.cs` (`HeatBuckets.Aligned`) |
| 칸 수 상한 | 4000 고정 → IO 수 × 칸 수 ≤ 300 만 (≈ 84 MB, 칸 하나 28 바이트), 4000 ~ 20000 칸. 판은 보이는 칸만 그림 | `HeatmapBuilder.cs` (`AutoMaxBuckets`) |
| 고를 수 없을 때 끔 | 시간축이 시각이 아니거나 가로가 단계면 콤보 꺼짐, 마우스를 올리면 까닭 (`BucketHint`, 꺼져 있어도 보임) | `HeatmapVm.cs`, `HeatmapView.xaml` |

```
1 분:  |27.4초~04:00| 04:00~05:00 | 05:00~06:00 |06:00~10초|
```

## 확인

- 시험 1162 통과 (새 5: 1 분 칸 정각 경계 · 빈틈 없이 덮음 · 1 초 칸 11 개 · 시각 아니면 예전 · 상한 60 / 200 / 2000 IO). 기존 히트맵 시험 그대로 통과.
- check 스크립트 · 실제 csc 빌드 · XAML 형식 통과.
- **Windows 에서 못 본 것**: 콤보를 바꿀 때 다시 세는 동안의 창 (BackgroundJob), 1 초 칸으로 긴 로그일 때 걸리는 시간 · 메모리, 가로축 글자.
