# 73 — 가로축 바꾸기 걷어냄 · 그룹은 그래프로 · DB 요약 글귀

> 가로축 맞추기 기능은 빼면 될꺼같고
> 단계끼리 묶는거 기능이 ui에 없는 거 같은데?
> 그리고 메인화면에서 파일들 넣으면 바로 비교되게 바꿔주고 메인화면에서
> 그룹눌렀을때 히트맵이 아니라 그래프로 이동하고
>
> 그리고 db분석 요약에는 fail이면 차이가 너무 많습니다 파일을 다시
> 확인해주세요 / warning이면 어떤 항목들이 차이가 나는지 / 성공이면
> 차이 없다고 알려주셈

## 먼저 물어본 것

"가로축 맞추기" 가 둘 중 어느 것인지 물었습니다 — 도구 줄의
**[가로축 · 시간 맞추기]** 단추 안에 **가로축 바꿔 끼우기**(로그의 시간 열
대신 다른 IO 를 가로축으로)와 **시간 맞추기**(특정 IO 가 어떤 값이 되는
순간으로 두 로그를 맞추기)가 같이 들어 있었습니다.

→ **가로축 바꿔 끼우기만** 빼기로 하셨습니다.

## 1. 가로축 바꿔 끼우기 걷어냄

| 어디 | 무엇 |
|---|---|
| `LogDataset` | `SetAxisChannel` · `ClearAxisChannel` · `CanBeAxis` · `AxisChannel` · `AxisNote` · 원래 시간축 보관 — **194 줄** |
| `AppSettings` | `AxisIo` + 저장/읽기 |
| `AppState` | `ApplyAxisChannel` · `ResetAxis` · `AxisCandidates` · `AxisNote` — 77 줄 |
| `AlignVm` | 가로축 목록·고르기·갈무리 |
| `AlignPanel.xaml` | 맨 위 "가로축" 칸 |
| `AnalysisRecord` | `AxisIo` (저장된 분석의 기준 한 줄) |
| 시험 | 시험 묶음 셋 (100 줄) |

되넣을 자리는 `LogDataset` 의 "가로축" 주석 한 곳입니다. **그리는 쪽도
견주는 쪽도 눈금 글자도 전부 `Times` 만 봅니다** — 그래서 그때도 그 밖에는
손댈 곳이 없었고, 지금 되넣어도 마찬가지입니다. 조건은 "값이 뒤로 가면
안 된다" 하나였습니다 (이진 탐색과 픽셀 열 접기가 오름차순을 전제합니다).
코드는 git 기록의 0.91 에 있습니다.

**저장된 분석 기록**에서도 그 줄이 빠집니다. 옛 파일은 그대로 읽히지만
(없는 칸은 빈 값), 기준 줄에 "가로축 …" 이 더 안 적힙니다.

단계를 **표본 번호**로 적어 둔 덕을 여기서 봤습니다. 시각으로 적어 두었다면
축 기능을 걷어내는 것만으로도 단계가 흔들렸을 텐데, 손댈 것이 없었습니다.

## 2. 그룹을 누르면 그래프로

메인 화면의 요약에서 그룹 줄을 누르면 히트맵으로 갔습니다. **그래프로
바꿨습니다.**

그룹을 누르는 뜻은 "이 IO 들이 어떻게 달라졌나" 인데, 히트맵은 *어느
시간대가 심한가* 를 보는 화면입니다. 값이 어떻게 달라졌는지는 그래프에서
봐야 합니다.

넘어가면 그 그룹의 IO 만 골라 둡니다. 두 가지를 챙겼습니다.

- **검색 글자를 비웁니다.** 검색이 걸려 있으면 고른 IO 가 왼쪽 목록에 안
  보여서, 골라 놓고도 "아무 일도 안 일어났다" 로 보입니다.
- **못 찾은 이름을 셉니다.** 그룹은 사람이 손으로 담는 것이라 지금 열어 둔
  로그에 없는 이름이 있을 수 있습니다. 아래 줄에 적습니다 —
  `"압력" 그룹의 IO 3 개를 골라 두었습니다.  담아 둔 5 개 중 2 개는 지금
  열어 둔 로그에 없습니다.` 조용히 세 개만 그리면 그룹이 세 개인 줄 압니다.

손으로 다시 고르면 그 글은 사라집니다 (이제 그 그룹이 아니니까요).

## 3. 메인 화면에서 파일을 놓으면

**이미 바로 비교됩니다** — 놓으면 읽고(진행 창), 둘 다 차 있으면 견주고
(진행 창), 메인 화면을 다시 그립니다. `TakeFiles → LoadInto → AfterLoad →
Recompare` 입니다. 코드를 짚어 보고 그대로 두었습니다.

그런데 **메인 화면만 보면 그게 안 보였습니다.** 분석 1 칸에 적히는 것이
`100 / 100`(자리만 잡아 둔 점수)과 그룹 요약뿐이라, 놓기 전과 거의 같아
보입니다. 그래서 칸에 **견준 수**를 되넣었습니다.

```
차이 난 IO        한쪽에만 있는 IO
12 / 180          3개
```

0.85 에 뺐던 것입니다 (같은 수가 칸·종합·대시보드 세 군데에 있었습니다).
끌어다 놓자마자 견주는 흐름에서는 칸이 그대로면 "넣었는데 아무 일도 안
했다" 로 보여서 되넣었습니다. 종합 칸과 **같은 값**을 씁니다 (둘 다
`CompareResult` 를 그대로 읽습니다) — 따로 셈하면 두 수가 어긋납니다.

## 4. DB 요약 — 판정마다 다른 말

```
PASS      차이 없습니다.
WARNING   차이 발생 3개 — TEMP_MAX, PRES_SET, VALVE_1
FAIL      차이가 너무 많습니다 (1,200개). 파일을 다시 확인해 주세요.
```

- **WARNING 은 이름을 적습니다.** 개수만 보면 결국 분석 2 를 열어 목록을
  뒤져야 합니다. 여덟 개까지 적고, 넘으면 `외 N개` 를 붙입니다 — **몇 개를
  안 적었는지는 말해 줍니다.**
- **FAIL 은 이름을 안 적습니다.** 1200 개 중 여덟 개만 적으면 "이 여덟 개가
  문제" 로 읽히는데, 그 수가 되면 파일이 잘못 걸렸을 가능성이 먼저입니다.
  그래서 "파일을 다시 확인" 이 그 자리에 들어갑니다.
- **판정에 안 들어간 수는 어느 경우든 덧붙습니다** —
  `(판정에 안 넣음: 없어진 IO 20개 · 새로 생긴 IO 0개)`. 없어진 IO 가 스무
  개인데 "차이 없습니다" 만 보이면 거짓말입니다.

글귀는 `DbVerdict` 한 곳에 있고, **분석 2 화면의 요약 줄도 같은 글을
씁니다.** 두 화면이 다른 말을 하면 어느 쪽이 참인지 알 수가 없습니다.

덤으로 `DbVm.Take` 가 같은 목록을 **세 번** 짓고 있었습니다 (요약 · 개수 ·
이름). 한 번만 짓게 고쳤습니다 — 10M 칸짜리 표에서는 그 자체가 세 배 일입니다.

## 5. 단계끼리 묶기 — 아직 안 만들었습니다

여쭤 본 뒤에 만들겠습니다. "묶는다" 가 셋으로 읽혀서입니다.

1. **여러 단계를 포개 보기** — 가열 1 회와 2 회를 같은 0 자리에 겹쳐 그리기
2. **같은 이름끼리 묶기** — 가열이 세 번 나오면 히트맵 칸 하나로 합치기
3. **이어진 단계를 한 덩이로** — 가열~유지를 한 구간으로 묶어 보기

셋 다 쓸모가 있지만 만드는 것이 다릅니다 (1 은 그리는 쪽을 손대야 하고,
2 는 칸 자르기, 3 은 구간 잡기). 잘못 짚으면 만든 것을 버리게 됩니다.
