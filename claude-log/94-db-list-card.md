# 94 — 분석 2 목록: 카드로 띄우기 + 칸 폭을 창에 맞추기 (A + C)

> 아 근데 분석 2번에서 list창이 왼쪽 오른쪽 꽉차니까 안예쁜데 어떻게 바꾸지?

→ 세 가지(A 카드 · B 가운데 고정 폭 · C 칸 폭 맞추기)를 보여 드리고 A + C 를 추천

> a+c로 ㄱㄱ

## 바뀐 것

```
전 (1.13)
│IO명            │이전 value │이후 value        │                 (빈 칸)│
│TEMP_MAX        │1          │4  (+3)           │                        │

후 (1.14)
  [데이터 읽기] [SQL 문 출력]
  ┌ ● 이전 … ─────────┐ ┌ ● 이후 … ─────────┐
  ╭─ 차이 목록 ⚠ 보기 [차이 발생][전체] … [.CSV로 저장] ─────────╮
  │ IO명 (40%)              │ 이전 value (30%) │ 이후 value (30%) │
  │ TEMP_MAX                │ 1                │ 4  (+3)          │
  ╰──────────────────────────────────────────────────────────────╯
```

### A. 카드

- 목록을 둥근 모서리(5) · 테두리(1) 카드 안에 넣었습니다 — 메인 화면 카드와 같은 모양.
- 바깥 여백 12 는 위쪽 칸의 안쪽 여백 12 와 같아서, `[데이터 읽기]` 줄 · 이전/이후
  칸 · 목록의 왼쪽 끝이 한 줄로 맞습니다.
- 카드 바깥은 위쪽 칸과 같은 바탕색이라 위·아래가 한 판으로 보이고, 카드만
  흰(어두운 테마에선 어두운) 바탕으로 떠 보입니다.

### C. 칸 폭

- 목록 크기가 바뀔 때마다 `IO명 40% · 이전 30% · 이후 30%` 로 다시 나눕니다
  (`DbView.FitColumns`). 넓은 화면에서 오른쪽 빈 칸이 사라지고, 좁은 화면에서 이후
  칸이 잘리지 않습니다.
- 세로 스크롤 막대 자리는 빼고 나눕니다 (안 빼면 가로 막대가 생깁니다).
- 목록이 420 보다 좁아지면 더 줄이지 않고 가로 스크롤로 봅니다.
- 칸 경계를 손으로 끌어 바꿀 수는 있지만, 창 크기가 바뀌면 이 비율로 돌아갑니다.
  비율을 바꾸려면 `Share = { 0.40, 0.30, 0.30 }` 한 줄입니다.

## Windows 에서 확인 못 한 것

- XAML 과 칸 폭 계산은 여기서 돌려 볼 수 없습니다 (스텁 + 검사기만 통과).
- 카드 아래 둥근 모서리에 목록 줄이 삐져나와 보이지 않는지 (목록 바탕을 투명으로
  했지만 칠한 줄이 맨 아래에 닿으면 모서리가 각져 보일 수 있습니다).
- 마지막 칸 오른쪽에 가로 스크롤 막대가 생기면 `FitColumns` 의 `- 8` 을 조금 키우면
  됩니다.
- 검사: 컴파일 · 테스트 861 통과 · `check_sources` / `check_handlers` /
  `check_shadowing` 지적 없음.
