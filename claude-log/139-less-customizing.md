# 139 — 사용자가 정할 게 너무 많지 않나 → 대부분 저절로, 사람이 정하는 건 둘만

> 근데 지금 우리 말한거 살펴보면 사용자가 커스터마이징 해야되는게 너무 많은거 아니야?

맞습니다. 138 의 표는 IO 마다 7 칸이라 수백 IO 면 아무도 안 채웁니다. 줄이는 안 (제안 — 코드 안 바꿈):

## 사람이 정하는 것: 둘 (둘 다 안 해도 돌아감)

| | 무엇 | 기본 |
|---|---|---|
| 1 | **중요 표시** — 그룹(또는 IO)에 체크 하나. 체크된 것은 짧은 차이도 FAIL | 아무것도 체크 안 함 |
| 2 | **엄격도** — 느슨 · 보통 · 엄격 (프로그램 전체 하나). 아래 자동 값들을 한꺼번에 조이거나 풂 | 보통 |

## 프로그램이 저절로 정하는 것

| 항목 | 어떻게 | 보통일 때 (예) |
|---|---|---|
| 시간 허용 Δt | 단계마다 시작을 맞춘 뒤 남는 어긋남만 보면 되므로 **단계 길이의 일정 비율** (짧은 단계는 작게, 긴 단계는 크게), 아래 · 위 한도 | 단계 길이 2 % · 0.5 ~ 5 s |
| 짧은 튐 무시 | Δt 와 같게 (Δt 안의 튐은 시간차와 구별 안 됨) | Δt |
| 단계 시작 안정화 | 따로 안 둠 — Δt 와 비율 기준이 대신 흡수 | — |
| 경고 / 실패 비율 | 전체 공통 하나 | 5 % / 20 % |
| 중요 IO 의 실패 지속 | 전체 공통 하나 | Δt (= 시간차로 설명 안 되는 차이면 바로 FAIL) |
| 값 허용 오차 | 지금처럼 전체 % · 절대 하나 (IO 별 표는 그대로 두되 안 써도 됨) | 지금 값 |

엄격도는 이 숫자들을 함께 움직임: 느슨 = Δt ×2 · 비율 10 / 40 %, 엄격 = Δt ×0.5 · 비율 2 / 10 %.
숫자를 꼭 바꾸고 싶은 사람만 설정의 "자세히" 에서 (기본은 접혀 있음).

## 나중에 더 줄이는 길
정상 로그를 여러 개 넣으면 Δt · 비율을 **그 로그들의 흔들림에서 배움** → 엄격도조차 안 만져도 됨.

## 결과로 보이는 것은 그대로
IO 마다 PASS / WARNING / FAIL + 정도(차이 시간 · 비율 · 가장 긴 연속 · 단계 · 최대 오차), 분석 1 판정 = 가장 나쁜 것.
