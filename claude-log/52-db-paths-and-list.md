# 52. DB 분석 — 자리 고르기, 이름, 목록 칸 (0.62)

> db 분석쪽에서 이전 이후 파일 내가 넣을 수 있게하고
> 화면에서 db분석이라고 적혀있는거 내가 config.txt에서 변경한 이름으로 바뀌게해주고
> 지금 list뜨는거 항목에 IO명, 이전 value, 이후 value랑 v1, v2 넣어줘
> 왼쪽에 표랑 상태는 빼도 될 것같아
> 그리고 안에 데이터 파싱하는 파일은 위치만 알려줘 내가 직접 코딩할게

## 1. 자리를 화면에서 고르기

이전·이후 줄마다 **`[찾기]`**(폴더) 와 **`[파일]`**(덤프 하나) 를 붙였습니다.
**칸에 폴더나 파일을 끌어다 놓아도** 됩니다.

고른 자리는 `LogScope.settings.json` 의 `dbBefore` / `dbAfter` 에 **그 자리에서**
저장됩니다 (0.61 의 그룹과 같은 방식입니다).

**config.txt 에 되쓰지 않습니다.** 그 파일은 사람만 고치는 파일이고, 프로그램이
거기 쓰면 적어 둔 주석과 줄 차례가 날아갑니다. 그래서 순서가 이렇습니다.

```
화면에서 고른 것  →  있으면 이김
config.txt        →  없을 때의 기본값 (켤 때마다 같은 자리)
```

화면에서 고른 것을 비우면 config.txt 로 돌아갑니다.

**폴더 고르는 창이 없습니다.** .NET Framework 의 WPF 에는 폴더 선택 창이
없고, 바깥 라이브러리를 더하지 않기로 했으니 **저장 창을 폴더 고르기로**
씁니다 — 그 폴더로 들어가서 `[저장]` 을 누르면 그 폴더가 잡힙니다. 파일 이름
칸은 쓰지 않습니다. 보기엔 어색하지만 라이브러리를 하나 더하는 것보다 낫다고
봤습니다.

## 2. 화면 이름

`DB 분석` 이 코드에 박혀 있었습니다. 이제 `config.txt` 의 `analysis2` 이름을
씁니다 — 위 줄의 단추와 메인 화면 칸과 **같은 이름**입니다. 한 군데만 박아
두면, 이름을 바꾼 사람이 이 화면만 안 바뀐 것을 봅니다.

## 3. 목록 칸

```
전 : 표 · 갈래 · 구분 · 행 · 열 · 이전 · 이후 · 설명
지금: 표 · IO명 · 이전 value · 이후 value · v1 · v2 · 열 · 구분 · 설명
```

**왼쪽의 표 목록(표 · 상태)은 없앴습니다.** 목록이 표 이름을 칸으로 들고
있어서 같은 것을 두 군데서 보고 있었고, 목록이 폭을 다 쓰는 쪽이 값을 읽기에
낫습니다. 고를 표가 없어졌으니 `[전체 표] / [고른 표만]` 도 함께 뺐습니다.

**표 칸은 남겼습니다.** 말씀하신 "표랑 상태" 는 왼쪽 목록의 두 칸으로
읽었습니다. 폴더에 DB 가 여럿이면 같은 IO 이름이 표마다 나와서, 이 칸이 없으면
**어느 DB 의 값인지 알 수가 없습니다.** 한 DB 만 보신다면 `DbView.xaml` 의
그 `GridViewColumn` 한 줄만 지우면 됩니다 — 그걸 원하셨다면 말씀해 주세요.

### IO명

"그 줄을 가리키는 가장 좁은 이름" 을 넣습니다.

| 줄 | IO명 |
|---|---|
| 값이 바뀐 행 | 행 열쇠 (`id=7`) |
| 열이 바뀜 | 열 이름 |
| 표가 한쪽에만 | 표 이름 |

DB 에 IO 이름이 담긴 열이 따로 있으면 거기 값을 넣는 쪽이 맞습니다. 고치는
자리는 아래에 적습니다.

### v1 · v2 — 일부러 빈 칸입니다

설비 DB 마다 함께 봐야 하는 열이 다릅니다 (설정값 · 단위 · 판본). 그래서 이름을
박지 않고 **빈 칸 둘**로 뒀습니다.

**아무 값이나 채워 두지 않았습니다.** 채워 두면 그게 DB 에서 읽은 값인 줄 알고
읽게 됩니다. 비어 있으면 "아직 안 채웠다" 가 그대로 보입니다.

채우면 **목록 · CSV · 마우스 설명**에 그대로 나갑니다 (시험으로 지킵니다).

## 4. 파싱하는 파일 — 어디를 고치면 되나

전부 `src/LogScope.Core/Db/` 안이고, **화면이 없어도 돌아갑니다**
(`LogScope.Tests` 에서 바로 시험됩니다).

| 파일 | 하는 일 |
|---|---|
| **`DbDiffList.cs`** | **목록 줄을 만듭니다. `Io` · `V1` · `V2` 를 채우는 자리.** `OneRow` 함수 머리에 어떻게 꺼내는지 적어 뒀습니다 |
| `DbModel.cs` | 자료 모양 — `DbSnapshot` → `DbTable` → `DbColumn` / `DbRow` |
| `DbFolderReader.cs` | 폴더를 훑어 어느 파일을 누가 읽을지 정합니다 (하위 폴더 · 상한 · 표 이름 앞에 붙는 폴더 이름) |
| `SqlDumpReader.cs` | `.sql` 덤프 — `CREATE TABLE` 과 `INSERT` 를 글자로 훑습니다 |
| `CsvTableReader.cs` | `.csv` — 파일 이름이 표 이름, 첫 줄이 열 이름 |
| `FrmReader.cs` | `.frm` — MySQL 5.x 의 표 정의 (바이트 직접 읽기) |
| `DbDiff.cs` | 두 벌을 견주는 세 단계 (표 → 열 → 행) |
| `SqlScript.cs` | 맞추는 SQL 글 만들기 |
| `DbCreateSql.cs` | 읽은 모양을 `CREATE TABLE` 글로 |

**v1 · v2 와 IO명을 채우려면 `DbDiffList.cs` 의 `OneRow` 한 곳**입니다.
값을 꺼내는 방법은 그 바로 위 "달라진 열" 을 꺼내는 코드와 같습니다.

```csharp
int i = td.Before.IndexOf("v1");          // 그 표에서 열 자리 찾기
string v = i < 0 ? null : rd.Before.Get(i);
ln.V1 = DbRow.Show(v);                     // NULL 은 "NULL" 로
```

**새 파일 형식을 더하려면** `DbFolderReader.TakeFile` 에 확장자 한 줄을 더하고
읽는 파일을 하나 만들면 됩니다. 읽은 결과를 `DbTable` 로만 맞춰 주면 그 뒤
(견주기 · 목록 · SQL)는 그대로 돕니다.

## 검사

- 테스트 **599 통과 / 0 실패** (8 개 새로 더함). IO명이 줄 갈래마다 맞게
  채워지는지, v1·v2 가 **비어 있는지**, 채우면 CSV 와 설명 글에 나가는지,
  CSV 머리글이 바뀐 칸과 맞는지.
- 검사 넷 다 통과. 새로 만든 끌어다 놓는 칸도 **되돌릴 배경을 Tag 에** 적어
  0.59 에서 만든 검사를 지납니다.
- WPF 스텁에 `CheckPathExists` 가 없어 더했습니다.

**못 해 본 것**: 폴더 고르기 창이 실제로 쓸 만한지입니다. 저장 창을 빌려 쓰는
것이라 윈도우에서 한 번 해 보셔야 합니다. 어색하면 경로를 직접 타 넣는 칸으로
바꾸겠습니다 (그게 더 편할 수도 있습니다).

## 뒷이야기 — 칸을 더 줄이고, 파일도 받고 (0.64)

> 지금 db분석쪽에 구분이랑 설명 빼주고 표 정의 저장도 빼주셈
> 가리고 폴더말고 파일 넣어도 가능하게 만들어줘

### 칸

```
표 · IO명 · 이전 value · 이후 value · v1 · v2 · 열
```

`구분` 과 `설명` 을 뺐습니다.

**여기서 그냥 지우면 안 되는 것이 하나 있었습니다.** `설명` 칸에만 적히던 글이
있습니다.

```
기본 키가 없어 모든 열이 같은 행끼리만 짝지었습니다. 값이 하나 바뀐 행은
"없어진 행 1 + 생긴 행 1" 로 보입니다.

이 표의 차이가 5,000 줄을 넘어 그 뒤는 적지 않았습니다 (상한).
```

이게 사라지면 **목록이 차이의 전부인 줄 알고 읽게 됩니다.** 상한에 걸린 표는
"차이가 5,000 개" 로, 키가 없는 표는 "행이 다 지워지고 새로 생겼다" 로 보이는데
왜 그런지가 어디에도 없습니다.

그래서 `알림` 줄을 목록에서 빼내 **목록 위 안내로 올렸습니다.** 거기에는 못 읽은
파일 안내가 이미 적히는 자리가 있어서 같이 보입니다. 겹치는 글은 한 번만,
스무 줄까지 적습니다.

**CSV 에는 알림 줄이 그대로 나갑니다.** 내보낸 파일에서 그 글이 빠지면, 그
파일을 나중에 보는 사람은 물어볼 사람도 없습니다.

### 표 정의 저장

단추를 뺐습니다. 만드는 코드(`Core/Db/DbCreateSql.cs`)와 그 시험은 **남겨
뒀습니다** — 지우면 `.frm` 읽기를 `SHOW CREATE TABLE` 과 견주는 길이 없어지고,
다시 필요할 때 처음부터 짜야 합니다. 단추 하나만 붙이면 돌아옵니다.

뷰모델에서 쓰지 않게 된 부분(`_before` · `_after` · `HasSnapshots` ·
`CreateSqlText`)은 지웠습니다.

### 폴더가 아니라 파일

**이미 되고 있었습니다** (0.62 의 `[파일]` 단추와 끌어다 놓기). 다만 쓰기가
불편했습니다 — 폴더 고르는 창이 저장 창을 빌려 쓰는 것이라 어색하고,
`[찾기]` 라는 이름만 봐서는 폴더용인지 파일용인지 알 수 없었습니다.

- `[찾기]` → **`[폴더]`** 로 이름을 바꿨습니다. 옆이 `[파일]` 입니다.
- 경로 칸을 **고칠 수 있게** 했습니다. 탐색기 주소 칸에서 복사해 붙여넣는
  것이 창을 띄워 찾는 것보다 빠를 때가 많습니다. 타 넣어 고친 것도 그 자리에서
  저장됩니다 (단추와 끌어다 놓기만 챙기면, 타 넣은 사람은 저장이 안 되는 것을
  다시 켤 때 압니다).

그리고 **파일 하나를 주는 길에 시험이 없었습니다.** 10 개를 더했습니다 —
`.sql` · `.csv` · `.frm` 하나씩 주면 읽히는지, 파일 하나일 때 표 이름 앞에
폴더 이름을 붙이지 않는지, 없는 파일과 못 읽는 파일이 **이유를 적는지**.

테스트 **609 통과 / 0 실패**, 검사 넷 다 통과.

## 뒷이야기 2 — 맞춤 방향 고르기를 뺐습니다 (0.71)

> db분석쪽에 이전 이후 맞춤 방향들 지워줘

`맞출 방향  [이전 → 이후] [이후 → 이전]` 두 단추를 뺐습니다. 늘
**`이전 → 이후`** 입니다 — 이전 DB 를 이후와 같게 만드는 글입니다.

실제로 쓰는 쪽이 한쪽뿐이면 고르는 칸은 자리만 먹습니다. 그리고 방향을
잘못 고른 채 글을 저장하면 **되돌리는 SQL 을 맞추는 SQL 로 착각할** 수
있는데, 그 위험도 같이 없어집니다.

**만드는 길은 Core 에 그대로 뒀습니다** (`SqlScript.Direction.ToBefore`).
시험도 그대로 돕니다. 지우면 다시 필요할 때 처음부터 짜야 하고, 남겨 두는
값은 `BuildScript` 한 줄과 단추 하나입니다.

만든 글의 머리에는 어느 방향인지 적혀 있습니다 — 저장한 `.sql` 을 나중에
열어 본 사람이 방향을 짐작하게 두면 안 됩니다.

테스트 **630 통과 / 0 실패**, 검사 넷 다 통과.
