# 16 — "jump 문제가 아직도 난다"

> 요청: ".core빌드할 때 jump관련 문제가 아직도 발생함"

먼저 지금 저장소 상태를 확인했습니다. **고쳐져 있고 올라가 있습니다.**

---

## 1. 지금 코드는 어떤가

```
$ grep -rn '\bjump\b' src/ --include=*.cs
src/LogScope.Tests/Program.cs:956:  ChannelDiff jump = r.Items.Find(...)
src/LogScope.Tests/Program.cs:958:  ...
src/LogScope.Tests/Program.cs:959:  ...
src/LogScope.Tests/Program.cs:967:  ...
src/LogScope.Tests/Program.cs:968:  ...
```

다섯 군데 모두 **메서드 바깥 수준**의 같은 변수 하나입니다. 반복문 안쪽은
`vNear` / `vJump` 로 갈라 놨습니다. 겹치는 이름이 없으니 `CS0136` 이 날 수가
없습니다. 이름 겹침 검사(`scripts/check_shadowing.py`)도 0 건입니다.

고친 커밋은 **`d6cb0ce` (2026-09-18)** 이고, 지금 가지 끝에서 세 칸 뒤입니다.

---

## 2. 그런데 "Core 빌드"라면 애초에 날 수 없는 오류입니다

`jump` 가 든 `Program.cs` 는 **LogScope.Tests** 의 파일입니다.

```
LogScope.Tests  ──참조──▶  LogScope.Core
LogScope.Core   ──참조──▶  (없음)
```

- `Core` 는 아무것도 참조하지 않습니다.
- `Core` 의 `.csproj` 에는 `Program.cs` 가 들어 있지 않습니다 (확인했습니다).

그래서 **LogScope.Core 만 빌드하면 그 파일은 컴파일되지도 않습니다.**
Core 빌드에서 그 오류가 나왔다면 컴파일 결과가 아니라 다른 데서 온 글자입니다.

---

## 3. 그럼 왜 보이나 — 두 가지 중 하나입니다

### (가) 받아온 사본이 고친 커밋보다 앞

제일 흔한 경우입니다.

```
git log --oneline -1     ← 지금 내 사본
git pull                 ← 받아오기
```

`d6cb0ce` 보다 앞이면 아직 안 받으신 것입니다.

### (나) Visual Studio 오류 목록에 남은 옛 오류

오류 목록에는 **빌드 결과만** 나오는 게 아닙니다. IntelliSense 가 실시간으로
낸 오류도 섞여 나오고, 그건 **솔루션 전체**(지금 빌드하지 않은 프로젝트까지)를
대상으로 합니다. 그래서

- Core 만 빌드했는데 Tests 의 오류가 보일 수 있고,
- 파일을 고친 뒤에도 옛 오류가 남아 보일 수 있습니다.

**[빌드] → [솔루션 다시 빌드]** 로 확인하시고, 그래도 남으면 VS 를 닫았다
여세요. (`bin` / `obj` 를 지우면 더 확실합니다.)

---

## 4. 다음부터 이걸 바로 가릴 수 있게 했습니다

문제는 "고쳤다"와 "안 고쳐졌다" 를 **화면만 보고는 가릴 수가 없었다**는
점입니다. 어느 판본을 빌드하고 있는지 아무 데도 안 적혀 있었습니다.

`build.bat` 이 시작할 때 찍습니다.

```
  MSBuild : C:\Program Files (x86)\...\MSBuild.exe
  로그     : C:\...\build.log
  커밋     : 66b456a1c2d3
  버전     : 0.16
```

찍힌 커밋이 고친 커밋보다 앞이면 그냥 안 받아오신 것입니다. 고친 내용이
커밋 안 된 채로 섞여 있으면 그 줄도 한 줄 덧붙습니다. git 이 PATH 에 없으면
이 줄들은 조용히 빠집니다 — 빌드는 그대로 됩니다.

설정 창 → [정보] 에도 버전과 커밋 해시가 원래 나옵니다. 그건 **실행 중인
exe** 가 어느 판본인지이고, 이번에 넣은 것은 **지금 빌드하려는 소스**가 어느
판본인지입니다. 둘이 다를 수도 있어서 양쪽 다 필요합니다.

---

## 5. 그래도 나면

오류 **전문**을 그대로 붙여 주세요. 특히

- 오류 번호 (`CS0136` 인지 `CS0103` 인지 다른 것인지)
- 파일 경로와 줄 번호
- "출력" 창의 내용인지 "오류 목록" 탭인지

이 셋이면 어느 쪽인지 바로 가려집니다. `build.bat` 을 돌리셨다면
`build.log` 를 통째로 주셔도 됩니다.
