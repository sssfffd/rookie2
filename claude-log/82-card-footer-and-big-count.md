# 82 — 파일은 카드 바닥글로 · 분석 2 는 차이 개수를 크게

> 분석 2 메인화면에 차이발생 0개 뒤에오는 io명들 다 날리고 차이발생만 보이게
> 그리고 차이발생 갯수 눈에 잘보이게
> 그리고 log파일 여는 곳들이 저기 있는게 맞나? 뭔가 안예쁘네

## 1. 차이 발생 — 수만, 크게

```
전 (1.01)                              후 (1.02)
WARNING                                WARNING
차이 발생 3개 — TEMP_MAX, PRES_SET,     차이 발생  12 개
VALVE_1 외 9개 (판정에 안 넣음: …)                 ^^ 30pt, 판정 색
```

작은 글 한 줄에 문장 · 수 · 이름 · 덧말이 다 섞여 있었습니다. **제일 먼저
찾는 수가 그 줄에서 제일 안 보였습니다.**

이름을 뺀 것은 중복이라서입니다 — 0.98 부터 **아래 요약 칸이 달라진 IO 를
한 줄씩** 적고 있습니다. 같은 이름이 한 칸 안에 두 번 적혀 있었던 셈입니다.

없어진·새로 생긴 IO 수도 메인 칸에서는 뺐습니다 (말씀대로 "차이 발생만").
**없어진 것은 아닙니다** — 분석 2 화면 위쪽에 셋 다 적혀 있고, 달라진 IO 가
하나도 없을 때는 요약 칸이 "없어진 IO N개 · 새로 생긴 IO N개는 분석 2
화면에서 볼 수 있습니다" 라고 적습니다.

분석 2 화면의 요약 줄(판정 문장 — FAIL 이면 "파일을 다시 확인해 주세요")은
그대로 뒀습니다. 메인 화면만 바꾸라고 하셔서입니다.

## 2. 파일 여는 곳 — "저기 있는 게 맞나?"

**맞지 않았습니다.** 두 가지가 잘못돼 있었습니다.

- **자리**: 카드 가운데, 점수 바로 아래였습니다. 메인 화면이 먼저 답할 것은
  "결과가 어떤가" 인데, 결과보다 파일 칸이 먼저 눈에 들어왔습니다.
- **모양**: 카드(테두리) 안에 상자(테두리) 둘, 그 안에 줄 셋씩. 0.99 에
  위아래로 쌓으면서 더 무거워졌습니다.

그래서 **카드 맨 아래 바닥글**로 내리고 **한 줄씩**으로 줄였습니다.

```
│ 요약 …                                              │
│ ──────────────────────────────────────────────────  │
│ ● 이전  2026-03-14_가열_A.csv     IO 180 · 표본 5,000 │
│ ● 이후  2026-03-20_가열_A.csv     IO 180 · 표본 5,100 │
```

- 줄은 평소 **카드와 같은 색**이라 안 띕니다. 파일을 끌어 올리면 밝아지고
  테두리가 그쪽 색(이전 파랑 · 이후 주황)으로 바뀝니다.
- 안 열었으면 이름 자리에 흐리게 "누르거나 끌어다 놓아 여세요".
- 발생시간 칸은 뺐습니다 — 파일 이름 앞 10 글자를 떼어 온 것이라 바로 옆의
  이름과 같은 글자를 두 번 적고 있었습니다.
- 머리글("로그 (칸을 누르거나 …)") 도 뺐습니다. 줄이 이전/이후라고 적고 있고,
  할 일은 흐린 글이 말합니다.

177 줄을 들어내고 바닥글 두 묶음을 넣었습니다. 카드가 0.99 보다 짧아집니다.

## 놓칠 뻔한 것 — 끌어 올린 뒤 테두리가 남는 고장

납작한 줄을 만들면서 **테두리를 카드 색(안 보이게)** 으로 뒀습니다. 그런데
`CardTag.Lit` 이 끌기가 끝나면 테두리를 **코드에 박힌 `Brush.Border`** 로
되돌리고 있었습니다. 그대로 냈으면 **한 번 끌어다 놓은 줄만 테두리가 생긴
채** 남았을 겁니다 — 배경으로 0.59 에 겪은 것과 똑같은 모양입니다.

- Tag 에 셋째 칸을 뒀습니다: `"before|Brush.Panel|Brush.Panel"` (방향 ·
  되돌릴 배경 · **되돌릴 테두리**). 없으면 예전대로 `Brush.Border` 입니다 —
  다른 칸들은 고칠 것이 없습니다.
- 검사기(`check_sources.py`)에 규칙을 더했습니다: **놓는 칸의 BorderBrush 와
  Tag 의 셋째 칸이 같은지.** 일부러 셋째 칸을 지워서 규칙이 잡는 것을 보고
  되돌렸습니다.
- 그 김에 배경 규칙이 Tag 를 "첫 `|` 뒤 전부" 로 읽던 것을 "둘째 칸" 으로
  고쳤습니다 (셋째 칸이 생기자 바로 틀린 답을 냈습니다).

컴파일도 되고 XAML 도 읽히는 어긋남이라, 이 검사가 없으면 **Windows 에서
파일을 한 번 끌어다 놓아 봐야** 압니다.
