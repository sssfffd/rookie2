# 33 — 분석 이름을 파일에서 바꾸기 (screens.txt)

> 요청: "지금 분석 1 옆에 있는 로그비교랑 분석 2 옆에 분석 2 그리고 분석 3도
> 내가 변경하고 싶어 근데 프로그램 위에서 변경하는 게 아니라 파일을 고쳐서
> 변경하고싶은데 어떻게 할까"

## 어디서 바꾸나

**`screens.txt` 한 곳입니다.** 실행 파일 옆(`out\screens.txt`)에 있습니다.

```
# 분석 1·2·3 의 이름입니다. 위에서부터 차례로 한 줄씩.
# 세로줄(|) 뒤는 메인 화면 칸에 적히는 한 줄 설명입니다 (없어도 됩니다).

로그 비교 | 이전 Log 파일과 이후 Log 파일을 비교합니다. 대시보드 · 그래프 · 히트맵.
분석 2 | 아직 정해지지 않았습니다.
분석 3 | 아직 정해지지 않았습니다.
```

고치고 **프로그램만 다시 켜면** 됩니다. 이렇게 하면

| 어디 | 무엇이 바뀌나 |
|---|---|
| 메인 화면의 분석 칸 | 제목과 그 아래 한 줄 설명 |
| 왼쪽 위 `LogScope ▾` 목록 | `2.  분석 1 — 타이밍 점검` |
| 위 줄의 지금 화면 이름 | `분석 2 — 압력 비교` |
| 분석 2·3 의 빈 화면 가운데 글자 | 같음 |

## 왜 빌드할 때가 아니라 실행할 때인가

프로그램 이름(`appname.txt`)은 **빌드할 때** 읽습니다. 그건 실행 파일 이름이
되기 때문에 그럴 수밖에 없습니다 — 빌드가 시작되기 전에 정해져 있어야
합니다.

분석 이름은 그런 것이 없습니다. 그래서 **실행할 때** 읽습니다. 이게 낫습니다:

- 이름 하나 바꾸자고 Visual Studio 를 켜거나 `build.bat` 을 돌리지 않아도 됩니다.
- `out` 폴더를 복사해 간 다른 PC 에서도 그 자리에서 고칠 수 있습니다.

저장소 루트에도 `screens.txt` 를 뒀고, `build.bat` 이 `out` 폴더로 넣어
줍니다. **이미 있으면 덮지 않습니다** — 거기서 고쳐 놓았을 수 있으니까요.

## 손으로 고치는 파일이라서 한 일

### 1. 메모장 인코딩

요즘 메모장은 UTF-8 로 저장하지만 **예전 메모장은 CP949(ANSI)** 로 저장합니다.
UTF-8 로만 읽으면 그 경우 한글이 깨집니다. BOM → UTF-8 → CP949 순으로 봅니다.

```csharp
try
{
    // throwOnInvalidBytes: CP949 로 저장된 파일이면 여기서 걸립니다.
    text = new UTF8Encoding(false, true).GetString(raw);
}
catch (DecoderFallbackException)
{
    text = Legacy().GetString(raw);   // CP949
}
```

`build.bat` 에서 겪은 것과 같은 문제입니다. 거기서는 파일을 CP949 로 고정했지만,
이 파일은 **사용자가 고치는 파일**이라 고정할 수가 없습니다.

### 2. 엉망으로 적혀 있어도 돌아야 합니다

| 적힌 것 | 어떻게 되나 |
|---|---|
| 파일이 없음 | 기본값 |
| 줄이 한 줄뿐 | 첫 칸만 바뀌고 나머지는 기본값 |
| 네 줄 이상 | 넷째 줄부터 안 봄 |
| `| 설명만 있음` | 이름은 기본값, 설명만 바뀜 |
| 빈 줄, `#` 로 시작하는 줄 | 건너뜀 |
| 읽을 수 없는 파일 | 기본값 |

**이름 하나 때문에 프로그램이 안 켜지면 안 됩니다.** 잘못 적힌 모든 경우가
기본값으로 떨어집니다.

### 3. "분석 2 — 분석 2" 가 되지 않게

위 줄과 목록은 `분석 2 — 압력 비교` 처럼 번호와 이름을 같이 적습니다.
이름을 그대로 둔 자리는 `분석 2 — 분석 2` 가 되므로, 그때는 번호만 적습니다
(`IsDefaultTitle`).

## 치운 것

이름이 다섯 군데에 적혀 있었습니다. 이제 다 `ScreenNames.Current` 를 봅니다.

- `MainVm` 의 칸 셋 (제목 + 설명)
- `ShellVm.ScreenName`
- `ShellWindow.xaml` 의 화면 목록 단추 넷 → `{Binding MenuMain}` 등으로
- `ShellWindow.xaml` 의 `PlaceholderView Heading` 둘 → `{Binding Analysis2Name}` 등으로

## 자체 테스트

**테스트 24 개를 더했습니다 (328 → 352).** 읽기 규칙과 인코딩을 다 덮습니다 —
BOM 붙은 UTF-8, BOM 없는 UTF-8, CP949(있는 환경에서만), 없는 파일, 빈 파일,
`null`, 모자란 줄, 남는 줄, 이름 없는 줄, 범위 밖 번호.

`check_sources.py` 가 새 파일을 `.csproj` 에 넣는 것을 잊은 것을 잡아냈습니다
(`csproj 누락 Settings/ScreenNames.cs`). Visual Studio 에서만 나는 오류라
이 검사가 없으면 윈도우에서 빌드할 때 알게 됐을 것입니다.

### 아직 확인 못 한 것

`Encoding.GetEncoding(949)` 는 **윈도우에서만** 확인됩니다. 리눅스 mono 에는
CP949 가 없어 그 검사는 건너뜁니다 (없으면 기본 인코딩으로 물러서게 해
뒀습니다). 메모장에서 ANSI 로 저장한 파일은 윈도우에서 한 번 봐 주세요.
