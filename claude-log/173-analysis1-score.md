# 173 — 분석 1 을 점수로 · 차이 a / b IO · 평균 오차율 (1.81)

> 그리고 분석1은 점수로 나타내야하는데나타내야하는데
> 점수차이 발생자리네 점수 쓰고 오른쪽에
> 차이개수/전체개수(IO)이렇게 쓰고
> 그리고 이제 전체 로그 시간을 100칸으로 나누고
> 몇칸동안 차이가 발생했는지가 오차율이야 ㅇㅋ? 그리고 각 IO 오차율의 평균을 차이개수 밑쪽에다가 적어주셈

물어서 정한 것: 점수 = **100 − 평균 오차율** (사용자 고름). 평균 대상은 "뭐가 좋아보임?" → **차이 난 IO 만**으로 함
(전체로 하면 IO 200 개 중 5 개가 50 % 여도 평균 1.25 % → 98.75 점으로 묽어짐. "몇 개" 는 옆의 a / b 가 보여 줌).

## 칸

```
 ┌ 분석 1 ─────────────────────────────────┐
 │ 88.3 / 100   차이 5 / 120 IO              │
 │              평균 오차율 11.7 %           │
```

| | 셈 |
|---|---|
| 오차율 (IO) | 이전 로그 전체 시간을 100 칸 → 허용 안 된 판정 오차가 걸친 칸 수 (%). 끝이 칸 경계에 딱 걸리면 그 칸은 안 셈. 한쪽 로그에만 있는 IO 100 % |
| 평균 오차율 | 차이 난 IO 만의 평균 |
| 점수 | 100 − 평균 오차율 (0.1 단위), 없으면 100. 색은 점수 색 (90 · 70) |
| a / b | 차이 난 IO 수 / 두 로그 IO 합집합 (단계 IO 뺌) |

- 판정 오차 = 그동안의 정상 판정 그대로 (시간 여유 · 단계 맞춤 · 허용 반영) — 허용하면 점수 · 개수가 그 자리에서 바뀜
- 고른 단계 반영 중이면 점수 옆에 그 글 (1.69)
- History 에도 점수 · a / b · 평균 오차율 저장 (예전 기록은 그때 것 그대로)
- LLM 입력 (Analysis1Judgement) 맨 위에 점수 줄. PASS · WARNING · CRITICAL 낱말은 LLM 글에 그대로

## 확인
- 테스트 1134 통과 (새 것: 10 칸 + 1 칸 = 11 %, 허용은 안 셈, 한쪽에만 있는 IO 100 %, 평균 55.5 → 44.5 점, 차이 없으면 100 · 단계 IO 뺌;
  메인 칸 테스트들을 점수 · a / b 로 바꿈), 실제 csc 7.3 오류 0, 검사 스크립트 · XAML 모양 통과
- **Windows 에서 못 봄**: 칸 모양 (점수 옆 두 줄이 42 px 안에 들어가는지)
