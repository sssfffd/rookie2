# 56 — 표시명 하나 바꾸는데 네 파일 (0.75)

## 주신 말

> 위에 1번 2번이 이런게 문제라는거야 간단하게 표시명만 바꾸는데
> 이렇게 많은 파일을 참고해야 하잖아

바로 앞 질문("v1 v2 이름 바꿀려면 뭐 수정해야돼?")에 제가 파일 네 개를
적어 드렸고, 그게 답이 아니라 **문제**라는 지적입니다. 맞는 지적입니다.

## 뭐가 문제였나

`v1` 이라는 **같은 글자**가 네 군데에 따로 적혀 있었습니다.

| 어디 | 무엇 |
|---|---|
| `Views/DbView.xaml` | 화면 머리글 `Header="v1"` |
| `Db/DbCompare.cs` `ToCsv` | CSV 머리글 글자 한 줄 |
| `Db/DbCompare.cs` `Tip` | 마우스 올리면 뜨는 설명 글 |
| `Tests/Program.cs` | 머리글 글자를 그대로 비교하는 시험 |

이러면 두 가지가 생깁니다.

1. 이름 하나 바꾸려고 **네 파일**을 엽니다.
2. 한 군데를 빠뜨리면 화면은 `설정값`, CSV 는 `v1` 이 됩니다. 컴파일도 되고
   시험도 통과합니다 — **눈으로 봐야만 알게 됩니다.** 더 나쁜 쪽입니다.

## 고친 방향

이름이 적힌 곳을 **하나**로 만들고, 거기 하나만 보면 되게 했습니다.
그리고 흔한 쪽(이름만 바꾸기)은 코드를 아예 안 고치게 했습니다.

### 1) `src/LogScope.Core/Db/DbNames.cs` — 새 파일, 이름이 있는 유일한 곳

```csharp
public const  string DefaultV1 = "v1";                        // 기본 이름
public static string V1 { get { return Of("v1", DefaultV1); } } // 지금 쓰는 이름
public static string[] CsvNames() { ... }                      // CSV 순서
```

11 칸(표 · IO명 · 갈래 · 구분 · 행 · 열 · 이전 value · 이후 value · v1 ·
v2 · 설명) 전부 여기 있습니다.

### 2) `config.txt` 한 줄로 바뀌게

```
db.col.v1 = 설정값
db.col.v2 = 단위
```

`out\config.txt` 에 적고 **프로그램만 다시 켜면** 화면 머리글 · CSV 머리글 ·
설명 글이 같이 바뀝니다. 빌드도, Visual Studio 도 필요 없습니다.
`AppConfig` 는 `db.col.` 로 시작하는 줄을 전부 받아 둡니다 — 칸을 더할 때
설정 읽는 쪽을 고치지 않아도 됩니다.

### 3) 쓰는 쪽 셋이 그 한 곳을 보게

- `DbView.xaml` → `Header="{x:Static db:DbNames.V1}"`
- `DbCompare.ToCsv` → `DbNames.CsvNames()` 를 돌며 머리글을 찍습니다
- `DbDiffLine.Tip` → `Label(sb, DbNames.V1, V1)`

### 4) 시험에서 글자를 뺐습니다

전에는 시험이 `"표,IO명,…,v1,v2,설명"` 을 그대로 들고 있어서, 이름을
바꾸면 **시험이 깨졌습니다**. 이름을 바꿨을 때 고칠 곳이 하나 더 있는
셈이었습니다. 이제는 "머리글이 `DbNames` 의 이름과 같은 순서로 나오는지"
만 봅니다. 이름을 바꿔도 시험은 안 건드립니다.

새 시험 `DbColumnNames()` 는 **이 약속 자체**를 지킵니다 (12 개):

- `db.col.v1` 한 줄로 화면·CSV·설명 글이 같이 바뀌는지
- 안 적은 칸은 기본 이름 그대로인지
- 이름에 쉼표가 들어가도 CSV 가 안 깨지는지 (값과 같은 함수로 찍습니다)
- 비워 둔 줄 · 모르는 열쇠로 칸 이름이 사라지지 않는지
- 열쇠 대소문자를 안 가리는지

## 왜 `Binding` 이 아니라 `x:Static` 인가

목록 칸(`GridViewColumn`)은 화면 나무(visual tree)에 들어가지 않습니다.
그래서 보통 `{Binding}` 이 **조용히 실패**하고 머리글이 빈 칸으로 나옵니다
(실패한 Binding 이 아무 말도 안 하는 건 이 프로젝트에서 이미 두 번 당한
자리입니다). `x:Static` 은 나무가 필요 없습니다 — XAML 을 읽을 때 정적
속성을 바로 읽습니다. 설정은 `App.OnStartup` 에서 창보다 먼저 읽으므로
순서 문제도 없습니다.

## 이제 "이름 바꾸려면 뭘 고치나"

| 하려는 것 | 고칠 곳 |
|---|---|
| 이름만 바꾸기 | `out\config.txt` **한 줄** (빌드 없음) |
| 기본 이름 바꾸기 | `DbNames.cs` 의 `Default...` **한 줄** |
| 칸을 더하기 | `DbNames.cs` + `ToCsv` 의 값 쓰는 줄 + `DbView.xaml` |

## 확인한 것 · 못 한 것

- `통과 642 / 실패 0`, 네 검사기 모두 지적 없음 (시험 630 → 642)
- **Windows 에서 확인 못 했습니다**: `x:Static` 으로 바뀐 머리글이 실제로
  어떻게 보이는지. XAML 은 여기서 컴파일되지 않습니다.
