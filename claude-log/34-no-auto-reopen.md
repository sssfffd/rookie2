# 34 — 켤 때 지난번 로그를 저절로 열지 않기

> 요청: "아 그리고 프로그램 열면 전에 열었던 파일들 자동으로 열리는게 안하게
> 해주셈"

## 무엇을 하고 있었나

`ShellWindow.OnLoaded` 에서, 명령줄 인자가 없으면 지난번 세트를 그대로
열었습니다.

```csharp
// 지난번에 보던 세트를 그대로 다시 엽니다.
LogSet s = _state.Settings.ActiveLogSet;
bool any = (!string.IsNullOrEmpty(s.BeforePath) && File.Exists(s.BeforePath))
        || (!string.IsNullOrEmpty(s.AfterPath) && File.Exists(s.AfterPath));
if (any) LoadSet();
```

"이어서 보기" 를 편하게 하려던 것인데, **이 프로그램에서는 오히려 방해**
였습니다. 로그가 1000 만 칸까지 갑니다. 켤 때마다 몇십 초씩 읽고 앉아 있는데
정작 열고 싶은 것은 대개 다른 파일입니다. 읽는 동안 기다렸다가, 그걸 닫고,
새로 여는 순서가 됩니다.

## 어떻게 했나

그 블록을 없앴습니다. **켜면 빈 화면으로 시작합니다.**

여는 길은 그대로입니다.

- 위 줄의 **[이전 로그 열기] / [이후 로그 열기]**
- 메인 화면의 **이전 / 이후 칸에 파일을 끌어다 놓기**
- 명령줄 인자 (`LogScope.exe a.xlsx b.xlsx`) — 이건 사용자가 시킨 것이라
  그대로 둡니다

## 경로는 그대로 남습니다

세트(LogSet)에 적힌 `BeforePath` / `AfterPath` 는 **지우지 않았습니다.**

- 파일 대화상자가 **지난번 그 폴더**에서 열립니다. 로그가 쌓이는 폴더는
  대개 정해져 있어서, 이게 없으면 매번 같은 경로를 찾아 들어가야 합니다.
- 세트를 바꾸면(`OnSetChanged` → `LoadSet`) 그때는 엽니다. 그건 **누른
  것**이니까요. 저절로 여는 것과 눌러서 여는 것은 다릅니다.

지우는 편이 "깨끗" 해 보이지만, 그러면 위의 두 가지를 같이 잃습니다.
바꾼 것은 **켤 때 저절로 읽는 것 하나**입니다.

## 자체 테스트

테스트 352 통과(그대로). 시작할 때의 동작이라 Core 에 붙일 것이 없습니다 —
지운 코드가 있던 자리가 창(`ShellWindow`)입니다.

### 아직 확인 못 한 것

빈 화면으로 뜨는 모습은 윈도우에서 봐 주세요. 처음 켠 것과 같은 상태라
새로 생긴 화면은 아닙니다.
