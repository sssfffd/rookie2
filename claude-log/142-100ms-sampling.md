# 142 — 0.1 초 단위 데이터도 되나

> 근데 데이터가 0.1초 단위로 넣을껀데 위 기법이랑 분석 1로 가능?

(확인만 — 코드 안 바꿈)

## 결론: 됨

| 확인 | 지금 코드 | 결과 |
|---|---|---|
| 시각 읽기 | `ValueParse.TryClock` "12:00:00.1" → ms, `TryDateTime` "…56.7" 도 ms, 엑셀 시각 칸(일 단위 실수)도 ms | 0.1 s 그대로 |
| 초 단위로만 적힌 시각 (같은 초가 10 줄) | `TimeAxis.SpreadRepeats` 가 다음 시각까지 고르게 펼침 | 0.1 s 간격으로 펴짐 |
| 시간축 저장 | `double[]` ms | 정밀도 충분 |
| 양 | 1 시간 = 36,000 줄. 1000 만 칸 = IO 280 개 × 1 시간 (또는 IO 100 개 × 2.8 시간) | 지금 분석 1 이 다루는 크기 안 |
| 새 기법 계산 | 허용 띠 = 미는 창 최소/최대 (O(n)), IO 하나씩 처리 | 1000 만 칸 1 초 안쪽 예상 · 메모리 IO 하나 분량만 |

## 0.1 초라서 정해 둘 것 (141 계획에 반영)
- Δt 하한 = 2 샘플 = 0.2 s. 단계 길이 2 % 규칙 (0.5~5 s) 이 대부분 이김
- 아킹 같은 튐이 **샘플 1 개 (0.1 s)** 로만 찍힐 수 있음 → 중요 IO 는 튐 지우기 끔 (141 #2) 이 꼭 필요
- 창 · 튐 · 지연은 **줄 수가 아니라 시각** 으로 셈 — 로거가 0.098 / 0.103 처럼 흔들리거나 줄이 빠져도 안 틀어짐
- 이전 · 이후 샘플 시점이 0.05 s 어긋나도 띠가 흡수
