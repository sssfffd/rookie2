# 38 — 위 줄을 두 칸으로: 화면 전환은 왼쪽, 하던 메뉴는 오른쪽

> 요청: "지금 분석1에서 사용하는 상단 메뉴가 메인화면에서 있잖아( log 읽기
> 관련) 그거 메인화면에선 안뜨게해주고 로그 세트 기능은 지우고 다시 읽기랑
> 비교다시하기 중에 하나만 있으면 될꺼같아. 그리고 지금 좌측상단의 프로그램명을
> 클릭하면 나오는 list에서 화면들을 전환하는데 상단 메뉴바에서 이동가능하게
> 모든화면에서. 모든화면으로. 메인 분석 1 2 3 이 다 버튼으로 존재하게해야지.
> 그리고 원래 메뉴들하고는 칸 구분되게하고 화면전환이 왼쪽 원래 메뉴가
> 오른쪽에 배치되게 해줘"

## 전

```
LogScope ▾  분석 1 — 로그 비교  v0.44  [대시보드][그래프][히트맵]
로그 세트 [세트 1          ▾] [이전 로그 열기][이후 로그 열기][다시 읽기][비교 다시 하기][설정]
```

- 화면을 옮기려면 **[LogScope] 를 눌러 목록을 펼쳐야** 했습니다. 네 화면을
  오가는 것이 이 프로그램의 기본 동작인데 그걸 접어 두고 두 번 눌러야 했습니다.
- 로그 열기 단추들이 **메인 화면에서도** 보였습니다. 메인 화면에는 이전/이후
  칸이 따로 있어서 할 일이 겹칩니다.
- **로그 세트** 가 위 줄에서 자리를 제일 많이 차지했습니다.

## 후

```
LogScope v0.45  [메인][분석 1][분석 2][분석 3] │ [대시보드][그래프][히트맵]  [이전 로그 열기][이후 로그 열기][비교 다시 하기]  [설정]
```

**왼쪽 = 어디를 볼까. 오른쪽 = 무엇을 할까.** 가운데 선으로 칸을 나눴습니다.

| 어디 | 무엇 | 언제 보이나 |
|---|---|---|
| 왼쪽 | 메인 · 분석 1 · 2 · 3 | **늘** |
| 오른쪽 | 대시보드 · 그래프 · 히트맵 | 분석 1 에서만 |
| 오른쪽 | 이전/이후 로그 열기, 비교 다시 하기 | 분석 1 에서만 |
| 오른쪽 | 설정 | **늘** |

화면 단추는 라디오 단추라 **지금 보고 있는 화면이 눌린 모양**으로 남습니다.
이름은 `screens.txt` 를 따라갑니다 (분석 2 를 "압력 비교" 로 바꾸면 단추도
그렇게 적힙니다).

## 없앤 것

### 1. 로그 세트

이전+이후 한 쌍을 여섯 개까지 기억하고 골라 가며 보는 기능이었습니다.
위 줄에서 폭을 제일 많이 먹었는데, 쓰이지 않았습니다.

**설정은 그대로 삽니다.** 기본 폴더와 마지막으로 연 파일 경로가 거기 들어
있어서, 기능을 지웠다고 그 값을 버리면 안 됩니다. 설정 창의 `로그 세트` 탭은
**`폴더` 탭**이 되었습니다 — 세트 목록과 세트 이름 칸만 빠지고, 이전/이후
기본 폴더와 기억된 파일은 그 자리에 있습니다.

### 2. [다시 읽기]

둘이 하는 일이 겹쳤습니다.

| 단추 | 하던 일 |
|---|---|
| 다시 읽기 | 파일을 디스크에서 **다시 읽고** → 다시 견줌 |
| 비교 다시 하기 | 이미 읽어 둔 것으로 **다시 견줌** |

**[비교 다시 하기] 를 남겼습니다.** 자주 쓰는 쪽이 이쪽입니다 — 허용 오차나
시간 맞추기를 고친 뒤 누르는 것. 파일을 다시 읽는 쪽은 1000 만 칸을 또 읽어
몇십 초가 걸리는데, 파일이 바뀌었으면 다시 열거나 끌어다 놓으면 됩니다.

### 3. 왼쪽 위 목록 (팝업)

네 화면이 다 단추로 나왔으니 쓸 자리가 없어졌습니다. 프로그램 이름은 그냥
글자가 되었습니다. 팝업에 딸려 있던 `250 ms 방금 닫힘` 처리도 같이 빠졌습니다
— 팝업이 없으면 그 문제도 없습니다.

`Esc` 는 그대로 메인으로 돌아갑니다. `F1`·`F2`·`F3`·`F5` 도 그대로입니다.

## 걸렸던 것

**XAML 주석 안에 `--` 를 쓸 수 없습니다.** 칸을 나눈 자리에
`<!-- ---- 왼쪽 ---- -->` 라고 적었다가 XML 파싱에서 걸렸습니다. 검사
스크립트(`check_sources.py`)가 XAML 을 XML 로 읽어 보기 때문에 그 자리에서
잡혔습니다 — 없었으면 윈도우 빌드에서 알았을 오류입니다.

**위 줄이 두 칸이라 좁은 창에서 어떻게 되나.** 왼쪽은 `Auto`, 오른쪽은 `*`
칸에 넣었습니다. 그래서 좁아지면 **오른쪽만** 두 줄로 접힙니다. 왼쪽(화면
전환)은 늘 한 줄에 그대로 남습니다 — 어디로 갈 수 있는지가 접히면 안 됩니다.

## 자체 테스트

테스트 389 통과(그대로). 위 줄 모양이라 Core 에 붙일 것이 없습니다.
`x:Name`·처리기 서명·XAML 파싱·테마 열쇠 검사는 다 돌았습니다.

### 아직 확인 못 한 것

- 화면 단추 넷의 **폭과 줄바꿈**. 특히 `screens.txt` 로 긴 이름을 넣었을 때.
- 칸 구분 선이 보이는 굵기인지 (1 픽셀, 흐리게 45%).
- 최소 폭(900) 에서 오른쪽이 두 줄로 접히는 모습.

## 뒷이야기 — 단추 이름 (0.46)

> 요청: "위에 분석 1 2 3 대신에 로그비교처럼 내가 설정한 이름으로 띄워지게
> 해주셈"

단추에 `분석 1` 이 적혀 있었습니다. 이름을 그대로 둔 자리는 번호만 적고,
바꾼 자리만 `분석 2 — 압력 비교` 로 적게 해 뒀던 것입니다. 번호를 잃지 않으려
한 것인데, **정해 놓은 이름이 어디에 쓰이는지 알 수 없게** 됩니다.

이제 `screens.txt` 에 적은 이름이 그대로 나옵니다.

```
메인  로그 비교  분석 2  분석 3          ← 기본값
메인  로그 비교  압력 비교  타이밍 점검    ← screens.txt 를 고치면
```

번호는 `screens.txt` 의 **줄 순서가 이미 말해 줍니다.** 단추에 또 적을 이유가
없었습니다.

같이 치운 것:

- `ShellVm.ScreenName` — 위 줄에 "지금 어느 화면" 을 적던 글자. 화면 단추가
  눌린 모양으로 남으니 같은 말을 두 번 하는 자리였습니다 (0.45 에서 이미
  화면에서 빠졌고, 이제 속성도 없앴습니다).
- `ScreenNames.IsDefaultTitle` — "이름을 그대로 뒀는지" 를 묻던 것. 번호를
  붙일지 말지 가리는 데만 쓰였으므로 같이 없앴습니다. 그 자리를 메우려고
  검사 세 줄을 이름 자체를 보는 것으로 바꿨습니다.

빈 화면(분석 2·3) 가운데 글자도 같은 이름입니다.
