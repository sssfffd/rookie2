> 요청: "이제 분석 2에 DB 분석을 넣을 거임 / config.txt랑 비슷하게 내가 기존
> db 데이터 위치 넣으면 db데이터들 읽을수 있게 그리고 db파일들은 .frm이랑
> .ibd로 나뉘어 있거나 .csv 파일혹은 .sql로 저장되어있슴 / 이거 db파일들
> 비교해서 값이 바꼇거나 이름이 다르면 알 수 있게하고 다른 부분 동일하게 적용도
> 가능하게 해야되는데 쿼리문으로 들어가게끔 하는게 좋나 그리고 외부
> 라이브러리는 자제해야되는데 가능?"
>
> 고른 것: `.sql` + `.csv` 를 직접 읽고, **MySQL 도구 호출도 같이**.

## 먼저 — 제가 틀린 것을 바로잡습니다

앞 답에서 "**.frm/.ibd 폴더를 주면 mysqldump 를 불러 텍스트로 뽑아 읽는다**"
고 했습니다. **틀렸습니다.**

`mysqldump` 는 **돌고 있는 서버에 접속해서** 뽑습니다. 멈춰 있는 데이터
폴더(.frm/.ibd)만 가리켜서는 아무것도 뽑을 수 없습니다. 오프라인 파일에서
쓸 수 있는 공식 도구는 `ibd2sdi` 뿐이고, 그건 **정의(이름·타입)만** 꺼냅니다.

그래서 세 길을 각각 다르게 뒀습니다.

| 무엇을 주면 | 무엇을 읽나 | 서버가 돌아야 하나 |
|---|---|---|
| `.sql` / `.csv` | **모양 + 값** | 아니오 |
| `db.dump.*` 명령 줄 | **모양 + 값** (덤프를 받아 읽음) | **예** |
| `db.ibd2sdi` + `.ibd` | **이름·타입만** | 아니오 |
| `.frm` | 못 읽습니다 | — |

`.frm` 은 공개 규격이 없고 MySQL 8 부터는 쓰지도 않습니다. 못 읽는 것을
못 읽는다고 적습니다 — 폴더에 `.ibd` 가 40 개인데 화면에 표가 없으면
"차이 없음" 으로 읽히므로, 그렇게 되지 않게 합니다.

## config.txt 에 적는 것

```
db.before = D:\db\2026-03-14
db.after  = D:\db\2026-03-21

# 선택 — 돌고 있는 서버에서 받아 읽기
db.dump.before = "C:\...\mysqldump.exe" --login-path=old --databases mydb
db.dump.after  = "C:\...\mysqldump.exe" --login-path=new --databases mydb

# 선택 — 멈춘 .ibd 에서 이름만
db.ibd2sdi = C:\...\ibd2sdi.exe
```

**접속 정보를 우리가 들고 있지 않습니다.** 명령 줄을 그대로 적게 뒀습니다 —
사용자 이름과 암호를 받아 두면 "그걸 어디에 어떻게 저장할지" 가 새 문제가
되고, 명령 줄에 암호를 박으면 작업 관리자에 그대로 보입니다. 접속 방법은
MySQL 쪽 방식(`--login-path`, `--defaults-extra-file`)에 맡기는 편이
안전합니다. 이 결정과 위험은 `config.txt` 주석과 `DbTools` 머리말에
적어 뒀습니다 — 파이썬 모듈(`AiBridge`)에 적어 둔 것과 같은 수준입니다.

## 라이브러리는 0 개입니다

- `.sql` 은 글자를 직접 훑습니다 (`SqlDumpReader`). 세미콜론으로 문장을
  끊되 **따옴표와 주석 안의 세미콜론은 끊지 않습니다** — 값에 세미콜론이
  들어 있는 것은 흔합니다.
- `.csv` 는 이미 있는 로그용 `CsvReader` 를 그대로 씁니다. 구분자·인코딩
  판별과 따옴표 안 줄바꿈 처리가 거기 있습니다. 같은 일을 두 번 만들면
  한쪽만 고치게 됩니다.
- `ibd2sdi` 가 내는 JSON 도 이미 있는 `Json` 으로 읽습니다.
- `mysqldump`/`ibd2sdi` 는 **라이브러리가 아니라 이미 깔려 있는 프로그램**을
  자식 프로세스로 띄우는 것입니다.

**SQL 을 실행하지 않습니다.** 덤프 글자를 읽어 표로 만들 뿐이고, 모르는
문장은 건너뜁니다. 덤프에 무엇이 적혀 있어도 이 프로그램이 그걸 수행하는
일은 없습니다.

## 비교 — 세 단계

```
1. 표    한쪽에만 있는 표
2. 열    추가·삭제·타입/NULL/기본값/자리 변경, 그리고 이름 변경 짐작
3. 행    키 기준 추가·삭제·값 변경 (바뀐 열만 집어냅니다)
```

### 이름 변경은 "짐작" 으로만

사라진 열과 새로 생긴 열이 **모양(타입·NULL·기본값)과 자리가 같고, 그런 짝이
하나뿐일 때만** `이름이 "x" 로 바뀐 듯` 이라고 덧붙입니다.

단정하지 않는 이유가 분명합니다. 단정하면 그걸 믿고 `ALTER TABLE ... CHANGE`
를 돌리는데, 실제로는 한 열을 지우고 다른 열을 더한 것일 수 있습니다. 그러면
**값이 사라집니다.** 그래서 SQL 쪽에서도 이 경우는 **주석으로만** 내놓고,
"맞다면 이것, 아니라면 둘로 나누어" 를 같이 적습니다.

### 키가 없으면 그렇다고 적습니다

기본 키가 없는 표(특히 `.csv`)는 **어느 행이 어느 행이 되었는지 알 방법이
없습니다.** 그때는 "모든 열이 같은 행끼리" 묶으므로 값이 하나 바뀐 행은
`없어진 행 1 + 생긴 행 1` 로 보입니다. 짐작으로 짝지어 "이 행의 이 값이
바뀌었다" 고 적으면 거짓말이 되므로, 아는 만큼만 적고 **왜 그렇게 보이는지**
를 화면에 적습니다.

### 값은 글자 그대로 들고 있습니다

숫자로 바꿔 두면 `1.10` 과 `1.1` 이 같아져 "안 바뀌었다" 가 되는데, DB 에서
그 둘은 다르게 적힌 것입니다. 반대로 **이스케이프는 되돌립니다** (`\'` →
`'`) — 같은 값을 다르게 적어 둔 두 덤프를 차이로 세면 안 됩니다.

`NULL` 은 `null` 로 둡니다. 빈 글자와 다릅니다.

## "다른 부분 동일하게 적용" — SQL 글로, 실행은 안 함

**맞추는 SQL 을 만들어 보여 주고 파일로 저장합니다.** 방향도 고릅니다
(`이전 → 이후` / `이후 → 이전`).

```sql
-- 이전 DB 를 이후와 같게 만드는 글
-- 프로그램이 직접 돌리지 않습니다. 읽어 보고 직접 돌리세요.
--   START TRANSACTION;  ... 확인 ...  COMMIT;  (아니면 ROLLBACK;)

ALTER TABLE `recipe` ADD COLUMN `added` int NULL DEFAULT '0';
UPDATE `recipe` SET `temp_max` = 999.90 WHERE `id` = 1;
INSERT INTO `recipe` (`id`, `name`, `temp_max`, `added`) VALUES (4, '새 행', 2.00, 6);
-- 한쪽에만 있는 행입니다. 지우려면 주석을 풀어 주세요:
-- DELETE FROM `recipe` WHERE `id` = 3;
```

**돌리지 않는 이유**는 둘입니다. ① 접속에 라이브러리가 필요하고, ② 무엇보다
한 번 잘못 돌리면 되돌릴 수 없습니다. 지금까지 이 프로그램은 읽기만 했고,
그 선을 넘는 것은 따로 정할 일입니다.

**지우는 문장은 늘 주석**입니다 (`DROP TABLE`, `DROP COLUMN`, `DELETE`).
글만 보고 돌렸을 때 값이 사라지면 안 됩니다. 검사에서 그걸 확인합니다.

**따옴표는 반드시 막습니다.** 값에 `'` 가 들어 있으면 글이 깨지고, 깨진 글을
사람이 돌리면 엉뚱한 문장이 됩니다.

## 뒷이야기 — mysqldump 경로를 따로 (0.52)

> 요청: "근데 mysqldump도 내가위치정해줄게"

처음에는 `db.dump.before` 한 줄에 **명령 줄 전체**를 적게 했습니다. 실행 파일
경로와 인수가 한 줄에 섞여 있어서, 서버 둘을 견주려면 **같은 경로를 두 번**
적어야 했습니다. 경로가 바뀌면 두 줄을 다 고쳐야 하고, 한 줄만 고치면 한쪽은
옛 경로로 돕니다.

이제 경로를 따로 적습니다.

```
db.mysqldump   = C:\Program Files\MySQL\MySQL Server 8.0\bin\mysqldump.exe
db.dump.before = --login-path=old --databases mydb
db.dump.after  = --login-path=new --databases mydb
```

갈림길은 **하나**입니다.

| `db.mysqldump` | `db.dump.*` 는 |
|---|---|
| 적혀 있음 | **인수만** |
| 비어 있음 | **명령 줄 전체** (예전 방식 그대로) |

두 경우를 섞어 짐작하지 않습니다 — "`.exe` 로 끝나는 낱말이 있으면 실행
파일인가" 같은 규칙을 넣으면, 인수에 경로가 들어간 날 조용히 틀립니다.
**글만 보고 어느 쪽인지 알 수 있어야** 합니다.

경로에 따옴표를 붙여 적어도 됩니다 (`"C:\My Tools\mysqldump.exe"`). 공백이
든 경로를 그렇게 적는 습관이 있는데, 그걸 그대로 실행 파일 이름으로 넘기면
파일을 못 찾습니다.

`ibd2sdi` 는 처음부터 경로만 받았으니 그대로입니다.

검사 5 개를 더했습니다 (469 → 474) — 경로+인수, 따옴표 떼기, 경로 없을 때의
예전 방식, 인수가 없는 경우, 둘 다 빈 경우.

## 뒷이야기 — 하위 폴더까지 (0.54)

> 요청: "할때 경로안에있는 파일들 다 읽어줘(db) / 이게 폴더 안에 또 폴더들이
> 나뉘어있어서"

MySQL 데이터 폴더가 `Data\<DB 이름>\<표>.ibd` 꼴이라, DB 마다 폴더가
나뉩니다. 전에는 **준 폴더 바로 아래만** 봤으니 표가 하나도 안 잡혔을
것입니다.

### 폴더 이름을 표 이름에 붙입니다

```
recipe.csv            →  recipe
mydb\users.csv        →  mydb.users
other\users.csv       →  other.users
mydb\old\dump.sql     →  mydb.old.<덤프 안의 표 이름>
```

**이게 이번의 핵심입니다.** 표 이름은 DB 안에서만 다릅니다. 그냥 `users` 로
두면 `mydb` 와 `other` 가 서로를 덮어 **한쪽 DB 가 조용히 사라집니다.**
(전에 쓴 코드가 같은 이름이면 뒤의 것으로 바꿔치우게 돼 있었으니, 하위 폴더를
읽게만 하고 이름을 그냥 뒀다면 그 자리에서 값이 사라졌을 것입니다.)

양쪽 폴더 구조가 같으면 이름도 같게 나오므로 그대로 짝지어 견줍니다 —
검사에 그것도 넣었습니다.

### `Directory.GetFiles(..., AllDirectories)` 를 쓰지 않았습니다

한 줄로 끝나는 그 방법을 안 쓴 이유가 둘입니다.

1. 가는 길에 **못 읽는 폴더 하나가 있으면 전체가 예외로 끝납니다.** 데이터
   폴더에는 권한이 막힌 자리가 섞여 있습니다. 직접 훑으면 그 폴더만 건너뛰고
   나머지를 읽을 수 있습니다.
2. **바로 가기 고리를 걸러낼 자리가 없습니다.** 폴더 안의 바로 가기가 자기
   위를 가리키면 끝없이 돕니다.

그래서 직접 훑습니다. 바로 가기(ReparsePoint)에는 들어가지 않고, 겹 수
상한(8)과 파일 수 상한(5 만)을 마지막 방패로 둡니다. 건너뛴 폴더 수는
화면에 적습니다 — **조용히 덜 읽는 것이 제일 나쁩니다.**

### `.ibd` 쪽도 같은 걸음으로

`ibd2sdi` 로 모양을 읽는 쪽(`DbView.TakeIbd`)이 따로 `Directory.GetFiles` 를
쓰고 있었습니다. 그대로 두면 **한쪽은 하위 폴더를 보고 다른 쪽은 안 보는**
엇갈림이 생깁니다. 같은 `DbFolderReader.Files` 를 쓰게 고쳤습니다.

### 자체 테스트

**검사 16 개를 더했습니다 (474 → 490).** 뿌리 파일, 한 겹, 두 겹, 같은 이름의
표가 폴더마다 있을 때 **값이 섞이지 않는지**, 겹 수 상한, 파일 수 상한,
폴더 이름 붙이기 자체(뿌리/한 겹/두 겹/바깥 경로), 그리고 폴더 구조가 같은
