# 50. 이전 파랑 · 이후 빨강, 그리고 긴 이름 (0.60)

> 버전 있는 위치에 작은 글씨로 프로그램의 full name을 넣을 꺼야
> 해당 이름 config.txt에서 설정할 수 있게하고
>
> 그래프 색깔은 이전 파랑 이후 빨강으로하고 구분잘되게 나타내고
> 그래프 화면 한쪽에 빨간석은 이후 파란선은 이전 표시되게 해줘

## 긴 이름

```
LogScope  v0.60  Log 비교 · 분석 도구
  ↑짧은 이름  ↑판   ↑긴 이름 (config.txt 의 fullname)
```

`name` 과 **따로** 둔 이유가 있습니다. `name` 은 창 제목과 **실행 파일
이름**까지 따라가므로 짧고 파일 이름에 쓸 수 있는 글자여야 합니다. 긴 이름은
보여 주기만 하는 값이라 길어도 되고, 괄호나 가운뎃점이 들어가도 됩니다.

비워 두면 **그 줄 자체가 사라집니다.** 짧은 이름으로 대신 채우지 않습니다 —
같은 이름이 나란히 두 번 적히면 지저분합니다.

## 선 색

| | 전 | 지금 |
|---|---|---|
| 이전 | 파랑 `#1662C9` | 파랑 `#1662C9` (그대로) |
| 이후 | **주황** `#E0620D` | **빨강** `#D81F2A` |

어두운 테마는 `#5AA6FF` / `#FF6E6E` 입니다.

파랑·빨강은 색맹에게도 가장 안전한 짝이고, 흑백으로 뽑아도 밝기가 달라
구분됩니다. 주황은 파랑과 밝기가 비슷해서 흑백에서 겹쳐 보였습니다.

차이 영역의 그늘색도 이후 색을 따라가므로 같이 바뀝니다 — 그늘은 "이후가
이만큼 벗어났다" 는 표시라 이후 색인 쪽이 맞습니다.

## 범례를 왼쪽 칸에 둔 이유

그래프 **안에도** 범례를 그립니다 (0.47 에서 넣었습니다). 그런데 그림 위의
글은 두 가지 문제가 있습니다.

1. 선이 그 위를 지나가면 **글이 선에 가려집니다.**
2. 확대하거나 레인을 늘리면 **자리를 옮깁니다.** 찾아야 합니다.

그래서 왼쪽 IO 칸 아래에 **늘 같은 자리**에 하나 더 뒀습니다.

```
┌──────────────────────┐
│ ── 파란 선 = 이전    │
│ ── 빨간 선 = 이후    │
└──────────────────────┘
```

## 거짓말하는 범례는 없는 것보다 나쁩니다

여기가 이번 작업의 핵심입니다. **"파란 선 = 이전" 이 늘 참이 아닙니다.**

`[겹쳐]` 로 보면서 IO 를 여럿 고르면 **색이 IO 를 가리킵니다.** 그래야 어느
선이 어느 IO 인지 알 수 있습니다. 그때 같은 IO 의 이전/이후는 **같은 색의
옅고 짙음**으로 나뉩니다. 거기서 "파란 선은 이전" 이라고 적어 두면 **거짓**
입니다.

범례가 없으면 사람이 물어봅니다. 범례가 있으면 **믿습니다.** 그래서 틀린
범례가 없는 범례보다 나쁩니다.

그래서 그 경우에는 파랑·빨강 범례가 **사라지고**, 대신 왜 그런지와 어떻게
하면 파랑·빨강으로 볼 수 있는지가 적힙니다.

> 겹쳐 보기에서 IO 가 여럿이라 색이 IO 를 가리킵니다. 같은 IO 의 이전/이후는
> 같은 색의 옅고 짙음입니다. 파랑·빨강으로 보려면 [레인] 으로 보거나 IO 를
> 하나만 고르세요.

**겹쳐 보기라도 IO 가 하나면 파랑·빨강입니다.** 가릴 IO 가 없으니 그게 더 잘
보입니다. 전에는 IO 가 하나여도 색표의 첫 색과 그 짙은 색을 쓰고 있었는데,
이제 그 경우도 파랑·빨강으로 그립니다.

## 규칙을 한 줄로 모았습니다

이 판단을 **두 곳에서 각자** 하고 있었습니다.

```
선을 그리는 쪽 (GraphCanvas)   _laneMode ? BeforePen : SeriesPen(k)
범례를 적는 쪽 (GraphVm)       (새로 만들어야 함)
```

이대로 두면 조건을 한쪽만 고친 날부터 범례가 거짓이 됩니다. 그래서
`LogScope.Core/Render/TraceColors.cs` 한 줄로 모았습니다.

```csharp
public static bool ByIo(bool laneMode, int channelCount)
{
    return !laneMode && channelCount > 1;
}
```

화면이 없어도 돌아가는 규칙이라 **여기서 시험할 수 있습니다.** App 쪽은 이
컨테이너에서 눈으로 볼 수 없으니, 눈으로 볼 수 없는 것을 Core 로 내리는 것이
이 저장소에서 계속 해 온 일입니다.

## 뒷이야기 — 범례를 그래프 쪽에 하나만 (0.67)

> 파란선 빨간선 설명해주는걸 그래프 창에서 왼쪽 위에 두니까 왼쪽 창이 너무
> 작아진 느낌임 오른쪽 그래프 창에 띄워주셈

**그래프 그림 안에는 이미 범례가 있었습니다** (0.47 에 넣은 것, 오른쪽 위).
0.60 에서 왼쪽 IO 칸에 하나를 더 둔 것이 문제였습니다 — 같은 말이 두 군데에
적혀 있었고, 왼쪽 칸이 그만큼 좁아졌습니다.

**왼쪽 상자를 지웠습니다.** 그래프 쪽 하나만 남습니다.

0.60 에 왼쪽에 둔 이유는 "그림 위의 글은 선에 가려지고 확대하면 자리를
옮긴다" 였습니다. 다시 보니 두 걱정 모두 이 범례에는 맞지 않았습니다.

- **자리를 옮기지 않습니다.** 그림의 오른쪽 위에 그려지는데, 그 자리는 확대와
  상관없이 그림틀 기준입니다. 자리를 옮기는 것은 레인마다 따라다니는 글이고
  이건 그게 아닙니다.
- **가려지지 않습니다.** 뒤에 판을 88% 불투명으로 깔아 둡니다.

### 글을 분명하게 했습니다

전에는 `이전` / `이후` 였습니다. 옆에 선 조각이 있으니 알 수는 있지만,
요청하신 말 그대로 적는 쪽이 낫습니다.

```
전     ──  이전          지금  ──  파란 선 = 이전
       ──  이후                ──  빨간 선 = 이후
```

**색이 이전/이후를 가리킬 때만 색 이름을 적습니다.** 겹쳐 보기에서 IO 가
여럿이면 색이 IO 를 가리키므로 "파란 선 = 이전" 이 거짓이 됩니다. 그때는 색
이름을 떼고 `이전` / `이후` 로 돌아가고, "IO 마다 색이 짝을 이룹니다" 가
붙습니다.

옆의 **선 조각은 그 화면에서 실제로 쓰는 펜**입니다. 그래서 색이 어떻든 글과
선이 어긋날 수가 없습니다 — 0.60 에 Core 로 모은 규칙(`TraceColors`)을 선과
범례가 같이 보는 것이고, 이제 범례가 그리는 쪽 안에 있으니 어긋날 자리 자체가
없어졌습니다.

### 지운 것

왼쪽 상자만 쓰던 뷰모델 속성(`ColorByIo` · `ShowSideLegend` · `ColorNote`)과
그것들을 다시 읽게 하던 `RaiseLegend` 를 지웠습니다. `Core/Render/TraceColors`
는 그대로입니다 — 그리는 쪽이 그 규칙을 씁니다.

테스트 **626 통과 / 0 실패**, 검사 넷 다 통과.

**못 해 본 것**: 그림이 좁을 때 범례가 접히는 자리입니다. 그림 폭이 범례보다
좁으면 아예 안 그립니다 (글이 그림을 덮는 것보다 낫다고 봤습니다). 창을 좁혀
보시고 너무 쉽게 사라지면 알려 주세요.
