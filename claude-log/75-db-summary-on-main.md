# 75 — 분석 2 요약을 메인 화면 요약 칸에

> 1단계 시작할때로 맞춘게 맨 왼쪽 2단계 시작으로 맞춘 구간 2번 이런식으로
> 해서 그래프를 차이를 단계별로 쭉 비교할 수 있게
>
> 그리고 분석 2 요약이 메인화면에 나와여되는데 요약칸 있잖아 거기 나오게
> 해달라고

## 앞의 것은 0.93 에 올라가 있습니다

말씀하신 그 모양입니다 — 그래프 도구 줄의 **[나눠 보기]**.

```
[1. 준비 ][ 2. 가열          ][3. 유지 ][ 4. 냉각   ]
 1단계 시작    2단계 시작         3단계 시작  4단계 시작
 으로 맞춤     으로 맞춤          으로 맞춤   으로 맞춤
```

칸마다 그 단계의 밀기 값으로 이전·이후를 맞춥니다. [차이 영역 표시] 나
세로 눈금의 [차이] 를 켜면 **칸마다 그 단계의 차이**가 그려집니다.

단추가 잠겨 있으면 단계가 없는 것입니다 — 설정 [비교] 의 **단계 IO** 에
단계를 담은 IO 이름을 적고 로그를 다시 읽으면 켜집니다. 단추 옆에 그 말이
적혀 있습니다.

## 분석 2 요약을 메인 화면 요약 칸에

분석 1 칸에는 그룹별 수가 줄로 적히는 **요약** 칸이 있는데, 분석 2 칸의
그 자리는 비어 있었습니다 ("아직 만들지 않았습니다" 가 떠 있었습니다).

```
┌ 분석 2 ─────────────────────┐
│ WARNING                     │
│ 차이 발생 12개 — TEMP_MAX, … │
│                             │
│ 견줄 자리  …                 │
│                             │
│ 요약                        │
│ ● 차이 발생        12개      │
│ ● 없어진 IO         3개      │
│     판정에는 안 넣습니다.     │
│ ● 새로 생긴 IO      0개      │
│ ● 달라진 IO                 │
│     TEMP_MAX, PRES_SET, …   │
└─────────────────────────────┘
```

- 점 색은 분석 1 의 그룹 줄과 같은 뜻입니다 (초록·노랑·빨강).
- **줄을 누르면 분석 2 화면으로 넘어갑니다** — 그룹 줄과 같은 손놀림입니다.
- 없어진·새로 생긴 IO 줄에는 "판정에는 안 넣습니다" 가 붙습니다. 수만
  적어 두면 그게 판정에 들어간 줄 압니다.
- **FAIL 이면 이름을 안 적습니다.** `DbVerdict` 에서 한 번 가린 것을 여기서
  또 가르지 않으려고, 판정 낱말을 받아서 그대로 따릅니다 (1200 개 중 여덟
  개만 적으면 "이 여덟 개가 문제" 로 읽힙니다).
- 아직 안 읽었으면 그 자리에 **"아직 읽지 않았습니다. 위 칸에 견줄 자리를
  넣으면 그 자리에서 읽습니다."** 가 적힙니다. 빈 칸으로 두면 "봤는데
  아무것도 없다" 와 가릴 수 없습니다.

낱말 아래 한 줄(0.92 에 만든 판정 문장)과 겹치지 않습니다 — **거기는
"그래서 어떻다" 는 문장이고, 요약 칸은 수입니다.**

## 줄을 그룹 줄과 따로 둔 까닭

요약 칸에는 이미 그룹 줄(`GroupSummaryVm`)이 있었습니다. 거기에 DB 수를
억지로 끼울 수 있었지만, 그룹 줄은 **누르면 그 그룹의 IO 만 골라 그래프로
넘어가는 줄**입니다. DB 수를 같은 줄로 쓰면 "이 줄을 누르면 무엇이
되는지" 가 줄마다 달라집니다.

그래서 `CardLineVm` 을 따로 뒀습니다 (이름 · 수 · 점 색 · 아래 작은 글).
칸은 하나라서 둘 중 들어 있는 쪽이 보입니다.

## 덤으로 고친 것

분석 2 칸이 `Ready = false` 로 남아 있었습니다 (0.43 에 분석 2 를 만들었는데
그 깃발을 안 바꿨습니다). 그래서 요약 칸에 **"아직 만들지 않았습니다"** 가
떠 있었습니다.

## 아직 못 본 것

요약 줄의 자리와 점 색, 그리고 "달라진 IO" 줄의 이름이 칸을 넘지 않는지는
Windows 에서 봐야 합니다. 이름이 길면 줄이 접히므로 칸이 그만큼 길어집니다 —
넘치면 `DbVerdict.MaxNames`(8) 를 줄이면 됩니다.
