# 15 — 값이 심하게 바뀌는 IO 에서 그래프가 굼뜨던 것

> 요청: "그리고 그래프가 엄청 변화가 심한거 0.1초마다 1씩 바뀌는 io글
> 그래프로 그리면 렉이 너무 심한데?"

0.1 초마다 바뀌면 1 시간 로그가 36,000 표본, 10 시간이면 36 만 표본입니다.
그리는 쪽에 **표본 수에 딸린 비용**이 세 군데 있었고, 셋 다 "값이 자주
바뀔수록" 나빠지는 모양이었습니다.

---

## 1. (가장 큼) 차이 음영이 픽셀 열마다 도형을 하나씩 만들었습니다

```csharp
for (int x = 0; x < columns; x++)
{
    ...
    ctx.BeginFigure(new Point(px, t), true, true);   // ← 열마다 닫힌 도형
    ctx.LineTo(...); ctx.LineTo(...); ctx.LineTo(...);
}
```

값이 잔잔한 채널은 벌어지는 열이 몇 개 안 되니 티가 안 났습니다. 그런데
**거의 모든 열이 벌어져 있으면** 도형이 열 수만큼 생깁니다. 화면 폭 2000 px
에 화면 배율 150% 면 3000 개입니다. WPF 는 닫힌 도형마다 따로 삼각형으로
쪼개기 때문에, 이게 프레임마다 반복되면 눈에 띄게 굼떠집니다.

### 이어진 열을 한 덩어리로 묶었습니다

```
예전:  ▮▮▮▮▮▮▮▮▮▮▮▮   도형 3000 개 (1 px 짜리 사각형)
지금:  ▟▙▟▙▟▙▟▙▟▙▙▟   도형 1 개 (위 경계 →, 아래 경계 ←)
```

이어져 있는 열들을 모아 **폴리곤 하나**로 칠합니다. 위쪽 경계를 왼쪽에서
오른쪽으로 따라간 뒤, 아래쪽 경계를 오른쪽에서 왼쪽으로 되짚어 닫습니다.
점 개수는 비슷하지만 **도형 개수가 수천 개에서 몇 개로** 줄어듭니다.
칠해지는 모양은 그대로입니다.

---

## 2. 선을 그릴 때 점을 두 배로 찍고 있었습니다

접은 열 하나를 그릴 때 네 점을 찍었습니다.

```csharp
double px = ColumnToX(inner, x);
... (px, yFirst) (px, yTop) (px, yBottom) (px, yLast)
```

**x 가 전부 같습니다.** 한 열은 가로로 1 픽셀이니까요. 결국 최소~최대를
잇는 세로 선 하나인데, 같은 선 위에 점 네 개를 겹쳐 찍고 있었습니다.

값이 잔잔하면 `yTop == yFirst` 같은 조건에 걸려 점이 걸러졌는데, 위아래로
꽉 찬 채널은 네 점이 전부 살아남습니다. 그래서 **변화가 심할수록** 점이
정확히 두 배였습니다.

위끝과 아래끝 두 점만 찍습니다. 화면에 보이는 것은 똑같습니다. 다만 찍는
**차례**는 직전 열이 끝난 높이에 맞춰 가까운 쪽부터 — 그래야 열과 열 사이를
잇는 선이 쓸데없이 가로지르지 않습니다.

덕분에 `Column` 구조체에서 `First` / `Last` 를 뺐습니다. 그리는 데 안 쓰이는
값을 표본마다 채우고 있었습니다.

---

## 3. 표본마다 배열의 구조체를 읽고 고쳐 다시 썼습니다

접기의 안쪽 고리입니다. 여기가 **표본 수만큼** 도는 유일한 곳이라
36 만 표본이면 36 만 번 돕니다.

```csharp
private static void Put(Column[] cols, int c, float value)
{
    Column col = cols[c];      // ← 구조체 통째로 읽고
    ...
    cols[c] = col;             // ← 통째로 다시 씀
}
```

표본은 시간 순서라 **열 번호가 뒤로 가지 않습니다.** 그러니 지금 열의
최소/최대를 지역 변수에 모았다가, 열이 바뀔 때 한 번만 배열에 쓰면 됩니다.
읽고-쓰기가 표본 수만큼에서 열 수만큼(수천 번)으로 줄어듭니다.

---

## 4. 확인한 것

세 가지 모두 "보이는 그림은 그대로, 만드는 비용만 줄이기" 입니다.
그래도 경계 처리를 틀리기 쉬운 곳이라 테스트를 하나 넣었습니다.

`DecimationAccumulatesPerColumn`

- 값이 0 에서 999 까지 늘어나는 표본 1000 개를 10 열로 접었을 때
  열이 모두 차는지, 열마다 최소 ≤ 최대인지
- 값이 커지는 채널이라 **열끼리 값 범위가 겹치지 않는지**
  (열 경계를 한 칸 밀리면 바로 깨집니다)
- 전체 최소 0, 최대 999 — 마지막 표본이 빠지지 않는지
- 구간을 좁혀 잡아도 오른쪽 끝 너머의 한 점이 마지막 열에 들어가는지
  (선이 화면 오른쪽 끝까지 이어지려면 필요합니다)

기존 접기 테스트 두 개(꼭짓점이 살아남는지, 확대했을 때 선이 남는지)도
그대로 둡니다.
