# 36 — IO 별 허용 오차 (퍼센트 · 값 둘 다)

> 요청: "그리고 정상 오차 판정 값 설정할 때 IO별로 설정할 수 있게하고
> 퍼센트/ Value값 둘다 가능하게"

## 왜 필요한가

허용 오차가 **기본값 하나**였습니다. 어느 IO 든 같은 잣대였습니다.

그런데 온도처럼 원래 조금씩 흔들리는 값과, 밸브 열림처럼 조금도 달라지면
안 되는 값이 한 로그 안에 같이 있습니다. 같은 잣대를 대면

- 느슨하게 잡으면 → 밸브가 달라진 것을 **놓칩니다**
- 빡빡하게 잡으면 → 온도가 **늘 빨갛습니다**

어느 쪽으로 맞춰도 한쪽이 못 쓰게 됩니다.

## 어디서 설정하나

**[설정] → [비교] 탭 → IO 별 허용 오차**

```
IO 이름                퍼센트 (%)    값 (절대)     
흔들리는 온도 TT-01    20                        [지우기]
밸브 OPEN                            0           [지우기]
압력 PT-01             5             0.1         [지우기]
                                                 [IO 추가]
```

- 로그를 열어 두면 IO 이름을 **목록에서 고릅니다.** 안 열었으면 손으로 적어
  미리 걸어 둘 수도 있습니다 (`IsEditable="True"`).
- 줄이 늘어도 칸이 늘어나지 않게 그 안에서 굴립니다 (`MaxHeight="190"`).

## 정한 것들

### 1. 빈 칸 = 기본값. 0 과 다릅니다.

`Percent` 와 `Absolute` 는 **NaN 이면 "안 정함"** 입니다.

0 으로 두면 안 되는 이유가 분명합니다.

| 값 | 뜻 |
|---|---|
| 절대값 **0** | 절대 오차를 **끈다** (퍼센트만 본다) |
| 퍼센트 **0** | **조금이라도** 벌어지면 차이 |
| 빈 칸 | 그 자리는 **기본값** |

셋 다 실제로 쓰는 상태라 "안 정함" 을 0 으로 적을 수가 없습니다. 화면에서는
빈 칸으로 보이고, 설정 파일에는 **그 열쇠를 아예 안 적습니다** (JSON 에
NaN 을 담을 수 없기도 하고, 없는 것이 곧 기본값입니다).

### 2. 이름은 느슨하게 맞춥니다

```csharp
string key = LogDataset.LooseKey(r.Io);   // 공백과 _ - . 를 떼고 대문자로
```

두 로그에서 같은 IO 가 `밸브_OPEN` 과 `밸브 OPEN` 으로 적히는 일이 흔합니다.
비교 자체가 이미 그 규칙으로 짝을 짓고 있어서, **여기만 엄격히 보면 설정한
값이 조용히 안 먹습니다.** 안 먹는 설정이 제일 나쁩니다 — 걸어 뒀다고 믿게
됩니다.

### 3. 세 화면이 같은 표를 씁니다

대시보드(`DiffEngine`) · 그래프 · 히트맵(`HeatmapBuilder`) 이 모두
`ToleranceTable` 하나를 받습니다. 각자 계산하면 같은 로그인데 화면마다
"차이 난 IO" 가 달라집니다. 테스트에서 **두 엔진이 같은 답을 내는지** 함께
봅니다.

표본마다 표를 뒤지지 않게, **채널 하나당 한 번만** 풀어 둡니다.

```csharp
double limitAbs = opt.AbsoluteTolerance, limitPct = opt.RelativePercent;
if (opt.Tolerances != null)
{
    limitAbs = opt.Tolerances.AbsoluteFor(bc.Name);
    limitPct = opt.Tolerances.PercentFor(bc.Name);
}
```

1000 만 칸짜리 로그에서 표본마다 사전을 뒤지면 그대로 느려집니다.

### 4. 저장해 둔 분석과의 "같은 기준"

저장된 분석 목록은 지금 결과와의 **차이**를 보여 주는데, 기준이 다르면 그
뺄셈이 뜻이 없어서 아예 빼지 않습니다. 여기에 **IO 별 규칙도 들어갑니다.**

```csharp
rec.ToleranceRules = table.Signature();   // "열쇠=퍼센트/절대값;..." 을 열쇠 순으로
```

줄 순서만 다른 같은 규칙은 **같은 서명**이 나와야 해서 정렬해서 적습니다.
기본값만 같다고 "같은 기준" 이라고 하면 거짓말이 됩니다.

옛 기록에는 이 값이 없습니다. 없으면 "규칙이 없었다" 로 봅니다 — 그때는
정말 없었습니다.

### 5. 봐준 IO 도 오차 퍼센트는 그대로

10 → 11 은 20% 를 걸어 뒀어도 **화면에는 10% 로 적힙니다.** 잣대를 바꾼
것이지 값이 바뀐 것이 아닙니다. "10% 인데 차이 아님" 이 이상해 보이지만,
여기서 퍼센트까지 깎으면 **왜 안 걸렸는지 알 수 없게** 됩니다.

### 6. 쓸모없는 줄은 닫을 때 버립니다

이름을 안 고르고 [IO 추가] 만 누른 줄, 두 칸을 다 비운 줄은 창을 닫을 때
버립니다(`PruneTolerances`). 남겨 두면 다음에 열었을 때 왜 있는지 알 수 없는
빈 줄이 됩니다. 설정 파일에도 안 적힙니다.

## 자체 테스트

**테스트 34 개를 더했습니다 (352 → 386).**

- 표: 퍼센트만/절대값만 건 IO, 안 건 IO, 느슨한 이름 맞추기, 같은 IO 가 두 번,
  쓸모없는 줄, `null` 목록, 서명의 순서 무관성
- 실제 비교: 같은 크기로 벌어진 두 IO 중 **하나만** 빠지는지,
  **히트맵도 같은 답**인지, 절대값으로도 되는지, 봐준 IO 의 퍼센트는 그대로인지
- 설정 파일: 담았다 꺼내도 그대로인지, **안 정한 자리가 0 으로 떨어지지
  않는지**, 쓸모없는 줄이 저장되지 않는지
- 기준 비교: 규칙이 다르면 "다른 기준" 으로 보는지
