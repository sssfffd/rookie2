## 2. "달라짐" 개수의 근거 (질문 — 코드 안 바꿈)
| 메인 분석 1 칸의 자리 | 근거 |
|---|---|
| 낱말 옆 "차이 발생 N 개" | 1.56 판정의 **허용 안 된 오차 항목 수** (JudgeResult.OpenCount). IO 수가 아님 — IO 하나에 오차 구간이 여럿이면 여럿, 단계 길이 · IO 없어짐도 하나씩 |
| 그룹 줄 "3 / 10 달라짐" | **예전 비교 (DiffEngine)** — 시간 맞춘 뒤 같은 시각끼리, 최대 2 만 점으로 줄여서, 한 점이라도 값 허용 오차를 넘으면 그 IO 는 달라짐. 시간 여유 · 허용 없음 |
| 대시보드 "차이 발생 IO 개수" · 목록 | 그룹 줄과 같은 예전 비교 |

→ 판정(PASS)인데 그룹 줄은 "달라짐" 이 있을 수 있음 (0.3 초 늦은 IO), 거꾸로 0.1 초 아킹은 2 만 점으로 줄일 때 건너뛸 수 있음.
제안: 그룹 줄(과 대시보드)도 판정 기준으로 — "허용 안 된 값 오차가 있는 IO = 달라짐". 사용자에게 물음.
