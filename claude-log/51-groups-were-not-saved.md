# 51. 그룹이 바로 저장되지 않던 것 (0.61)

> 내가 그룹변경한거 어디에 저장됨?

## 답 — 그리고 답하다가 찾은 고장

**`LogScope.settings.json` 의 `groups`** 입니다. 실행 파일 옆이고, 거기에
못 쓰면 `%APPDATA%\LogScope\settings.json` 입니다.

```json
"groups": [
  { "name": "가열부", "members": ["TEMP_1", "TEMP_2"], "expanded": true },
  { "name": "압력",   "members": ["PRS_MAIN"],          "expanded": false }
]
```

그런데 **언제** 적히는지를 확인하다가 고장을 찾았습니다.

## 아무도 듣지 않는 이벤트

그룹을 고치면 `ChannelListVm` 이 `GroupsChanged` 를 올립니다. 그걸 받아
설정을 저장하면 되는데 — **받는 쪽이 없었습니다.**

```
그룹 고치기 → GroupsChanged 올림 → ...아무도 없음
```

컴파일도 되고 검사도 통과합니다. 이벤트를 올리는 쪽은 할 일을 다 했고,
`+=` 한 줄이 없을 뿐입니다.

그래서 그룹은 **다른 일에 얹혀서** 저장되고 있었습니다.

| 저장되는 때 | |
|---|---|
| 로그를 열거나 끌어다 놓을 때 | 우연 |
| 시간 맞추기를 바꿀 때 | 우연 |
| 설정 창에서 적용할 때 | 우연 |
| **창을 닫을 때** | 이게 사실상 전부 |

창을 제대로 닫으면 남습니다. 그래서 눈에 잘 안 띕니다. **작업 관리자로 끄거나
전원이 나가거나 프로그램이 죽으면** 그때까지 묶어 둔 것이 전부 사라집니다.
그룹 나누기는 IO 를 수십 개 손으로 넣는 일이라, 이 저장소에서 잃어서 가장
아까운 값입니다.

## 고친 것

`GroupsChanged` 를 듣고 그 자리에서 저장합니다. 만들기 · 이름 바꾸기 ·
차례 바꾸기 · 지우기 · IO 넣고 빼기 · 끌어다 놓기 · 펼치고 접기 — 전부
이 하나로 덮입니다 (고치는 함수마다 이미 이 이벤트를 올리고 있었습니다).

저장은 **임시 파일에 쓰고 바꿔치는** 방식이라, 저장하는 중에 죽어도 반쪽짜리
설정이 남지 않습니다. 그래서 자주 저장해도 안전합니다.

펼치고 접는 것도 저장합니다. 한 번 누를 때마다 파일을 쓰는 셈이지만, 작은
JSON 이고 "접어 둔 채로 다시 켜진다" 는 쪽이 맞습니다.

## 검사를 하나 더 만들었습니다

이 고장의 모양이 특이합니다 — **잘못 쓴 코드가 없습니다.** 있어야 할 한 줄이
없는 것이고, 그래서 어떤 컴파일러도 어떤 검사도 울지 않았습니다.

그래서 `check_handlers.py` 에 규칙을 더했습니다. **선언한 이벤트마다 어딘가에서
`+=` 로 붙는지** 봅니다 (XAML 의 `CloseRequested="OnX"` 도 듣는 것으로 셉니다).

만들면서 두 번 걸렸습니다.

1. **`PropertyChanged` 가 걸렸습니다.** WPF 가 바인딩에서 대신 듣는 것이라
   우리 코드에 `+=` 가 없습니다. 런타임이 듣는 것들(`PropertyChanged` ·
   `CollectionChanged` · `ErrorsChanged`)은 뺐습니다.
2. **구독을 주석으로 막아 놓고도 검사가 통과했습니다.** 주석에 적힌 `+=` 를
   듣는 것으로 센 것입니다. 줄 주석을 떼고 보게 고쳤습니다. 검사를 만들 때는
   **일부러 어긋나게 해서 우는 것까지 봐야** 한다는 걸 또 확인했습니다 —
   이번에는 그 확인에서 검사 자체의 버그가 나왔습니다.

  다 통과.
- 테스트 **591 통과 / 0 실패**.

**못 해 본 것**: 실제로 그룹을 고쳐 파일이 바로 바뀌는지는 윈도우에서 봐
주세요. 그룹을 하나 만들고 **창을 닫지 않은 채** `out\LogScope.settings.json`
을 메모장으로 열어 `groups` 에 그 이름이 있으면 된 것입니다.
