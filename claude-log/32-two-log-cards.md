# 32 — 열어 둔 로그를 좌우 두 칸으로, 큰 안내 판은 없앰

> 요청: "이거 위에 이전 이후 로그 칸 하나로 되어있는거 좌우 2개로 나누고 각
> 칸으로 파일 드래그하면 넣어지게끔 바꿔줘 지금은 드래그했을 때 뜨는게
> 너무크네"

앞 글([31](31-drop-zones.md))에서 만든 **화면 전체를 덮는 안내 판은
없앴습니다.** 파일을 하나 끌어다 놓는 일에 화면을 다 덮는 것은 과했습니다.
대신 원래 자리를 과녁으로 쓸 만하게 키웠습니다.

## 전

```
┌──────────────────────────────────────────────────────────────┐
│ 열어 둔 로그                                                 │
│ ● 이전  발생시간 2026-03-14  before.xlsx  IO 184 · 표본 52,310│  ← 높이 20 px
│ ● 이후  발생시간 2026-03-21  after.xlsx   IO 187 · 표본 49,882│  ← 높이 20 px
└──────────────────────────────────────────────────────────────┘
```

한 칸 안에 글자 두 줄. 놓을 자리가 **높이 20 픽셀짜리 줄**이라 겨냥할 수가
없었습니다. 그래서 31 에서 화면을 덮는 판을 만들었고, 그게 너무 컸습니다.

## 후

```
열어 둔 로그    (칸에 Log 파일을 끌어다 놓으면 열립니다)
┌───────────────────────────┐ ┌───────────────────────────┐
│ ● 이전 (기준)             │ │ ● 이후 (견줄 것)          │
│ 발생시간  2026-03-14      │ │ 발생시간  2026-03-21      │
│ 2026-03-14_before.xlsx    │ │ 2026-03-21_after.xlsx     │
│ IO 184  ·  표본 52,310    │ │ IO 187  ·  표본 49,882    │
└───────────────────────────┘ └───────────────────────────┘
2026-09-29 14:02 에 비교한 결과입니다
```

- **왼쪽이 이전, 오른쪽이 이후.** 칸 전체가 놓을 자리입니다.
- 칸 위에 커서를 올리면 **그 칸이 밝아지고 테두리가 그 쪽 색으로** 바뀝니다
  (이전은 파랑, 이후는 주황 — 그래프 곡선과 같은 색).
- 비어 있으면 그 자리에 `이전 로그를 열어 주세요` 가 그대로 남아 있어,
  어느 칸이 비었는지 한눈에 보입니다.
- 전체 경로는 칸에 마우스를 올리면 나옵니다.

**놓는 순간 그 칸으로 들어갑니다 — 묻지 않습니다.** 어느 쪽인지 이미 고른
것이니까요.

다른 화면(분석 1·2·3)에서 놓으면 예전 규칙대로입니다: 두 개면 이름 순으로
이전/이후, 한 개면 비어 있는 자리로, 둘 다 차 있으면 어느 쪽인지 묻습니다.

## 밝힌 것을 되돌릴 때

색을 직접 써 놓고 그대로 두면, 테마를 바꿨을 때 **그 칸만 옛 색으로**
남습니다. 그래서 되돌릴 때는 값을 지웁니다.

```csharp
card.ClearValue(Border.BackgroundProperty);
card.ClearValue(Border.BorderBrushProperty);
card.ClearValue(Border.BorderThicknessProperty);
```

지우면 XAML 에 적어 둔 `DynamicResource` 가 다시 살아나서, 테마를 따라갑니다.

## 치운 것

- `ShellWindow.xaml` 의 `DropOverlay` 와 그 반쪽 둘
- 그에 딸린 처리기 여섯 개 (`OnFileDragEnter`, `OnFileDragLeave`,
  `OnWindowMouseMove`, `OnZoneDragOver`, `OnZoneDragLeave`, `OnZoneDrop`)
  와 도우미 넷 (`ShowDropOverlay`, `HideDropOverlay`, `SlotNote`, `Lit`)
- 테마의 `Brush.DropBack` / `Brush.DropZone` / `Brush.DropZoneHot`
  (쓰는 곳이 없어졌습니다. 칸을 밝히는 데는 이미 있던 `Brush.DropTarget`)

창 전체의 `DragOver` / `Drop` 은 남겨 뒀습니다 — 다른 화면에서도 놓을 수
있어야 하니까요.

## 자체 테스트

테스트 328 통과(그대로). WPF 흉내 파일에 `ClearValue` 와 `Border` 의
의존 속성 셋을 더했습니다 — 진짜 WPF 에 있는 API 인데 아직 안 써서
빠져 있었습니다.

XAML 15 개가 XML 로 읽히는지, 테마 열쇠가 Light/Dark 에서 같은지,
`x:Name` 이 진짜 WPF 타입으로 붙는지, 처리기 시그니처가 맞는지까지
확인했습니다.

### 아직 확인 못 한 것

칸 크기와 칸 안 글자 줄바꿈은 **윈도우에서 봐야** 합니다. 특히 파일 이름이
아주 긴 경우 칸이 세로로 늘어나는지, 두 칸의 높이가 서로 달라지지 않는지
(`Grid` 의 두 열은 높이를 맞춰 주지 않습니다).
