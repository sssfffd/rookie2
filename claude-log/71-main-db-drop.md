# 71 — 메인 화면에서 분석 2 의 자리도 넣기

> 그리고 분석1처럼 2도 메인화면에서 로그 넣을 수 있게 해줘

분석 1 칸 안에 이전/이후 로그 칸이 있는 것과 같은 모양으로, **분석 2 칸 안에
견줄 자리 두 칸**을 넣었습니다. 폴더도 파일도 됩니다.

```
┌ 분석 2 ─────────────────────┐
│ PASS                        │
│ 차이 발생 0개 · …            │
│                             │
│ 견줄 자리  (끌어다 놓기 · 둘 다 차면 바로 읽습니다)
│ ┌─ ● 이전 ──┐ ┌─ ● 이후 ──┐ │
│ │ before    │ │ after     │ │
│ │ 폴더      │ │ 폴더      │ │
│ └───────────┘ └───────────┘ │
└─────────────────────────────┘
```

## 놓으면 바로 읽습니다

자리가 **둘 다 차면 그 자리에서 읽고 견줍니다.** 분석 2 화면의 [DB 읽기] 를
누르지 않아도 됩니다.

분석 1 이 그렇게 동작하기 때문입니다 — 메인 화면에 로그를 놓으면 묻지 않고
읽고 견줘서 칸의 점수가 바뀝니다. DB 만 "이제 분석 2 로 가서 [DB 읽기] 를
누르세요" 가 되면, **놓고 나서 칸이 그대로인 까닭을 알 수가 없습니다.** 바로
위에 `PASS`·`FAIL` 이 뜨는 칸이라 더 그렇습니다.

오래 걸리는 동안은 진행 창이 뜨고 거기서 멈출 수 있습니다 (로그를 읽을 때와
같은 창입니다). 한쪽만 놓으면 읽지 않고 자리만 적힙니다.

## 자리를 적는 곳은 여전히 한 곳

메인 화면 칸은 **보여 주기만** 합니다. 놓은 것은 분석 2 화면(`DbView`)으로
그대로 넘어가고, 자리를 적고 저장을 알리고 읽는 일은 거기서 합니다.

```
MainView (칸에 놓음)  →  DbDropped 알림
ShellWindow           →  Db.TakePaths(…)
DbView                →  DbVm.SetPath (저장 알림) → 둘 다 찼으면 Read()
DbVm.Take             →  ResultChanged → ShellWindow → 메인 칸의 판정
```

메인 화면에서 설정을 직접 고치면 **자리를 적는 곳이 둘**이 됩니다. 그러면
한쪽만 알림을 내보내는 날이 오고, 화면에는 들어갔는데 저장은 안 되는 일이
생깁니다 (0.77 에서 겪은 것과 같은 모양입니다 — 그때는 화면과 config.txt 가
각자 자리를 들고 있었습니다).

메인 화면이 보여 주는 글도 **설정에서 그때그때 읽습니다.** 메인용으로 베껴
두면 분석 2 화면에서 자리를 고친 날 두 화면에 다른 자리가 적힙니다.

## 같은 글을 두 곳에 적지 않기

칸 아래 한 줄("폴더" · "파일" · "이 자리에 아무것도 없습니다")은 분석 2
화면에도 있는 글입니다. 각자 적어 두면 한쪽만 고치는 날이 오고, **같은 자리를
보는데 두 화면에 다른 말이 적힙니다** — 그 둘 중 어느 쪽이 참인지는 화면만
봐서는 알 수 없습니다.

그래서 `src/LogScope.Db/DbPathText.cs` 한 곳으로 모았습니다. `DbVm.Note` 는
이제 거기로 넘깁니다. WPF 를 쓰지 않는 자리에 둔 것은 `DbVerdict` 와 같은
까닭입니다 — **시험이 닿습니다.**

## `Path.GetFileName` 을 쓰지 않은 까닭

칸이 좁아 전체 경로는 안 들어가므로 마지막 조각만 보여 줍니다. 그런데 저
함수는 **돌고 있는 운영체제의 구분 기호만** 봅니다. 제 시험은 리눅스에서
도는데 거기서는 `\` 가 구분 기호가 아니라, `C:\db\io` 가 통째로 "이름" 이
됩니다 — 칸에 전체 경로가 박혀 들어가고, 그건 **Windows 에서 열어 봐야만**
드러납니다. 두 기호를 다 보고 직접 끊습니다.

시험 일곱: 파일 · 폴더 · 끝에 붙은 구분 기호 · 빗금 경로 · 조각 하나 ·
드라이브만(`C:\` → `C:`) · 빈 글. 빈 칸을 보여 주면 "안 넣었다" 로 읽혀서
뿌리만 적어도 무엇이든 남깁니다.

## 이름을 고친 자리

로그 칸과 DB 칸이 밝아지는 모양이 똑같아서 처리기를 한 짝으로 씁니다.

| 전 | 후 |
|---|---|
| `OnLogRowDragOver` · `OnLogRowDragLeave` | `OnDropCardDragOver` · `OnDropCardDragLeave` |
| `OnLogRowDrop` | `OnLogDrop` · `OnDbDrop` (받는 쪽이 달라 둘) |
| `MainView.LogDropEventArgs` | `MainView.FileDropEventArgs` |

`통과 700 / 실패 0`.

## 아직 못 본 것

칸이 하나 늘어 **분석 2 칸이 길어졌습니다.** 세 칸의 높이는 UniformGrid 가
맞추므로 메인 화면에 스크롤이 생길 수 있습니다 (0.65 에서 MinHeight 를 390
으로 줄인 까닭이 그것입니다). 끌어다 놓기가 실제로 먹는지, 칸이 밝아지는지,
놓자마자 판정이 바뀌는지도 **Windows 에서만 확인됩니다.**
