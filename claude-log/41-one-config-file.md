# 41 — 손으로 고치는 설정을 config.txt 한 파일로

> 요청: "이거Appname이나 screen.txt로 여러개 text파일에서 변경하잖아 근데
> config txt파일 하나로 통합해서 해당파일에서 변경 가능하게"

## 전 / 후

```
전:  appname.txt   프로그램 이름 한 줄          (빌드할 때 읽음)
     screens.txt   분석 이름 세 줄              (실행할 때 읽음)
     version.txt   버전                         (빌드할 때 읽음)

후:  config.txt    프로그램 이름 + 분석 이름     (실행할 때 읽음)
     version.txt   버전                         (빌드할 때 읽음)
```

고칠 것이 늘어날 때마다 파일이 하나씩 생기면 **무엇을 어디서 바꾸는지
기억해야 합니다.** 게다가 둘은 읽는 시점도 달랐습니다 — 하나는 빌드할 때,
하나는 실행할 때. "왜 이건 다시 빌드해야 하고 저건 안 해도 되나" 를 설명해야
했습니다.

## config.txt

```
# name      창 제목과 왼쪽 위에 적히는 이름.
# analysis1 분석 화면의 이름. "이름 | 한 줄 설명" 으로 적습니다.

name = LogScope

analysis1 = 로그 비교 | 이전 Log 파일과 이후 Log 파일을 비교합니다.
analysis2 = 분석 2 | 아직 정해지지 않았습니다.
analysis3 = 분석 3 | 아직 정해지지 않았습니다.
```

규칙 셋:

1. `열쇠 = 값`. 열쇠는 **대소문자를 가리지 않습니다.**
2. 분석 이름의 **세로줄(`|`) 뒤는 설명.**
3. **없는 줄은 기본값.** 파일을 지워도 그대로 돕니다.

`열쇠 = 값` 꼴로 간 이유는 **늘릴 수 있기 때문**입니다. 전의 screens.txt 는
"줄 순서가 곧 분석 번호" 였는데, 거기에 프로그램 이름을 끼우면 순서가
무너집니다. 열쇠가 있으면 줄 순서가 상관없고, 나중에 무엇을 더해도 아래에
한 줄 붙이면 됩니다.

**모르는 열쇠는 건너뜁니다.** 뒤 버전에서 생긴 열쇠가 적힌 파일로 옛
프로그램을 켜도 터지지 않아야 합니다.

## 옛 파일을 버리지 않습니다

`config.txt` 가 없고 **`appname.txt` / `screens.txt` 가 옆에 있으면 그 둘을
읽습니다.** 거기 적어 둔 것을 파일 이름이 바뀌었다는 이유로 잃으면 안 됩니다.
`config.txt` 가 있으면 그쪽이 이깁니다 — 둘 다 있을 때 어느 것이 이기는지
헷갈리면 안 되니 한쪽으로 정했습니다.

## 실행 파일 이름만 조금 다릅니다

`name` 을 바꾸면 `out\<이름>.exe` 가 됩니다. 다만 **다시 빌드해야** 바뀝니다.
빌드 자체는 늘 `LogScope.exe` 를 만들고, `build.bat` 이 `out` 으로 복사할 때
이름을 붙입니다.

0.37 에서는 MSBuild 가 `appname.txt` 를 직접 읽어 `AssemblyName` 에 넣었습니다
(`tools/AppName.props`). `config.txt` 로 옮기면서 그 방식을 버렸습니다.

| | MSBuild 가 읽기 | 복사할 때 이름 붙이기 |
|---|---|---|
| 한 줄이 잘못됐을 때 | **빌드 전체가 멈춥니다** | 이름만 틀린 exe 가 나옵니다 |
| 필요한 것 | 줄을 갈라 읽는 property function | `for /f` 한 줄 |
| 확인 | 이 컨테이너에 MSBuild 가 없어 **못 해 봄** | 같음 |

`name = ` 한 줄을 읽자고 빌드가 멈출 위험을 지는 것은 맞지 않습니다.
`AssemblyName` 은 `LogScope` 로 고정하고, `AppName.props` 를 지웠습니다.

파일 속성 창에 보이는 이름(`AssemblyInfo.cs`)도 `LogScope` 로 고정입니다 —
어트리뷰트 인자는 컴파일할 때 값이 박혀야 해서 실행할 때 읽는 값을 쓸 수
없습니다. `BuildInfo.Product` 도 같이 없앴습니다 (이제 화면에 쓰이는 이름은
`AppConfig.Current.Name` 하나입니다).

### version.txt 는 남겨 뒀습니다

버전은 **빌드할 때 박혀야 하는 값**입니다. 오류 창에 적히는 "버전 0.49
(커밋 해시)" 는 그 exe 가 어느 소스로 만들어졌는지를 말하는 것이라, 실행할
때 읽는 파일에서 오면 거짓말이 될 수 있습니다 — 파일만 고쳐도 버전이
바뀌어 버립니다. 성격이 다른 값이라 같은 파일에 넣지 않았습니다.

## build.bat 의 `:kv`

```bat
for /f "usebackq eol=# tokens=1,* delims==" %%K in ("%ROOT%config.txt") do (
  call :kv "%%K" "%%L"
)
```

- `eol=#` : 주석 줄을 건너뜁니다.
- `tokens=1,* delims==` : **첫 `=` 에서만** 자릅니다. 값에 `=` 가 들어 있어도
  됩니다.
- `:kv` 가 열쇠와 값의 앞 공백을 떼고, `name` 일 때만 `APPNAME` 을 바꿉니다.

## 자체 테스트

**테스트 6 개를 더했습니다 (393 → 399).** `ScreenNames` 검사를 `AppConfig` 로
옮기면서 늘렸습니다 —

- `열쇠 = 값` 읽기, **열쇠 대소문자 무시**, 앞뒤 공백 떼기
- 모르는 열쇠 / 열쇠 없는 줄 / 값이 빈 줄은 건너뛰는지
- 이름 자리를 비운 분석 줄은 기본 이름을 쓰고 설명만 바뀌는지
- 빈 파일, `null`, 범위 밖 번호
- 인코딩 (BOM UTF-8 / BOM 없는 UTF-8 / CP949)
- **옛 파일 두 개를 읽는지**, 그리고 `config.txt` 가 있으면 그쪽이 이기는지
- 본보기 글(`Sample()`)이 기본값과 같은지

### 아직 확인 못 한 것

- `build.bat` 의 `for /f` 한 줄은 **윈도우 cmd 에서 돌려 봐야** 압니다.
  특히 한글이 든 `name` 값과, 값 안에 `=` 가 있을 때.
- `out\LogScope.exe` 에서 `out\<이름>.exe` 로 바뀌므로, 바로 가기를 만들어
  두셨다면 다시 만들어야 합니다.
