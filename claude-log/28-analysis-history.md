# 28 — 분석 결과 저장, 그리고 지난번과 견주기

> 요청: "메인 화면에 분석 결과 저장 시스템도 만들어줘
> 그래서 새로 분석했을 때 이전결과랑 비교할 수 있게"

---

## 1. 무엇을 남기나 — 로그가 아니라 **몇 개의 수**

가장 먼저 정한 것이 이겁니다.

로그 값을 통째로 남기면 파일이 **원본만큼 커집니다.** 표본이 수백만 개인데
그걸 그대로 복사해 두면, "지난번과 견줘 보기" 가 사실상 로그를 한 번 더 여는
일이 됩니다. 그런데 정작 견줄 때 쓰는 것은 **몇 개의 수**뿐입니다.

그래서 요약만 남깁니다.

| 남기는 것 | 왜 |
|---|---|
| 저장 시각 · 이름 | 어느 것인지 |
| 이전/이후 파일 **이름 전체**와 **경로**, 발생시간 | 무엇을 견줬는지 |
| 점수 **셋** (분석 1·2·3) | 결과 |
| 견준 IO · 달라진 IO · 한쪽에만 | 결과 |
| 허용 오차 · 절대 오차 · 시간 맞추기 · 가로축 · 밀기 값 | **어떤 기준으로 나온 수인지** |

마지막 줄이 중요합니다. 허용 오차를 0.1% 에서 1% 로 바꿔 놓고 "달라진 IO 가
줄었다" 고 읽으면 안 되기 때문입니다. 이건 4 장에서 다시 다룹니다.

**파일 이름은 앞 10 글자가 아니라 전체**입니다. 발생시간만 남기면 같은 날
두 번 딴 로그를 나중에 가릴 수가 없습니다. 경로도 따로 두는데, 폴더를 옮겨
놓고 "이게 그때 그 파일이 맞나" 를 볼 때 이름만으로는 알 수 없기 때문입니다.

**점수는 셋 다** 남깁니다. 하나만 남기면 나중에 분석 2·3 이 생겼을 때 그때
기록에는 그 점수가 없어서, 견줄 수 있는 것과 없는 것이 섞입니다. 아직 없는
분석은 `??` 로 둡니다 — 0 점으로 적으면 "다 틀렸다" 는 뜻이 됩니다.

> 점수가 하나뿐이던 시절에 저장한 파일도 그대로 읽힙니다. 그때 점수는
> 분석 1 것으로 봅니다.

---

## 2. 어디에 어떻게 쌓이나

설정 파일 옆의 `history` 폴더입니다. 설정이 실행 파일 옆에 있으면 거기,
`%APPDATA%` 로 밀려났으면 거기 — 설정이 가는 곳을 그대로 따라갑니다.
USB 에 담아 들고 다녀도 기록이 같이 갑니다.

```
LogScope.settings.json
history/
  20260314-093000-000.json
  20260321-170500-000.json
```

**기록 하나에 파일 하나**입니다. 한 파일에 몰아 담으면

- 저장하다 죽었을 때 지난 기록까지 통째로 날아가고,
- 한 건 지우는 데 파일 전체를 다시 써야 합니다.

나눠 두면 하나가 깨져도 나머지는 그대로 읽힙니다. 실제로 읽는 쪽은 깨진
파일을 만나면 **그것만 건너뜁니다** — 하나 때문에 나머지를 못 보면 안 됩니다.

파일 이름은 저장 시각입니다. 이름만 봐도 차례가 서고, 밀리초까지 있어서
같은 초에 두 번 눌러도 안 겹칩니다. 그래도 겹치면 1 밀리초씩 밀어 빈자리를
찾습니다 — 조용히 덮어쓰면 한 건이 사라집니다.

쓸 때는 설정 저장과 같습니다. 임시 파일에 먼저 쓰고 바꿔치기해서, 쓰는 중에
죽어도 반쪽짜리 파일이 남지 않습니다.

## 3. 화면

```
┌──────────────────────────────────────────────────────────────────────────┐
│ 저장된 분석                                        [ 지금 결과 저장 ]     │
│ 각 줄의 오른쪽이 지금 결과와의 차이입니다.                                │
│ ─────────────────────────────────────────────────────────────────────── │
│ 3월 정기점검                    100 / ?? / ??   달라진 IO +8개  [삭제]   │
│ 2026-03-14_before.xlsx → 2026-03-21_after.xlsx                           │
│ 허용 오차 0.1% / 절대 0.25  시간 맞추기 "START"                          │
│ ─────────────────────────────────────────────────────────────────────── │ ▲
│ 2026-02-02 11:20:41             100 / ?? / ??   기준 다름       [삭제]   │ │
│ 2026-02-01_a.xlsx → 2026-02-02_b.xlsx                                    │ ▼
└──────────────────────────────────────────────────────────────────────────┘
```

**세 줄까지만 보이고 그 다음부터는 이 칸 안에서 굴립니다.** 기록이 쌓일수록
메인 화면이 끝없이 길어지면 아래 요약 칸이 화면 밖으로 밀려납니다. 네 번째
줄이 살짝 보이게 높이를 잡아, "더 있다" 는 것이 눈에 띄도록 했습니다.

점수는 `분석 1 / 2 / 3` 차례로 한 줄에 적습니다.


**차이를 미리 빼서 적습니다.** 지난 수를 나란히 늘어놓기만 하면 머릿속으로
빼야 합니다. `달라진 IO +8개` 처럼 부호를 붙여 두면 바로 읽힙니다.

색도 붙였습니다 — **달라진 IO 가 늘면 빨강, 줄면 초록.** 지난번보다 어긋난
곳이 많아졌다는 뜻이니까요.

저장할 때 이름을 물어봅니다. **비워 둘 수 있습니다** — 그러면 저장 시각으로
적힙니다. 뭘 적을지 몰라 저장을 안 하게 되는 것보다 낫습니다.

삭제는 한 번 묻습니다. 되돌릴 수 없습니다.

**[삭제] 는 줄 단추 밖에 뒀습니다.** 안에 넣으면 삭제를 눌렀을 때 그 Click 이
위로 올라가 바깥 줄 단추까지 같이 눌립니다 — 지우면서 창이 뜹니다.

## 3-2. 줄을 누르면 펼쳐 보는 창

목록 줄에는 자리가 없어서 이름과 몇 개의 수만 적습니다. 줄을 누르면 그때의
기록을 다 펼쳐 보는 창이 뜹니다.

```
┌─ 저장된 분석 ────────────────────────────────────────────┐
│ 3월 정기점검                                             │
│ 저장  2026-03-14 09:30:00                                │
│                                                          │
│ ┌ 그때 견준 로그 ────────────────────────────────────┐   │
│ │ ● 이전  2026-03-14_before.xlsx                     │   │
│ │         D:\로그\2026-03-14_before.xlsx             │   │
│ │ ● 이후  2026-03-21_after.xlsx                      │   │
│ │         D:\로그\2026-03-21_after.xlsx              │   │
│ └────────────────────────────────────────────────────┘   │
│ ┌ 그때의 점수 ───────────────────────────────────────┐   │
│ │  분석 1      분석 2      분석 3                    │   │
│ │   100         ??          ??                       │   │
│ │  견준 IO 184개 · 달라진 IO 12개 · 한쪽에만 3개     │   │
│ │  허용 오차 0.1% / 절대 0.25  시간 맞추기 "START"   │   │
│ └────────────────────────────────────────────────────┘   │
│ ┌────────────────────────────────────────────────────┐   │
│ │ 이 기록을 지금 분석과 나란히 놓고 봅니다.          │   │
│ │ 미구현                    [ 현재 분석과 비교 ]     │   │
│ └────────────────────────────────────────────────────┘   │
│                                              [ 닫기 ]    │
└──────────────────────────────────────────────────────────┘
```

**[현재 분석과 비교] 는 자리만 잡아 뒀습니다.** 무엇을 어떻게 나란히 놓을지
정해지지 않았습니다. 눌러도 아무 일이 없으면 고장으로 보이므로, 그 자리에
아직 없다는 것만 적습니다.

## 4. 기준이 다르면 견주지 않습니다

이게 이번 작업에서 제일 조심한 자리입니다.

```
지난번   허용 오차 0.1%   달라진 IO 31개
이번     허용 오차 1.0%   달라진 IO 12개
```

그냥 빼면 `-19개` 입니다. **좋아진 것처럼 보입니다.** 그런데 로그는 하나도
안 좋아졌고 잣대만 넓어졌을 수 있습니다.

그래서 저장할 때 기준도 같이 남기고, 지금 기준과 다르면 **수를 빼지 않습니다.**

```csharp
public bool SameBasis(double tolerancePercent, double absoluteTolerance,
                      string alignIo, string axisIo)
```

다르면 그 자리에 `기준 다름` 이라고 적고 왜 그런지 한 줄 붙입니다.
지워 버리지 않는 이유는, 그 기록이 있었다는 사실 자체는 보여야 하기
때문입니다.

---

## 5. 점수는 여전히 만점입니다

저장하는 점수도 지금은 만점입니다. 점수 규칙이 정해지면 `MainVm` 의 그
한 줄만 바꾸면 되고, 그때부터 저장되는 기록에 진짜 점수가 들어갑니다.

이미 저장해 둔 기록은 그때의 값을 그대로 들고 있습니다 — 나중에 규칙이
바뀌어도 **옛 기록을 새 규칙으로 다시 계산하지 않습니다.** 그러면 그때
봤던 수와 달라져서, 기록이라는 말이 무의미해집니다.

## 6. 자체 테스트

이번에는 **Core 에 넣어서 진짜로 돌렸습니다** (308개 통과, 33개 늘었습니다).
저장·읽기·삭제는 화면 없이 도는 계산이라 테스트가 닿습니다.

| 테스트 | 확인하는 것 |
|---|---|
| `HistorySaveAndLoad` | 저장한 값이 그대로 돌아오는지(이름·파일·발생시간·점수·세 가지 수·허용 오차·맞추기·가로축·밀기 값·저장 시각), 파일 이름이 시각으로 서는지, **최근 것이 앞**인지, 이름을 안 붙이면 저장 시각으로 적히는지, 지우기와 "없는 것 지우기", 그리고 **경로가 섞인 열쇠(`..\settings.json`, `sub/other.json`)를 거부**하는지 |
| `HistoryEdgeCases` | 같은 밀리초에 두 번 저장해도 한 건이 사라지지 않는지, 기준 견주기가 허용 오차·절대 오차·맞추기·가로축 각각에 반응하는지, 없는 폴더를 읽어도 터지지 않는지 |

### 아직 확인 못 한 것

화면 쪽(목록 · 저장 단추 · 삭제 확인)은 XAML 이라 여전히 윈도우에서만
확인됩니다.
