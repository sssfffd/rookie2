# 135 — build.bat 을 돌리면 out 이 새것으로 바뀌나 (전에는 지워야 됐음)

> 지금 내가 build.bat 실행하면 기존 out파일 업데이트되나? 이전에는 삭제하고 해야 코드 변경 반영됬는데

## 1.51 까지 — 대개 되지만, 안 되는 두 경우가 있었습니다

`build.bat` 은 MSBuild 로 빌드한 뒤 `out\` 에 exe 를 `copy /y` 로 덮어씁니다. 그런데:

| 경우 | 왜 | 보이는 증상 |
|---|---|---|
| **zip 을 받아 덮어 풀었을 때** | MSBuild 는 "증분 빌드" — 소스 파일 시각이 지난 빌드보다 새로울 때만 다시 컴파일합니다. zip 안의 파일 시각은 시간대가 없어서(한국은 9 시간 차이가 날 수 있음) **풀린 파일이 지난 빌드보다 옛날 시각**이 되면 MSBuild 가 "바뀐 것 없음" 으로 보고 건너뜀 | 빌드는 "완료" 인데 옛 exe 그대로 |
| **out 의 프로그램이 켜져 있을 때** | 실행 중인 exe 는 덮어쓸 수 없는데, 복사 오류를 `>nul` 로 숨겨 조용히 넘어감 | 〃 |

그래서 out(또는 bin/obj)을 지우면 반영되던 것 — 지우면 처음부터 다시 만드니까.

## 1.52 — 지우지 않아도 늘 반영

| | 전 | 후 |
|---|---|---|
| 빌드 | 증분 (파일 시각으로 건너뜀) | **`/t:Rebuild` — 늘 처음부터** (작은 프로젝트라 몇 초 더) |
| out 의 exe 복사 실패 | 조용히 넘어감 | **멈추고 알림**: "out 폴더의 exe 를 새것으로 바꾸지 못했습니다. 프로그램이 켜져 있으면 닫고 다시 build.bat 을 돌려 주세요." |

그대로인 것 (일부러): `out\config.txt` · `out\groups.txt` 는 **이미 있으면 덮어쓰지 않습니다** — 사용자가 고친
파일이라서. 저장소의 새 기본값을 쓰려면 그 파일을 지우고 build.bat.

`build.bat` 은 CP949 · CRLF 그대로 (cp949 로 읽고 고쳐 다시 씀).
못 한 것: Windows 에서 실제로 돌려 보기.
