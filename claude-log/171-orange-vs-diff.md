# 171 — 주황 띠가 차이난 곳을 다 알려 주나? (질문 · 코드 안 바꿈)

> 근데이거 주황색으로 색칠해주는거 차이난 부분 다 알려주는거 맞음? 아닌거 같은데

## 답: 아니요 — 일부러 다릅니다

그래프의 두 표시는 서로 다른 셈입니다.

| | 옅은 빨강 ([차이 영역 표시]) | 주황 띠 (판정 오차) |
|---|---|---|
| 셈 | **같은 시각끼리** 이전 · 이후가 허용 오차를 넘는가 (화면 픽셀 열마다 한 점) | 정상 판정 (메인 칸 수 · 그룹 · 히트맵이 쓰는 것) |
| 시간 어긋남 | 조금만 늦어도 차이 | **시간 여유** (단계 · 로그 길이의 2 %, 최대 5 초) 안이면 같음 |
| 단계가 있으면 | 고른 맞춤 하나로 | 단계 맞춤 · 전체 맞춤 (· 고른 단계 맞춤) **모두에서** 벗어난 곳만 |
| 단계 IO | 칠하지 않음 (1.66) | 안 셈 |
| 허용한 오차 | 그대로 칠함 | 회색 |
| 짧은 튐 · 이전에만 있던 펄스 | 화면을 넓게 보면 픽셀 열 사이에 빠질 수 있음 | **모든 표본 · 양쪽으로** 봐서 잡음 |

그래서
- 옅은 빨강인데 주황이 아닌 곳 = 같은 시각으로는 다르지만 판정은 정상으로 본 곳 (조금 늦음 · 단계 맞추면 맞음 · 허용)
- 주황인데 옅은 빨강이 없는 곳 = 판정이 잡은 짧은 튐 · 빠진 펄스 (넓게 볼 때 칠하기에서 빠짐)

예 (테스트 로그 judge_a/b): RAMP 는 0.3 초 늦게 오름 — 옅은 빨강은 칠해지지만 주황은 없음 (여유 1.2 초 안).
PULSE 는 이전에만 0.3 초 펄스 — 주황은 있지만 넓게 보면 옅은 빨강이 안 보일 수 있음.

주황 띠는 그려지는 그대로 판정 오차 목록 (메인 IO 창의 줄) 과 같습니다 — 빠진 버그는 아님 (`GraphCanvas.DrawJudgeMarks` 가 판정 값 오차를 IO 마다 모두 그림).

## 바꿀 수 있는 것 (고르면 만듦)
1. 지금대로 + 범례에 "주황 = 판정 오차 (시간 여유 · 단계 맞춤 반영), 옅은 빨강 = 같은 시각 차이" 를 적어 둠
2. 주황을 "같은 시각 차이 전부" 로 (= 옅은 빨강과 같은 곳 · 판정과 달라짐)
3. 판정을 더 엄하게 (시간 여유를 줄임 → 주황이 늘고 메인 칸 수도 늚)
