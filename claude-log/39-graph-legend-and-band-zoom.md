# 39 — 그래프에 이전/이후 범례, 오른쪽 끌기로 네모 확대

> 요청: "그리고 그래프 볼때 그래프 화면에서 어떤게 이전이고 이후인지
> 표시해주고 그래프 우클릭 드래그 하면 해당 영역만큼 확대되게 해줘"

## 1. 어느 선이 이전인가

색만 다르게 그려 놓고 **어디에도 적어 두지 않았습니다.** 도구 줄의 글자로는
부족합니다 — 보고 있는 자리에서 멀고, 겹쳐보기(Overlay)에서는 IO 마다 색이
달라 "파랑이 이전" 같은 설명이 아예 성립하지 않습니다.

그래서 그래프 오른쪽 위에 작은 범례를 그립니다. **그 화면에서 실제로 쓰는
선을 그대로** 보여 줍니다.

```
┌──────────────────┐
│ ──  이전         │   Lane: 파랑 / 주황
│ ──  이후         │
└──────────────────┘

┌──────────────────────────┐
│ ──  이전                 │   Overlay: 첫 IO 의 두 선
│ ──  이후                 │
│ IO 마다 색이 짝을 이룹니다 │
└──────────────────────────┘

┌──────────────────────┐
│ ──  차이 (이후 − 이전) │   차이 눈금: 선이 하나
└──────────────────────┘
```

- **Lane** : `p.BeforePen` / `p.AfterPen` — 어느 IO 든 같은 두 색
- **Overlay** : `p.SeriesPen(0)` / `PairPen(p, 0)` — 첫 IO 의 두 선을 그대로
  보여 줍니다. 짝의 규칙(어두운 테마에서는 연한 쪽이 이후, 밝은 테마에서는
  진한 쪽이 이후)을 **글로 설명하지 않고 색으로 보여 주는** 편이 맞습니다.
  IO 가 둘 이상이면 "IO 마다 색이 짝을 이룹니다" 를 한 줄 더 적습니다.
- **차이 눈금** : 선이 하나뿐이니 한 줄만.

놓는 자리를 한 번 옮겼습니다. 처음에 플롯 맨 위 오른쪽에 뒀더니 **레인
머리글의 커서 값 표시와 겹칩니다** (그쪽도 오른쪽 정렬입니다). 머리글
한 줄(`HeaderH`) 아래로 내렸습니다. 바탕은 88% 불투명으로, 뒤로 선이
지나가도 아주 가려지지는 않습니다.

## 2. 오른쪽 끌기로 그 네모만큼 확대

휠은 가운데를 기준으로 커지고 작아집니다. "이 구간만 크게" 를 하려면 휠과
끌기를 번갈아 여러 번 해야 했습니다.

```
오른쪽 단추를 누르고 끌면 네모가 그려지고, 놓으면 그만큼 확대됩니다.
```

| 어떻게 끌었나 | 무엇이 바뀌나 |
|---|---|
| 가로로만 | **시간만** |
| 세로로도 | 시간 + **그 레인의 값 범위** |
| 6 픽셀보다 작게 | 아무 일도 없음 (그냥 누른 것) |

### 정한 것들

**세로 확대는 시작한 레인에만.** 레인을 넘나든 네모의 값 범위는 뜻이
없습니다. 시작점의 레인을 적어 두고, 놓을 때 그 레인이 맞는지 다시 봅니다.

**세로를 먼저, 시간을 나중에.** 시간을 먼저 바꾸면 `BaseRange` 가 달라져
(구간 맞춤이 켜져 있으면 보이는 구간의 min/max 로 기준이 잡힙니다) 값 범위
계산이 어긋납니다.

**[구간 맞춤] 이 켜져 있으면 세로는 건드리지 않습니다.** 그 모드는 값 범위를
보이는 시간 구간에 저절로 맞춥니다. 네모 값을 적어 둬도 다음 그림에서
덮이므로, 시간만 좁히면 위아래는 알아서 그 구간에 맞습니다.

**그리는 식을 거꾸로 풉니다.**

```csharp
// 그리는 쪽: span = (hi - lo) / Zoom,  vlo..vhi = Center ± span/2
// 그래서 원하는 vlo..vhi 에서 Zoom 과 Center 를 냅니다.
ly.Center = (vTop + vBottom) * 0.5;
ly.Zoom   = full / (vTop - vBottom);
```

`YToValue` 는 `ValueToY` 를 그대로 뒤집은 것입니다. 둘이 어긋나면 **네모를
그린 자리와 다른 곳으로** 확대됩니다. 이미 있던 `FitLaneToVisible` 과 같은
자리의 규칙이라, 그 주석에 적힌 이유를 그대로 따릅니다.

**너무 얇게 자르는 것은 막습니다.** 휠 확대와 같은 한계
(`전체 구간 x 1e-7`)를 씁니다. 네모를 1 픽셀로 그려도 시간축이 무너지지
않습니다.

## 자체 테스트

테스트 389 통과(그대로). 둘 다 그리기와 마우스라 Core 에 붙일 것이
없습니다 — `YToValue` 는 App 쪽 private 이라 Tests 에서 부를 수 없습니다.
WPF 흉내 파일에 `OnMouseRightButtonUp` 을 더했습니다 (진짜 WPF 에 있는
메서드인데 아직 안 써서 빠져 있었습니다 — 컴파일 검사가 그 자리에서
잡았습니다).

### 아직 확인 못 한 것

**마우스로 해 봐야 아는 것들입니다.**

- 오른쪽 끌기 중에 네모가 따라 그려지는지, 놓은 자리와 확대된 구간이 맞는지
- 오른쪽 단추를 누른 채 창 밖으로 나갔다 놓았을 때
- 범례가 레인 머리글이나 값 눈금 글자와 겹치지 않는지, 좁은 창에서 접히는지
- 겹쳐보기에서 첫 IO 를 끄면 범례의 색이 다음 IO 로 바뀌는지 (`SeriesPen(0)`
  은 보이는 목록의 첫 번째라 자동으로 따라갑니다)
