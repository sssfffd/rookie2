# 70 — 메인 화면 DB 칸을 점수에서 PASS · WARNING · FAIL 로

> 메인 화면에 db쪽은 점수말고 pass/warning/fail로 뜨게 해주셈
> 차이 발생 100개 이상이 fail, 0개는 pass

## 왜 점수가 아니라 낱말인가

점수로 적으려면 "차이 100 개는 몇 점인가" 를 정해야 합니다. 그 환산에는 근거가
없고, 한 번 숫자로 적히면 읽는 사람은 그 수를 진짜로 믿습니다. 통과·실패는
환산 없이 그 자체로 정해져 있으니 그대로 적는 쪽이 정직합니다.

| 낱말 | 차이 발생 | 색 |
|---|---|---|
| `PASS` | 0 개 | 초록 |
| `WARNING` | 1 ~ 99 개 | 노랑 |
| `FAIL` | 100 개 이상 | 빨강 |

가운데 `WARNING` 은 요청에 없던 칸입니다. 0 과 100 만 정해 주셨으니 1 ~ 99 는
빈 곳인데, 여기를 `PASS` 로 묶으면 **차이 99 개가 "통과" 로 적힙니다.** `FAIL` 로
묶으면 반대로 한 개만 달라도 실패가 됩니다. 둘 다 거짓이라 노랑 한 칸을
두었습니다. 기준을 바꾸고 싶으면 `DbVerdict.FailFrom` 하나만 고치면 됩니다.

## 판정에 안 들어가는 수를 숨기지 않기

판정에 쓰는 수는 **차이 발생** 하나뿐입니다 (요청대로). 그런데 DB 비교는 수를
셋 냅니다 — 차이 발생 · 없어진 IO · 새로 생긴 IO. 없어진 IO 가 스무 개인 날에
`PASS` 만 크게 떠 있으면 "아무 일 없었다" 로 읽힙니다.

그래서 **낱말은 차이 발생만 보고 정하고, 낱말 아래 한 줄에는 세 수를 다 적습니다.**

```
PASS
차이 발생 0개 · 없어진 IO 20개 · 새로 생긴 IO 0개 (이 둘은 판정에 안 넣습니다)
```

`WARNING` 일 때는 "(100개부터 FAIL)" 이 붙습니다 — 노랑을 보고 "얼마나 더
가면 빨강인가" 를 화면에서 바로 알 수 있게.

## 안 읽어 본 것과 0 개는 다릅니다

DB 를 한 번도 읽지 않은 상태의 차이 발생은 0 입니다. 그 0 을 그대로 규칙에
넣으면 **아무것도 견주지 않은 칸에 `PASS` 가 뜹니다.** 그러니 DB 를 한 번
읽기 전까지 칸은 비어 있습니다 (`AppState.HasDbResult`).

이 턱은 `AppState` 주석에도 적어 두었습니다 — 나중에 누가 `DbChanged` 만 보고
판정을 다시 짜면 같은 구멍을 다시 팝니다.

## 수가 메인 화면까지 오는 길

DB 화면은 메인 화면을 모릅니다 (그래야 분석 2 를 떼어도 메인이 안 깨집니다).
그래서 **셈한 결과를 알림으로 내보내고, 창(Shell)이 그걸 받아 메인에 넣습니다.**

```
DbVm.Take()  →  _tally 채우고 ResultChanged 알림
DbView       →  그 알림을 그대로 위로 넘김
ShellWindow  →  받아서 AppState 에 적고 MainVm.Refresh()
MainVm       →  DbVerdict.Of(차이) → 낱말, DbVerdict.Why(셋) → 아래 한 줄
```

| 무엇 | 어디 |
|---|---|
| 판정 규칙 (경계 100, 세 낱말, 아래 한 줄 글) | `src/LogScope.Db/DbVerdict.cs` |
| 셈한 수를 내보내는 곳 | `src/LogScope.App/Db/DbVm.cs` (`Tally`, `ResultChanged`) |
| 받아서 적는 곳 | `src/LogScope.App/Shell/ShellWindow.xaml.cs` (`OnDbResultChanged`) |
| 수를 들고 있는 곳 | `src/LogScope.App/Common/AppState.cs` (`HasDbResult` 외 셋) |
| 칸에 낱말을 세우는 곳 | `src/LogScope.App/Shell/MainVm.cs` (`ShowDbVerdict`) |
| 점수 자리에 낱말을 그리는 칸 | `src/LogScope.App/Shell/AnalysisCardVm.cs` (`SetVerdict`) |

## 글자가 칸을 넘지 않게

점수 자리의 글자 크기는 34 로 박혀 있었습니다. `98` 은 두 글자지만
`WARNING` 은 일곱 글자라 그대로 두면 칸을 넘칩니다. 크기를 `ScoreSize` 로
빼서 **낱말일 때 24, 숫자일 때 34** 가 되게 했습니다 (`MainView.xaml` 의
`FontSize="{Binding ScoreSize}"`). 그리고 낱말 모드에서는 `/ 100` 을 숨깁니다 —
`WARNING / 100` 은 뜻이 없습니다.

> 창을 열어 본 것이 아니라 숫자만 맞춘 것이라, **글자가 정말 안 넘치는지는
> Windows 에서 봐야 확인됩니다.** 넘치면 24 를 줄이면 됩니다.

## 시험

경계를 네 점에서 봅니다 — 0 · 1 · 99 · 100 (`101` 까지). "100 개 이상" 을
99/100 으로 한 번 잘못 쓰면 딱 100 개인 날에 `FAIL` 이 안 뜨고 아무도
모릅니다. 그리고 **차이 0 · 없어진 IO 20** 인 경우에 아래 한 줄이 그 20 을
정말 적는지 봅니다 — 숨기지 않기로 한 것이 코드에서 지켜지는지가 색보다
중요합니다.

`통과 687 / 실패 0`.

## 아직 못 본 것

`PASS` 가 초록으로, `FAIL` 이 빨강으로 칠해지는지 · 24 로 줄인 글자가 칸에
들어가는지 · DB 를 읽자마자 메인 칸이 실제로 바뀌는지는 **Windows 에서만
확인됩니다.** 여기서는 XAML 이 컴파일되지 않습니다.
