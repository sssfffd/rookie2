# 30 — 말 다듬기, 파일 끌어다 놓기, 프로그램 이름은 한 곳에서

> 요청: "메인화면에서 한쪽에만 이거 없애고 / 견준 IO를 비교한 IO로 이름변경
> / 그리고 만점이란 글자도 빼고 / 다른 견준다는 표현은 Log 파일을 비교한 후로
> 바꿔줘 / 그리고 log파일을 드래그로도 넣을 수 있게 해주고
> 프로그램명을 내가 직접바꾸고싶은데 어디서 바꿔야할까"

---

## 1. 말 다듬기

| 전 | 후 |
|---|---|
| 견준 IO | **비교한 IO** |
| 한쪽에만 | *(뺐습니다)* |
| 만점 | *(뺐습니다)* |
| 로그를 견주면 점수가 나옵니다 | **Log 파일을 비교한 후** 점수가 나옵니다 |
| 견준 뒤 [지금 결과 저장] 을 … | **Log 파일을 비교한 후** [지금 결과 저장] 을 … |
| 두 개를 다 열어야 견줄 수 있습니다 | 두 개를 다 열어야 **비교**할 수 있습니다 |
| 기준이 달라 그대로 견줄 수 없습니다 | 기준이 달라 그대로 **비교**할 수 없습니다 |
| 그때 견준 로그 | 그때 **비교한 Log 파일** |

**"한쪽에만" 을 뺀 자리**는 남은 두 칸이 나눠 가집니다 (`UniformGrid` 를
3 열에서 2 열로). 칸이 셋으로 나뉘어 좁은데 숫자를 셋씩 넣으니 빽빽했습니다.
그 목록은 대시보드에 따로 있습니다.

**"만점" 을 뺀 자리**는 색 설명과 같은 말이 들어갑니다 — 100 점이면
`이상 없음`. 점수 자체가 `100 / 100` 이고 글자도 초록이라, "만점" 은 같은
말을 세 번째로 하는 것이었습니다.

## 2. Log 파일을 끌어다 놓기

**두 가지 길을 뒀습니다.**

### 창 아무 데나

어느 화면에 있든 됩니다.

```
두 개 이상 놓으면   이름 순으로 앞의 것을 이전, 다음을 이후
한 개를 놓으면      비어 있는 자리에
                   둘 다 차 있으면 어느 쪽인지 묻습니다
```

**둘 다 차 있을 때 묻는 이유**가 있습니다. 말없이 한쪽을 덮으면 방금 덮인
것이 무엇이었는지 알 수가 없습니다. 짐작하지 않고 묻습니다.

**이름 순인 이유**도 있습니다. 두 개를 한꺼번에 놓으면 앞의 것을 이전으로
봐야 하는데, 이 프로그램은 이미 파일 이름 앞에 날짜가 붙는다는 관행을 쓰고
있습니다 (발생시간). 그러면 이름 순이 곧 시간 순입니다. 파일의 수정 시각으로
정하면 **복사만 해도 뒤바뀝니다.**

### 메인 화면의 이전/이후 줄

```
● 이전  발생시간 2026-03-14  2026-03-14_before.xlsx  IO 184 · 표본 52,310
● 이후  발생시간 2026-03-21  2026-03-21_after.xlsx   IO 187 · 표본 49,882
```

각 줄이 놓을 자리입니다. **여기 놓으면 묻지 않습니다** — 어느 쪽인지 이미
고른 것이니까요.

읽을 수 없는 파일(`.xls`, 그림 파일 등)을 끌어오면 마우스 모양이 바뀌지
않습니다. 놓을 수 있는지 놓기 전에 알 수 있습니다.

## 3. 프로그램 이름을 바꾸는 곳

**`appname.txt` 한 곳입니다.** 저장소 루트에 있습니다 (`version.txt` 옆).

```
appname.txt  →  LogScope
```

이 파일을 고치고 다시 빌드하면 아래가 다 따라옵니다.

| 어디 | 무엇 |
|---|---|
| 창 제목 | `LogScope — IO 로그 그래프 뷰어` |
| 왼쪽 위 글자 | `LogScope ▾` |
| 오류 창 제목 | `LogScope 오류` |
| 설정 파일 안의 `savedBy` | `LogScope 0.36` |

버전과 같은 방식입니다. `tools/BuildInfo.targets` 가 빌드할 때
`BuildInfo.Product` 로 넣어 줍니다 — 소스 여러 군데에 이름을 적어 두면
바꿀 때 한두 군데가 남습니다.

### 따라가지 <b>않는</b> 것

| 무엇 | 왜 |
|---|---|
| `LogScope.settings.json`, `%APPDATA%\LogScope` | 이름을 바꿨다고 그때까지 쌓인 설정을 못 찾으면 안 됩니다 |
| `history` 폴더 | 같은 이유 |
| 실행 파일 이름 `LogScope.exe` | 빌드 산출물 이름입니다. 바꾸려면 `src/LogScope.App/LogScope.App.csproj` 의 `<AssemblyName>` |
| 어셈블리 정보 | `src/LogScope.App/Properties/AssemblyInfo.cs` 의 `AssemblyTitle` / `AssemblyProduct` (파일 속성 창에 보이는 값) |

**화면에 보이는 이름만 바꾸고 싶으면 `appname.txt` 하나면 됩니다.** 실행 파일
이름까지 바꾸려면 위 두 줄을 같이 고쳐야 하고, 그러면 `build.bat` 이 복사하는
파일 이름도 같이 맞춰야 합니다.

## 4. 자체 테스트

테스트 328 통과(그대로). 이번 것은 화면 글자와 끌어다 놓기라 Core 에 붙일
것이 없었습니다.

`DataFormats` 를 WPF 흉내 파일에 더했습니다 — 진짜 WPF 에 있는 타입인데
아직 안 쓰고 있어서 빠져 있었습니다.

### 아직 확인 못 한 것

끌어다 놓기는 실제로 마우스로 해 봐야 압니다. 특히 창 아무 데나 놓는 것이
그래프 화면의 IO 끌어다 놓기(그룹에 담기)와 부딪히지 않는지 — 그쪽은 창
안에서 시작한 끌기이고 이쪽은 탐색기에서 온 파일 끌기라 형식이 달라
갈라지지만, 실제로 겪어 봐야 확실합니다.
