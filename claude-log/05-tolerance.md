# 05 — 허용 오차

> 요청: "허용 오차값 디폴트가 0.1%고 사용자가 변경 가능하게 해줘"

## 1. 고치기 전에 어긋나 있던 것

이 요청을 받고 코드를 보니 화면마다 기준이 달랐습니다.

| 화면 | 그때 쓰던 기준 |
|---|---|
| 대시보드 (차이 난 IO 목록·개수) | **절대 오차, 기본 0** — 아주 작은 차이도 전부 "차이" |
| 그래프 (차이 구간 음영) | 같은 절대 오차 |
| 히트맵 | **값 범위의 0.1%** — 여기만 제대로 |

같은 로그인데 대시보드는 "차이 난 IO 40개", 히트맵은 "3개" 로 나올 수 있었다는
뜻입니다. 어느 쪽을 믿어야 할지 알 수 없는 상태였습니다.

이번에 **셋을 하나의 규칙으로 묶었습니다.**

## 2. 규칙 — 왜 절대값이 아니라 비율인가

기준값은 두 가지 중 **큰 쪽**입니다.

```
기준값 = max( 절대 오차 , 그 채널의 값 범위 x 비율 )
         기본 0 (끔)      기본 0.1%
```

비율을 쓰는 이유는 **채널마다 값의 크기가 다르기 때문**입니다.

| 채널 | 값 범위 | 0.1% | 1 만큼 벌어지면 |
|---|---|---|---|
| 아날로그 (0 ~ 4000) | 4000 | 4 | **잡음** — 안 셉니다 |
| 아날로그 (0 ~ 100) | 100 | 0.1 | **차이** — 셉니다 |
| 디지털 (0 / 1) | 1 | 0.001 | **차이** — 완전히 다른 상태 |

절대값 하나로는 이 셋을 같이 다룰 수 없습니다. 4 로 잡으면 디지털의 0↔1 을
놓치고, 0.001 로 잡으면 아날로그가 전부 빨개집니다.

### 값 범위를 어떻게 재나

먼저 **값이 오르내린 폭(최대 − 최소)** 을 봅니다. "그 채널의 범위" 라는 말에
가장 가깝기 때문입니다.

다만 로그 내내 한 자리에 머문 채널은 폭이 0 이라 비율 오차가 통째로 사라집니다.
3000 에 가만히 있던 값이 3001 이 된 것까지 차이로 세게 되는데, 그건 잡음에
가깝습니다. **폭이 0 이면 값의 크기를 대신 씁니다** (3001 x 0.1% = 3 → 안 셈).

## 3. 어디서 바꾸나

같은 값 하나를 세 군데에서 고칠 수 있고, 어디서 바꾸든 나머지에 그대로 반영됩니다.

| 자리 | 무엇 |
|---|---|
| **설정 창 → [비교]** | 비율(%)과 절대값 둘 다. [허용 오차를 기본값으로] 버튼 |
| **그래프 화면 도구 줄** | 비율(%) — 옆에 "값 범위의 0.1% 까지는 같은 것으로 봅니다" 안내 |
| **히트맵 화면 도구 줄** | 비율(%) |

**설정 파일에 저장됩니다.** 프로그램을 껐다 켜도 유지됩니다.
(예전 설정 파일의 `tolerance` 키는 절대 오차로 그대로 읽어 들입니다.)

대시보드와 그래프는 비교 결과를 다시 계산해야 반영되므로, 값을 바꾼 뒤
위 메뉴의 **[비교 다시 하기]** (F5) 를 누르면 됩니다. 히트맵은
[히트맵 다시 계산] 입니다.

## 4. 코드에서

규칙이 한 곳에만 있습니다.

```
src/LogScope.Core/Compare/ToleranceRule.cs
    ToleranceRule.For(이전채널, 이후채널, 절대오차, 비율)  ->  기준값
```

- `DiffEngine` (대시보드·목록·필터)
- `HeatmapBuilder` (히트맵 칸)
- `GraphCanvas` (차이 음영)

셋 다 이 함수를 부릅니다. 각자 계산하던 것을 없앴기 때문에, 앞으로도 화면마다
답이 갈릴 수 없습니다.

`ChannelDiff.Threshold` 에 그 채널에 실제로 적용된 기준값이 담겨 있어서,
"왜 이건 차이로 안 잡혔지" 를 되짚어 볼 수 있습니다. 히트맵은 칸 위에 마우스를
올리면 아래 띠에 기준값이 함께 나옵니다.

## 5. 테스트

`ToleranceIsRelativeToRange` 가 정확히 위 표를 확인합니다.

- 범위 5000 인 아날로그가 2 만큼 벌어지면 → **차이 아님** (기준 5)
- 범위 1 인 디지털이 1 만큼 벌어지면 → **차이 맞음** (기준 0.001)
- 기준을 0.01% 로 낮추면 아날로그도 잡힘
- 절대 오차를 3 으로 주면 둘 중 큰 쪽이 기준이 됨
- 3000 에 머물던 값이 3001 이 된 것은 잡음 (폭이 0 일 때의 대체 규칙)

히트맵 쪽 `HeatmapRelativeTolerance` 도 같은 규칙을 쓰므로 그대로 통과합니다.
