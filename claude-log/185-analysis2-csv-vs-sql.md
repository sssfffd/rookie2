# 185 — (질문) 분석 2 에서 .csv 와 .sql 을 견줄 수 있나

## 요청 (요청 212)

> 이거 분석 2 csv 랑 .sql 도 비교 가능한가?

## 답 (코드 변경 없음 — 실제로 돌려 봄)

같은 자료를 `.csv` 와 `.sql` 로 만들어 `DbFolderReader.Read` → `DbDiff.Compare` → `DbDiffList` 를 그대로 돌렸습니다.

| 경우 | 결과 |
|---|---|
| ① 표 이름이 같음 (`io.csv` ↔ `CREATE TABLE io`) + `.sql` 열 이름 = `.csv` 머리글 3 · 4 번 (`IO`, `VALUE`) | **됨.** 값 차이 `TEMP_MAX 10 → 12` 를 잡고 같은 줄 2 개, 차이 개수 1 (판정 정상). 이전 · 이후를 바꿔도 같음 |
| ① 의 덤 | 목록에 **열 줄이 2 개 더 나옴** (`IO: NULL → VARCHAR(64) NOT NULL` 등) — .csv 에는 타입이 없어서. **차이 개수 · 판정에는 안 들어감** (값 줄만 셈) |
| ② 표 이름이 다름 (`io.csv` ↔ `recipe`), 또는 `.sql` 표에 열이 더 있음 (`id`, `IO`, `VALUE`, `note`) | **안 됨.** 짝을 못 지어 "이전에만 있는 표 · 이후에만 있는 표" 로 나옴 (사라짐 2 · 생김 4). 이름이 달라도 짝짓는 규칙은 "열 구성이 똑같은 표가 양쪽에 하나씩" 뿐이라서 |

짝짓는 법 (`DbCompare.cs`): ① 표 이름이 같으면 (대소문자 무시) → ② 아니면 열 이름 구성이 똑같은 것끼리 (`PairLeftovers`).
행은 열쇠로 짝지음 — `.csv` 는 3 번 열, `.sql` 은 `PRIMARY KEY`.

## 고칠 수 있는 것 (사용자 결정 기다림)

1. `.csv` 열은 타입을 "모름" 으로 두어 `.sql` 과 견줄 때 타입 · NULL 줄을 안 내기 (지금 `.frm` 기본값을 "모름" 으로 둔 것과 같은 방식).
2. 이름이 달라도, `.csv` 표 하나와 **그 두 열 (IO · 값) 을 다 가진 `.sql` 표가 하나뿐**이면 짝짓고 그 두 열로만 견주기.
   (직접 만드실 `SqlUserReader` 가 표를 `.csv` 와 같은 모양 — 이름 · 열 — 으로 만들어 주면 지금도 ① 로 됩니다.)
