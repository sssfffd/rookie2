# 125 — 사내 LLM 종합 분석에 분석 1 · 2 에서 무엇을 보낼까 (제안)

> 이제 사내 LLM을 활용해서 분석 1,2,3 결과의 종합 분석 결과를 뽑아내고 싶은데 1, 2는 어떤 내용이 가면
> 좋을까?? 길이는 상관 없을 것 같긴해. 사실 분석 1의 로그가 몇천만 자인데 몇십만으로 줄이고 분석 2 로그는
> 몇백만 자 인데 이것도 몇십만으로 줄여서 보내면 깔끔할 것 같긴 해

코드는 아직 안 바꿨습니다 — 무엇을 담을지 정한 뒤 만듭니다.

## 원칙

1. **원본을 줄이는 게 아니라 "차이"를 보낸다.** LLM 은 숫자 천만 개에서 패턴을 못 찾습니다. 프로그램이 이미
   계산한 것(차이 지표 · 단계 · 시간대 · 판정)을 표로 주고, LLM 은 **해석과 연결**만 하게.
2. **중요한 것부터, 층으로.** 앞 20k 자만 읽어도 결론이 나오게 쌓고, 뒤로 갈수록 근거 자료. 길게 보낼수록
   가운데가 덜 읽힙니다 (긴 입력의 흔한 약점).
3. **표는 TSV(탭 구분).** JSON 보다 30~50 % 짧고 LLM 이 잘 읽습니다. 표마다 첫 줄에 열 설명 한 줄.
4. **분석 사이 연결은 프로그램이 미리.** 같은 IO 이름이 분석 1(동작이 달라짐)과 분석 2(설정값이 바뀜)에 다
   나오면 그 짝을 표로 — LLM 에게 맞추게 하면 빠뜨리거나 지어냅니다.

**확인할 것**: 사내 LLM 의 **입력 한도(토큰)**. 한국어 · 숫자는 1 자 ≈ 0.5~1 토큰이라 30 만 자가 15~30 만 토큰일 수
있습니다. 한도가 32k · 128k 면 아래 L1 · L2 만, 그 이상이면 L3 까지.

## 분석 1 (로그 비교, 수천만 자 → 수십만 자)

| 층 | 내용 | 크기 (대략) |
|---|---|---|
| **L1 머리** | 파일 이름 · 길이 · 샘플 수 · 시간 맞추기(기준 IO · 밀린 시간) · 허용 오차 · 단계 수 · 판정(점수 · 차이 발생 N 개 · 한쪽에만 있는 IO 수) | 1~2k |
| **L1 그룹** | 그룹마다 IO 수 · 달라진 수 · 등급 · (적어 둔) 설명 | 2~5k |
| **L1 달라진 IO 표** | IO · 종류(디지털/아날로그/상태) · 그룹 · MaxAbs · Max% · Mean · RMS · 차이 시간 비율 · 구간 수 · 처음 달라진 시각 — **달라진 것 전부**, 지표 순 | IO 당 ~100 자 → 1,000 개면 100k |
| **L2 단계 비교** | 단계마다 이전/이후 길이(초) · 길이 차 · 그 단계에서 달라진 IO 수 · 상위 5 개 IO | 단계 당 ~200 자 |
| **L2 사건 비교** (디지털 · 상태) | IO 마다 바뀐 시각 목록 이전 vs 이후 짝 — "VALVE_1 ON  12.30 s → 12.85 s (+0.55)" · 횟수가 다르면 그 사실 | 사건 당 ~40 자, IO 당 상한 50 개 |
| **L2 시간대** (히트맵) | 시간 칸(예: 100 칸) × 달라진 IO 수 — "어디서 몰리나" | 2~5k |
| **L3 모양** (아날로그 상위 K 개) | 달라진 아날로그 상위 20~50 개만, 단계별 최소/평균/최대 이전 vs 이후, 또는 200 점으로 줄인 곡선(구간 최대/최소 봉투) | IO 당 2~5k |
| 한쪽에만 있는 IO | 이름 목록 | 수 k |
| 안 바뀐 IO | **개수만** (이름은 안 보냄) | — |

예:
```
## 분석 1 — 로그 비교
파일	before_20261028.xlsx → after_20261029.xlsx
판정	점수 87 / 100 · 차이 발생 152 개 · 한쪽에만 4 개
기준	허용 오차 1% / 절대 0.01 · 시간 맞추기 START (+0.240 s)

### 달라진 IO (지표 순, 152 개)
IO	종류	그룹	MaxAbs	Max%	RMS	차이시간%	구간	처음
PRES_MAIN	아날로그	압력	3.20	12.4	0.81	34.0	7	12.30
VALVE_1	디지털	밸브	1	-	-	2.1	3	12.30
…
### 단계 (이전 → 이후 초)
단계	이전	이후	차	달라진IO	상위
1 예열	10.0	12.0	+2.0	31	PRES_MAIN, TEMP_1, …
```

## 분석 2 (DB 비교, 수백만 자 → 수십만 자)

| 층 | 내용 | 크기 |
|---|---|---|
| **L1 머리** | 이전 / 이후 자리 · 표 수 · 판정(PASS/WARNING/FAIL) · 바뀐 표 / 한쪽에만 있는 표 수 | 1k |
| **L1 IO 값 변화** | 분석 2 요약 칸의 "IO · 열 · 이전 → 이후" 전부 (`DbChangedIo`) — 사람이 제일 먼저 보는 것 | 줄 당 ~60 자 |
| **L1 구조 변화** | 표 · 열 추가/삭제/이름 바뀜 추정 · 타입 · NULL · 기본값 변화 | 수 k |
| **L2 표별 요약** | 표마다 행 추가/삭제/변경/같음 개수 | 표 당 ~80 자 |
| **L2 바뀐 행** | 키 + **바뀐 열만** "열: 이전 → 이후" (안 바뀐 열은 안 보냄) | 행 당 ~100 자, 표 당 상한 200 행 |
| **L3 추가/삭제 행** | 키만, 표 당 상한 100 개 + "외 N 개" | — |
| 같은 행 | **개수만** | — |

## 분석 사이 연결 (프로그램이 미리 만드는 표)

```
### 분석 1 ↔ 분석 2 같은 IO
IO	분석 2 (설정)	분석 1 (동작)
PRES_SET	limit: 5 → 6	PRES_MAIN MaxAbs 3.2, 1 예열 단계에서 처음 달라짐
```
IO 이름 맞추기는 이미 쓰는 느슨한 비교(대소문자 · 공백 무시)로.

## LLM 에 주는 요청 (끝에 한 번)

- 종합 판정 (PASS / WARNING / FAIL) 과 한 줄 이유
- 원인 후보 — 분석 2 의 설정 변화 → 분석 1 의 동작 변화 짝을 근거로
- 확인할 것 목록 (어느 IO · 어느 단계 · 어느 표)
- **표에 없는 수치는 지어내지 말 것**, 근거 줄을 인용할 것
