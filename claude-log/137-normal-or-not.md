# 137 — 목적은 "다르다/같다" 가 아니라 "같은 공정이 정상으로 돌았나"

> 지금 다르다 같다보다는 같은 프로세스가 돌아갈 때 정상이냐 아니냐를 판단하는 프로그램이야

(질문 — 코드 안 바꿈. 136 의 추천을 이 목적에 맞게 고침)

## 핵심 차이

"다른가" 는 두 로그를 견주면 되지만, **"정상인가" 는 정상의 범위를 알아야** 합니다. 정상도 매번 조금씩 다르므로
그 흔들림의 크기가 판정 기준이 됩니다.

| 정상 기준 | 범위는 어디서 | 판정 |
|---|---|---|
| 정상 로그 **1 개** (지금의 "이전") | 사람이 정한 허용치 — 값 % · 시간 Δt 를 IO/그룹마다 | 허용치 안 = 정상 |
| 정상 로그 **여러 개** (5 ~ 20 회) | **로그들 자체에서 배움** — 단계 · IO 마다 평균 ± kσ, 또는 최소~최대 + 여유 | 배운 범위 안 = 정상, 벗어난 정도 = 이상 점수 |

→ 여러 개를 모을 수 있으면 그쪽이 훨씬 좋습니다 (허용치를 감으로 안 정해도 됨).

## 추천 구성 (정상 판정용)

```
 정상 로그 N 개 ──▶ 단계로 자름 ──▶ "정상 모델" (단계 × IO)
                                    ├ 특징값 범위: 단계 길이 · 최대 · 최소 · 평균 · 오버슈트 · 상승/안정 시간 · 기울기
                                    ├ 곡선 띠: 단계 안 시각(0~100 %)마다 평균 ± kσ  (+ 시간 허용 Δt)
                                    └ 사건 순서: 디지털이 켜지는 차례 · 횟수 · 간격 범위
 검사할 로그 ──▶ 단계로 자름 ──▶ 모델과 견줌 ──▶ 정상 / 주의 / 이상 + "왜" (벗어난 단계 · IO · 특징 · σ)
```

| 검사 | 잡는 것 | 비고 |
|---|---|---|
| **1. 사건 순서 · 간격** (디지털 · 상태) | 순서가 뒤바뀜 · 빠짐 · 한 번 더 · 간격이 범위 밖 | 공정 이상을 제일 먼저 · 확실하게 잡음 |
| **2. 단계별 특징값 범위** (SPC 관리 한계처럼) | 늦음 · 과열 · 압력 부족 · 오버슈트 | 설명이 쉬움 — "2 단계 길이 14.2 s, 정상 10.1~11.3 s (+4.8σ)" |
| **3. 곡선 띠** (단계 안 시각 비율 기준 + Δt) | 특징값으로 안 잡히는 모양 이상 (중간에 튐 · 출렁임) | 단계 길이가 달라도 비율로 맞춤 |
| **4. DTW 거리** (선택) | 전체 모양이 정상들과 얼마나 먼지 | 정상끼리 DTW 거리 분포의 99 % 를 넘으면 이상. 판정 보조로만 · 단계별 · 줄여서 |

점수 → 판정: 벗어난 정도(σ 또는 허용치 배수)를 모아 **정상 / 주의 / 이상** 과 **원인 상위 5 개**.
그대로 LLM 입력(LlmExport)에도 넣으면 LLM 이 "왜 이상인지" 를 문장으로 씀.

머신러닝(Isolation Forest · 오토인코더 등)은 정상 로그가 수십 ~ 수백 개 쌓인 뒤의 일 · 바깥 라이브러리가 필요해 지금은 비추천.
위 1~4 는 전부 C# 로 직접 (바깥 라이브러리 없이) 만들 수 있음.

## 사용자에게 물은 것
1. 정상 로그를 **여러 개** 모을 수 있는지 (몇 개쯤)
2. 공정이 늘 **같은 단계**로 나뉘는지 (단계 IO 가 있는지)
3. 먼저 만들 것: 1(사건 순서) + 2(특징값 범위) 부터를 추천
