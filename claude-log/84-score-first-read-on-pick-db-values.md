# 84 — 점수가 맨 위 · 열면 바로 비교 · 분석 2 요약에 이전 → 이후

> 아니 그래도 점수가 파일 연것보단 위에있어야지 그리고 열었으면 바로 비교되게 해주고
> 분석 2 요약에서 이전 이후 값도나타나게
> 1 -> 2이런 형식으로

## 1. 차례 — 제목 → 점수 → 파일 → 숫자·요약

```
┌ 분석 2 · DB 비교 ─────────────────── ↗┐
│ FAIL   차이 발생 152 개                 │   ← 결과가 맨 먼저
│ ● 이전  before.sql            파일      │   ← 무엇과 무엇을 견줬나
│ ● 이후  after.sql             파일      │
│ 요약                                   │
│ ● TEMP_MAX                    1 → 2    │
└────────────────────────────────────────┘
```

파일 칸의 두 모양(열기 전 상자 / 연 뒤 한 줄)은 1.03 그대로입니다. 자리만
점수 아래로 옮겼습니다.

## 2. 열면 바로 비교 — 고친 곳은 분석 2 "눌러서 고르기"

| 여는 길 | 분석 1 | 분석 2 (1.03) | 분석 2 (1.04) |
|---|---|---|---|
| 칸에 끌어다 놓기 | 바로 비교 | 바로 읽음 | 바로 읽음 |
| 칸을 눌러 고르기 | 바로 비교 | **자리만 적고 안 읽음** | 바로 읽음 |

원인: 끌어다 놓기(`DbView.TakePaths`)는 "둘 다 차면 읽기" 를 했는데, 1.00 에
붙인 누르기(`PickFileFor`)는 분석 2 화면의 [파일] 단추와 같은 길만 타서 자리만
적었습니다. 그래서 두 파일 이름이 메인 칸에 다 보이는데 요약은 "아직 읽지
않았습니다" 였습니다. `PickFile` 이 "골랐는지" 를 돌려주게 하고, 메인 칸에서
부를 때는 둘 다 차면 `Read()` 합니다.

분석 1 은 이미 열자마자(`AfterLoad` → `Recompare`) 견주고 있었습니다.
혹시 분석 1 에서 안 되는 경우를 보셨으면 어떻게 열었는지 알려 주세요.

**켤 때 지난번 DB 자리는 저절로 읽지 않습니다.** DB 를 읽을 때 `mysqldump` ·
`ibd2sdi` 를 띄울 수 있는데, 켜자마자 묻지도 않고 바깥 프로그램을 띄우는 것은
피했습니다 (로그도 켤 때 저절로 열지 않습니다). 원하시면 바꿀 수 있습니다.

## 3. 분석 2 요약 — "1 → 2"

```
요약
● TEMP_MAX                        1 → 2
    VALUE: 1 → 2  ·  MAX: 5 → 6          ← 열이 여럿 달라졌을 때만
● PRES_SET                  (빈 값) → 3
● 외 8개 더
```

- 화살표는 `→` 로 적었습니다 (`->` 보다 눈에 잘 들어와서). 글자 하나라
  `DbChangedIo.Arrow` 만 고치면 바뀝니다.
- 한 IO 에서 열이 여럿 달라졌으면 오른쪽에는 **먼저 나온 열** 을, 줄 아래에
  열마다 적습니다 (셋 넘으면 "외 N칸").
- 빈 값은 `(빈 값)` 으로 적습니다 — 안 적으면 `→ 3` 이 잘린 줄로 보입니다.
- 값이 길면 오른쪽 칸(최대 240)에서 잘립니다 — IO 이름을 밀어내지 않게.

## Windows 에서 확인 못 한 것

- XAML 은 여기서 컴파일되지 않습니다 (스텁 + 검사기만 통과).
- 메인 칸을 눌러 두 번째 DB 를 고르면 진행 창이 뜨고 바로 PASS/WARNING/FAIL
  이 나오는지.
- `→` 가 Win7 기본 글꼴에서 잘 보이는지 (맑은 고딕에는 있습니다).
- 검사: 컴파일 · 테스트 841 통과 · `check_sources` / `check_handlers` /
  `check_shadowing` 지적 없음.
