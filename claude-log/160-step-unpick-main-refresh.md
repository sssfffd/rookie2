# 160 — 단계를 풀어도 메인 칸 수 · 요약이 안 돌아오던 것 (1.69)

> 아니 그리고 단계 누르면 메인화면 차이난 갯수가 바뀌는데 다시 풀러도 차이난 갯수가 돌아오질 않는데?
> 요약칸도 안바뀜

## 찾은 것

- 계산 (AppState · 판정 · MainVm) 은 맞음 — 화면이 하는 길 그대로 (ShellVm + 단계 콤보 PickIndex) 흉내 내면
  고름 1 → B 0 → A 1 → 전체 1, 요약 그룹도 같이 바뀜 (테스트로 넣음)
- 다른 곳은 **창**: 단계 콤보는 바인딩 (PickIndex 세터) 으로 오는데, 그 안에서 바로
  다시 견줌 (진행 창 = 모달) → 모든 화면 다시 그리기 (콤보 목록도 새로) 를 했음
  - 바인딩 세터 안에서 난 오류는 WPF 가 **조용히 삼킴** → 그 뒤의 메인 칸 새로 그리기가 안 돌 수 있음
  - 모달 창 · 목록 새로 만들기가 콤보가 고르는 중간에 끼어 고른 것이 되돌아갈 수 있음

## 고친 것

| | |
|---|---|
| 단계 바뀜 처리 | 바로 하지 않고 **미룸** (Dispatcher.BeginInvoke, 여러 번 와도 한 번 · 그때의 고른 단계로) — 바인딩 밖이라 오류가 숨지 않음 |
| 화면 다시 그리기 (ReloadAll) | 앞의 화면이 실패해도 **메인 칸은 꼭** 새로 (try/finally) |
| 메인 판정 아래 글 | 단계를 골라 둔 동안 "그래프에서 고른 단계 'B' 맞춤 반영 중 — [전체 구간] 으로 돌리면 원래 수" |

알아 둘 점: "단계로 나눠 보기" 를 끄고 켜는 것은 고른 단계를 풀지 않습니다 (예전부터) — 풀려면 [전체 구간] 또는 칸 머리를 한 번 더.

## 확인
- Linux: 테스트 1098 통과, 실제 csc 7.3 오류 0, 검사 스크립트 통과
- **Windows 에서 못 봄** — 이번 원인이 창 (WPF 콤보 · 모달) 쪽이라 여기서는 재현 못 함. 고친 뒤에도 안 돌아오면
  그때 화면 (콤보에 뭐가 보이는지 · 점수 아래 글) 을 알려 주세요
