# 06 — 그래프 화질과 목록 정렬

> 요청: "그래프 그려지는 게 좀 이상함 해상도가 낮고 확대하면 거의 사라지네"
> "차이난 io 정렬할 때 ... 목록에서 최대차이 같은 지표들 클릭하면 해당 기준으로
> 정렬되게 정렬된건 삼각형으로 정렬됬다 표시 넣어줘"

## 1. 확대하면 사라지던 것 — 진짜 버그였습니다

원인은 **"표본이 없는 열" 과 "값이 끊긴 자리" 를 같은 것으로 본 것**입니다.

그릴 때 화면을 픽셀 열로 나누고 열마다 최소/최대를 뽑습니다(접기). 그런데
선을 그리는 쪽이 이렇게 돼 있었습니다.

```csharp
if (!c.HasValue) { 선을 끊는다; continue; }
```

크게 확대하면 화면 안에 표본이 서너 개뿐입니다. 열은 1000 개인데 값이 든 열은
3 개, 나머지 997 개가 "빈 열" 입니다. 그래서 **표본마다 선이 끊겨** 점 하나짜리
도형이 되었고, 점 하나짜리 도형은 선분이 없으니 **아무것도 그려지지 않습니다.**
확대할수록 심해지던 게 이것입니다.

빈 열에는 두 가지 뜻이 섞여 있었습니다.

| 빈 열의 뜻 | 해야 할 일 |
|---|---|
| 기록이 정말 끊겼다 (NaN) | 선을 끊는다 |
| 표본이 픽셀보다 성기다 | **이어야 한다** |

### 고친 방법 — 성길 때는 접지 않습니다

이제 그리기 전에 화면 안의 표본 수를 셉니다.

```
표본 수 <= 열 수  →  표본을 그대로 잇는다 (접지 않음)
표본 수 >  열 수  →  접어서 그린다 (기존 방식)
```

성긴 쪽으로 가면 빈 열이라는 개념 자체가 없으니 선이 끊길 일이 없습니다.
촘촘한 쪽에서는 모든 열에 표본이 들어가므로, 거기서 빈 열이 나오면 그건 정말로
기록이 끊긴 자리입니다 — 그때만 선을 끊습니다.

덤으로, 표본을 그대로 그리게 되면서 **디지털·상태 채널을 계단으로** 그릴 수
있게 됐습니다. 예전에는 표본끼리 비스듬한 선으로 이었는데, 그건 없던 중간값을
그린 셈입니다. 0 에서 1 로 바뀌는 IO 는 다음 표본 시각까지 0 을 유지하다가
거기서 한 번에 올라가는 게 맞습니다.

## 2. 해상도가 낮던 것

WPF 의 좌표 단위는 픽셀이 아니라 **DIP**(1/96 인치)입니다. 화면 배율이 150% 면
1000 DIP 가 실제로는 1500 픽셀입니다.

그런데 접을 열 수를 DIP 로 세고 있었습니다.

```csharp
int columns = (int)Math.Floor(plot.Width);        // DIP 단위 → 1000
```

실제 픽셀의 2/3 만 쓴 셈이라 파형이 뭉개져 보였습니다. 이제 화면 배율을 읽어
장치 픽셀 수만큼 셉니다.

```csharp
int columns = (int)Math.Floor(plot.Width * _pixelsPerDip);   // 1500
```

열 번호를 다시 화면 좌표로 옮길 때도 배율로 나눕니다.

### 계단처럼 보이던 것

요소 전체에 `EdgeMode.Aliased` 가 걸려 있었습니다. 눈금선은 또렷해지지만
**비스듬한 파형까지 계단처럼** 보이게 만듭니다. 이 설정을 걷어내 파형은
부드럽게 두고, 눈금선과 커서선만 장치 픽셀 한가운데로 맞춰(`Snap`) 또렷하게
남겼습니다.

## 3. 차이 음영도 같은 문제였습니다

이전/이후 사이를 칠하는 음영도 접은 값을 쓰고 있어서, 확대하면 같이 사라졌습니다.

칠하려면 양쪽 값이 **같은 자리에서 하나씩** 있어야 합니다. 그래서 접은 값
(최소/최대) 대신 열마다 "그 시각의 값" 을 하나씩 뽑는 함수를 따로 뒀습니다
(`Decimator.SampleColumns`). 계단 채널은 직전 값을 유지하고, 아날로그는 앞뒤를
보간합니다. 표본이 성겨져도 열이 비지 않습니다.

표본을 앞에서부터 한 번만 훑습니다. 열마다 이진 탐색을 하면 열 1500 개 x 채널
20 개마다 탐색이 돌아 프레임이 무거워집니다.

## 4. 목록 제목을 눌러 정렬

위에 있던 [정렬 기준] 콤보를 없애고, **제목 칸을 누르면 그 기준으로** 정렬되게
했습니다.

- 정렬 중인 칸에만 **삼각형**이 붙습니다. 내림차순(큰 값이 위)이면 아래쪽,
  오름차순이면 위쪽 삼각형이고, 글자도 강조색으로 바뀝니다.
- **같은 칸을 다시 누르면 방향이 뒤집힙니다.**
- 차이량 칸은 큰 값이 위로 오는 게 보통이라 **내림차순으로 시작**하고,
  [IO 이름] 은 가나다순이 자연스러우니 **오름차순으로 시작**합니다.
- [IO 이름] 과 [구분] 으로도 정렬됩니다.
- 고른 기준과 방향은 **설정에 저장**되어 다음에 켜도 그대로입니다.

제목 칸에는 손 모양 커서와 누르는 느낌(배경색 변화)을 달아, 눌러도 되는
곳이라는 게 보이게 했습니다.

## 5. 테스트

`ZoomedInTraceSurvives` 가 1번 버그를 못 박아 둡니다.

- 크게 확대한 구간에서 **접으면 열의 대부분이 빈다**는 것을 먼저 확인합니다
  (그래서 접어 그리면 안 된다는 근거).
- 같은 구간에서 **열마다 뽑으면 빈 칸이 하나도 없다**는 것을 확인합니다.
- 양쪽 끝 바깥의 표본 하나씩이 포함되는지 (화면 가장자리에서 선이 잘리지 않게).
- 아날로그는 보간되어 매끈하고, **디지털은 0 과 1 만** 나온다는 것.
- 촘촘한 구간에서는 모든 열이 차서 접는 길이 맞다는 것.
