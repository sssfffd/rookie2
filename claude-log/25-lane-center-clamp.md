# 25 — 값이 0 으로 붙박이던 것, 이름 정리

> 요청: "겹쳐보기랑 레인 왔다갔다할때 io값이 0으로 고정되는 오류가 있음
> 그리고 레인 대신 Lane / 겹쳐보기 대신 Overlay
> 그리고 해당 메뉴 칸에 괄호로 여러 IO 선택시 를 표기해줘
> 그리고 변화량 대신 적당한 표현 써주고
> 그리고 구간맞춤과 계속맞춤의 차이가 뭐야?"

---

## 1. 값이 0 으로 붙박이던 것

### 어디가 잘못돼 있었나

레인마다 **세로 가운데 값**을 하나씩 적어 둡니다. 끌기, Shift+휠,
[구간 맞춤] 이 여기를 씁니다.

```csharp
private sealed class LaneY
{
    public double Zoom = 1.0;
    public double Center = double.NaN;   // NaN 이면 기준 범위의 한가운데
}
```

문제는 이 `Center` 가 **그 채널의 값과 아무 관계가 없는 그냥 숫자**였다는
점입니다. 6466 언저리로 움직이는 채널에 `Center = 0.5` 가 적혀 있어도
아무도 안 막았습니다. 그러면 눈금은 0.5 언저리를 비추고, 선은 화면 밖
저 위에 있습니다 — **IO 값이 전부 0 으로 고정된 것처럼 보입니다.**

### 0.5 같은 값이 어디서 들어오나

`BaseRange` 는 쓸 만한 값을 하나도 못 찾으면 **0~1 을 돌려줬습니다.**

```csharp
if (a > b) { a = 0; b = 1; }      // 그릴 게 없을 때
```

그릴 게 없어서 아무 눈금이나 그린 것이지 데이터가 아닙니다. 그런데
돌려받는 쪽은 그걸 구분할 수가 없었습니다. 그래서 그 0~1 에서 뽑은
가운데 값이 그대로 `Center` 에 적혔습니다.

**쓸 만한 값이 없는 순간**은 생각보다 자주 있습니다.

- 레인/겹쳐보기를 오가는 사이 (레인 열쇠가 바뀌고 채널 목록이 다시 밀려
  들어오는 그 틈)
- 한쪽 로그에만 있는 IO
- 차이 눈금인데 두 로그가 겹치는 구간이 없을 때
- [계속 맞춤] 이 켜져 있는데 보이는 구간에 표본이 하나도 없을 때

그중 하나에서 한 번 적히면 그 뒤로는 값이 제대로 돌아와도 **그 숫자가
그대로 남습니다.** 되돌리려면 [초기화] 를 눌러야 했습니다.

### 두 겹으로 고쳤습니다

**(1) 가짜 범위에서는 가운데 값을 적지 않습니다.**

`BaseRange` 가 "이게 진짜 값에서 나온 건지" 를 같이 돌려주게 했습니다.

```csharp
private void BaseRange(IoRowVm[] ios, out double lo, out double hi, out bool usable)
```

끌기 · Shift+휠 · [구간 맞춤] 은 `usable` 이 거짓이면 그냥 돌아갑니다.
끌기는 아예 시작도 안 합니다.

**(2) 적힌 값도 기준 범위 안에 가둡니다.**

```csharp
private static double CenterOf(LaneY ly, double lo, double hi, bool usable)
{
    double mid = (lo + hi) * 0.5;
    if (double.IsNaN(ly.Center)) return mid;
    if (!usable) return mid;              // 믿을 수 없는 범위
    if (ly.Center < lo) return lo;        // 밖으로 나가면 끌어당김
    if (ly.Center > hi) return hi;
    return ly.Center;
}
```

(1)만으로도 이번 경로는 막히지만, (2)가 있으면 **어떤 경로로 들어온 값이든**
데이터가 화면 안에 들어옵니다. 이런 건 한 군데서 막는 편이 낫습니다 —
값을 적는 자리가 셋이고, 앞으로 더 늘 수 있습니다.

### 정직하게 말하면

윈도우에서 돌려서 재현해 본 것은 아닙니다. "레인과 겹쳐보기를 오갈 때
값이 0 으로 고정된다" 는 증상을 만드는 구조를 코드에서 찾아 막은 것입니다.
같은 증상이 또 나오면 **[초기화] 로 풀리는지** 알려 주세요. 풀리면 세로
위치 문제가 맞고 다른 경로가 남아 있는 것이고, 안 풀리면 다른 데를 봐야
합니다.

## 2. 이름

| 전 | 후 |
|---|---|
| 보기: 레인 / 겹쳐 | **보기 (여러 IO 선택시)**: `Lane` / `Overlay` |
| 세로 눈금: 변화량 | 세로 눈금: **차이 (이후−이전)** |

**"여러 IO 선택시"** 를 묶음 이름에 넣은 건, IO 를 하나만 골랐을 때는
`Lane` 과 `Overlay` 가 **같은 그림**이기 때문입니다. 그걸 모르면 단추가
고장 난 줄 압니다.

**"변화량"** 은 한 신호가 시간에 따라 변하는 양처럼 읽힙니다. 실제로는
두 로그를 뺀 것이라 **"차이 (이후−이전)"** 로 적었습니다. 괄호까지 넣은 건
부호 방향(어느 쪽에서 어느 쪽을 빼는지)을 짐작하게 두지 않으려는 것입니다.

## 3. [구간 맞춤] 과 [계속 맞춤] 의 차이

둘 다 **"지금 보이는 시간 구간에 세로 눈금을 맞춘다"** 는 같은 계산을
합니다. 다른 것은 **그 뒤에 손을 떼느냐** 입니다.

| | 언제 맞추나 | 그 뒤 |
|---|---|---|
| **[구간 맞춤]** (단추) | 누른 **그 순간 한 번** | 그대로 둡니다 |
| **[계속 맞춤]** (토글) | 시간축을 **움직일 때마다** | 계속 따라다닙니다 |

```
[구간 맞춤] 한 번 누르고 시간축을 오른쪽으로 밀면
  └─ 세로 배율 그대로 → 값이 작아진 구간은 납작하게 보임 (그게 사실이니까)

[계속 맞춤] 켜 두고 같은 일을 하면
  └─ 밀 때마다 다시 맞춤 → 늘 꽉 차 보임. 대신 "커졌다/작아졌다" 를 못 느낌
```

**값이 얼마나 커졌는지 견주려면 [구간 맞춤]**, **모양만 들여다보려면
[계속 맞춤]** 입니다.

[계속 맞춤] 은 위아래 움직임이 심한 채널에서 눈금이 계속 출렁여 어지러울
수 있습니다. 그때는 끄고 [구간 맞춤] 을 한 번씩 누르는 편이 낫습니다.

히트맵에서 칸을 눌러 넘어올 때 자동으로 도는 것이 [구간 맞춤] 쪽입니다.
가로축만 그 구간으로 맞춰 주고 세로축을 로그 전체 범위에 둬 버리면,
4000 짜리 채널에서 3 벌어진 것은 선 두 개가 딱 붙어 보여 아무것도 알 수
없기 때문입니다.
