# 09 — 세로축 자동 맞춤, 숫자 표기, 도구 줄 정리

> 요청:
> "히트맵에서 구간 클릭했을때 가로축은 적당하게 뜨거든? 근데 세로축 value가
> 해당 구간에서 차이 보여줄만큼 자동으로 확대나 축소가 안되서 내가 직접 다시
> 바꿔줘야된단말이야 가로축도 잘 맞춰준 것 처럼 세로축도 잘 맞춰줘"
> "대시보드에서 이전에만 있는 io 이후에 있는 io 칸 크기 줄여주고"
> "e+n으로 10의 n승 표현하면 보기 힘들어 고쳐주고 차이 면적은 필요 없을 것 같아"
> "그래프에서 전체 구간 보기/ 시간축 확대 시간축소 줄이 안맞는거 맞게끔
> 그리고 알아보기 쉽게 위에 tool바 카테고리별로 구분되게 만들어줘"

---

## 1. 히트맵에서 넘어올 때 세로축도 맞춥니다

넘어올 때 하던 일이 이랬습니다.

```csharp
Graph.FocusOnIo(e.Name);        // 그 IO 만 켜고 → 세로 배율은 초기화
Graph.SetTimeRange(t0, t1);     // 가로축만 그 구간으로
```

가로축은 맞춰 주고 세로축은 **로그 전체 범위**로 돌려놨습니다. 0~4000 짜리
채널에서 3 벌어진 것을 보러 들어갔는데 세로 눈금이 0~4000 이면, 두 선이 딱
붙어 있어서 아무것도 안 보입니다. 매번 손으로 확대해야 했던 게 이것입니다.

이제 시간축을 맞춘 다음 세로축도 그 구간에 맞춥니다.

```csharp
Plot.SetTimeRange(t0, t1);
Plot.FitValueToVisibleOnce();
```

### "계속 맞춤" 토글을 켜지 않은 이유

이미 있던 "보이는 구간에 맞춤" 토글을 켜 버리면 될 것 같지만, 그건 성격이
다릅니다. 그 토글은 **계속 따라다니면서** 시간축을 밀 때마다 세로 배율을
다시 잡습니다. 그러면 옆으로 스크롤할 때마다 그래프가 위아래로 출렁여서
두 구간을 눈으로 견줄 수가 없습니다.

그래서 **한 번만 맞추고 손을 떼는** 동작을 따로 만들었습니다.

```
FitValueToVisibleOnce()   한 번 맞추고 끝. 그 뒤 배율은 사용자 것.
FitVisible (토글)          시간축을 밀 때마다 계속 다시 맞춤.
```

계산은 그리는 쪽과 **같은 식을 거꾸로** 풉니다. 그리는 쪽이
"기준 범위 ÷ Zoom 을 Center 에 놓는다" 이므로, 맞추는 쪽도 같은 식에서
Zoom 과 Center 를 냅니다. 각자 따로 계산하면 또 어긋납니다.

도구 줄에도 **[보이는 구간에 맞추기]** 단추로 내놨습니다. 예전 토글은
**[계속 맞춤]** 으로 이름을 바꿔 성격을 드러냈습니다.

## 2. 지수 표기(e+n)를 없앴습니다

`1.234e+06` 은 한 번 머리로 옮겨야 읽히는 숫자입니다. `1,234,000` 이 낫습니다.

원인은 .NET 의 `"G4"` 서식이었습니다. 자리 수가 크거나 작아지면 **알아서**
지수 표기로 바뀝니다. 대시보드 목록, 그래프 세로 눈금, 히트맵 칸 세 군데가
모두 이걸 쓰고 있었습니다.

`Model/NumberText.cs` 한 곳으로 모으고, 지수로 바뀌지 않는 서식만 씁니다.

| 값 | 예전 | 지금 |
|---|---|---|
| 12345678 | `1.235e+07` | `12,345,678` |
| 0.000123 | `1.23e-04` | `0.000123` |
| 0.0000001 | `1e-07` | `0.0000001` |

큰 수는 천 단위로 끊고, 작은 수는 유효한 자리가 보일 때까지 소수점을
늘립니다. 그래도 0 으로 뭉개질 만큼 작으면(1e-13 같은 값) 숫자 대신
"0 보다 조금 큼" 이라고 적습니다 — `0` 이라고 적으면 차이가 없다는 뜻으로
잘못 읽히기 때문입니다.

세 화면이 같은 함수를 쓰므로 같은 값이 화면마다 다르게 보일 일도 없습니다.

## 3. 차이 면적을 화면에서 뺐습니다

단위가 **"값 × 시간"** 이라 채널끼리 견줄 수가 없습니다. `bar·초` 와
`도·초` 를 나란히 놓고 큰 쪽이 더 문제라고 말할 수 없습니다. 게다가
"오래 벌어졌나" 는 **차이 시간**이, "크게 벌어졌나" 는 **최대 차이**가
이미 알려 줍니다.

- 대시보드 목록에서 칸을 뺐습니다.
- 설정 창의 정렬 기준 콤보에서도 뺐습니다.
- **계산은 `Core` 에 그대로 남겨 뒀습니다.** 나중에 필요하면 칸만 다시
  붙이면 됩니다.
- 예전 설정에 "면적으로 정렬" 이 저장돼 있으면 최대 차이로 돌립니다.
  그러지 않으면 어느 칸에도 삼각형이 붙지 않는 상태가 됩니다.

## 5. 도구 줄 — 줄이 안 맞던 것과 갈래 나누기

### 줄이 안 맞던 이유

두 가지가 겹쳐 있었습니다.

**(가) 컨트롤마다 여백이 달랐습니다.**

| 컨트롤 | 여백 |
|---|---|
| `Button` | `3` (사방) |
| `SegmentButton` / `TextBox` | `0,3,2,3` |

그래서 `[전체 구간 보기]` 같은 버튼만 좌우로 3px 씩 밀려 있었습니다.
여백을 `0,3,2,3` 으로 통일하고, 모든 도구 줄 컨트롤에
`VerticalAlignment="Center"` 를 넣어 높이가 달라도 가운데로 맞도록 했습니다.

**(나) 줄바꿈이 묶음 한가운데에서 일어났습니다.**

도구 줄은 좁아지면 `WrapPanel` 이 알아서 줄을 바꿉니다. 그런데 버튼을 그냥
늘어놓으면 `시간축` 이라는 글자와 그 버튼 세 개가 **서로 다른 줄**로 찢어집니다.
"줄이 안 맞는다" 의 절반은 이것이었습니다.

### 갈래별로 묶었습니다

이제 갈래마다 테두리 상자로 싸고, 그 상자들을 `WrapPanel` 에 넣습니다.
줄은 **상자 단위로** 바뀌므로 묶음이 찢어질 수 없습니다.

```
┌ 보기 방식 ─────────┐ ┌ 세로 눈금 ─────────────────┐
│ [레인] [겹쳐보기]  │ │ [원래값] [0–1] [변화만]    │
└────────────────────┘ └────────────────────────────┘
┌ 시간축 ────────────────────────────────┐
│ [전체 구간 보기] [시간 확대] [시간 축소] │
└────────────────────────────────────────┘
┌ 값 축 ────────────────────────────────────────────────────────┐
│ [값 확대] [값 축소] [보이는 구간에 맞추기] [값 배율 되돌리기]  │
│ [계속 맞춤]                                                    │
└────────────────────────────────────────────────────────────────┘
┌ 두 로그 비교 ──────────────────────┐ ┌ 허용 오차 ──────┐
│ [차이 구간 음영] [벌려 그리기]     │ │ [0.1] %         │
└────────────────────────────────────┘ └─────────────────┘
```

여백 통일은 `Themes/Controls.xaml` 의 스타일을 고친 것이라 **히트맵 도구
줄도 같이** 반듯해집니다.

## 6. 새로 넣은 자체 테스트

| 테스트 | 확인하는 것 |
|---|---|
| `NumberTextHasNoExponent` | 경계가 되는 값 19 개를 넣어 `e` / `E` 가 한 번도 안 나오는지, 대시보드 칸도 같은 서식을 쓰는지 |

세로축 맞춤과 도구 줄은 화면을 그려 봐야 알 수 있는 것이라 자체 테스트로는
잡히지 않습니다. 이 컨테이너에 빌드 도구가 없어 **여전히 컴파일은 못 해
봤습니다.** XAML 유효성 · 리소스 열쇠 · 이벤트 처리기 · 바인딩 경로 ·
괄호 균형 · csproj 파일 목록은 모두 기계로 확인했습니다.
