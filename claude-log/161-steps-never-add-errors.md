# 161 — 단계를 켜면 오차가 늘던 것 (1.70)

> 이거 문제가 단계별로 돌리면 오차가 더 늘어나버림
> 이럼 안되는데 로직에 뭔가 이상있는거 아냐?
> 다시 꼼꼼히 검증하고 이게 설정에 단계 on시키는 순간 단계별 풀어도 메인화면에 갯수나 히트맵쪽 갯수가 안쭐어들거든? 이것도 해결해야할듯

## 재현

무작위 로그 300 쌍을 단계 켬 · 끔으로 판정해 견줌 → **143 쌍에서 단계를 켜면 없던 오차 IO 가 생김**.
모두 "고르게 몇 표본 늦은 IO" (단계 길이는 같음).

## 까닭

1.63 에 "단계 맞춤 ∩ 전체 맞춤" 으로 했는데, 전체 맞춤 쪽을 **단계 구간 안에서 · 단계 시간 여유로** 봤음.

| | 단계 없이 | 단계 켬 (1.69 까지) |
|---|---|---|
| 시간 여유 | 전체 길이 2 % (600 표본 → 12) | 단계 길이 2 % (60 표본 → 2) |
| 앞뒤 창 | 로그 전체 | 단계 경계에서 잘림 |

→ 4 표본 늦은 IO: 단계 없이는 정상, 단계를 켜면 단계 맞춤 · "전체 맞춤" 둘 다 오차 → 오차로 남음.

## 고침

```
 오차 = 단계 맞춤 오차 ∩ 단계 없이 본 오차 (로그 전체 · 전체 여유) ∩ 고른 단계 맞춤으로 전체를 본 오차
```

→ 단계를 켜거나 골라도 오차 IO 는 **단계 없이 볼 때의 부분 집합** — 늘 수 없음 (늘 줄거나 같음).
메인 칸 · 히트맵 · 대시보드 수는 모두 판정 (1.68) 이라 같이 줄어듦.

## 검증
- 무작위 1000 쌍 (단계 2 ~ 5, 길이 같음 / 다름, 0 ~ 8 표본 늦음, 튐, 잔떨림, 단계 하나 골라 둠): 어긋남 0.
  오차 IO 합 단계 켬 1265 / 끔 2411
- 테스트에 넣음: 콕 집은 예 (4 표본 늦음 — 켬 0 · 끔 0) + 정해진 씨앗 80 쌍. 테스트 1102 통과, 실제 csc 오류 0
- 속도 그대로 (60 IO × 10 만 표본 9.1 초, 리눅스 mono)
- **Windows 에서 못 봄**
