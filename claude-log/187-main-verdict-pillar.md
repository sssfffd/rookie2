# 187 — 1.92 메인 화면: 왼쪽 판정 기둥 · 칸 셋이 같은 판정 말 · 점수 셈 바꿈

## 요청 (요청 214)

> 메인 화면 UI 가 한눈에 알아보기 불편하다는 피드백이 많아. 분석 1 이 메인으로 보여져야 되고, 최종 판정 결과가 한눈에,
> 각각의 판정 결과도 뭘 의미하는지와 어떤지 한눈에 보여야 되는데 어떻게 할까

물어서 정한 것:

| 물음 | 사용자 답 |
|---|---|
| 배치 | **왼쪽 판정 기둥 + 분석 1** |
| 최종 판정 | **분석 1 기준, 2 · 3 은 참고** |
| 분석 1 판정 | **점수로** (차이 개수는 옆에) — 단 **점수 셈을 바꿀 것** |
| 셈 | (고르지 않음) → 추천안 **100 × (1 − 차이 IO / 전체 IO) × (1 − 평균 오차율 / 100)** |

## 한 것

### 1) 점수 셈 (`JudgeScore.ScoreOf`)

| 경우 (전체 IO 120) | 1.91 까지 (100 − 평균) | 1.92 |
|---|---|---|
| IO 5 개: 3 · 8 · 1 · 100 · 6.5 % | 76.3 | 73.1 |
| IO 1 개: 2 % | 98.0 | 97.2 |
| IO 30 개: 각 2 % | 98.0 | 73.5 |

판정 경계는 `config.txt` 의 `score.good` (90) · `score.warn` (70) — 뒤집혔거나 숫자가 아니면 기본값. `ScoreBands.GoodFrom` · `WarnFrom`
이 그것을 읽음 (`Grade*` 이름은 그대로 — 사용자 `LlmExport` 가 씀). LLM 에 보내는 분석 1 글도 새 셈 · 최종 판정 줄로.

### 2) 칸 셋이 같은 판정 말 (`AnalysisCardVm.Lamp*`)

✔ 정상 · ⚠ 주의 · ✖ 이상 · ○ 아직 · – 못 씀. 칸의 색 (Grade — 이미 셋이 같은 세 가지) 을 낱말로. 근거 한 줄 (`LampLine`):
분석 1 "점수 73.1 · 차이 5 / 120 IO", 분석 2 "바뀐 값 3 개", 분석 3 모듈 글. 뜻 (`Meaning`) = config.txt 의 설명.

### 3) 최종 판정 (`Main/OverallVm.cs`, 새)

= 분석 1 판정. 분석 2 · 3 이 그보다 나쁘면 "참고: 분석 2 이상 — 따로 확인해 보세요". 못 쓰는 칸은 뺌. 칸이 바뀌면 바로 따라감.

### 4) 화면 (`MainView.xaml`)

