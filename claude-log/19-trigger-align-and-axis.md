# 19 — 사건으로 시간 맞추기, 가로축 바꿔 끼우기

> 요청: "이전과 이후 io에서 이게 시작 시간이 다를 수 있잖아 그래서 특정 io가
> 변화되는 시점을 기준으로 이걸 맞추고 싶어. 해당 io를 디지털 값으로 두고
> 바뀔때를 기준으로 시간축 정렬해주는 기능 만들어줘
>
> 그리고 가로 축이 시간으로 뜨는데 다른 시간 관련 io로도 가로 축으로 삼아서
> 볼 수 있게 선택 가능하게 만들어줘"

---

## 1. 사건으로 시간 맞추기

### 왜 시작 시각 맞추기로는 부족한가

지금까지는 두 로그의 **시작 시각**끼리 맞췄습니다. 그건 기록을 시작한
시점이 같을 때만 뜻이 있습니다. 실제로는 기록을 언제 걸었느냐가 제각각이라,
**설비가 기동한 순간** 같은 로그 안의 사건으로 맞춰야 두 로그가 같은
이야기를 하게 됩니다.

```
시작 시각으로 맞추면            사건으로 맞추면
이전 │──────┐                   이전 │──────┐
     0     30                        0     30
이후 │────────────┐             이후 │──────┐
     0           45                  0     30      ← 겹침
```

### 어떻게 맞추나

기준이 될 IO 를 하나 고르면, 그 IO 를 **0/1 로 보고** 바뀌는 순간을 양쪽에서
각각 찾아 그 둘이 겹치도록 이후 로그를 밉니다.

```
밀기 값 = 이전 로그의 변화 시각 − 이후 로그의 변화 시각
```

이 값을 더하면 이후 로그의 시각이 이전 로그의 시각으로 옮겨집니다. 그리는
쪽과 견주는 쪽이 원래 "이후 시각 + 밀기 = 이전 시각" 으로 돼 있어서, 밀기
값 하나만 바꿔 끼우면 대시보드 · 그래프 · 히트맵이 한꺼번에 따라옵니다.

### 아날로그 IO 도 됩니다

"디지털 값으로 두고" 라고 하셔서 그대로 했습니다.

| 채널 | 0/1 로 바꾸는 방법 |
|---|---|
| 디지털 | 값 그대로 |
| 상태(문자열) | 상태 번호를 0.5 로 가름 |
| **아날로그** | **값 범위의 한가운데**를 문턱으로 |

4~20mA 든 0~10V 든 "켜짐/꺼짐" 을 나누는 자리는 대체로 한가운데입니다.
문턱값은 설명에 같이 보여 줍니다.

### 고를 수 있는 것

- **어느 쪽 변화**: `0 → 1` / `1 → 0` / 어느 쪽이든
- **몇 번째 변화**: 같은 IO 가 여러 번 바뀔 때 1 번째, 2 번째 …

### 목록에 아무 IO 나 올리지 않습니다

기준이 되려면 **양쪽 로그에 다 있고, 양쪽 모두 한 번은 바뀌어야** 합니다.
늘 1 인 IO 로는 맞출 수가 없습니다. 그래서 도구 줄의 목록에는 그 조건을
만족하는 IO 만 올라옵니다. 그래도 못 맞추는 경우(고른 뒤 로그를 바꿨다든가)
에는 **조용히 넘어가지 않고 이유를 말합니다.**

```
"START" 로는 맞출 수 없습니다. 이후 로그: 이 로그에서는 그 IO 가
한 번도 바뀌지 않았습니다.
```

맞춰지면 아래 띠에 결과가 뜹니다.

```
"START" 의 0 → 1 변화 로 맞췄습니다.   이전 00:00:30  ↔  이후 00:02:25
```

### 시작 시각 맞추기는 자동으로 꺼집니다

둘을 겹쳐 걸면 서로를 밀어 엉뚱한 자리로 갑니다. 사건으로 맞추는 순간
자동 맞추기를 끄고 밀기 값을 그 자리에 적습니다. [맞추기 해제] 를 누르면
원래대로 돌아갑니다.

## 2. 가로축 바꿔 끼우기

로그의 시간 열 대신 **다른 IO 를 가로축**으로 놓습니다. 경과 시간
레지스터, 스캔 번호, 별도로 찍힌 타임스탬프 열 같은 것들입니다.

### 어떻게 했나

`LogDataset.Times` 배열을 그 채널의 값으로 **갈아 끼웁니다.**

그리는 쪽, 견주는 쪽, 접는 쪽, 눈금 글자 — 전부 `Times` 만 봅니다. 그래서
배열 하나만 바꿔 끼우면 나머지는 손댈 곳이 없습니다. 원래 시간축은 그대로
보관하고 있다가 되돌릴 때 씁니다.

### 조건 하나 — 값이 뒤로 가면 안 됩니다

이진 탐색과 픽셀 접기가 **오름차순을 전제**합니다. 뒤로 가는 채널을 끼우면
값을 엉뚱한 자리에서 읽어 오고, 그림도 앞뒤로 왔다 갔다 합니다.

그래서 끼우기 전에 훑어보고, 뒤로 가면 거부하고 이유를 말합니다.

```
"WOBBLE" 는 값이 뒤로 갑니다 (6 → 0). 가로축은 늘어나기만 해야 합니다.
```

목록에도 **늘어나기만 하는 IO** 만 올라옵니다. 값이 비어 있는 자리는
직전 값을 끌고 갑니다 — 그래야 오름차순이 깨지지 않고, 어차피 그 구간에는
그릴 값이 없습니다.

### 두 로그에 같이 겁니다

한쪽만 다른 축으로 그리면 두 로그가 아예 다른 이야기가 됩니다. 한쪽이라도
못 끼우면 **양쪽 다 원래 시간축으로 되돌리고** 그 사실을 알립니다.

## 3. 어디서 쓰나

그래프 도구 줄에 묶음 두 개가 생겼습니다.

```
┌ 가로축 ──────────────┐
│ [(로그의 시간)  ▼]   │
└──────────────────────┘
┌ 시간 맞추기 ───────────────────────────────────────────────┐
│ [(안 씀 — 시작 시각으로 맞춤) ▼] [0 → 1 로 바뀔 때 ▼]      │
│ 몇 번째 [1]  [맞추기 해제]                                  │
└─────────────────────────────────────────────────────────────┘
```

고른 값은 **IO 이름으로** 설정에 저장됩니다. 다음에 로그를 열면 그대로
다시 걸립니다 — 채널 번호가 아니라 이름으로 저장해서, 열 순서가 달라진
로그에도 붙습니다.

로그를 새로 열 때도 자동으로 다시 겁니다. 그때 조건이 안 맞으면
(그 IO 가 없다거나) 그 자리에서 알려 줍니다.

## 4. 자체 테스트

이번에는 **컴파일하고 실제로 돌려서** 확인했습니다 (204개 통과).

| 테스트 | 확인하는 것 |
|---|---|
| `TriggerAlignOnEdge` | 시작 시각이 100 다르고 사건 시각이 115 다른 두 로그에서 밀기 값이 −115 로 나오는지, 밀고 나면 사건이 실제로 겹치는지, 아날로그 채널도 한가운데 문턱으로 같은 값이 나오는지, 없는 방향(내려가는 변화)을 고르면 실패하는지 |
| `TriggerAlignRefusesBadIo` | 안 바뀌는 IO · 한쪽에만 있는 IO · 안 고른 경우에 각각 이유를 돌려주는지 |
| `AxisChannelSwap` | 늘어나는 IO 로 갈아 끼우면 `TimeStart/TimeEnd` 와 값 읽기가 새 축을 따르는지, 되돌리면 원래 시간축이 살아 있는지, 오르내리는 IO 는 거부하고 그때 시간축이 그대로인지 |
| `SettingsRoundTrip` | 새 설정 네 개(기준 IO · 변화 방향 · 몇 번째 · 가로축 IO)가 저장/불러오기를 견디는지 |
