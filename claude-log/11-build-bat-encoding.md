# 11 — build.bat 한글 깨짐, 두 번째 시도

> 요청: "근데 build할때 글자 깨지는건 어케 못함?"

지난번([06 무렵](00-user-messages.md))에 고쳤다고 한 것이 안 고쳐졌습니다.
제가 쓴 방법이 애초에 틀린 방법이었습니다.

---

## 1. 지난번에 뭘 잘못했나

이렇게 했었습니다.

```
build.bat 을 UTF-8(BOM 없음)로 저장
  ↓
시작할 때  chcp 65001   (콘솔을 UTF-8 로)
  ↓
끝날 때    chcp 949     (원래대로)
```

인터넷에 제일 많이 나오는 방법이고, 저도 그걸 그대로 썼습니다.
**그런데 이 방법은 한국어 윈도우에서 잘 안 됩니다.**

### 이유 (가) — 글꼴

코드 페이지 65001 로 바꾸면 옛 콘솔(conhost)은 **TrueType 글꼴로만** 글자를
찍을 수 있습니다. 그런데 한국어 윈도우의 기본 콘솔 글꼴은 **굴림체 같은
비트맵 글꼴**입니다. 그래서 65001 로 바꾸는 순간 한글 자리가 네모, 물음표,
또는 빈칸이 됩니다. 코드 페이지는 "맞게" 바뀌었는데 화면에 못 찍는 것입니다.

### 이유 (나) — 윈도우 7 에서는 더 나쁩니다

cmd.exe 는 배치 파일을 한 번에 읽어 두지 않고 **한 줄 돌릴 때마다 파일을
다시 읽습니다.** 65001 에서는 이 다시 읽기가 자기 바이트를 잘못 세서,
`goto` 대상을 못 찾거나 줄 중간에서 끊기는 일이 알려져 있습니다.
요구사항에 윈도우 7 이 들어 있으니 이건 그냥 못 쓸 방법입니다.

---

## 2. 이번에는 어떻게 했나

**콘솔을 바꾸지 않습니다. 콘솔이 기다리는 바이트를 씁니다.**

```
build.bat 을 CP949(ANSI / EUC-KR)로 저장
  ↓
chcp 를 아예 부르지 않음
```

한국어 윈도우 콘솔은 **이미 CP949 로 시작합니다.** 바꿀 이유가 없었습니다.
글꼴 문제도, 윈도우 7 다시 읽기 문제도 애초에 생기지 않습니다.

### 그래도 949 가 아닌 컴퓨터라면?

메시지를 **두 벌** 넣었습니다.

```bat
call :msg "빌드 실패. 오류 줄만 추려 보면:" "Build failed. Just the error lines:"
```

```bat
:msg
if defined KO goto :msg_ko
echo   %~2          rem  ASCII 쪽
goto :eof
:msg_ko
echo   %~1          rem  한글 쪽
goto :eof
```

시작할 때 `chcp` 출력을 읽어 949 면 `KO` 를 세웁니다. 아니면 ASCII 쪽을
찍고, 맨 위에 왜 영어가 나오는지 한 줄 적습니다(이것도 ASCII 라 어디서든
읽힙니다). **이제 깨진 글자가 나올 수 있는 경우가 없습니다.**

`:msg` 를 `if ... ( ... ) else ( ... )` 로 안 쓰고 `goto` 로 쓴 이유가
있습니다. 괄호 블록 안에서는 메시지에 `)` 가 하나라도 들어가면 그 자리에서
블록이 닫혀 버립니다. 같은 이유로 제목 줄도 `(%CONFIG%)` 에서
`[%CONFIG%]` 로 바꿨습니다.

### CP949 바이트가 cmd 를 깨뜨리지는 않나

한 번 확인하고 넣었습니다. CP949 의 두 번째 바이트는 `0x41~0xFE` 범위인데,
이 중 cmd 가 특별하게 보는 글자는 `^`(0x5E)와 `|`(0x7C) 둘뿐입니다
(`& < > " % ( )` 는 모두 0x41 보다 작아서 나올 수가 없습니다).
파일에 쓴 한글을 전부 인코딩해서 그 두 바이트가 나오는지 훑었고, 없었습니다.

줄바꿈 변환도 안전합니다. 뒤 바이트가 `0x0A`/`0x0D` 가 될 수 없어서
git 의 CRLF 변환이 글자를 건드릴 수 없습니다. `.gitattributes` 에
`build.bat text eol=crlf` 로 못박고 이유도 적어 뒀습니다.

---

## 3. 덤으로 고친 것 — 오류 메시지도 깨지고 있었습니다

빌드가 실패하면 로그에서 오류 줄만 추려 화면에 찍습니다. 그런데 그 로그를
**UTF-8 로** 남기고 있었습니다. UTF-8 파일을 CP949 콘솔에 그대로 찍으면
컴파일러가 낸 한글 오류 메시지가 깨집니다. 정작 제일 읽어야 할 글자가요.

로그를 두 개로 나눴습니다.

| 파일 | 인코딩 | 쓰임새 |
|---|---|---|
| `build.log` | UTF-8 | 전체 기록. 편집기로 열 것 |
| `build.err.log` | 콘솔 인코딩(기본 ANSI) | 오류 줄만. 화면에 찍을 것 |

MSBuild 는 파일 로거를 여러 개 붙일 수 있습니다.

```
/fl1 "/flp1:logfile=build.log;verbosity=normal;encoding=UTF-8"
/fl2 "/flp2:logfile=build.err.log;errorsonly;verbosity=normal"
```

화면에 찍을 것은 콘솔 인코딩으로, 편집기로 열 것은 UTF-8 로. 한 파일로
두 가지를 다 하려던 게 욕심이었습니다.

---

## 4. 확인하지 못한 것

이 컨테이너에는 cmd.exe 가 없어서 **배치 파일을 실제로 돌려 보지 못했습니다.**
대신 이렇게 확인했습니다.

- CP949 로 인코딩했다가 다시 풀어서 글자가 그대로인지 (왕복 확인)
- 한글 바이트에 `^` `|` 가 섞이지 않았는지
- 괄호가 짝이 맞는지 (따옴표 안·주석 제외: 15 / 15)
- `goto` / `call` 대상 라벨이 모두 있는지 (`collect` `fail` `hold` `msg` `msg_ko`)
- 괄호 블록 안의 메시지에 `(` `)` 가 들어가지 않았는지

그래도 안 되면, **화면에 뭐가 나오는지 그대로** 알려 주세요. 깨진 모양이
`?????` 인지 `ë¹Œë"œ` 인지 네모인지에 따라 원인이 다릅니다.
