# 80 — 분석 2 칸에서 군글자 빼기 · 칸을 누르면 파일 고르기

> 그리고 메인화면 분석 2에 견줄자리, log파딜을 비교한 후 점수 이런 글자들
> 다 빼주셈
> 그리고 파일 드래그로 넣는 칸 클릭하면 폴더 열려서 파일 선택할 수 있게도
> 해주고

## 1. 분석 2 칸에 로그 이야기가 적혀 있었습니다

DB 를 읽기 전 분석 2 칸이 이랬습니다.

```
┌ 분석 2 ─────────────────────┐
│ ?? / 100                    │   ← 점수 자리를 쓰고 있었습니다
│ Log 파일을 비교한 후 점수가   │   ← DB 칸에 로그 이야기
│ 나옵니다                     │
│                             │
│ 견줄 자리  (끌어다 놓기 · …)  │   ← 칸이 이미 "이전/이후" 라고 적고 있음
│ ┌ 이전 ─┐                   │
```

점수 자리를 **쓰지 않는 칸**이라는 깃발(`UsesVerdict`)을 뒀습니다. 분석 2 는
점수가 아니라 PASS·WARNING·FAIL 을 적는 칸이라, 읽기 전에는 **아무것도 안
적습니다** — `??` 는 "점수가 올 자리인데 아직 안 나왔다" 는 뜻이고, 이 칸에는
점수가 올 자리가 없습니다. 적을 글이 없으면 그 줄은 아예 사라집니다.

"읽기 전" 이라는 말은 **아래 요약 칸**이 합니다 ("아직 읽지 않았습니다. 위
칸에 견줄 자리를 넣으면 그 자리에서 읽습니다"). 같은 말을 두 군데에 적지
않습니다.

"견줄 자리 (…)" 머리글도 뺐습니다. 칸이 **이전 / 이후**라고 이미 적고 있고,
무엇을 넣는 자리인지는 칸 아래 작은 글이 말합니다.

## 2. 칸을 누르면 파일 고르는 창

네 칸 다입니다 (분석 1 의 로그 둘, 분석 2 의 견줄 자리 둘).

끌어다 놓기만 되면 탐색기를 띄워 놓고 끌어와야 합니다. 그리고 무엇보다
**끌어다 놓기가 된다는 것을 모르는 사람에게는 그 칸이 그림일 뿐입니다.**
커서도 손 모양으로 바꿨습니다.

고르는 규칙은 **원래 있던 자리**를 그대로 씁니다 — 분석 1 은 위쪽
[이전 로그 열기] 와 같은 길(`OpenLog`), 분석 2 는 그 화면의 [파일] 과 같은
길(`DbView.PickFileFor`). 두 군데에 적어 두면 한쪽만 고치는 날이 옵니다.

**폴더는 그 창으로 못 고릅니다** (파일용 창입니다). 그래서 칸 아래 글을
화면마다 다르게 둡니다.

| 어디 | 아직 안 정했을 때의 글 |
|---|---|
| 메인 화면 칸 | `누르면 파일 고르기 · 폴더는 끌어다 놓기` |
| 분석 2 화면 | `끌어다 놓거나, 타 넣거나, 단추로 고르세요` |

두 화면이 같은 글을 쓰면 한쪽이 거짓이 됩니다 (메인 화면에는 단추도 타 넣는
자리도 없고, 분석 2 화면의 칸은 눌러도 창이 안 뜹니다 — 거기 칸 안에는 타
넣는 자리가 있어서 누르기를 그쪽이 받습니다). **글은 둘이지만 자리는
`DbPathText` 한 곳**입니다.

## 이름이 겹쳤던 것

`HasScore` 가 이미 있었습니다 ("점수를 재 봤는지"). 새로 둔 것은 "적을 글자가
있는지" 라서 뜻이 다릅니다 — `HasScoreText` 로 갈랐습니다. 컴파일러가
잡아 줘서 바로 알았습니다 (같은 이름으로 두면 둘 중 하나가 조용히 다른
뜻으로 쓰입니다).

## 시험

`통과 823 / 실패 0` — 늘어난 것은 없습니다. 이번 것은 화면 글자와 누르기라
시험이 닿지 않는 자리입니다 (검사기 셋은 다 통과).

## 아직 못 본 것

Windows 에서 봐 주셔야 합니다: 칸을 눌렀을 때 창이 뜨는지(끌어다 놓기와
부딪히지 않는지), 분석 2 칸이 읽기 전에 깔끔한지, 커서가 손 모양으로
바뀌는지.
