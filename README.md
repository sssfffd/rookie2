# LogScope — IO 로그 그래프 뷰어

엑셀(.xlsx) / CSV 로 뽑은 IO 로그를 열어 그래프로 보고, 개조 전/후 로그 두 개를
견주는 윈도우 데스크톱 프로그램입니다.

화면은 셋입니다. 위 메뉴에서 오갑니다 (**F1 / F2 / F3**).

- **대시보드** — 켜면 먼저 나옵니다. 이전/이후를 견준 요약 네모 칸과
  차이가 난 IO 목록. 목록에서 IO 를 누르면 그 IO 만 켜진 채로 그래프로 넘어갑니다.
- **그래프** — 시간에 따른 파형. 왼쪽 목록/그룹에서 직접 골라 볼 수도 있습니다.
- **히트맵** — 시간을 1 분씩 잘라 "어느 IO 가 어느 시간대에 벌어졌는지" 를
  한눈에. 칸을 누르면 그 IO 와 그 시간대로 그래프가 열립니다.

---

## 1. 빠르게 쓰기

```
build.bat
out\LogScope.exe
```

`out` 폴더를 통째로 복사하면 다른 PC 에서도 그대로 실행됩니다.
설치 프로그램이 없고, 레지스트리도 건드리지 않습니다.

| 필요했던 것 | 쓴 것 | 어디 것인가 |

## 4. 어느 것을 빌드하고, 실행 파일은 어디에 생기나

솔루션에 프로젝트가 셋 있습니다. **직접 고를 필요는 없습니다** — `LogScope.App`
하나만 빌드하면 나머지는 따라옵니다.

| 프로젝트 | 무엇 | 결과물 |
|---|---|---|
| **LogScope.App** | **실행 파일. 이게 시작 프로젝트입니다** | `LogScope.exe` |
| LogScope.Core | App 이 참조하는 라이브러리 (자동으로 같이 빌드됨) | `LogScope.Core.dll` |
| LogScope.Tests | 콘솔 자체 테스트 (실행 파일과 무관) | `LogScope.Tests.exe` |

### 실행 파일 위치

```
out\LogScope.exe                           <- build.bat 을 돌린 뒤. 이 폴더째 복사하면 됩니다
src\LogScope.App\bin\Release\LogScope.exe   <- Release 로 빌드한 자리
src\LogScope.App\bin\Debug\LogScope.exe     <- Visual Studio 에서 F5 로 돌릴 때
```

### Visual Studio 에서 F5 가 엉뚱한 걸 실행한다면

솔루션 탐색기에서 **LogScope.App 을 오른쪽 클릭 → "시작 프로젝트로 설정"**.
(`LogScope.Tests` 가 시작 프로젝트로 잡혀 있으면 콘솔 창만 뜹니다.)

## 5. 빌드하는 네 가지 방법

**(1) build.bat** — 가장 간단합니다. MSBuild 를 스스로 찾아 빌드하고 테스트까지 돌립니다.

```
build.bat            Release + 테스트
build.bat Debug      Debug
build.bat Release nt 테스트 건너뛰기
```

**(2) Visual Studio 2017** — `LogScope.sln` 을 열고 F5.

**(3) VS Code (확장 없이)** — `Ctrl+Shift+B`. `.vscode/tasks.json` 이 `build.bat` 을 부릅니다.
   C# 확장이나 OmniSharp 이 없어도 빌드는 됩니다 (자동완성만 없습니다).

**(4) CMake (선택)**

```
cmake -S . -B build -G "Visual Studio 15 2017" -A x64
cmake --build build --config Release
```

### 한글이 깨져 보인다면

`build.bat` 은 UTF-8(BOM 없음)로 저장돼 있고, 시작할 때 콘솔을 UTF-8
(`chcp 65001`)로 바꿨다가 끝날 때 원래대로 되돌립니다. 한국어 윈도우 콘솔은
기본이 코드 페이지 949 라서, 이 과정이 없으면 한글이 전부 깨집니다.

파일을 고칠 때 **UTF-8(BOM 없음)을 유지**해 주세요. BOM 이 붙으면 cmd.exe 가
첫 줄에서 이상한 글자를 찍거나 아예 실패합니다.

빌드 로그(`build.log`)도 UTF-8 로 남깁니다. 메모장·VS Code 어디서 열어도
한글이 제대로 보입니다.

### 빌드가 실패하면

`build.bat` 은 모든 출력을 **`build.log`** 에 남깁니다. 창이 닫혀 버려도 그
파일을 열어 보면 됩니다. 더블클릭으로 실행한 경우에는 끝나고 창을 붙들어
두므로 오류를 그 자리에서 읽을 수 있습니다.

## 7. 허용 오차 (차이로 셀지 말지의 기준)

기본값은 **채널 값 범위의 0.1%** 입니다. 채널마다 값의 크기가 달라서
절대값 하나로는 다룰 수 없기 때문입니다.

| 채널 | 값 범위 | 기준값 | 1 만큼 벌어지면 |
|---|---|---|---|
| 아날로그 (0 ~ 4000) | 4000 | 4 | 잡음 — 안 셉니다 |
| 아날로그 (0 ~ 100) | 100 | 0.1 | 차이 — 셉니다 |
| 디지털 (0 / 1) | 1 | 0.001 | 차이 — 완전히 다른 상태 |

바꾸는 곳은 세 군데이고 **모두 같은 값**입니다. 설정 파일에 저장됩니다.

- 설정 창 → [비교] — 비율(%)과 절대값, [허용 오차를 기본값으로]
- 그래프 화면 도구 줄 — 비율(%)
- 히트맵 화면 도구 줄 — 비율(%)

절대값도 함께 넣으면 **둘 중 큰 쪽**이 기준이 됩니다.
바꾼 뒤에는 [비교 다시 하기](F5) 를 눌러야 대시보드에 반영됩니다.

자세한 이유는 [claude-log/05-tolerance.md](claude-log/05-tolerance.md).

### 히트맵 칸의 숫자

칸에 적히는 값은 **기준을 넘은 표본들의 평균 차이**입니다. "벌어졌을 때
이만큼 벌어졌다" 는 뜻이라, **빨간 칸의 숫자는 언제나 허용 오차보다 큽니다.**
구간 전체의 평균을 적으면, 60 표본 중 하나만 크게 튄 칸이 빨간데도 허용 오차보다
작은 숫자를 달게 되어 위아래가 어긋나 보입니다
([claude-log/08](claude-log/08-heatmap-tolerance-mismatch.md)).

허용 오차를 바꾸면 요약 위에 안내 줄이 떠서, 지금 보이는 히트맵이 아직 예전
기준으로 그려져 있다는 것을 알려 줍니다. [히트맵 다시 계산] 을 누르면 사라집니다.
로그가 크면 계산이 몇십 초 걸릴 수 있어서 자동으로 다시 돌리지는 않습니다.

상태(문자열) 채널에는 허용 오차를 매기지 않습니다 — 이름이 다르면 차이입니다.
칸에는 "다른 표본의 비율" 이 적힙니다.

### 값이냐 퍼센트냐

히트맵 도구 줄의 [값 그대로] / [% (값 범위 대비)] 로 고릅니다.

같은 "평균 차이 3" 이라도 0 ~ 5 를 오가는 IO 에서는 60% 틀어진 것이고,
0 ~ 4000 인 IO 에서는 0.075% 짜리 잡음입니다. 퍼센트로 보면 IO 끼리 견줄 수
있습니다. 나누는 밑값은 **허용 오차와 같은 값 범위**라서, 칸에 `0.09%` 라고
적혀 있으면 기본 기준(0.1%) 아래라고 그대로 읽으면 됩니다.

칸에 마우스를 올리면 아래 띠에 그 칸의 값·퍼센트·**기준값**이 나란히 나옵니다.
기준값도 값과 %로 함께 적어서, 위 도구 줄의 허용 오차와 바로 견줄 수 있습니다.

```
압력 PT-01   09:12 ~ 09:13   차이 발생
차이 난 구간의 평균 6 bar (0.15%)   (기준을 넘은 표본 3 / 60)
기준 4 bar (0.1%)   최대 7 bar (0.175%)   구간 전체 평균 0.3 bar (0.0075%)
```

고른 값은 설정에 저장됩니다.

### 그래프 세로축

세로 눈금 왼쪽 위에 그 눈금이 무엇인지 적습니다 — 단위(`bar`), `상태`,
`0–1 정규화`, `Δ bar` 중 하나입니다. 겹쳐보기에서 단위가 서로 다른 채널이
한 눈금을 같이 쓸 때는 어느 하나를 적으면 거짓말이 되므로 비웁니다.

단위는 엑셀에서 가져옵니다.

| 어디 | 생김새 |
|---|---|
| 머리 행 바로 아래의 단위 줄 | `Time / sec`, `PT01 / bar` |
| IO 이름 끝의 괄호 | `압력 PT-01 [bar]`, `AI_TEMP(degC)` |

IO 이름은 엑셀에 적힌 그대로 둡니다. 단위를 떼어내 이름을 줄이지 않습니다.

눈금 글자도 채널에 맞춥니다.

| 채널 종류 | 눈금 |
|---|---|
| 상태 (문자열) | 번호 대신 **상태 이름** (`IDLE`, `RUN` …) |
| 디지털 (0 / 1) | `0` 과 `1` 에만 |
| 아날로그 | 보기 좋은 간격의 숫자 |

자세한 이유는 [claude-log/07-units-and-percent.md](claude-log/07-units-and-percent.md).

## 8. 조작 방법

| 하고 싶은 것 | 방법 |
|---|---|
| 시간 확대/축소 | 그래프 위에서 **휠** (한 칸에 약 14% 씩만 바뀝니다) |
| **값(세로) 확대/축소** | **Shift + 휠**. 커서가 가리키던 값이 제자리에 남습니다 |
| 이동 | 그래프를 **끌기** (가로 = 시간, 세로 = 값) |
| 커서 A | 그래프를 **누르기** |
| 커서 B | **Shift + 누르기** |
| 전체 구간 | **Home** 또는 [전체 구간 보기] |
| 화면 전환 | **F1** 대시보드 / **F2** 그래프 / **F3** 히트맵 |
| 로그 열기 | **Ctrl+O** 이전 / **Ctrl+Shift+O** 이후 |
| 비교 다시 하기 | **F5** |
| IO 여러 개 고르기 | **Shift + 누르기** 로 범위 (화면에 보이는 순서대로) |
| IO 끄기 | 켠 IO 를 **다시 누르기**. 다른 IO 를 눌러도 꺼지지 않습니다 |
| 그룹에 IO 넣기 | IO 를 그룹 이름 줄로 **끌어다 놓기**, 또는 [고른 IO를 이 그룹에 담기] |
| 히트맵 칸 너비 | **Ctrl + 휠** |
| 히트맵 옆으로 | **Shift + 휠** |
| 히트맵에서 그래프로 | 칸을 **누르기** (그 IO, 그 시간대로 열립니다) |
| 차이 난 IO 목록 정렬 | **제목 칸을 누르기**. 같은 칸을 다시 누르면 방향이 뒤집힙니다 |

## 9. 알아 둘 점 / 아직 못 한 것

- 모니터별 DPI 는 `App.config` 의 스위치로 켭니다. 그 PC 에 .NET Framework
  4.6.2 이상이 깔려 있어야 동작합니다 (윈도우 10/11 은 4.8 이 기본).
  윈도우 7 에 4.6.1 만 있으면 조용히 시스템 배율로 돕니다.
- `.xls` (예전 엑셀 이진 형식) 는 읽지 못합니다. 엑셀에서 `.xlsx` 로 저장해 주세요.
- 히트맵은 이전 로그와 이후 로그가 **둘 다** 있어야 나옵니다.
- 그래프는 화면 배율(DPI)에 맞춰 장치 픽셀 수만큼 접어 그립니다. 표본이
  픽셀보다 성긴 구간(크게 확대했을 때)에서는 접지 않고 표본을 그대로 잇고,
