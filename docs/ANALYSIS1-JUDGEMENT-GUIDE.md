# 분석 1 정상 판정 — 쉽게 정리 (입문자용)

> 공정 입문자 · 개발 입문자가 읽도록 쓴 글입니다. 어려운 말(DTW, envelope, Δt …)은 쉬운 말로 바꿨고,
> 처음 나올 때 괄호에 원래 이름을 적었습니다. 아직 **제안**이며 코드는 만들지 않았습니다
> (대화 기록 136 ~ 142 를 한 곳에 모은 것).

---

## 0. 이 프로그램이 하려는 일

**같은 레시피로 두 번 돌린 공정 로그를 놓고, 두 번째(이후)가 정상으로 돌았는지 판단합니다.**

요리로 비유하면:

```
 이전 로그 = 잘 된 요리를 만들 때 적어 둔 기록 (불 세기 · 온도 · 시간)   ← 정상 기준
 이후 로그 = 오늘 만든 요리의 기록                                       ← 검사 대상
 질문     = "오늘 요리, 정상적으로 만든 거 맞아?"
```

중요한 점: **정상이어도 두 기록은 똑같지 않습니다.**
- 물이 끓는 데 10 초 더 걸릴 수도 있고 (시간 차이)
- 온도계가 0.5 ℃ 다르게 읽을 수도 있습니다 (작은 값 차이)

그래서 "똑같은가?" 가 아니라 **"정상 범위 안에서 다른가, 정상 범위를 벗어났는가?"** 를 봐야 합니다.

---

## 1. 지금 방식의 문제

지금 분석 1 은 시작 시각을 맞춘 뒤 **같은 시각의 값끼리 하나씩 빼서** 허용 오차를 넘는지 봅니다.

```
 이전   ____/‾‾‾‾‾‾‾‾‾‾
 이후   _____/‾‾‾‾‾‾‾‾‾      ← 0.3 초 늦게 올라감 (정상 범위)
 차이       ▲                ← 그 0.3 초 동안 값이 크게 다르다고 "차이" 로 잡힘
```

→ **정상인데도 차이가 많이 나옵니다.** 그래서 시간 차이에 덜 예민하면서도, 진짜 이상은 놓치지 않는 방법이 필요합니다.

## 2. 용어 정리 (이 글에서 쓰는 말)

| 쉬운 말 | 원래 이름 | 뜻 |
|---|---|---|
| 이전 로그 | reference | 정상으로 돈 기록. 판단 기준 |
| 이후 로그 | target | 검사할 기록 |
| IO | 채널 · 태그 | 센서 하나 (온도, 압력, 밸브 열림 …) |
| 단계 | step, 레시피 스텝 | 공정 순서 하나 (가스 넣기 → 압력 맞추기 → 플라즈마 켜기 …) |
| 샘플 | sample | 기록 한 줄. 0.1 초마다 한 줄이면 1 시간 = 36,000 줄 |
| 값 허용 오차 | tolerance | 이만큼 값이 달라도 같다고 봄 (예: ±2 %, ±0.5 ℃) — **지금도 있음** |
| 시간 여유 | Δt (델타 t) | 이만큼 시간이 어긋나도 같다고 봄 (예: ±1 초) |
| 튐 | glitch, spike | 아주 잠깐 값이 튄 것 |
| 차이 구간 | segment | 정상 범위를 벗어난 채 이어진 시간 |
| 치우침 | drift | 범위 안이지만 계속 한쪽으로 쏠린 것 |
| 중요 IO | critical | 짧게만 달라도 불량인 IO (인터락, RF 반사파 …) |
| 판정 | verdict | PASS(정상) · WARNING(확인 필요) · FAIL(이상) |

## 3. 쓰는 기법 — 하나씩: 무엇을 하나 · 무엇이 해결되나 · 부작용은?

### ① 단계마다 시작 맞추기 (지금도 있음)

**하는 일**: 단계가 시작된 시각끼리 맞춥니다.
```
 이전   [1단계 ][2단계   ][3단계 ]
 이후   [1단계  ][2단계   ][3단계 ]    ← 2단계가 늦게 시작
          ↓ 단계마다 시작을 맞춤
 이후   [1단계  ][2단계   ][3단계 ]    ← 2단계 시작이 이전과 겹침
```
**해결**: 앞 단계가 조금 늦어진 것이 뒤 단계 전체를 "차이" 로 만들지 않습니다.
**부작용**: "늦게 시작했다" 는 사실이 묻힐 수 있음.
**막는 장치**: 단계 길이 · 시작 지연은 ⑦ 에서 따로 검사하고 화면에 적습니다. → **남는 부작용 없음.**

### ② 단계 안을 비례로 늘이고 줄이기

**하는 일**: 단계 길이가 다르면 단계 안을 고무줄처럼 늘이거나 줄여 맞춥니다.
(예: 이전 10 초, 이후 11 초 → 이후를 10 % 줄여서 비교)
**해결**: 중간 동작이 조금 느려도 모양이 같으면 정상으로 봅니다.
**부작용**: 진짜로 느려진 것(고장 징후)을 숨길 수 있음.
**막는 장치**: 늘이기 **전에** 길이 차이를 먼저 판정합니다 — 5 % 또는 0.2 초(2 샘플)를 넘으면 WARNING, 이유에 "2 단계가 1.1 초 길어짐" 이라고 적습니다. → **숨겨지지 않음.**

### ③ 시간 여유 띠로 비교 (핵심, 원래 이름: envelope)

**하는 일**: 이후의 어떤 순간 값을, 이전의 **같은 시각 앞뒤 시간 여유 안에 있던 값들의 최소 ~ 최대** (+ 값 허용 오차) 와 비교합니다. 그 안에 들어오면 같다고 봅니다.
```
 이전 값으로 만든 띠  ░░░░░▓▓▓▓▓▓▓▓▓▓      ← 올라가는 구간은 띠가 넓어짐 (앞뒤로 여유)
 이후                ____/‾‾‾‾‾‾‾‾‾       ← 0.3 초 늦어도 띠 안 → 같음
```
**해결**: 작은 시간 차이 **와** 작은 값 차이를 한 번에 흡수합니다.
**부작용**: 값이 급하게 변하는 순간에는 띠가 넓어져서, 그 짧은 순간의 이상은 덜 보입니다.
**막는 장치**: 시간 여유를 작게 잡습니다 — **단계 길이의 2 %** (최소 0.2 초 ~ 최대 5 초). 중요 IO 는 ④ 의 예외를 적용합니다. 시간 여유보다 긴 이상은 그대로 잡힙니다.

### ④ 짧은 튐 지우기

**하는 일**: 시간 여유보다 짧게 끝난 차이는 셈에서 뺍니다.
**해결**: 센서 잡음 한 번에 FAIL 이 나지 않습니다.
**부작용**: **아킹(순간 방전) 같은 진짜 짧은 이상까지 지울 수 있습니다.** (0.1 초 기록이면 한 점으로만 찍힐 수도 있음)
**막는 장치**:
- 중요 IO 는 튐 지우기를 **끕니다** → 0.1 초짜리 한 점도 FAIL
- 일반 IO 도 허용 오차의 **3 배를 넘는 튐은 남깁니다** → 큰 튐은 안 지워짐

### ⑤ 정도 재기

**하는 일**: IO 마다 아래를 셉니다.
- 다른 시간 · 비율 (예: 10 분, 16.7 %)
- 가장 길게 이어진 차이 (예: 8 분 연속)
- 차이가 난 단계 · 최대 오차
**해결**: "1 분 다름" 과 "50 분 다름" 을 구분하고, 화면 · LLM 에 **왜 그 판정인지** 를 적습니다.
**부작용**: 비율을 로그 **전체**로 계산하면, 짧지만 중요한 단계(메인 식각 등)의 이상이 긴 대기 시간에 묻힙니다.
**막는 장치**: 비율을 **단계마다** 계산하고 가장 나쁜 단계로 판정합니다. → **남는 부작용 없음** (계산만 늘어남).

### ⑥ 치우침 검사 (원래 이름: drift)

**하는 일**: 단계 평균값을 비교합니다.
**해결**: 띠 안에 있지만 단계 내내 한쪽으로 쏠린 것(예: 압력이 계속 조금 높음)을 잡습니다.
**부작용**: 장비마다 원래 조금씩 치우쳐 있어 괜히 경고가 늘 수 있음.
**막는 장치**: 허용 오차의 **절반 넘게** 치우칠 때만, 그리고 **WARNING 까지만** 냅니다 (이것만으로 FAIL 안 남).

### ⑦ 공정 순서 검사

**하는 일**:
- 단계 수 · 순서가 같은지 → 다르면 FAIL
- 단계 길이 차이 (② 참고) → WARNING
- 켜짐/꺼짐 IO(밸브 등)가 켜지는 순서 · 횟수가 같은지 → 다르면 WARNING (중요 IO 면 FAIL)
**해결**: "밸브 B 가 A 보다 먼저 열림" 같은 순서 이상을 확실하게 잡습니다.
**부작용**: 로그에 단계 정보가 없으면 할 수 없음.
**막는 장치**: 단계가 없으면 로그 전체를 한 단계로 보고 ③ ~ ⑥ 만 합니다. 기존처럼 돌아갑니다.

### ⑧ 사람이 정하는 것은 둘뿐

| 설정 | 하는 일 | 기본 |
|---|---|---|
| **중요 표시** | 그룹이나 IO 에 체크. 체크한 것은 짧은 차이도 FAIL, 튐도 안 지움 | 체크 없음 |
| **엄격도** | 느슨 · 보통 · 엄격 하나로 위 숫자들을 한꺼번에 조이거나 풂 | 보통 |

나머지(시간 여유, 경고/실패 비율 등)는 프로그램이 정합니다.
**해결**: IO 수백 개에 숫자를 일일이 넣지 않아도 됩니다.
**부작용**: 중요 표시를 안 하면, 인터락처럼 짧은 이상이 치명적인 IO 가 WARNING 에 그칠 수 있음.
**막는 장치**: 처음 쓸 때 안전 · 인터락 · RF 그룹에 체크하도록 설정 화면에 안내합니다.

## 4. 판정 규칙 (최종)

| 대상 | PASS | WARNING | FAIL |
|---|---|---|---|
| 일반 IO | 단계별 차이 비율 5 % 미만 | 5 % 이상 · 단계 길이 차이 · 치우침 · 켜짐 순서 다름 | 20 % 이상 |
| 중요 IO | 차이 없음 | — | 시간 여유보다 긴 차이 · 큰 튐 하나라도 |
| 공정 전체 | — | — | 단계 수 · 순서 다름 |
| **분석 1 판정** | 가장 나쁜 판정을 따름 + 원인 상위 5 개 | | |

엄격도: 느슨 = 시간 여유 ×2 · 비율 10 / 40 %, 엄격 = 시간 여유 ×0.5 · 비율 2 / 10 %.

### 예 (60 분 로그, 엄격도 보통)

| 상황 | 결과 | 이유 |
|---|---|---|
| 2 단계가 30 초 늦게 시작, 모양은 같음 | PASS | ① 로 맞춰짐 |
| TEMP 가 시작 후 1 분만 다름 | PASS | 해당 단계 비율이 낮음 (정도는 기록) |
| PRES 가 10 분 다름 | WARNING | 비율 16.7 %, 8 분 연속, 2 · 3 단계 |
| PRES 가 50 분 다름 | FAIL | 비율 83 % |
| DOOR_LOCK(중요) 10 초 다름 | FAIL | 중요 IO, 시간 여유보다 김 |
| RF 반사파(중요) 0.1 초 튐 | FAIL | 중요 IO 는 튐을 안 지움 |
| 3 단계가 1 초 길어짐 (10 초 단계) | WARNING | 단계 길이 10 % 차이 |

## 5. 쓰지 않는 것과 그 이유

| 기법 | 왜 안 쓰나 |
|---|---|
| **DTW** (시간을 자유롭게 휘어 맞추는 방법) | 밸브가 1 초 늦게 열린 **진짜 문제까지 휘어 맞춰서 숨김**. 계산도 매우 느림 (1 천만 칸이면 사실상 불가) |
| 정상 로그 여러 개로 배우기 | 가장 정확하지만 정상 로그를 모으는 공수가 큼 → **나중** |
| 머신러닝 | 정상 로그 수백 개 · 바깥 라이브러리 필요 (보안상 자제) |

## 6. 다른 곳에 미치는 영향 (사이드 이펙트)

| 걱정 | 답 |
|---|---|
| 그래프 · 히트맵 · 단계 고르기 등 기존 화면이 바뀌나? | **안 바뀜.** 새 판정은 비교 결과 위에 계산을 하나 더 하는 것 |
| 지금 쓰는 값 허용 오차 표는? | **그대로 씀** (③ 의 값 허용 오차) |
| 메인 칸 점수 | 지금 100 고정 → 판정 · 점수가 실제로 나옴 (**의도한 변화**) |
| "차이 개수" 가 줄어드나? | 줄어듦. 정상 범위의 작은 시간 차이를 더 이상 세지 않기 때문 (**의도한 변화**) |
| 예전에 저장한 History | 예전 기준 그대로 남음. 새 판정과 섞어 비교할 때만 주의 |
| 속도 · 메모리 | 로그 길이에 비례하는 계산. 1 천만 칸 1 초 안쪽 예상, IO 하나씩 처리라 메모리 거의 안 늘어남 (추정 · 실측 전) |
| 바깥 라이브러리 | **안 씀** (모두 C# 로 직접) |

### 그래도 남는 위험 (기법으로 못 막는 것)

| 위험 | 대응 |
|---|---|
| 이전 로그 자체가 비정상이면 판정이 다 틀림 | 같은 장비 · 챔버 · 레시피의 정상 로그를 기준으로. PM 직후 · 시즈닝 런은 기준으로 쓰지 않기 (화면 안내) |
| 중요 표시를 빠뜨림 | 처음 쓸 때 안전 · 인터락 · RF 그룹 체크 안내 |
| 시간 여유보다 짧은데 큰 튐도 아닌 일반 IO 의 짧은 이상 | 일반 IO 에서는 정상 잡음과 구별할 수 없어 일부러 넘김. 중요하면 중요 표시 |

## 7. 만드는 순서 (제안)

1. ③ ~ ⑥ + 판정 (시간 여유 띠 · 튐 지우기 · 정도 · 치우침 · IO 판정 · 분석 1 판정)
2. ① ~ ② · ⑦ (단계 검사 · 비례 늘이기 · 켜짐 순서)
3. 화면: 그룹에 "중요" 체크, 설정에 엄격도, 메인 칸에 판정과 정도
4. (나중) 정상 로그 여러 개로 배우기
