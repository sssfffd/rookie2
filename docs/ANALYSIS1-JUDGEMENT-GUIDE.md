# 분석 1 정상 판정 — 쉽게 정리 (입문자용)

> 공정 입문자 · 개발 입문자가 읽도록 쓴 글입니다. 어려운 말(DTW, envelope, Δt …)은 쉬운 말로 바꿨고,
> 처음 나올 때 괄호에 원래 이름을 적었습니다. 아직 **제안**이며 코드는 만들지 않았습니다
> (대화 기록 136 ~ 142 를 한 곳에 모은 것, 146 · 147 에서 사용자 의견으로 고침).
>
> **1.56 에 만들었습니다** — 메인 분석 1 칸의 판정과, 그 아래 그룹 → IO → 구간별 오차 펼치기 · 허용 (1.59).
> 만든 것은 ① ③ ⑤ ⑦ ⑨ 입니다. 맨 아래 "8. 1.56 에 만든 것" 에 정리했습니다.

## 0. 이 프로그램이 하려는 일

**같은 레시피로 두 번 돌린 공정 로그를 놓고, 두 번째(이후)가 정상으로 돌았는지 판단합니다.**

요리로 비유하면:

```
 이전 로그 = 잘 된 요리를 만들 때 적어 둔 기록 (불 세기 · 온도 · 시간)   ← 정상 기준
 이후 로그 = 오늘 만든 요리의 기록                                       ← 검사 대상
 질문     = "오늘 요리, 정상적으로 만든 거 맞아?"
```

중요한 점: **정상이어도 두 기록은 똑같지 않습니다.**
- 물이 끓는 데 10 초 더 걸릴 수도 있고 (시간 차이)
- 온도계가 0.5 ℃ 다르게 읽을 수도 있습니다 (작은 값 차이)

그래서 "똑같은가?" 가 아니라 **"정상 범위 안에서 다른가, 정상 범위를 벗어났는가?"** 를 봐야 합니다.

## 1. 지금 방식의 문제

지금 분석 1 은 시작 시각을 맞춘 뒤 **같은 시각의 값끼리 하나씩 빼서** 허용 오차를 넘는지 봅니다.

```
 이전   ____/‾‾‾‾‾‾‾‾‾‾
 이후   _____/‾‾‾‾‾‾‾‾‾      ← 0.3 초 늦게 올라감 (정상 범위)
 차이       ▲                ← 그 0.3 초 동안 값이 크게 다르다고 "차이" 로 잡힘
```

→ **정상인데도 차이가 많이 나옵니다.** 그래서 시간 차이에 덜 예민하면서도, 진짜 이상은 놓치지 않는 방법이 필요합니다.

## 2. 용어 정리 (이 글에서 쓰는 말)

| 쉬운 말 | 원래 이름 | 뜻 |
|---|---|---|
| 이전 로그 | reference | 정상으로 돈 기록. 판단 기준 |
| 이후 로그 | target | 검사할 기록 |
| IO | 채널 · 태그 | 센서 하나 (온도, 압력, 밸브 열림 …) |
| 단계 | step, 레시피 스텝 | 공정 순서 하나 (가스 넣기 → 압력 맞추기 → 플라즈마 켜기 …) |
| 샘플 | sample | 기록 한 줄. 0.1 초마다 한 줄이면 1 시간 = 36,000 줄 |
| 값 허용 오차 | tolerance | 이만큼 값이 달라도 같다고 봄 (예: ±2 %, ±0.5 ℃) — **지금도 있음** |
| 시간 여유 | Δt (델타 t) | 이만큼 시간이 어긋나도 같다고 봄 (예: ±1 초) |
| 튐 | glitch, spike | 아주 잠깐 값이 튄 것 |
| 차이 구간 | segment | 정상 범위를 벗어난 채 이어진 시간 |
| 치우침 | drift | 범위 안이지만 계속 한쪽으로 쏠린 것 |
| 판정 | verdict | PASS(정상) · WARNING(확인 필요) · CRITICAL(이상) |

## 3. 쓰는 기법 (146 에서 고침 — ② 늘이기 · ④ 튐 지우기는 뺌, ⑨ 오차 허용을 더함)

| ② | 단계 안을 늘이고 줄이기 | **안 씀** — 단계 시간 차이는 그대로 오차로 알림 |
| ③ | 시간 여유 띠 | 씀 (아래 다시 설명) |
| ④ | 짧은 튐 지우기 | **안 씀** — 아킹을 잡아야 함. 튐도 오차로 알림 |
| ⑤ | 정도 재기 | 씀 |
| ⑥ | 치우침 검사 | **안 씀** (147) |
| ⑦ | 공정 순서 검사 | 씀 |
| ⑧ | 중요 표시 · 엄격도 | **안 씀** (147) — 대신 오차를 사람이 하나씩 허용 (⑨) |
| ⑨ | **오차를 펼쳐 보고 그 자리에서 허용** | 새로 |

### ① 단계마다 시작 맞추기 (지금도 있음)

**하는 일**: 단계가 시작된 시각끼리 맞춥니다. 단계 안의 시간은 **늘이거나 줄이지 않습니다.**
**해결**: 앞 단계가 늦어진 것이 뒤 단계 전체를 "차이" 로 만들지 않습니다.
**부작용**: "늦게 시작했다" 는 사실이 묻힐 수 있음.
**막는 장치**: 단계 시작 지연 · 단계 길이 차이는 ⑦ 에서 **오차 항목**으로 그대로 알립니다.

### ③ 시간 여유 띠 — 다시 설명

**한 문장**: 이후 로그의 어떤 순간 값이, **이전 로그에서 그 순간 앞뒤 몇 초 동안 나왔던 값의 범위** 안에 있으면 같다고 봅니다.

예 — 시간 여유 1 초, 값 허용 오차 ±2:

```
 이후 로그의 12:00:10.0 값을 볼 때

 1) 이전 로그의 12:00:09.0 ~ 12:00:11.0 (앞뒤 1 초) 값을 모두 봄
 2) 그중 가장 작은 값 ~ 가장 큰 값을 구함
 3) 값 허용 오차 ±2 를 양쪽에 더함  → 이것이 "정상 범위"
 4) 이후 값이 범위 안 → 같음,  밖 → 오차
```

| 구간 | 이전 로그의 앞뒤 1 초 값 | 정상 범위 | 이후 값 | 결과 |
|---|---|---|---|---|
| 평평한 구간 | 49 ~ 51 | 47 ~ 53 | 50 | 같음 |
| 평평한 구간 · **아킹** | 49 ~ 51 | 47 ~ 53 | 300 | **오차** (범위가 좁아 바로 잡힘) |
| 올라가는 구간 (이후가 0.3 초 늦음) | 20 ~ 80 (올라가는 중) | 18 ~ 82 | 50 | 같음 (늦은 0.3 초를 흡수) |
| 올라가는 구간 · 이후가 3 초 늦음 | 20 ~ 80 | 18 ~ 82 | 10 (아직 안 올라감) | **오차** (1 초보다 큰 지연) |

그림으로는 **이전 그래프를 형광펜으로 덧칠한 것**입니다. 형광펜 굵기가 가로로 시간 여유, 세로로 값 허용 오차.
평평한 곳은 형광펜 띠가 얇고, 가파르게 변하는 곳은 띠가 넓어집니다. 이후 선이 형광펜 밖으로 나가면 오차.

```
 값                      ▓▓▓▓▓▓▓▓▓▓▓▓▓    ← 평평: 얇은 띠 (값 허용 오차만큼)
                     ▓▓▓▓▓
                   ▓▓▓▓▓                    ← 올라가는 곳: 앞뒤 1 초 사이의 값이 다 들어가 넓어짐
 ▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓
 └──────────────────────────────────── 시간
```

**해결**: 작은 시간 어긋남과 작은 값 차이를 함께 흡수합니다 → 오차 목록이 정상 흔들림으로 넘쳐나지 않습니다.
**데이터를 바꾸나?**: 안 바꿉니다. 늘이거나 줄이지 않고 "범위를 넓게 보는 것" 뿐입니다. 시간 여유보다 큰 지연은 그대로 오차.
**부작용**: 가파르게 변하는 바로 그 순간에는 띠가 넓어서, 그 범위 안에 머무는 작은 이상은 안 보입니다.
평평한 구간의 아킹은 잡힙니다 (위 표).
**막는 장치**: 시간 여유를 작게 — 단계 길이의 2 % (최소 표본 간격 × 2, 최대 5 초). 시간 여유가 0 이면 예전처럼 같은 시각끼리만 비교하는 것과 같습니다.

### ⑤ 정도 재기

**하는 일**: 오차마다 · IO 마다 아래를 셉니다.
- 다른 시간 · 비율 (예: 10 분, 16.7 %) — 비율은 **단계마다**
- 가장 길게 이어진 오차 (예: 8 분 연속)
- 어느 단계 · 최대 오차 (예: 2 단계, +3.2 ℃)
**해결**: "1 분 다름" 과 "50 분 다름" 을 구분하고, 목록을 **큰 것부터** 보여 주며, 판정 이유를 적습니다.
**부작용**: 없음 — 세기만 합니다. 짧은 메인 단계가 긴 대기 시간에 묻히지 않도록 비율을 단계마다 냅니다.

### ⑥ 치우침 검사 — 안 씀 (147)

### ⑦ 공정 순서 검사

- 단계 수 · 순서가 다름 → CRITICAL
- 단계 길이 차이 → 오차 항목 ("2 단계가 1.1 초 길어짐") — **늘이거나 줄여서 숨기지 않음**.
  시간 여유보다 많이 다르면 오차 항목 (WARNING)
  (앞 단계가 길어져 뒤 단계가 늦게 시작한 것은 앞 단계의 길이 오차로 한 번만 셈)
- 켜짐/꺼짐 IO 의 순서 · 횟수 차이 → 오차 항목
- 단계 정보가 없으면 전체를 한 단계로 봄

### ⑧ 중요 표시 · 엄격도 — 안 씀 (147)

시간 여유 · CRITICAL 비율은 고정입니다 (단계 길이의 2 % · 0.2 ~ 5 초, 단계 안 20 %).
어떤 오차가 괜찮은지는 ⑨ 에서 사람이 하나씩 고릅니다.

### ⑨ 오차를 보고 허용 (1.59 · 1.62)

프로그램이 정상/이상을 혼자 다 정하지 않고, **오차를 보여 주고 사람이 고릅니다.**
메인 화면 분석 1 칸 아래에서 그룹을 누르면 IO 들이 펼쳐지고, IO 를 누르면 작은 창이 뜹니다.

```
 분석 1  CRITICAL   차이 발생 4 개
 › ● 공정 단계                                         오차 1      ← 누르면 창
 ▾ ● 밸브                                    2 / 8 달라짐   [그래프]
     › ● PRES_MAIN  오차 1                                  [그래프]   ← 누르면 창 ↓
     › ● RF_REFL    오차 1                                  [그래프]
     › ● TEMP_1     허용됨 1                                [그래프]
       ● V1         오차 없음                               [그래프]

 ┌ PRES_MAIN ─────────────────────────────────────────────────────────┐
 │ 오차 1                                                              │
 │ WARNING  2 · 12:10:00 · 8분 3초 · 최대 3.1   [그래프][이번만 허용][앞으로도 허용] │
 │          이후 63.1 · 이전 범위 59.8 ~ 60.2 · … · 이 단계 오차 16.2 %  │
 └──────────────────────────────────────────────────────── [닫기] ┘
```

- 허용한 오차 줄은 흐리게 "허용됨 · 이번만 / 규칙" 과 **[허용 풀기]**
- 공정 단계 오차 · 한쪽에만 있는 IO 는 맨 위 줄 둘에 모임
- **앞으로도 허용**한 것은 설정 창 **[허용한 오차]** 에서 보고 지움
- **허용된 오차는 판정에서 빠지고** 회색 "허용됨" 으로 목록에 남습니다 (사라지지 않음)
- **앞으로도 허용**은 규칙으로 저장 → 다음 비교에서 같은 IO · 단계 · 이 크기 **이하**면 저절로 "허용됨"
- 판정은 허용 안 된 오차만으로 다시 계산

**해결**:
- 시간 여유 · 비율 같은 숫자를 사람이 감으로 정하지 않아도, 실제로 본 오차를 보고 정함
- 허용 기록이 쌓이면 그 자체가 "정상 범위" 가 됨 — 정상 로그 여러 개로 배우는 것의 간단한 대신

**부작용과 막는 장치**:

| 부작용 | 막는 장치 |
|---|---|
| 잘못 허용하면 진짜 이상을 숨김 | 허용 범위를 **이번에 본 크기까지만** 저장 → 더 커지면 다시 오차로 뜸. 허용됨도 목록에 남음 |
| 허용 규칙이 쌓여 무엇을 허용했는지 모름 | 설정에 허용 목록 (IO · 단계 · 크기 · 허용한 날짜), 하나씩 지울 수 있음 |
| 단계가 없어지거나 차례가 바뀐 것을 계속 허용 | 이것들은 "이번만" 만 됩니다 |
| 오차가 수백 개면 누르다 지침 | 같은 IO 의 오차를 한 줄로 묶고 큰 것부터. 묶음 째 허용 가능 |
| History · LLM 에 허용한 것이 빠짐 | 허용된 오차도 "허용됨" 으로 같이 저장 · 전송 |

## 4. 판정 규칙 (허용 안 된 오차만으로, 1.64)

**분석 1 판정 = 허용 안 된 오차가 있는 IO 수.** 오차 구간 수로 세면 IO 하나의 잔떨림만으로 수가 커져서 IO 로 셉니다.

| 허용 안 된 오차가 있는 IO | 판정 |
|---|---|
| 0 개 | PASS |
| 1 ~ 10 개 | WARNING |
| 11 개 이상 | CRITICAL |
| (IO 수와 상관없이) 단계가 없어짐 · 생김 · 차례가 바뀜 | CRITICAL |
| (IO 오차 없이) 단계 길이 차이만 | WARNING |

오차 줄 하나의 낱말은 심한 정도 표시입니다 — 그 IO 의 그 단계에서 오차 시간이 20 % 이상이면 CRITICAL, 아니면 WARNING.
메인 칸 "차이 발생 N 개" 의 N 이 위 IO 수입니다. 1.64 에 FAIL 이라는 낱말을 모두 CRITICAL 로 바꿨습니다 (분석 2 도).

0.1 초짜리 아킹도 띠 밖이면 오차라서 **최소 WARNING** 입니다. 괜찮은 것이면 허용합니다.

### 예 (60 분 로그)

| 상황 | 결과 |
|---|---|
| 1 단계가 30 초 길어져 2 단계가 늦게 시작 (1 단계 10 분) | 1 단계 길이 **오차 항목** (+30 초, 5 %) → WARNING. 2 단계 안은 시작을 맞춰 비교. 사용자가 허용하면 PASS |
| 3 단계가 1 초 길어짐 (10 초 단계) | 단계 길이 **오차 항목** (+10 %) → WARNING — 늘여 맞추지 않음 |
| 4 단계가 0.1 초 길어짐 (10 초 단계) | 오차 항목으로 보이기는 함 (1 %) · 판정은 PASS |
| TEMP 가 시작 후 1 분만 다름 | 단계 비율 낮음 → PASS (오차 목록에는 보임) |
| PRES 10 분 / 50 분 다름 | WARNING / CRITICAL |
| RF 반사파 0.1 초 튐 (평평한 구간) | 띠 밖 → 오차 항목 (WARNING). 허용하지 않으면 판정에 남음 |
| 이전에 있던 0.3 초 펄스가 이후에 없음 | 거꾸로(이전 → 이후)도 보므로 오차 항목 |

## 5. 쓰지 않는 것과 그 이유

| 기법 | 왜 안 쓰나 |
|---|---|
| **DTW** (시간을 자유롭게 휘어 맞추는 방법) | 밸브가 1 초 늦게 열린 **진짜 문제까지 휘어 맞춰서 숨김**. 계산도 매우 느림 (1 천만 칸이면 사실상 불가) |
| 정상 로그 여러 개로 배우기 | 가장 정확하지만 정상 로그를 모으는 공수가 큼 → **나중** |
| 머신러닝 | 정상 로그 수백 개 · 바깥 라이브러리 필요 (보안상 자제) |

## 6. 다른 곳에 미치는 영향 (사이드 이펙트)
